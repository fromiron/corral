# Design kit source

The user supplied the local `design_kit` project and explicitly authorized copying it into Corral on 2026-10-23. The copied kit determines component appearance and interaction. Corral keeps its product behavior, data boundaries and accessibility; it does not keep a second visual system.

## Canonical entry and source graph

[index.ts](index.ts), exported as `@corral/react/design-kit`, is the canonical product entry. `packages/react/src/ui/*` contains compatibility reexports only. The source tree contains 79 imported component/helper files, including the extracted `WorkspaceTile` and page chrome, the adapted opaque, hex-only `ColorPicker` and the adapted text-only `ChatMessage`.

- `sidebar.tsx` composes `sidebar-core.tsx`, `sidebar-menu.tsx`, source Button, Tooltip, ScrollArea and shared shape, size, surface, icon, hover and spring helpers. `search-field.tsx` composes SidebarInput.
- Source Card, Badge, Table, InputGroup/InputField, CheckboxGroup, RadioGroup, Switch and Accordion provide product compositions. Card's Next.js Link is a native anchor in Corral.
- Source Tabs, TabsList, TabItem and TabPanel use the existing Base UI Tabs primitive and kit size, shape, surface, spring and fluid-hover helpers. Their component and prop types are exported directly, with no adapter or new dependency.
- `AgentGraphNode` extracts the supplied AgentGraph node tile, label hierarchy, elevation and working halo. As in the source, its labels ignore pointer hits. Besides the source's working halo, a waiting (needs you) agent breathes the same halo in the warning colour. Node labels take the surrounding surface level to remain readable across dense connections and keep their contrast when unrelated marks and edges are dimmed. Corral's run graph composes it on the source stage: an AgentCard, an SVG edge layer under the marks, centre-to-centre edges, the lead's orthogonal routes and the legend swatches, with no React Flow. Its `renderTrigger` slot composes the native animated button with the kit Popover trigger without nesting buttons or adding a focus target. Corral supplies localized status and accessible relationship descriptions, observed topology, stable positions, pan/zoom, a quick execution list and the explicit right inspector. The source fixed stage and demo metrics are omitted; popup content and selection belong to the run workspace.
- Source Slider uses the existing Base UI Slider primitive, Motion and kit shape, size, font-weight and spring helpers. The supplied compact size omits step dots by default; the comfortable default pips variant renders each step.
- Source Dialog, Select and Dropdown own their popup surfaces, nested elevation, layout and motion. MenuItem, dropdown search/submenu helpers and popup helpers complete their graph.
- `ui-provider.tsx`, exported as `DesignKitProvider`, supplies Motion's OS reduced-motion policy and the kit's shape, size and Lucide icon contexts. Corral wraps its app entry with this provider.
- Sidebar integrations use the source shell, labeled groups, nested menu and resize rail. Corral retains routing, drawer and preference state, passing `persist={false}` and `shortcut={null}` to avoid a second owner of application state. The provider exposes controlled width updates and bounds; the rail forwards localized accessible labels and keyboard resizing.
- Dialog's `left` position anchors the workbench navigation drawer without the centered popup's half-width/height translation; the caller owns its width and height.
- [components/blocks](components/blocks) holds the source's finished compositions: QueuedStack (source `components/queued-stack.tsx`) and the page chrome (PathBar, Page, SectionLabel and EmptyState) extracted from the sample screens' `components/screens/chrome.tsx`.

`tokens.css` is a copy of `design_kit/styles/tokens.css` (source SHA-256 `c227a3aad1d7e861ea6993e4f39d8acfcb10cde3a15bd710fda840fa68febcfd`) with three local divergences: its theme selectors read `.light:not(.react-flow)` and `.dark:not(.react-flow)`, so React Flow's OS-selected classes leave the graph on the app theme (a comment says so); it adds `--fs-field-touch: 16px`; and `--font-sans` names `"Pretendard Variable"` after `"Inter"`, the Hangul-only variable face declared in [fonts.css](../fonts.css), so Korean text takes the kit's `font-variation-settings` weights. Local SHA-256 `3da0e0f3f0305ddc226e55e84432c3ec5140291a68c0c2f4c723cf5b56f042a0`. Only this CSS snapshot skips formatting. Corral semantic and contrast adjustments live in [theme.css](../theme.css).

## Source adaptations

All imports use package-relative paths instead of the original `@/` alias. TypeScript formatting and import ordering follow Corral. Source timing, hover behavior and spacing remain authoritative.

- Proven wrapped array indices and two-element merge pairs have TypeScript assertions required by `noUncheckedIndexedAccess`. They add no runtime behavior. A radio equality lookup uses `indexOf`.
- Decorative SVGs are marked hidden; narrow lint explanations retain native keyboard scrolling, pointer-gap forwarding to existing operable controls, fixed logo tuple keys, div separator refs and optional cookie persistence. Two redundant source fragments remain unchanged.
- Elevated's default shadow follows the raise (`1 + offset`, capped at the surface level), not the nesting depth: a card nested in a card keeps a top-level card's shadow while its background still steps up, as the source's popups already did with `shadowLevel={3}`. This change was made here and mirrored into the source.
- ToolCallCard has a `row` variant: a group lists its calls as flat rows on a rail under the tool stack instead of raised cards, and a call shown alone keeps its card. This change was made here and mirrored into the source.
- SidebarMenu re-measures when a row's own inline style changes, so a virtualized host that moves rows without resizing them keeps the active and hover backgrounds on the moved row.
- SidebarMenu wraps its decorative hover, active and focus layers in a hidden, boxless list item. This keeps the `ul` structure valid without changing the overlay coordinate system or keyboard rows.
- SidebarMenuSub accepts `elbow`. The guide then ends at the vertical middle of the last mounted row's `[data-sidebar-guide-line]` (or of the row, when that line is absent) and turns into the row on a one-pixel border-colored stroke that stops at the row's edge. The straight left border remains the default, and remains while the last row is unmounted. The guide stays on the physical left.
- Button's content container fills the control and inherits its flex alignment so multi-part labels and trailing counts remain correctly arranged. The compatibility bridge supports Base UI render functions and composed refs; source icon/label components retain their own defaults. Decorative surface and label wrappers ignore pointer hits so the native button or link owns activation even over a `display: contents` label. Destructive actions and media overlays add only their required semantic contrast.
- Dialog exposes actual Base UI change details to consumers before changing state or starting an exit, and respects `details.cancel()`. This preserves settings' nested-popup Escape and IME guards. It also forwards `initialFocus` and `finalFocus` to the primitive.
- Select accepts controlled `open`/`onOpenChange`, supplied display labels, a React-node leading slot/placeholder and popup alignment. Its original selection acknowledgement and animation remain intact. The options bridge uses kit groups and separators for labeled groups and descriptive choices. Descriptions wrap inside content-sized rows in a viewport-bounded popup; plain choices keep their original density. Original-index keys preserve repeated option values.
- MenuItem accepts `labelContent` for existing JSX labels while retaining a text label for typeahead. The Menu bridge composes source rows with Base UI action/radio/checkbox/link behavior and assigns source row indices across groups and fragments.
- `agent-primitives` marks its status glyphs hidden (the status word carries the meaning) and keeps narrow lint explanations for labels set only with an image or progressbar role and for repeatable, static tool-mark keys. Corral passes its own localized status words as labels; the kit's six states choose only the glyph and colour. Inline marks (avatar tiles, tool stacks) take the next surface's background with only the first shadow step's hairline; this change was made here and mirrored into the source.
- AgentTree adds what the run's execution tree needs and the source lacks: `selectedId`/`onSelect` with a stretched card button and `aria-selected` treeitems (selection drawn with `--emphasis`), a per-node `statusLabel`, a `tag` after the name (an advisor's kind), `detail` slot and `cardProps`, `selectable: false` for a run root, localized `labels` (including the elapsed-time format), cost shown only when some node has one, and needs-you/failed lists without action buttons when `onResolve` is omitted. The card header wraps its status badge when the identity and localized status cannot fit together, in both wide and narrow trees. `summaryExcluded` keeps organizational Run and Loop groups out of agent counts and action summaries. `outsideFlow` counts an agent that watches from outside the flow (an advisor) as an agent but never as running. Its treeitems keep a narrow lint explanation because the card button takes focus. A card's `detail` passes clicks through to the card button except on its own links, buttons and inputs, so selecting by clicking anywhere on the card still works.
- AgentLanes adds a fixed window (`startAt` with `now`, or with `endAt` for an ended run; ticks counted from the start, no fading edge, and the `now` marker placed at the current time while a span is live) for a recorded run, hand-offs that can land mid-span (`toAt`) and, when two overlapping spans hand off at nearly the same moment, turn as rounded elbows in pixels (a trunk beside the span that starts or ends there, shared by simultaneous hand-offs) with a settled stroke in the muted foreground, `selectedTaskId`/`onSelectTask` so a span selects its execution (`aria-pressed`, outlined with `--emphasis`) instead of opening the popover, separate tracks for overlapping spans of one lane (the lane grows to fit them), per-span `statusLabel`, `waits` bands, `gaps` that break one span into separate rounded blocks (one button; selection and the live edge go on the blocks, the label sits in the widest), blocks on an opaque surface base so hand-off lines pass under them, a named block that opens to its measured content width on hover or focus with the moderate duration and soft ease (leftward near the right edge, no transition under reduced motion) and `buttonProps`, a hand-off `fromAt` with a `data-handoff` hook, and localized `labels`. Live-span and window-caption text use the foreground role for contrast on their tinted fills; the live fill and edge retain the emphasis accent. Iteration callbacks became loops and repeatable static keys keep narrow lint explanations.
- PlanVsActual shows actuals only when no step has a planned start and duration: plan ghosts, forecast bars, the Plan/ETA markers, the overrun band, the verdict badge and the legend are left out, and Cost appears only when a cost is given. It adds localized `labels`, per-step `statusLabel` and `rowProps`, a generated title id instead of the fixed `pva-title`, and finer axis steps for runs of a few seconds. Its list rows keep narrow lint explanations for the source's focusable ARIA list. `selectedStepId`/`onSelectStep` make each started step a stretched button (`aria-pressed`, its bar outlined with `--emphasis`) instead of a focusable row; steps not yet started stay plain rows.
- ToolCallCard's JSON helpers are exported as `formatJson` and `highlightJson` so other recorded values (the events view's payload) read with the same coloring.
- Popup `data-slot` hooks remain available for contextual dismissal, focus and responsive integration. ScrollArea accepts `viewportTabIndex` for existing keyboard navigation.
- ThinkingStepDetails accepts controlled `open`/`onOpenChange`, so the work log mounts an execution transcript only after its fold first opens. Source Step/Details/Sources parts compose observed model requests, tool groups and agent activity; ordinary response text remains in the answer stream. ThinkingStepsContent takes `settledOnMount` (default false, the source motion): when its panel is open at mount, the steps it mounts with start at their own height without the fade, for a view the host mounts again with its log already open; steps added later and every panel without it keep the source's grow-in. Its timing, layout and other parts remain the source's.
- Tabs retains the source's default segmented appearance, spacing, selected/hover/focus layers, animation and keyboard behavior. Its only adaptations are relative import paths, Corral formatting/import order and a narrow lint explanation that preserves remeasurement when tab children change. No runtime or type-assertion changes were needed.
- CommandMenu keeps the source's input-owned focus with `aria-activedescendant`, fluid hover highlight, grouped sections, shortcut caps, footer hints and dialog motion. Its adaptations are relative imports, Corral formatting, erased index assertions for proven nonempty rows and tabs under `noUncheckedIndexedAccess`, a `for…of` listener loop, and narrow lint explanations for the listbox rows whose keys the input owns.
- TabsSubtle keeps the source's text tabs, hover and selected layers, spring timing and keyboard behavior. Its adaptations are relative imports, Corral formatting/import order, a `Map.values()` loop for the element registry and narrow lint explanations that preserve remeasurement when tab children change.
- Slider retains the supplied styles, spacing, hover, spring timing, defaults and runtime branches. Its adaptations are relative imports, formatting, narrow lint explanations for the existing pointer/keyboard layering and spring synchronization, and erased tuple/index assertions for proven nonempty values, clamped step indices and ResizeObserver entries under `noUncheckedIndexedAccess`.
- ChatMessage imports its text/body/action slots without the unused `File[]` thumbnail branch. Corral's existing authorized artifact preview remains responsible for attachments; no PDF package or external worker is introduced.
- ColorPicker edits the opaque `#rrggbb` colors a theme carries. The alpha slider and alpha field, the format menu and the RGB/HSL/OKLCH channel fields (with their number fields, scrubbing and colour-space conversions), CSS colour resolution and the portal container are left out; `parseColor` accepts exactly six hex digits, with or without `#`. The hex field applies a whole value as it is typed, marks any other value invalid on Enter or blur with a message linked through `aria-describedby`, and Escape puts the value back before a second Escape closes the popover. `labels` localizes the area, hue, hex, eyedropper and invalid-value text; the hue slider passes its name with `label`, which names the thumb. Swatches take `{ color, label }` and carry the name in a tooltip and `aria-pressed`; the panel renders host `children` after them. ColorPickerPopover takes a host `trigger` element and a `popupLabel`, marks its popup `data-slot="color-picker-popup"` for contextual dismissal and keeps 8px from the viewport edge. The area, hue slider, eyedropper, popup motion and exit hold are the source's.

- InputMessage keeps the source input surface, content sizing, toolbar and submit animation. `renderInput`, `inputRef`, `contentSlot`, `renderAction` and submit availability labels let the application own slash/reference menus, IME, draft history, attachments and command delivery. The host disables the source automatic queue and shortcut handlers. The compact toolbar's fixed 24px button height leaves the model chip out: 24px is that chip's least height, so a long name takes another line. The toolbar wraps by default; `toolbar="single"` keeps it on one line from the `sm` width up, as the source does, with the right actions at their size and the left slot giving way, for a composer whose input must not move as its tools change. FileThumbnail keeps local image and generic-file previews without a PDF dependency or remote worker.
- ModelPicker retains the source chip, model rows, short settings row, conditional horizontal Effort tabs, footer text and motion. Base UI owns portal, focus and dismissal. Typed reasoning choices and host labels preserve actual policies and disabled or missing selections; an empty placeholder describes simulation without replacing a saved missing profile. The effort tabs use the foreground token for accessible contrast. Comparative ratings are omitted unless complete measured values are supplied. The chip's name wraps instead of truncating, so a narrow screen shows the whole name on more lines (its height becomes a least height); the trigger and popup carry `data-slot` hooks (`model-picker-trigger`, `model-picker-popup`) so the toolbar and the forced-colors outline in [theme.css](../theme.css) can reach them.
- ModelPicker adds an optional `search` field above the list: it takes the focus on open, the arrows, Home, End and Enter act on the list from the field through `aria-activedescendant`, and Escape closes and returns the focus to the trigger. Models may carry a `group` (consecutive models of one group are a named `role="group"`), search `keywords` and a `markText` for the initial of a model without a brand mark. The list draws only the rows in and near view, each kind of row (a group heading, a one-line row, a two-line row) placed by the height of the first one drawn and estimated until then, and centers the current model on open, so hundreds of models open and filter without drawing every row. Each drawn row carries its `aria-posinset` and `aria-setsize` among the matching rows, `aria-activedescendant` names only a drawn row, and the active row follows its model's id when the list is read again. A model with `imageInput` shows the kit's image mark after its name, named by `labels.image` in its accessible name. A `field` trigger serves forms (bordered, the popup at least the field's width, the model's description after its name, the placeholder while nothing is chosen), `footer={false}` leaves the footer out and `triggerId` names the trigger for a visible label.
- Connections (`connections.tsx`) is adapted from the MCP servers panel (`mcp-servers.tsx`). It keeps the card, the row anatomy (mark, name, one status line under the rolled status glyph, an inline action on a row that needs the person, the disclosure), the expand motion, the fluid hover highlight, arrow-key row navigation, the live announcements, focus after a removal and the sheet whose faces spring into each other. The tool switches, budget meter, permission mode, server URL form and OAuth consent face are left out. A row's expanded body is the host's `details`; every label comes through `labels`; a connection without a logo shows an initials tile. The sheet has its own localized close button and moves the focus to each later face's title. The directory face (a search field, arrows from the field into the rows, `trailing` marks such as `ConnectedMark`) and the discovery face (a count that rolls up from zero over a staggered list of the first eight) are built from the panel's own row, Roll and stagger pieces.
- AgentSteering accepts controlled composer, plan, activity and header-action slots, localized labels and actual directive receipt states. Its original plan rows are extracted as `AgentSteeringPlan` with optional title wrapping and accessible status labels, so the existing host plan controller can retain disclosure, owner selection and full-list access. Its optional activity height bound keeps the single composer outside a named keyboard-scrollable activity region on short screens. Corral supplies its existing single composer and command controller. Unsupported instant interruption, directive removal and per-agent pause actions are absent.
- ToolCallCard/ToolCallGroup add waiting and stopped states using the source status glyphs, so an unfinished tool does not animate as running during an approval wait, pause or cancellation. Expanded code uses the foreground token for punctuation contrast; the source grouping, disclosure and code layout remain intact.
- DecisionInbox keeps the source card, header, row anatomy, pills and motion. Its adaptations are relative imports, Corral formatting/import order, a `labels` prop for the region's accessible name (the heading, clear and empty lines were already props) and a guard in place of the non-null assertion on a missing secondary answer.
- DecisionInbox takes `optimistic` (default true, the source behavior): false sends `onDecide` without setting the confirmation pill, which then comes only from a decision's `resolution`, so a host can tie the pill to a receipt. A decision's `pending` disables both of its buttons through Button's own `disabled` while the host awaits that receipt; no new color, spinner or wording is added.
- AgentHandoff presents one observed agent pair at a time with factual relationship labels and selectable executions. It does not infer an ordered pipeline from unrelated agents. DecisionTree supports read-only recorded selections, explicit unknown branches and evidence details; inspection cannot invoke a workflow decision or choose a default branch.
Tooltip explicitly provides its popup role and trigger description linkage while retaining the supplied hover, focus, and motion behavior.

The Tooltip bridge sets its words beside a shortcut in a row only when there is a shortcut: inside an inline row the trim cut every line after the first. The Select bridge takes `trigger` to wrap its trigger (a tooltip that explains it). AgentTree takes `titleAction`, drawn right after the summary bar's title, and its `agents` label may return a node, so a host can draw the count for the eye and give a screen reader the whole count.

## Narrow API bridges

[adapters](adapters) is part of this design kit, not another component library. Button, Badge, Card, Tooltip, Dialog, Select, Menu and ScrollArea compose the copied components. Former visual variant names map onto kit roles; ordinary controls do not reproduce their old rendering.

The following needs have no matching source contract:

- `Input` preserves native input events, input refs, external labels and file inputs. Source InputField instead owns a controlled string value and a container ref. `Textarea` has no standalone counterpart in the supplied kit. These small native controls use the source field hover/focus states and type/shape tokens; their border stays inside the 36px/28px height, and coarse-pointer settings retain 44px targets.
- `PreviewCardGroup`, `PreviewCardGrid`, `PreviewCard` and `PreviewCardButton` make one choice among cards that each show a picture above a name (the appearance gallery). RadioGroup lists rows and CardGroup has no selection, so the bridge composes them: from RadioGroup one tab stop, arrow keys and Home/End that move and choose at once, a muted name that turns foreground on hover and semibold when chosen, and one selection that springs from option to option (it lands at once under reduced motion); from CardGroup grids with one fluid hover highlight each, whose gaps choose nothing; from ColorSwatch the chosen mark, a 2px gap and a 2px `--emphasis` ring around the picture, with a drawn check. A card's `action` (a menu) is its sibling, never inside the radio, and shows on hover, focus and touch. `PreviewCardButton` is an action tile in the same grid (a dashed frame where a card has its picture).
- Generic `Popover` is absent from the source catalog. Its bridge composes Base UI positioning with source Elevated, and a stable `keepMounted` content container preserves the request-options draft. It retains no separate popup visual skin.
- General horizontal/vertical separators and loading skeletons have no standalone source equivalent. Their small primitives consume kit tokens. Inline actions compose source Button.
- Virtualized scroll fades, scroll chaining and hidden scrollbar options preserve product scrolling behavior while using the source ScrollArea and scrollbar appearance.

## Dependencies and verification boundary

The source dependency versions are Base UI 1.9.0 and Motion 14.1.0, alongside Corral's React 19, Tailwind 4 and Lucide. The [Motion npm metadata](https://registry.npmjs.org/motion/14.1.0) declares MIT and React/React DOM 18 or 19 support. The [official MotionConfig contract](https://motion.dev/docs/react-motion-config) documents `reducedMotion="user"`. No alternate icon families, Next.js or PDF dependencies are imported. Dependency records and notices are maintained separately.

Source fingerprints identify copied files and adaptations. Type checks, browser checks and integrated product validation are separate from this provenance record.
