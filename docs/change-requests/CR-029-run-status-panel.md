# CR-029: 실행 상태 요약과 계측

- 상태: **순차 구현 승인** — Bell, 2026-10-19: “플랜대로 M0부터 순서대로 개선 진행해. CR 등록 → 실패 테스트 → 구현 순서로 하고, 기존 기능 회귀도 확인해.”
- 계획: [통합 개선 실행 계획](../plans/Corral-Improvement-Execution-Plan-2026-10-19.md), M2-2.
- 기준: `780591e`(PR #60 수정 포함). 구현/검증 완료 여부는 단계별 증거로 따로 기록한다.
- 추적: M2 착수 시 기존 panel/usage 시험 확장.

## 계약

1. CR-023 compact 패널을 환경·컨텍스트/비용·연결·변경 네 요약으로 확장한다. 전체 Run/설정 화면을 중첩하지 않고 정확한 상세/Reins 대상으로 연결한다.
2. 실측 usage와 역할별 context 추정을 구별한다. 역할 사용률을 합치지 않고 미정산/미측정을 0으로 표시하지 않는다.
3. 압축은 선택 execution/context version에 고정하고 CR-030의 안전 경계가 준비된 뒤 활성화한다. 인증 성공으로 현재 snapshot을 자동 바꾸지 않는다.
4. 좁은 화면 drawer의 focus 복귀와 기존 전역 명령 팔레트를 유지한다.

## 검증과 배포

새 동작과 데이터·권한·취소 경계의 대표 반례만 구현 전에 실패를 확인한다. 기존 통합 시험을 우선 확장하며 문구·내부 함수·모든 조합을 따라가는 시험은 추가하지 않는다. 적용되는 정상·실패·취소·중복·늦은 이벤트 경계는 기존 시험과 합쳐 확인한다. D&D·Reins·과거 snapshot/hash·전역 활성 Run 제한을 유지한다. live/OS/브라우저 증거는 결정적 fixture와 구별한다.


## C-102 계측 계약

ModelRequestRecord의 선택 필드로 messages에 대한 Pi 1.3.0 `estimateTokens` 추정값·방법을 기록한다. 실제 provider 과금량과 다르며 시스템/도구/메시지 표현에 따른 오차가 있다. 모델 contextWindow는 시작 시 고정하고 없는 과거 기록은 unknown이다. 실행 하나의 마지막 실제 요청을 표시하며 역할별 비율을 합산하지 않는다. 비용은 기존 BudgetInspector를 재사용한다. 연결 표시는 시작 시 인증 방식/실행 당시 하네스 로드 기록이고 현재 인증 probe를 대체하지 않는다. M3 이전에는 압축 버튼을 제공하지 않는다.
