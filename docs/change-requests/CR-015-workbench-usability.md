## Corral 경계

Project → Session → Run → Execution을 유지한다. 요청/지시/대기/결과 질문을 합쳐 하나의 가짜 실행으로 표시하지 않는다. 완료·지시 전달·검토 판정은 Coordinator projection에서만 읽는다. 자동 승인·자동 모델 실행·권한 확대는 하지 않는다. D&D·협업·Reins·불변 버전 검토 경로를 유지한다.

긴 모의 결과의 반복으로 `LIMIT_REACHED: output_tokens`가 발생한 실행도 평가에 포함했다. 한도 작동 자체는 정상이며, 실패 원인과 남은 결과를 이해하기 어려운 표시가 수정 대상이다. 실제 모델 품질 평가나 사람 5명의 사용성 평가를 대신한 결과로 주장하지 않는다.

## 직접 사용한 흐름과 평가

1280×720 한국어 다크 모드의 production Studio를 인앱 브라우저에서 사용했다. 임시 프로젝트·SQLite·Git 작업 복사본과 ScriptedAgentAdapter만 사용했으며 개인 프로젝트나 유료 모델은 사용하지 않았다.

1. **프로젝트 → 목적 → 팀 → 세션**: 팀 편집 왕복에서 초안이 사라지는 문제를 재현 후 수정했다. 새 세션의 첫 요청에 목적이 보존되며 사용자가 보내기 전에는 실행되지 않는다. 첫 화면에 폴더 연결·세션·팀·템플릿·Run 관리가 함께 나오는 정보 밀도는 후속 디자인 과제다. 캡처 01–04, 10.
2. **팀 협업 → 일시정지 → Reins → 재개**: 조사자의 위임, 작성자의 질문/응답, 검토 루프가 실제 실행 기록에 나타났다. 실행 번호와 역할을 드러내고 전달 상태와 정지 상태의 거짓 진행 표시를 수정했다. 캡처 05–07, 11.
3. **실패 → 부분 결과 검토**: 한도 초과는 정상적으로 실행을 멈췄다. 남은 결과와 실패 원인이 대화·산출물 패널에 일관되게 나타나도록 수정했다. 검토 JSON 대신 판정/대상 버전/지적 사항을 표시한다. 캡처 08–09.
4. **검토 대상 → 이전 버전 비교 → 사용자 승인 → 최종 출력 승인**: 두 승인 이후에만 성공했다. 실제 대상 버전은 변하지 않으며 표시 이름과 세션 내부 이동을 개선했다. 캡처 12–13; `review.spec.ts`와 세션 승인 회귀 테스트.
5. **파일 → 줄 참조 → 작업 복사본 → 변경 diff**: 격리된 Git 프로젝트에서 수행했다. 복사본 생성 직후 실행 범위 안내가 갱신되지 않는 오류도 재현 후 수정했다. 파일 도구 권한과 원본 반영 승인은 기존 경계를 유지한다. 캡처 14 이후와 `files.spec.ts`.
6. **긴 대화 → 팀 탭 왕복/재로드 → 과거 결과**: 350ms 늦게 도착하는 결과에서 1100px 읽기 위치가 4292px로 변하는 반례를 고쳤다. 조회 실패 후 재시도, 11회 실행의 가장 오래된 결과 접근까지 회귀 테스트한다.

## T3 Code·PI Desktop과의 비교

- [T3 Code](https://github.com/pingdotgg/t3code)의 프로젝트/대화 탐색, composer, 작업 기록을 기본 구조로 유지한다. Corral의 팀 실행·Reins·정확한 버전 승인은 대화 안에서 요약하고 상세 기록으로 연결한다.
- [PI Desktop](https://github.com/vastsa/pi-desktop)의 프로젝트/세션, 초안, 파일 참조, WorkPanel 흐름과 비교했을 때 이번에 재현한 초안·읽기 위치·결과 일관성 문제는 데스크톱 앱의 기본 사용성 부족으로 판단했다.
- Corral의 D&D 팀 구조, 위임/질문, 검토 루프, 버전별 승인, 한도 제어는 확인한 시뮬레이션 흐름에 적용되어 있다. 실제 모델의 협업 품질·장시간 운영 품질은 별도 검증이 필요하다.
- 비교는 각 저장소의 README와 Sidebar/ChatView, ChatSurface/ChatTranscript 소스에 근거한다. 두 경쟁 앱을 직접 설치·사용한 비교가 아니다. 터미널, 플러그인, 원격 연결, updater 등 별도 제품 기능을 구현했다고 주장하지 않는다.

## 검증 연결

`usability.spec.ts` 6개, 기존 `review.spec.ts`, `files.spec.ts`의 production 서버 E2E로 UX-015-01–08을 확인한다. 초안 유실, queued 정지, 실패 원인 누락, 읽기 위치 이동, 정지 중 진행 표시, 승인 이름, 복사본 안내의 실패를 먼저 재현했다. 구조화된 검토 표시는 기존 ArtifactViewer를 공유하며 HTML 실행 제한은 유지한다. 새 의존성은 없다.
