# CR-024: 세션 자동 팀 선택(auto)과 세션의 시뮬레이션 제거

- 상태: **승인** — Bell, 2026-10-18, "CR-024 승인. 추적 ID 등록 → 실패 테스트 → 구현 순서로 진행해."
- 기준: main `81df4a8`.
- 추적: C-087, CRL-AUTO-001~005, TC-AUTO-001-H/N~005-H/N.
- 보완: 2026-10-18 Bell "추론 auto는 시작 모델이 템플릿을 고를 때 추론 단계(low/medium/high)도 함께 골라서 적용하는 방식으로 해줘. CR-024 보완으로 진행." → §7.
- 바꾸는 계약: CR-011 §3(후속 요청은 세션 팀 필수), CR-021 §7(세션 실행 모드 첫 방문 mock).
- 이후 변경: "이전 결과가 있으면 CR-007대로 그 버전에서 시작한다"는 [CR-054](CR-054-session-conversation-continuity.md)가 대체한다. auto 후속 요청도 세션의 대화 차례를 받는다.
- 유지: CR-006 TeamPlan 패턴과 사람 승인, CR-012 작업 사본·파일 도구·검토, CR-014 D&D·Reins, CR-021 추론 우선순위와 permit, CR-023 화면 책임.

## 배경

1. 간단한 질문도 세션에 팀이 지정되어 있어야만 보낼 수 있다(`noTeamYet`).
2. 세션 Composer의 실행 모드 기본값이 시뮬레이션이다. 시뮬레이션은 팀을 작성할 때는 쓸모가 있지만, 일반 세션 대화에서는 의미가 없다.
3. 팀을 직접 고르지 않을 때 사용할 모델과 추론 단계를 정할 곳이 없다.

## 계약

1. **세션 팀 선택.** 세션의 팀 선택은 `auto` 또는 명시 팀(`corralId`) 중 하나다.
   - 새 세션의 기본은 `auto`다.
   - 팀이 지정된 기존 세션은 그 팀을 유지한다. 팀이 없던 기존 세션은 `auto`로 읽는다. 저장된 ID와 Run 기록은 바꾸지 않는다.
   - Composer의 팀 칩은 `자동`과 프로젝트의 팀 목록을 보여 준다. 명시 팀을 고르면 기존 CR-011 동작을 그대로 따른다.
2. **기본 팀 템플릿.** core가 버전이 붙은 기본 구성을 소유한다. 서버가 explain처럼 정의를 직접 만들며, 사용자 팀 목록에 저장하지 않는다.
   - `single`: 에이전트 하나 → 출력.
   - `write_review`: 기획 → 작성·검토 Loop → 출력.
   - `research_write_review`: 조사 → 작성·검토 Loop → 출력.
   - 구성은 CR-006 패턴과 같은 모양이다. 도구 권한·바인딩·Loop·한도는 템플릿이 고정한다. 사람이 설계한 팀이 아니므로 최종 승인 대기를 두지 않는다.
   - 세션에 작업 사본이 있으면 CR-012 파일 도구를 허용한다. 작성 역할(`worker`·`writer`)은 읽기·쓰기, 나머지 역할은 읽기(`list_files`·`read_file`)만 받는다. 작업 사본이 없으면 `write_artifact`만 허용한다. 모든 템플릿은 기존 컴파일러 검증을 통과해야 한다.
3. **시작 모델의 선택.** `auto`로 보낸 `next` 요청은 다음 순서로 처리한다.
   1. 세션에 고른 모델·추론으로 선택 요청을 한 번 보낸다. 전송 경로가 지원하면 출력 256 토큰을 요청하고, 모든 경로에서 스트림의 관측 가능한 출력(text·thinking)을 UTF-8 256바이트로 제한하며 30초 안에 선택 처리를 끝낸다. 한도를 넘으면 요청을 중단하고 `single`로 대체한다.
      - ChatGPT 구독 OAuth는 공급자가 출력 토큰 상한 필드를 거절한다. 이 경로에서는 바이트·시간 제한으로 응답 수집을 중단하며, 스트림에 노출되지 않는 내부 추론 토큰의 생성 상한까지 보장하지 않는다. 공급자가 보고한 실제 사용량은 실패·중단 응답에도 보존하고 이번 Run의 예산에 포함한다. 한도를 지원하는 것처럼 표시하지 않는다.
   2. 응답에서 `{ template, reason }` JSON만 받아 엄격히 검증한다. 허용 ID 밖의 값, 형식 오류, 시간 초과는 `single`로 대체하고 그 사유를 기록한다.
   3. 고른 템플릿으로 Run을 하나 시작한다.
   - 선택 요청은 Run이 생기기 전 서버가 보내는 요청이다(CR-006 모델 요청과 같은 경로). 그 대신 결과는 Coordinator의 Run 시작 명령으로만 기록한다. `run.started`에 선택 결과(템플릿 ID·버전·출처·대체 사유·모델·추론·입력 hash·사용량)를 남기고, 모델 요청을 썼으면 1회와 출력 사용량을 Coordinator의 예산 기록으로 반영한다. 실행 중 한도를 바꾸어도 이 사용량은 유지한다. 보고된 사용량이 없으면 알려지지 않은 사용량으로 예약해 보수적으로 계산한다. 모델 응답 원문은 남기지 않는다.
   - 선택 요청의 추론은 `fixed(level)`이면 그 단계, `auto`이면 CR-021 기준값 medium, `provider_default`나 생략이면 공급자 기본이다.
   - 같은 command ID와 같은 요청 내용이 이미 Run 시작 명령으로 기록돼 있으면 선택 요청 없이 그 결과를 돌려준다. 처리 중인 같은 명령도 그 처리를 기다린다. 같은 ID에 다른 세션·본문·모델·추론·참조·시작 버전·실행 모드를 보내면 충돌로 거절한다. 응답 연결이 선택 중에 끊기거나 Composer를 떠나면 Run을 시작하지 않는다. 파일 변경의 시작 snapshot과 파일 도구 허용은 선택 대기가 끝난 뒤 실제 Run을 시작하기 직전의 같은 작업 사본 상태에서 정한다. 응답이 불명확한 동안 화면은 처음 보낸 요청 전체(시작 버전·모드 포함)를 명령 ID와 함께 보존하며, 새 결과가 생겨도 재전송 본문을 바꾸지 않는다. Run 이전의 명시 취소는 Coordinator 명령 저장소에 세션 범위로 기록하며 시간 경과·서버 재시작 뒤에도 같은 ID를 다시 시작하지 않는다.
4. **모델과 추론.** `auto` 세션은 모델 프로필 하나와 추론 설정(`fixed(level)`/`auto`/`provider_default`, CR-021)을 저장한다.
   - 그 값은 선택 요청과 고른 템플릿의 모든 역할에 이번 Run의 역할 override로 적용한다. CR-021의 우선순위·지원 단계 검사·거절 규칙을 그대로 따른다.
   - `auto` 세션의 결과 질문(`explain`)은 팀 첫 역할 대신 이 모델을 쓴다.
5. **세션의 시뮬레이션.** live가 가능한 서버의 세션 Composer에는 실행 모드 선택이 없고 항상 live로 보낸다.
   - 모델이 연결되지 않았으면 mock으로 바꾸지 않는다. 시작을 막고 연결 안내를 보여 준다.
   - live가 불가능한 곳(브라우저 데모, 시뮬레이션 전용 서버)에서는 세션이 시뮬레이션만 쓰고, 그 사실을 계속 표시한다. 데모의 선택은 CR-006 로컬 제안 규칙으로 하며 모델을 호출하지 않는다.
   - 팀 편집기의 직접 실행은 mock/live 선택을 유지한다. 이전에 저장된 세션 범위 `mock` 값은 live 가능 서버에서 무시한다.
6. **표시.** Run 카드와 실행 전 요약은 `자동 · <템플릿 이름>`, 선택 사유, 대체 여부, 모델·추론을 보여 준다. 직접 전송과 대기 요청 실행에 같은 기록을 사용하며, 사용자가 고르지 않은 팀 이름처럼 보이게 하지 않는다. `explain`은 선택한 모델을 사용하지만 요청별 추론 선택을 지원하지 않으므로 추론 선택 칩이나 적용 요약을 표시하지 않는다.
7. **요청별 추론 선택(보완).** auto 세션의 추론 설정에 `route`(요청마다 시작 모델이 선택)를 더한다. CR-021의 `fixed`/`auto`/`provider_default`와 별개이며, auto 세션의 저장값에서만 쓴다. 역할 정의와 Run 계약의 추론 정책은 그대로 `fixed`다.
   - 후보는 low·medium·high 중 그 모델이 지원하는 단계다. medium이 없는 모델에서는 `route`를 고를 수 없고, 서버도 선택 요청 전에 거절한다.
   - 선택 요청은 템플릿과 함께 `reasoning`을 받는다. 후보 밖이거나 빠졌으면 템플릿 선택은 그대로 두고 추론만 medium으로 대체하며 그 사실을 기록한다. 템플릿이 대체(`single`)되면 추론도 medium이다. 로컬 규칙(데모·시뮬레이션)도 medium이다.
   - 고른 단계는 템플릿의 모든 역할에 `fixed(level)`로 들어간다. 이미 시작한 실행은 그 값을 유지한다(CR-021).
   - 선택 요청 자체의 추론은 CR-021 기준값 medium이다.
   - `run.started`의 선택 기록에 요청한 설정(`route`)과 고른 단계·출처(`model`/`local`/`fallback`)를 남긴다. 세션 기록과 실행 전 요약에도 표시한다.

## 반례와 검증

- **정상:** 짧은 질문이 `single`, 검토가 필요한 요청이 `write_review`로 시작한다. 명시 팀 세션은 기존과 같다. 이전 결과가 있으면 CR-007대로 그 버전에서 시작한다.
- **실패:** 선택 응답이 허용 밖 ID·깨진 JSON·시간 초과이면 `single`로 대체하고 사유를 남긴다. `route`에서 추론 단계가 후보 밖이거나 빠지면 medium으로 대체하고 사유를 남긴다. 모델 미연결·지원하지 않는 추론 단계이면 선택 요청 전에 거절하며, 초안은 남는다.
- **취소:** 선택 요청 중 취소하거나 화면을 떠나면 Run이 시작되지 않고 permit도 발급하지 않는다. 이미 시작된 Run의 취소는 기존 Reins 규칙을 따른다.
- **중복:** 같은 command ID로 다시 보내면 선택 요청과 Run이 하나뿐이다. 다시 보낼 때 선택 요청을 재호출하지 않는다.
- **늦은 이벤트:** 보낸 뒤에 팀·모델·추론을 바꿔도 보낼 때 정한 값으로 시작한다. 늦게 온 선택 응답이 다른 세션이나 새 초안에 적용되지 않는다.
- 단위·서버 시험이 대부분을 맡고, 모델 호출은 fake provider로 주입한다. E2E는 기존 세션 흐름 하나에 auto 경로를 더하는 정도로 둔다. 실계정 확인은 `pnpm corral dev`에서 opt-in으로, 한도를 정해 수행하며 fixture 증거와 구분한다.

## 하지 않는 것

- 사용자 팀 중에서 LLM이 고르기. 기본 템플릿만 고른다.
- 실행 중 팀 전환, 자동 대기열 실행, 템플릿 사용자 편집.
- auto 선택 결과를 사용자 팀으로 저장하는 것(필요하면 후속 CR에서 "이 구성으로 팀 만들기"를 다룬다).
