# CR-045: Workbench 입력·대화·모델 식별 개선

- 승인: 2026-10-21, Bell이 화면 검토에서 지적한 5개 항목을 우선순위대로 개선하고 기존 동작·실제 화면·관련 회귀를 검증하도록 요청했다.
- 기준: `183e0ce`; CR-043·044의 기본 대화, 설정·초안·권한·실행 수명을 보존한다.
- 추적: CRL-UX-007 / C-141 / TC-UX-007-H,N. 결정: ADR-038.
- 구현: C-141 완료. [검증 기록](../evaluation/Workbench-Identification-2026-10-21.md).

## 승인 범위와 순서

1. 공용 입력 경계는 비포커스·라이트·다크에서도 식별 가능해야 한다. 포커스·오류·비활성 상태와 장식 없는 Dialog 계약을 유지한다.
2. 이름과 목적을 지정하지 않고 만든 대화만 `autoTitle`로 표시한다. 첫 저장된 next/queue 요청의 첫 내용으로 60 code point 이내 제목을 한 번 확정한다. 추가 LLM 호출은 하지 않는다. 제목과 요청은 같은 저장에서 확정하고 revision을 증가시킨다. 직접 제목을 저장하면 자동 제목을 해제한다. 기존 데이터·명시 이름·중복 명령·실패한 저장·늦은 상태 갱신은 제목을 덮지 않는다.
3. 모델·추론·다음 요청의 의미를 유지하면서 320/390px에서 모델명에 우선 공간을 준다. 긴 이름은 줄바꿈하고 메뉴·키보드·Ultra 참여 모델 설정은 그대로 둔다.
4. 사이드바의 제목·목적 필터는 대화 목록 필터로 표시한다. 별도 세션·결과 검색과 비공개 본문·보관 항목 opt-in은 유지한다.
5. 팀 목록의 중복 선택 안내를 정리하고 JSON 형식 안내는 가져오기 제어에 연결한다. 저장 위치 안내, import·레이아웃·템플릿·편집기·D&D·Reins는 유지한다.
6. 같은 날 추가 승인: 일부 컴포넌트에만 테두리가 있는 이질감을 정리한다. 일반 입력·선택과 명시 outline 버튼은 공용 입력 경계 토큰을 사용한다. 대화 입력 그룹·연결된 계획·떠 있는 메뉴/팝오버의 장식 외곽선은 표면과 그림자로 통일한다. 탭 선택·분할선·오류·키보드 포커스·고대비 모드의 의미 있는 경계는 보존한다.
7. 같은 날 후속 수정 요청: 첨부 1·2는 각각 기본·포커스 테두리의 예시다. 기본 테두리는 기존 구분선 토큰 수준으로 낮추고 포커스는 분명히 구분한다. 일반·금고·모델 가져오기·작업 방식의 한 줄 입력/Select/버튼은 36px(터치 44px)로 맞추고 textarea는 줄 수와 크기 조절을 유지한다. 이전 비포커스 경계 3:1 수치 목표는 이 시각적 요청으로 대체하며, 포커스 대비·레이블·오류·비활성·고대비·키보드 동작을 별도로 검증한다. 전체 WCAG 적합성을 주장하지 않는다.
8. 실제 화면 추가 피드백: API 키 표시 버튼은 입력창과 8px 간격을 두고 같은 높이를 사용한다. 저장 버튼도 입력창 아래쪽에 정렬한다. 설정 컨테이너 안의 Input/textarea는 컨테이너보다 어두운 기존 surface 배경으로 통일하며 버튼의 밝은 배경·장식 그림자를 입력창에 쓰지 않는다. 같은 ApiKeyInput을 쓰는 모델 편집기와 표시/숨김·저장·부분 실패 동작도 검증한다.

## 검증

- H: 라이트/다크 입력 대비·키보드 포커스, 제목 영속성·검색 반영, 좁은 화면 모델/추론 표시, 필터와 별도 검색, 파일 가져오기와 템플릿 동선.
- N: 사용자 이름(기본 표시와 같은 문자열 포함)·기존 데이터 보존, 빈/실패/중복 요청·수동 변경과 stale revision·늦은 이벤트, 긴 한영 모델명·초안·메뉴 Escape·reduced motion, import 취소/오류.
- SQLite의 추가 boolean 열은 기존 행을 false로 둔다. 사용자 DB를 검증 fixture로 쓰지 않으며 업그레이드/재시작은 임시 DB로 확인한다.
- 결정적 provider fixture와 실제 브라우저로 확인한다. 외부 유료 호출·배포·커밋·병합은 이번 요청에 포함하지 않는다.
