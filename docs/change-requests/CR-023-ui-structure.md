# CR-023: 작업·설정·실행의 화면 책임 분리

- 상태: 승인 — Bell, 2026-10-18, Oracle 전체 UI 구조 검토 후 `ui 개선 구현해`.
- 기준: main `a9e1a83`, Oracle Pro의 소스·화면 01–06 검토.
- 추적: C-086, CRL-UX-004, TC-UX-004-H/N. [구현·검증 기록](../plans/UI-Structure-Plan.md).
- 유지: CR-011 입력 의도, CR-014 D&D·Reins·데스크톱, CR-020 합성, CR-021 추론, CR-022 불변 리소스·신뢰·명시 적용.

## 계약

1. 이동은 프로젝트·세션 사이드바, 현재 위치는 route와 로드된 객체에 근거한 상단 경로가 맡는다. 최근 프로젝트 선호를 전체 목록·일반 설정·다른 객체의 소속으로 표시하지 않는다. 사이드바가 닫히거나 좁은 창일 때 프로젝트 이동 메뉴를 제공한다.
2. 설정은 같은 왼쪽 영역을 앱·에이전트 구성·프로젝트 메뉴로 교체한다. 실행 상태·Inbox·알림 구독은 프레임에 유지한다. `작업으로 돌아가기`는 설정 최초 진입 위치를 기억하고 범주 이동으로 덮어쓰지 않는다.
3. 프로젝트 설정 대상은 검증한 명시 프로젝트다. 대상 변경은 같은 설정 범주를 유지한다. 공통 설정에 전역 프로젝트 선택기를 붙이지 않는다. 잘못되거나 없는 대상에 설정을 저장하지 않는다.
4. 세션 보조 실행 패널은 상태·대기 이유·사용량·역할 상태·제어 진입점이다. 전체 Run의 중첩 탭을 다시 넣지 않는다. 기존 상세 URL과 execution/artifact/view/result 선택을 보존하고 선택 execution의 Reins를 한 번의 조작으로 연다. 새 이벤트가 과거 Run 선택을 바꾸지 않는다.
5. 새 세션의 주 경로는 요청을 입력하지 않고 Composer로 이동한다. 실제 요청은 한 곳에서 작성한다. 기존 제목·목적·작성 중인 초안은 보존하며 저장된 목적이나 화면 전환으로 Run을 자동 시작하지 않는다.
6. 팀 편집은 D&D·연결·속성·역할별 모델/추론·작업 방식을 유지한다. 설계 속성과 이번 실행 준비·현재 실행 운영을 구분하고, 직접 실행과 세션 복귀 경로를 보존한다. 미저장 내용을 조용히 버리지 않는다.
7. 스킬·Hook 라이브러리는 관리가 기본이며 작업 방식 연결 시에만 사용 대상을 고른다. MCP는 명시된 프로젝트의 서버 관리가 기본이며 작업 방식 연결을 별도 동작으로 제공한다. 등록·신뢰·선택·실제 실행과 고정 revision의 의미는 바꾸지 않는다.
8. 사용자 용어는 팀·세션·실행으로 정리하고 앱 데이터 위치·프로젝트 원본 폴더·세션 작업 사본을 구별한다. 검색 범위를 표시한다. 좁은 창·키보드·focus·IME·Electron 제목 표시줄 동작을 보존한다.

## 반례와 검증

- 정상: 프로젝트→새 세션→실행→역할 제어/상세→설정 여러 범주→원래 작업으로 복귀.
- 실패: 설정 프로젝트 없음/삭제됨, 목록 조회 실패, 저장 충돌. 잘못된 대상 저장이나 초안 소실이 없어야 한다.
- 취소: 설정/편집 이탈 취소, Reins 닫기, 패널 닫기는 Run 취소가 아니다.
- 중복: 빠른 새 세션/실행 조작은 기존 중복 명령 계약을 유지한다. 화면 변경으로 별도 실행 경로를 추가하지 않는다.
- 늦은 이벤트: 프로젝트/세션/Run 전환 뒤 늦은 응답은 새 선택·초안·저장 대상을 덮지 않는다.
- 주요 E2E는 기존 탐색·설정·복귀, 세션 실행·확인·Reins, 팀 편집·직접 실행 흐름을 확장한다. 세부 분기는 단위 시험으로 검증하며 사소한 E2E를 늘리지 않는다.
- 실제 패키지에서 넓은/좁은 화면과 설정/작업 복귀를 직접 조작한다. 무료 fixture와 실계정 증거를 구분한다.

새 DB·Coordinator·프로필 상속 규칙·범용 내비게이션 엔진을 만들지 않는다. 기존 URL과 저장 데이터는 유지한다.
