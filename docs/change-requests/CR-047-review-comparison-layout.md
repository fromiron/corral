# CR-047 — 검토·비교 화면의 공간과 정보 위계

- 승인: 2026-10-23 사용자가 실제 화면 검토의 5개 개선 항목을 구현하도록 요청했다.
- 추적: C-172 / CRL-UX-008 / TC-WBUI-003-H,N.
- 범위: 변경 검토 중앙 폭, 실행 비교 표의 좁은 화면/수치 정렬, 후보 비교의 반영 버튼 노출과 카드 정보 위계, 실행 비교 제목 중복.

## 지킬 동작

기존 디자인 토큰·system-ui·공용 컨트롤·Lucide를 재사용한다. 레이아웃을 반복 설명하는 문구만 줄이며 필수 폼 레이블·컨트롤 이름·제목 의미·포커스·오류·미확정 사용량과 적용 대상 안내를 유지한다. D&D·Reins·파일 검토/의견 초안·선택 후보/tree·명령 receipt·재확인·늦은 결과 처리는 바꾸지 않는다.

## 변경 기준

1. 검토 영역의 실제 가용 폭을 기준으로 배치한다. 중간 폭에서는 우측 검토 도구를 아래 또는 접을 수 있는 영역으로 옮겨 중앙 diff를 우선한다. 파일·검사·의견 접근과 작성 중 내용은 유지한다.
2. 실행 비교 표는 390px에서도 항목명이 한 글자씩 줄바뀌지 않고 두 실행을 비교할 수 있어야 한다. 긴 ID는 축약하되 전체 값은 키보드로 확인 가능하게 유지한다. 이름·상태는 좌측, 수치는 우측과 고정폭 숫자로 비교한다.
3. 후보 비교의 반영/취소/명령 확인은 본문 스크롤과 분리해 계속 접근 가능하게 둔다. 짧은 diff가 불필요한 큰 빈 영역을 차지하지 않게 한다.
4. 동급 후보 카드는 후보명·상태·사용량·검사 결과를 같은 구조로 표시한다. 수치와 보조 설명의 글자 역할을 구분하며 unknown/오류를 숨기지 않는다.
5. 실행 비교는 본문 제목 하나를 유지하고 앱 상단의 중복 제목을 생략한다.

새 실행 기능·의존성·전역 디자인 체계·정보 삭제를 추가하는 범위가 아니다. 핵심 회귀와 현재 빌드의 390/1024/1280px 실제 화면으로 검증하며 전체 OS·공급자·출시 검증을 반복하지 않는다.
