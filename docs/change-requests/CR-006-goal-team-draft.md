# CR-006: 목표에서 팀 초안 만들기

- 변경 ID / 제안자 / 날짜: CR-006 / Claude(초안) / 2026-10-16
- 상태: **승인**(로드맵 10번. Bell의 /goal 지시 "제안한 개선·강화 플랜 끝까지 구현, UX/UI와 코어 기능이 가장 중요"에 포함된 항목. 2026-10-16)
- 연결 문서: 스펙 §3.1(편집), §3.2(임의 역할 생성 제외), §4.1(화면), [CR-005](CR-005-api-keys-and-compatible-endpoints.md)

## 기존 문구

- 스펙 §4.1: Workspace는 Corral 목록·실행 이력·연결 상태, Canvas는 팔레트·연결·속성. 새 Corral은 빈 캔버스나 템플릿(UX-A5)에서 시작한다.
- 스펙 §3.2: "실행 중 노드 추가/삭제/재연결, 임의 역할 생성"은 MVP 제외. 이것은 **실행 중** 그래프 변경에 관한 것이다.

## 제안

1. **팀 계획(TeamPlan) 계약.** 목표 한 줄에서 만든 초안은 정해진 패턴의 작은 JSON이다. 패턴은 세 가지다:
   - `single`: 에이전트 → 출력.
   - `write_review`: 기획(요점 정리) → 작성·검토 Loop → 출력. Loop는 진입점이 될 수 없으므로(스펙 §5.3) Loop 앞에 짧은 기획 단계를 둔다.
   - `research_write_review`: 조사 → 작성·검토 Loop → 출력.

   계획에는 다음이 들어간다(모두 길이 제한):
   - 이름, 실행 입력(brief), 기준(criteria).
   - 역할마다 이름과 할 일.
   - 검토 회차, 최종 승인 여부.

   Corral 정의 자체가 아니므로 도구 권한·연결·한도는 계획에서 정할 수 없다.
2. **정의로 변환.** Studio가 계획을 Corral 정의와 배치로 바꾼다(`draftFromPlan`). 도구 권한·입력 바인딩·Loop 포트·한도(기본값)는 패턴이 고정한다. 결과는 기존 컴파일러 검증을 통과해야 한다.
3. **초안 만드는 방법 두 가지:**
   - **로컬 제안**(모델 호출 없음, 데모 포함): 목표의 낱말(조사·비교·검토 등, 영어·한국어)로 패턴을 고르고 목표를 brief로 넣는다.
   - **모델에게 묻기**(로컬 서버 live, 1회 요청): 서버가 첫 모델 프로필로 한 번 요청하고, 응답에서 TeamPlan JSON만 받아 엄격히 검증한다. 출력은 1,500 토큰, 시간은 60초로 제한한다. 응답이 계약에 맞지 않으면 쓰지 않고 "로컬 제안을 쓰세요"라고 알린다. 모델 응답 원문, 토큰, 키는 응답·로그에 넣지 않는다. 이 요청은 Run 밖의 사용자 요청 1회이므로 Run 예산에 포함하지 않는다. 화면은 실행 전에 "모델 요청 1회를 씁니다"라고 알린다.
4. **사람 승인 후 편집기.** 초안은 미리보기(패턴·역할·할 일·기준)로 보인다. 사람은 이름·할 일·기준을 고칠 수 있다. "편집기에서 열기"를 눌러야 저장되고 편집기로 이동한다. 그 전에는 아무것도 저장하지 않는다.
5. **진입점.** Workspace의 템플릿 영역과 명령 팔레트(⌘K)에 "목표에서 팀 초안" 항목을 둔다.

## 이유

빈 캔버스나 고정 템플릿보다, 하려는 일을 한 줄로 쓰고 맞는 팀 모양에서 시작하는 편이 첫 Corral까지 걸리는 시간을 줄인다. 모델이 정의 전체를 쓰게 하지 않고 작은 계획만 받기 때문에, 도구 권한이나 그래프 규칙을 모델 출력이 정하지 않는다.

## 기존 합의와 충돌

없음. 실행 중 그래프 변경이 아니라 편집 전 초안이다. 모델 호출은 사용자가 누를 때 1회, 상한이 있다.

## 테스트

- 계약: 세 패턴의 TeamPlan 통과. 패턴과 역할 슬롯 불일치, 길이 초과, 알 수 없는 필드는 거절.
- 변환: 세 패턴 모두 컴파일 통과. 역할 이름·할 일·기준·검토 회차·승인 여부 반영. 계획이 도구 권한을 바꿀 수 없음.
- 로컬 제안: 영어·한국어 낱말별 패턴 선택, 빈 목표 거절.
- 서버: 가짜 모델의 JSON 응답 → 계획. 깨진 응답·계약 위반 → 422, 원문 미노출. 로그인 없음 → 403. live 없음 → 501. 목표 길이 제한. 요청 1회, 출력 상한 전달.
- E2E: 목표 입력 → 로컬 제안 미리보기 → 할 일 수정 → 편집기에서 열기 → 그래프와 고친 내용 확인. 취소하면 저장되지 않음.

## 일정·영향

새 의존성 없음. contracts(TeamPlan), react(변환·로컬 제안), server(초안 API), Studio(대화상자·팔레트)가 바뀐다.

## 진행 결과 (2026-10-16)

- 구현:
  - `packages/contracts/src/team-plan.ts`(TeamPlan).
  - `packages/react/src/team/draft.ts`(`planFromGoal`, `draftFromPlan`, 단계 이름 번역).
  - `apps/server/src/models/team-draft.ts`, `POST /api/v1/team-drafts`, 오류 코드 `MODEL_UNAVAILABLE`(502).
  - `apps/studio/src/TeamDraftDialog.tsx`, Workspace의 "목표에서 시작"과 `/?draft=1`, ⌘K 명령.
- 설계 변경: `write_review`는 Loop가 진입점이 될 수 없어(컴파일러 `ENTRY_INVALID`) 기획(planner) 단계를 앞에 둔다. 메시지 파일은 배열을 담지 않으므로 기본 기준은 이름 붙은 항목으로 둔다.
- 테스트:
  - react 6, 서버 2.
  - E2E: 브라우저 2(chromium·firefox), 서버 1(가짜 모델, 요청 1회 확인).
  - 기존 템플릿 갤러리 테스트(카드 3개)는 바꾸지 않았다. 목표 입력은 갤러리 밖의 별도 영역에 두었다.
- 실제 확인(1회): 로그인한 OpenAI 프로필(`gpt-6-luna`)에 한국어 목표로 요청했다. 11.7초 만에 계약을 통과하는 `research_write_review` 계획이 돌아왔다(역할 3, 기준 5, 회차 2). 출력 상한은 1,500 토큰.
- 화면 확인: 한국어 UI에서 제안 → 미리보기 → 편집기. 그래프가 1280px 캔버스에 들어가고 단계 이름도 번역된다.
