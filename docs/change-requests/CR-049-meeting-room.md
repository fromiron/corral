# CR-049 — 회의실: 역할 에이전트와의 협업 채팅과 작업 인계

- 상태: **승인, C-174–176 구현** — Bell, 2026-10-23: 발언 규칙 1–17 승인 후 구현을 지시했으며, 중단된 구현을 파악해 계속 진행하도록 재확인했다. 최초 CR 작성 때의 구현 보류는 현재 재개 지시로 대체됐다. Linux의 결정적/실제 연결 모델·서버·브라우저 검증과 그 경계는 [실행 기록](../evaluation/Meeting-Room-2026-10-23.md)을 따른다. 실행 Corral 추천·복제/신규 생성은 후속 범위다.
- 목적 근거: 같은 날 Bell이 회의실을 “역할별 ai에이전트(지정 가능)들과 의논하는 기능이고 카카오톡, 라인 같은 채팅방과 같음. 협업 채팅창으로 브레인스토밍, 의견 도출 등을 하고 비서가 회의록을 작성하여 플래닝 하는 기능”으로 정의했다. 회의 결과를 프로젝트 세션에 지시하거나 플랜을 실행하는 흐름은 Bell이 제공한 초안 「Corral 회의실 → 일반 프로젝트 세션 인계 구현 플랜」(2026-10-23, P0–P6)을 따른다.
- 추적: C-174–C-176 / CRL-MEET-001–003 / TC-MEET-001–003-H,N,F.
- 관계: [CR-048](CR-048-ultra-candidate-tournament.md)의 Ultra와 별개다. Ultra는 같은 과제를 여러 모델이 구현해 겨루는 실행 방식이고, 회의실은 사람이 주도하는 대화와 결정이다. 회의는 프로젝트를 바꾸지 않으며 실행은 인계받은 일반 세션의 기존 Coordinator·권한·취소 경로에서만 일어난다.

## 1. 발언 규칙 (먼저 확정할 계약)

Bell이 2026-10-23에 아래 1–17을 그대로 확정했다. 번호는 결정 단위이며 바꾸려면 이 CR을 갱신한다.

### 1.1 누가 말을 시작하는가

1. 회의의 한 **라운드**는 사람의 메시지 하나로만 시작한다. 에이전트는 스스로 라운드를 열거나 사람 없이 대화를 이어 가지 않는다.
2. 한 회의에서 진행 중인 라운드는 하나다. 라운드 중에 보낸 사람의 메시지는 하나까지 대기열에 두고 현재 라운드가 끝나면 다음 라운드로 시작한다. 사람은 현재 라운드를 중지할 수 있다. 대기 중인 메시지는 보내기 전까지 고칠 수 있다.

### 1.2 누가 답하는가

3. **@멘션이 없으면 전원 라운드**다. 비서를 뺀 참가자 전원이 한 번씩 답한다.
4. **@역할을 멘션하면 그 역할만** 답한다. 여러 명을 멘션하면 멘션한 사람만 답한다. 멘션은 메시지 본문의 `@역할명`과 입력창의 참가자 선택이 같은 결과를 낸다.
5. **@비서**는 비서만 부른다. 비서는 의견을 내지 않고 정리·요약·질문 목록·결정 후보만 쓴다.
6. 한 라운드에서 참가자는 한 번만 답한다. 같은 참가자의 연속 발언이나 에이전트끼리의 자동 호출은 없다.

### 1.3 독립 의견과 반론

7. 한 라운드 안의 답은 **서로 독립**이다. 각 참가자는 이전 라운드까지의 회의 기록과 이번 사람의 메시지를 보지만, 같은 라운드의 다른 참가자 답은 보지 않는다. 동시에 실행하고, 화면에는 도착 순서가 아닌 참가자 순서로 고정해 보여 준다.
8. 서로의 의견에 답하게 하려면 사람이 **반론 라운드**를 연다(버튼 또는 `/반론`). 반론 라운드에서는 직전 라운드의 답을 모두 보고 각자 한 번 더 답한다. 사람 메시지 하나에 이어지는 반론 라운드는 최대 2회다.
9. 반론 라운드도 참가자 범위는 직전 라운드와 같고, @멘션으로 좁힐 수 있다. 에이전트가 “다음엔 누가 말하라”고 써도 라운드가 열리지 않는다.

### 1.4 비서와 회의록

10. 비서는 라운드마다 자동으로 말하지 않는다. 사람이 @비서로 부르거나 **회의 정리**를 누를 때 회의록을 갱신한다.
11. 회의록은 쟁점, 참가자별 주장, 합의, **남은 이견**, 미확인 사실, 결정 후보, 다음 행동을 담은 구조화 문서다. 이견을 합의로 뭉개지 않으며, 답하지 않았거나 실패한 참가자를 찬성으로 세지 않는다.
12. 비서가 쓴 결정 후보는 사람이 채택하기 전까지 결정이 아니다(3절).

### 1.5 실패와 중지

13. 참가자 하나가 실패하면 그 자리에 “응답 실패”와 이유를 보이고 라운드는 나머지로 끝난다. 자동 재시도는 하지 않으며, 사람이 그 참가자만 @멘션해 다시 물을 수 있다.
14. 사람이 라운드를 중지하면 진행 중인 답을 모두 멈춘다. 이미 도착한 답은 남기고 중지 사실을 표시한다. 늦게 도착한 답은 그 라운드에만 귀속하고 이후 라운드에 끼어들지 않는다.
15. 회의를 닫았다 다시 열어도 저장된 기록만 보여 주며 새 호출을 하지 않는다.

### 1.6 구조상 상한과 사용량

16. 참가자는 비서를 빼고 2–6명이다. 라운드당 참가자 답은 1회, 반론 라운드는 사람 메시지당 최대 2회다. 이 구조 상한이 대화가 스스로 길어지지 않게 하는 장치다.
17. **사용량 한도 없음.** CR-048 Ultra와 같이 회의에는 Corral 사용량 한도(토큰·호출·시간)를 두지 않고 사람의 중지만 정지 수단으로 둔다. 위 구조 상한 때문에 끝나지 않는 대화는 생기지 않는다. 사용량은 참가자별로 보여 주고 미확인 사용량을 0으로 세지 않는다. 공급자 쪽 제한·과금은 그대로다.

## 2. 회의실과 참가자

1. 회의는 프로젝트 안의 세션 종류 `meeting`이다. 일반 작업 세션과 다른 session ID를 가지며 기존 세션 저장·목록을 공유한다. 기존 세션은 모두 `work`로 해석하고, 기록이 있는 세션의 종류 변환은 하지 않는다.
2. 참가자는 이름, 역할 설명(프롬프트), 모델 프로필로 정한다. 서로 다른 회사의 모델을 섞을 수 있고, 같은 모델을 여러 역할에 써도 된다(역할은 별개 에이전트다). 미연결 모델은 회의 시작 전에 표시하고 그 참가자를 뺄지 묻는다.
3. 처음 만들 때 템플릿을 제안한다(예: 아키텍처·구현·검증 + 비서). 템플릿은 편집 가능한 초기값일 뿐이며 참가자 수를 품질 보장으로 표시하지 않는다.
4. 회의 참가자는 프로젝트 파일을 바꾸거나 명령·검사를 실행하지 않는다. 사람이 고른 근거(파일, 결과, 링크한 산출물)만 읽기 입력으로 받는다. 같은 프로젝트라는 이유로 모든 자료를 읽지 않는다.
5. 회의 중 모델 출력의 “승인됨”, “실행하자” 같은 문장은 권한이나 실행 지시가 아니다.

## 3. 결정 채택

1. 사람은 회의록의 결정 후보를 고치거나 일부 행동만 골라 **결정 버전**으로 채택한다. 결정 버전은 목표·범위·제외 범위·완료 기준·남은 이견·근거를 담은 불변 기록이며, 바꾸면 새 버전이다.
2. 회의 종료와 결정 채택은 별개다. 회의를 닫은 뒤에도 채택할 수 있고 철회·대체도 사람의 기록으로 남긴다.

## 4. 작업 인계

Bell 초안의 방향을 따른다. 정확한 데이터 계약과 명령은 착수 시 이 CR에 기록한다.

1. **작업으로 넘기기**는 채택한 결정 버전에서만 연다. 대상은 같은 프로젝트의 기존 일반 세션 또는 새 일반 세션이다. 회의 세션·다른 프로젝트·보관된 세션은 서버도 거절한다.
2. 전달물은 전체 대화가 아니라 작업 요청서(목표·범위·제외·완료 기준·남은 이견·위험·선택한 근거)다. 기각된 대안은 “기각된 배경”으로 구분한다.
3. 실행 구성은 기존 Corral 또는 자동 방식(Ultra 포함)을 사람이 고른다. 세션의 기본 Corral은 바꾸지 않고 이번 요청에만 고정한다.
4. **초안으로 넘기기**는 대상 세션에 인계 항목만 남기고 실행하지 않는다. **넘기고 시작하기**는 기존 시작 경로로 새 Run을 연다. 대상 세션이 실행 중이거나 입력창에 보내지 않은 내용이 있으면 끼어들거나 덮지 않고 초안으로만 남긴다.
5. 같은 인계 명령의 재전송은 같은 세션·항목·Run을 돌려준다. 다른 결정·범위·대상은 새 명령이다. 응답이 불확실하면 기존 receipt를 먼저 조회한다.
6. 회의에는 대상 세션, 출처 결정 버전, 사용한 실행 구성, Run 상태와 결과 링크만 남긴다. 결과를 다시 논의하려면 사람이 **이 결과로 다시 논의**를 눌러 새 라운드의 입력으로 고정한다.

## 검증

구현 전에 대표 반례가 실패하는 것을 확인한다. 결정적 에이전트를 쓰고 일반 CI에 유료 호출을 넣지 않는다.

- TC-MEET-001-H/N/F: 전원 라운드와 멘션 라운드의 답한 참가자, 같은 라운드 독립성, 반론 라운드 2회 상한, 라운드 중 메시지 대기, 참가자 실패·사람 중지·늦은 답·재열기에서 새 호출 없음.
- TC-MEET-002-H/N/F: 이견을 보존한 회의록, 미응답을 찬성으로 세지 않음, 채택 전 결정 후보의 실행 불가, 결정 버전 변경·철회.
- TC-MEET-003-H/N/F: 기존/새 세션 인계, 회의 세션·다른 프로젝트 거절, 실행 중 대상과 미전송 입력 보존, 같은 명령 재전송의 중복 없음, 응답 유실 후 receipt 조회, 취소와 시작 경합.

## C-174 구현 설계 (2026-10-23)

Bell의 “진행해” 지시로 C-174부터 착수했다. 위 규칙을 바꾸지 않고 구현 단위를 정한다.

1. **저장**: 회의는 `WorkSession.meeting`(참가자 설정·라운드·대기 메시지)을 가진 세션이다. 없으면 `work`다. 회의 상태는 세션 revision CAS로만 바꾸며, 일반 세션 수정 경로(PATCH)로는 바꿀 수 없다. SQLite는 `meeting_json` 열을 추가한다.
2. **답 하나 = Run 하나**: 참가자 답은 그 참가자의 이름·역할·모델로 만든 단일 에이전트 Run이다. 산출물 작성·제출만 허용하고 파일·명령·검사 도구는 없다. 같은 라운드의 Run은 모두 같은 회의 기록(이전 라운드까지)으로 동시에 시작하므로 서로의 답을 보지 않는다. 시작 명령 ID는 `meeting_<roundId>_<participantId>`로 고정해 같은 라운드 재시도가 Run을 늘리지 않는다.
   실제 공급자가 도구 호출 없이 정상 종료한 텍스트 답변도 회의 답이다. worker가 정상 stop·비어 있지 않은 본문·도구 시도 없음을 확인하고, Coordinator가 현재 회의·시도·마지막 완료 호출·취소 여부를 대조한 뒤 기존 산출물 작성/제출 경로로 확정한다. 추가 모델 호출은 없으며 잘림·오류·빈 답·미완료 도구 작업이나 일반 작업 Run에는 적용하지 않는다.
3. **사용량 한도 없음**: Run 시작 요청의 `meeting` 출처(세션·라운드·참가자)가 있으면 Coordinator는 CR-048 version 2와 같은 방식으로 Corral 사용량 한도를 적용하지 않는다. 이 출처는 회의 서비스만 붙이며 HTTP Run 시작 요청에서는 거절한다.
4. **라운드 서비스**: core의 회의 서비스가 멘션 해석, 전원/멘션/비서/반론 라운드 규칙, 진행 중 라운드와 하나뿐인 대기 메시지, 중지(라운드의 모든 Run 취소)를 처리한다. 서버와 브라우저 데모가 같은 서비스를 쓴다. 답의 상태와 본문은 각 Run의 상태와 확정 산출물에서 읽는다.
5. **재시작**: 대기 메시지는 저장되지만 서버 재시작 뒤 자동으로 보내지 않는다. 사람이 보내기를 눌러야 한다. 시작 기록만 있고 Run이 없는 답은 “시작되지 않음”으로 보이며 다시 호출하지 않는다.
6. **선택한 근거**: 사람이 첨부한 텍스트 파일과 명시적으로 고른 결과만 원문·해시·크기를 고정해 라운드 입력에 넣는다. 프로젝트 자료를 자동으로 읽거나 링크를 따라가지는 않는다. 대기 메시지 편집도 같은 command ID와 대기 상태를 확인한다.

## C-175·C-176 구현 설계 (2026-10-23)

1. 비서의 확정 산출물은 구조화된 회의록으로 검증한다. 주장·이견·합의의 지지자는 이전 라운드의 실제 성공한 답을 참조해야 한다. 형식이나 참조가 틀리면 회의록 오류를 저장하고 자동으로 재호출하지 않는다.
2. 결정 후보는 회의록 안에만 둔다. 채택 명령은 사람이 편집한 목표·범위·제외·완료 기준·남은 이견·근거·위험·행동·기각된 배경을 불변 결정 버전에 저장한다. 대체는 새 버전, 철회는 별도 기록이며 명령 재전송은 같은 결과를 돌려준다.
3. 인계 명령은 결정 버전과 요청별 실행 구성을 고정한다. 기존 Corral은 선택 당시 정의·revision을 보존하고, 자동 방식은 모델·추론·품질·Ultra 선택을 보존한다. 대상 세션 기본값은 수정하지 않는다.
4. 서버는 receipt와 대상 항목을 실행 전에 저장한다. 동일 명령의 다른 본문은 거절하며, 응답이 불확실하면 저장된 receipt와 기존 시작 명령을 조회한다. 조회나 재열기는 실행을 재개하지 않는다.
5. 대상은 같은 프로젝트의 보관되지 않은 일반 세션이다. 진행 중 Run·대기 항목 또는 요청한 브라우저에 저장된 미전송 초안이 있으면 초안으로 남긴다. 다른 브라우저의 로컬 초안은 서버가 관찰할 수 없으므로 전역 초안 부재를 보장하지 않는다.
6. 인계 이력에는 출처 결정·대상 세션·실행 구성·Run 상태·결과 링크를 표시한다. 결과 재논의는 사람이 명령을 보낼 때만 확정 결과를 새 회의 입력으로 고정한다.
7. `meeting_` 접두사의 내부 시작 ID는 회의 서비스만 사용한다. 일반 시작·자동 시작/취소·결과 질문·분기·runtime 재개 API로 선점하지 못한다. 회의 답 Run의 분기·runtime 재개도 회의 발언 규칙을 우회하므로 거절한다.
