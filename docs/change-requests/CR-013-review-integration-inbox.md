## 제안

1. **버전 고정 의견(WB-REV-001).** 의견은 다음에 묶인다:
   - 비교한 두 tree(`from`·`to`), 파일 경로, 쪽(이전·이후), 줄 범위, 그 줄의 원문 인용.
   - 다른 비교로 바꾸면 원래 의견을 그 원문과 함께 "이전 비교의 의견"으로 보인다. 새 파일의 같은 줄 번호에 자동으로 다시 붙이지 않는다.
   - 상태: `draft`·`submitted`·`addressed`·`obsolete`. 모델이 고쳤다고 말한 것만으로 `addressed`가 되지 않는다. 사람이 표시한다.
2. **의견 묶음 → Reins·후속 Run(WB-REV-002).** 초안 의견을 한 번에 보낸다(한 줄마다 보내지 않음).
   - 세션의 Run이 실행 중이면 사람이 고른 실행에 지시(Reins)로 보낸다.
   - 아니면 같은 세션의 새 수정 Run을 직전 결과에서 시작한다.
   - 보낸 묶음은 세션 기록(CR-011)과 의견에 연결된다.
3. **검토 판단(WB-REV-003).**
   - "승인"·"수정 요청"은 특정 tree 쌍에 대한 판단이다. "검토함 표시"(읽음)와 다르다.
   - 작업 복사본이 그 뒤 바뀌면 판단은 지우지 않고 "지난 버전 기준"으로 표시한다.
4. **원본 반영(WB-REV-004).** 승인한 세션 변경(기준 tree → 승인 tree)을 연결한 원본 폴더에 쓰는 별도 명령이다.
   - 반영 계획: 파일마다 원본의 지금 내용을 기준 내용과 비교한다.
     - 같으면 반영한다.
     - 이미 승인 내용과 같으면 건너뛴다.
     - 다르면 충돌로 쓰지 않는다.
   - 적용: 승인 tree의 불변 내용(git 객체)을 쓴다. 승인 뒤 작업 복사본이 바뀌어도 승인한 내용만 들어간다.
   - 기록: 파일별 결과(applied·skipped·conflict·failed)를 남기고 반영 상태(applied·partial·conflict)를 보인다. 여러 파일을 원자적으로 쓴다고 약속하지 않는다.
   - commit·push는 하지 않는다. 경로 규칙(CR-012)과 symlink 거절은 원본에도 적용한다.
5. **되돌리기(WB-REV-005).** 실제로 반영된 파일만 되돌린다.
   - 지금 내용이 반영한 내용과 같으면 기준 내용으로 되돌린다(추가했던 파일은 지운다).
   - 그 뒤 사람이 바꾼 파일은 건드리지 않고 `revert_conflict`로 둔다.
6. **확인 필요 목록(WB-OBS-002).** 프로젝트 화면 맨 위에 사람이 처리할 것만 모은다.
   - 결정 대기 Run, 대기열의 다음 작업, 결과를 모르는 파일 쓰기, 반영 충돌·부분 반영, 최신 검증 실패, 마지막 검토 뒤 바뀐 작업 복사본.
   - 화면을 열었다고 닫히지 않는다. 해당 명령이 처리되면 사라진다.

## 테스트

- 서버: 의견 기록·상태, 판단의 지난 버전 표시, 반영 계획의 충돌·건너뜀, 반영 결과와 원본 내용, 되돌리기와 이후 수정 보호, 확인 필요 항목.
- E2E(서버): 검토 화면에서 의견 → 수정 요청 보내기(후속 Run 시작) → 승인 → 원본 반영 → 되돌리기.
