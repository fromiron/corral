## 1. 지금 가장 큰 문제 두 가지

Bell이 사용하면서 꼽은 문제다. 이번 플랜은 이 두 가지를 먼저 끝낸다.

1. **출력물을 확인하기 힘들다.**
   - Run 화면의 Output 탭은 화면 아래 15rem 높이 칸 안에 있다.
   - Output 노드가 받은 산출물 중 **첫 번째 하나만** 불러온다(`session.ts`의 `loadOutput`).
   - 실패·취소한 Run은 이미 만든 산출물이 있어도 "출력 대기"만 보인다.
   - HTML 문서 결과는 Markdown으로 그려져 태그가 사라진 글자 덩어리가 된다.
   - 복사·내려받기가 없고, 중간 산출물은 Tasks 탭과 오른쪽 패널을 오가며 하나씩 열어야 한다.
2. **프로젝트별로 구분되지 않는다.**
   - 홈은 모든 팀(Corral)과 모든 Run을 한 목록에 섞어 보인다.
   - 서로 다른 일의 결과가 같은 Run 목록에 쌓여, 어떤 Run이 어떤 일의 것인지 이름과 시각으로 추측해야 한다.

## 3. W1 설계 결정

제안과 다르게 정하거나 더 좁힌 점을 적는다. 나머지는 제안 문서를 따른다.

### 3.1 결과 화면 (21번, CR-009)

- **위치.** 새 Session 화면 대신 Run 화면에 `결과 | 실행` 보기 전환을 둔다. 보기와 선택한 산출물은 주소(`?view=results&result=<versionId>`)에 남아 새로고침·공유·뒤로가기에 유지된다.
  - 페이지를 열 때 이미 끝난 Run은 결과 보기로, 진행 중이던 Run은 실행 보기로 열린다.
  - 사용자가 고른 보기는 결과가 늦게 와도 바꾸지 않는다(제안 §6).
- **결과 집합.** 제안의 `ResultRevision`을 새로 저장하지 않는다. 이미 확정된 projection(`output.artifactVersionIds`, `artifacts`, `reviews`)에서 화면용으로 계산한다(`runResults`). 새 이벤트·저장 schema는 없다.
  - 최종 결과: Output 노드가 받은 모든 버전.
  - 중간 산출물: 그 밖의 산출물을 같은 산출물(artifactId)끼리 묶고 최신 버전을 먼저 보인다. 이전 버전도 고를 수 있다.
  - 부분 결과: 실패·취소·중단으로 끝난 Run은 Output이 없어도 이미 만든 산출물을 "부분 결과"로 보인다.
- **상태를 따로 보인다.** 실행 상태(Run 상태), 검토(이 버전에 대한 검토 판정 또는 "검토 없음"), 제출 여부를 각각 표시한다.
  - 파일 작업과 검증 명령은 아직 없으므로 "파일 작업 없음 · 검증 명령 없음"으로 적는다. "통과"나 "변경 없음"으로 적지 않는다.
- **읽기 화면.** 산출물 목록은 왼쪽, 본문은 넓은 가운데 칸에 둔다. 본문은 읽기 좋은 폭(약 75자)과 글자 크기로 보인다.
  - 보기 형식: 문서(안전한 Markdown) / 원문 / 미리보기(HTML 문서일 때).
  - 도구: 복사, 내려받기(사용자가 누를 때만), 이전 버전과 비교, 이 결과에서 새 Run(CR-007).
- **HTML 미리보기(WB-SEC-002).** Studio 페이지 안에서 HTML을 실행하지 않는다.
  - 로컬 서버: 미리보기 전용 주소가 산출물 본문을 별도 응답으로 준다. 이 응답에는 `sandbox` CSP(스크립트·폼·팝업 금지, opaque origin)와 `default-src 'none'`을 건다. 외부 이미지·네트워크는 막고 인라인 스타일만 허용한다. iframe에도 빈 `sandbox` 속성을 준다.
  - 브라우저 데모: 같은 CSP를 `meta`로 앞에 넣은 `srcdoc`을 빈 `sandbox` iframe에 넣는다.
  - Markdown 보기에서는 HTML 문서를 지금처럼 원문(escape)으로 보인다.
- **기존 화면.** 아래 칸의 Output 탭은 남긴다(기존 링크·테스트 보존). 대신 모든 최종 결과를 나열하고 "결과 화면에서 보기"로 넘어간다.

### 3.2 프로젝트 (22번, CR-010)

- **저장 위치.** 제안의 별도 AppStore DB 대신 지금의 작업 공간 DB(`<workspace>/.corral/corral.db`)에 `projects` 표를 더한다.
  - 데이터 폴더를 옮기지 않는다(WB-MIG-002).
  - 작업 폴더 연결(WorkspaceBinding)은 W3에서 별도 표로 더한다. 프로젝트는 폴더가 아니다(WB-PRJ-001).
- **소속.**
  - 팀(Corral)은 프로젝트 하나에 속한다.
  - Run은 **시작할 때** 팀이 속한 프로젝트에 고정된다. 팀을 다른 프로젝트로 옮겨도 지난 Run은 원래 프로젝트에 남는다(Run snapshot 원칙).
- **기존 기록.**
  - migration은 기본 프로젝트 하나를 만든다.
  - 프로젝트가 없는 기존 팀과 Run은 기본 프로젝트로 읽는다.
  - Run·이벤트·산출물 ID와 행은 바꾸지 않는다(WB-MIG-001). 불변 표(`run_events`, `artifact_texts`)에는 손대지 않는다.
- **보관.** 보관은 숨김일 뿐 삭제가 아니다. 보관한 프로젝트의 Run 링크는 그대로 열린다.
  - 기본 프로젝트는 보관하지 않는다.
  - 프로젝트 삭제는 이번 단계에 없다.
- **화면.**
  - `/projects`: 프로젝트 목록·만들기·보관 보기.
  - `/projects/$projectId`: 지금의 홈 화면을 프로젝트로 좁힌 화면. 팀·Run·템플릿·목표에서 시작이 있고, 여기서 만든 팀은 이 프로젝트에 속한다.
  - `/`: 마지막으로 연 프로젝트로 이동한다.
  - 헤더: 현재 프로젝트 이름과 전환 메뉴.
  - Run·편집기 화면: 그 Run·팀의 프로젝트를 헤더에 보인다.
  - ⌘K: "프로젝트 전환".
- **브라우저 데모.** 같은 규칙을 localStorage 저장소로 구현한다. 데모 Run은 탭을 닫으면 사라지므로 Run의 프로젝트는 팀에서 읽는다.

## 4. 이번 단계에서 하지 않는 것

- 세션·후속 Run·입력 의도: 23·24번에서 한다.
- 파일 쓰기·작업 폴더·diff 검토·원본 반영: W3·W4. 착수 전 Bell 확인이 필요하다.
- 프로젝트 삭제, 프로젝트별 지침·자료 버전, 프로젝트별 모델 설정.
- 실행 중 팀 구조 변경(기존 합의 그대로 제외).
