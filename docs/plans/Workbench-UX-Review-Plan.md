## 2. 고칠 내용과 완료 기준

### 묶음 A — 입력 의도와 참조 보존 (UX-01, UX-02)

- **고정**:
  - 입력을 시작한 순간의 의도(next·queue·steer·explain)와 지시 대상(execution)을 고정한다.
  - 상황이 바뀌어도(대상 종료, 승인 대기, Run 종료) 자동으로 바꾸지 않는다.
  - 고정한 값이 지금 불가능하면 보내기를 막고, 이유와 함께 "다른 실행 선택" · "대기로 옮기기" · "후속 작업으로 보내기"(가능할 때)를 보인다.
  - 끝난 대상도 대상 목록에 "(끝남)"으로 남아, 무엇이 고정돼 있었는지 보인다.
- **초안 저장 형식** v2: `{ text, intent, target, references: MentionItem[] }`. 예전 글자만 있는 초안은 그대로 읽는다.
- **복원할 때 참조 검사**:
  - 결과: 그 Run에 그 `artifactVersionId`가 있는지 본다.
  - 실행·역할: 지금도 존재하는지 본다.
  - 사라진 참조는 칩을 "없음"으로 표시하고 보내기를 막는다.
  - 같은 이름의 다른 버전으로 추측해 바꾸지 않는다.
- **테스트**:
  - 단위: `composerIntent`(고정·불가능 판정), 초안 v1/v2 읽기·쓰기.
  - E2E: 결과 참조 → 새로 고침 → 같은 칩과 같은 `references`로 시작.

### 묶음 B — 읽고 결정할 공간 (UX-03, UX-05)

- **컨테이너 기준 레이아웃**: 실행 상세와 결과 보기를 뷰포트가 아니라 실제 컨테이너 폭으로 나눈다. 패널 안에서는 한 열이고 목록은 위에 짧게 둔다. 넓을 때(확대·Run 페이지)는 지금처럼 여러 열이다.
- **결과 보기 안 승인**: 결과 보기에도 대기 중인 승인을 위에 둔다. 결과를 읽으며 바로 승인할 수 있다.
- **검토 화면 상태**: 다음을 서로 다른 상태로 보인다. 오류와 "준비 중"은 함께 남지 않는다.
  - 작업 복사본 없음: 결과 보기·작업 복사본 만들기·세션으로.
  - 변경 0개.
  - 이 Run은 파일을 바꾸지 않음.
  - 비교 실패: 다시 시도.
- **테스트**: 단위(검토 상태 판정), E2E(복사본 없는 세션의 검토 화면, 400px 패널에서 결과 본문 폭).

### 묶음 C — 거절 복구 (UX-04)

- **거절된 요청**: 입력칸을 비우지 않는다. 거절된 턴에는 한국어 설명과 "요청 다시 편집" · "모델 연결"(모델 관련일 때)을 둔다.
- **보내기 전 확인**: 실제 모델을 골랐는데 팀 역할의 프로필이 연결돼 있지 않으면, 보내기 전에 "연결 필요"와 설정 링크를 보이고 보내기를 막는다.
- **응답 유실**: 네트워크 실패 등은 입력을 남기고 "다시 보내기"를 둔다. 같은 command ID를 재사용해 중복 Run을 막는다(기존 `commandFor`). 명확한 거절은 새 command ID다.
- **테스트**: 단위(거절 사유 → 문구·액션 매핑). E2E(server, 모델 미연결 거절 → 입력 유지, 다시 편집).

### 묶음 D — 모델·상태·지시 표현 (UX-06, UX-07, UX-08)

- **실행 방식과 모델 배정 분리**:
  - 컴포저 칩 "실행 방식"(시뮬레이션/실제 모델), 명령은 `/mode`.
  - `/model`은 팀 역할별 모델 배정(프로필 → 공급자·모델명·연결 상태)을 보이고, 모델 설정과 팀 편집으로 잇는다.
  - 사이드바는 연결된 프로필이 없으면 "로컬 · 모델 미연결"로 표시한다.
  - 팀 편집의 모델 프로필은 서버가 아는 프로필 목록에서 고른다(이름·연결 상태 표시). 목록이 없는 데모에서만 직접 입력한다.
- **실행 상태 집계**:
  - "작업 중 n · 일시정지 n · 하위 작업 대기 n · 결정 대기 n"처럼 상태별로 센다.
  - 회전 표시는 실제로 진행 중일 때만 쓴다.
- **지시 턴의 수신자**:
  - 대상 역할·회차, 적용 시점("다음 모델 요청에"), 전달 상태를 고정 표시한다.
  - 명령 기록은 기술 ID 대신 행동 이름으로 보이고, ID는 title에 둔다.
  - "요청에 포함됨"을 "충족"으로 바꾸지 않는다.

### 묶음 E — 첫 시작·팀 편집·승인 단계 (UX-09, UX-10, UX-11)

- **첫 시작**:
  - 세션 상자의 팀 선택에 "추천 팀"(템플릿)을 함께 둔다. 고르면 팀을 만들고 세션을 바로 시작하므로 그래프를 거치지 않는다.
  - 템플릿 카드는 "이 팀으로 세션 시작"과 "팀 편집"으로 나눈다.
  - JSON 가져오기·빈 캔버스는 "직접 설계" 영역으로 묶는다.
  - 시작 안내를 세션 흐름(팀 고르기 → 첫 요청 → 결과 읽기)으로 바꾼다.
- **팀 편집**:
  - 속성 창을 "팀 기본값"(Run 지시문은 "세션 요청이 없을 때 쓰는 기본 지시"로 표시)과 "선택한 역할"로 나눈다.
  - 고급(도구·출력 형식)은 접는다. 프롬프트는 넓게 편집할 수 있게 한다.
  - 세션에서 왔으면 "세션으로 돌아가기"와 "다음 Run부터 적용" 안내를 보인다.
- **승인 단계**:
  - 단계 이름·승인 후 일어날 일을 보인다.
  - 버튼은 동작으로 쓴다("이 버전으로 계속" · "최종 결과로 확정").
  - 같은 Run에서 이미 승인한 단계를 바로 위에 남긴다.
  - 필수 승인을 없애거나 자동 승인하지 않는다.

### 묶음 F — 단축키 도움말 초점 (UX-12)

- 제목과 닫기를 위에 고정하고 목록만 스크롤한다. 초기 초점은 위쪽 닫기 버튼이다. Escape로 닫으면 원래 자리로 초점이 돌아간다(기존).

## 3. 순서

A → B → C(P1) → D → E → F. 묶음마다 커밋한다. A·B·C를 끝낸 뒤와 마지막에 바뀐 E2E만 돌린다. 끝나면 PR 하나를 만든다.

## 4. 검증하지 못하는 것

- 실제 공급자 응답, 모델 품질·비용, 다른 OS.
- 전반적인 스크린리더 적합성.
- 여러 사람의 사용성 평가(Bell 진행 예정).
