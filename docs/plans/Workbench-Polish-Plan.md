## 2. 목표 화면

원칙 네 가지. 각 PR 리뷰에서 이 원칙으로 판단한다.

1. **한 정보는 한 자리.** Run 상태는 대화 속 그 Run의 머리 한 곳과 사이드바 점 하나. 런타임·팀·제목도 한 자리씩.
2. **기본은 숨기고, 필요할 때 연다.** 오른쪽 패널, 작업 기록, 에이전트별 진행, 관리 설정은 기본으로 닫힌다. 단, 결정을 기다리는 일과 실패 이유는 숨기지 않는다.
3. **컨트롤은 한 벌.** 버튼·메뉴·선택·칩·탭은 `packages/react/ui`의 부품만 쓴다.
4. **키보드로 다 된다.** `/`, `@`, ⌘K, 단축키가 같은 명령 목록을 쓴다.

목표 배치(가설, P1에서 스크린샷으로 확정):

```
┌ 사이드바 ─────────┬ 대화 ──────────────────────────────┬ (패널: 기본 닫힘) ┐
│ ▾ 프로젝트 전환    │ 세션 제목            [변경 3] [⋯] │ 변경·파일·결과·검사 │
│ ＋ 새 세션   ⌘N    │                                   │                    │
│ ● 결정 필요 (2)    │      ┌ 사용자 요청 ┐               │                    │
│ 세션 행 한 줄 + 점 │  팀 · ● 실행 중 · 1:24            │                    │
│ …                 │  스트리밍 본문…                    │                    │
│                   │  ▸ 에이전트 3명 작업 중            │                    │
│                   │ ┌──────────────────────────────┐ │                    │
│ ⚙ 설정            │ │ 요청 입력… (/ 명령, @ 참조)   │ │                    │
│                   │ │ [@][팀▾][모델·노력▾][다음▾] [↑]│ │                    │
└───────────────────┴─┴──────────────────────────────┴─┴────────────────────┘
```

- 대화 열은 최대 폭(약 760px, 가설)으로 가운데 정렬한다.
- 사용자 요청은 말풍선, Run 결과는 본문 글로 보인다. 도구·에이전트 활동은 한 줄짜리 접이식 행이다.
- 컴포저는 입력칸 하나에 아래 칩 줄 하나: 참조, 팀, 모델×노력, 의도, 보내기/멈춤.
- 대기열은 컴포저 바로 위에 붙는다.

### P1. 정리와 화면 구조 (`audit-design` → `plan-structure`)

- **위쪽 바**: 프로젝트 전환은 사이드바 머리로 옮긴다. 런타임 문장 배지는 사이드바 아래 상태 점으로 바꾼다(누르면 상세). 제목은 한 번만 보인다.
- **세션 머리**: `<details>`를 없앤다. 한 줄에 제목(눌러서 편집), 변경 수 버튼, `⋯` 메뉴를 둔다. `⋯` 메뉴에는 팀 변경·고정·보관·작업 복사본·내보내기가 들어간다.
- **본 화면 탭**:
  - Work / Team design / Run detail 탭을 없애고 대화를 본 화면으로 한다.
  - Run 상세는 오른쪽 패널의 "Run" 탭으로 옮긴다.
  - 팀 설계는 기존 편집 라우트로 연다(메뉴·⌘K·`/team`).
- **오른쪽 패널**: 기본으로 닫는다. 변경·결정이 생기면 머리의 버튼에 개수를 보인다. 탭 줄이 곧 패널 머리가 되게 해 두 겹을 없앤다.
- **사이드바**:
  - 세션 행은 한 줄(32–36px)로 줄이고 상태 점과 상대 시각만 둔다. 설명 줄은 결정이 필요할 때만 보인다.
  - "결정 필요"는 개수 필터로 둔다.
  - 아래쪽에는 설정만 둔다.
- **프로젝트 홈**:
  - 히어로 + 컴포저 하나인 "새 세션" 화면으로 바꾼다.
  - 폴더 연결·검사·팀 관리는 "프로젝트 설정"으로 옮긴다.
- **마무리**: 바꾸기 전과 후를 `audit-design`으로 같은 기준(1280×720, ko, 다크/라이트)에서 비교한다.

### P2. 컴포저와 `/`·`@` (CR-016 먼저)

**명령 목록**:
- 명령은 하나의 레지스트리(`workbench/commands.ts`)에 둔다. id, 이름(en/ko), 설명, 단축키, 사용 가능 조건(`when`: 실행 중, 세션 있음 등), 실행 함수를 가진다.
- `/` 메뉴, ⌘K, 메뉴바, 단축키 도움말, 설정 › 단축키가 모두 이 목록을 읽는다. D-15 같은 불일치는 구조상 생기지 않는다.

**`/` 명령 첫 묶음**: 이미 있는 동작만 연결하고, 새 권한·새 실행 기능은 만들지 않는다.

| 명령 | 동작 | 이미 있는 근거 |
|---|---|---|
| `/next` `/queue` `/steer` `/ask` | 이번 입력의 의도를 정함(칩에 표시). 조용히 바뀌지 않음(CR-011) | `startFollowUp`, `steer`, queue |
| `/pause` `/resume` `/stop` | 현재 Run 제어. `/stop`은 확인 후 실행 | `RunActions` |
| `/team` `/model` | 팀·모델 칩 메뉴 열기 | `updateSession`, Models select |
| `/review` `/changes` `/files` `/checks` `/run` | 검토 화면 또는 패널 탭 열기 | 라우트, 패널 |
| `/copy` | 작업 복사본 만들기 | `createWorktree` |
| `/export` | Run 내보내기(지금은 UI가 없음) | `exportRun` |
| `/new` `/rename` `/pin` `/archive` | 세션 관리. `/archive`는 확인 후 실행 | `updateSession` |
| `/help` | 명령·단축키 목록 | 레지스트리 |

**`@` 참조**:
- 종류: 파일, 폴더, 결과(산출물, 버전 포함), Run, 역할(에이전트). 한 메뉴에 그룹으로 보인다.
- 메뉴 행: 16px 아이콘, 굵은 이름, 흐린 설명. 빈 결과 문구와 ↑↓·Enter·Tab·Esc 키, IME 조합 중 무시는 기존 동작을 유지한다.
- **검색 API**: `GET /api/v1/{projects|sessions}/:id/workspace/search?q=&limit=`(이름은 CR에서 확정).
  - 범위: git 추적 파일 + 무시되지 않은 새 파일, 그리고 그 폴더들.
  - 내용은 읽지 않는다. 기존 파일 broker 범위를 그대로 쓴다.
  - 같은 동작을 데모 워커(`demo/workspace.ts`)에도 둔다.
- **순위**: 파일 이름 우선, 부분열(fuzzy) 점수. 작은 함수로 직접 만들고 의존성을 추가하지 않는다. 같은 점수기를 ⌘K에도 쓴다.
- **입력칸**:
  - 우선 textarea를 유지하고, 참조 목록을 입력 위 칩 줄로 보인다(지울 수 있음). 본문의 `@경로` 글자와 위치를 함께 맞춘다.
  - 편집기 라이브러리(contenteditable)는 이번 범위에서 쓰지 않는다(추론: 위험 대비 이득이 작음).
- **의미(CR-016에서 확정)**:
  - `RunInput`에 `references: [{kind, path | artifactId+version | runId | roleId, lines?}]`를 더한다.
  - 참조는 **가리키기만 하고 권한을 주지 않는다**(CR-014 연장). 에이전트는 이미 허용된 파일 도구로만 읽는다.
  - 결과 참조는 보낸 시점의 버전으로 고정한다(AGENTS 6). `startFrom` 하나는 결과 참조 여러 개로 일반화한다.
  - 폴더 참조는 경로만 전달한다.
- **파일 패널·diff와 연결**: 파일 패널과 diff의 "참조로 넣기"는 같은 참조 객체를 만든다.

**컴포저 칩과 버튼**:
- 의도 라디오와 지시 대상의 칩+select 중복을 칩 하나로 합친다.
- 모델 네이티브 select는 "모델 × 노력" 칩 메뉴로 바꾼다.
- **보내기 버튼 상태**:
  - 쉬는 중: 보내기;
  - 실행 중이고 입력이 비었음: 멈춤(확인);
  - 실행 중이고 입력이 있음: 의도 칩에 따라 지시 또는 대기.
- **대기열**: 컴포저 위에 붙인다. 항목별 수정·삭제·지시로 올리기를 두되, API가 지원하는 것만 둔다. 삭제 API가 있는지는 미확인이므로 CR에서 확인한다.
- **입력 기록**: 빈 입력에서 ↑를 누르면 이전 요청을 불러온다.

### P3. 대화 흐름 표시 (`review-motion`, `edit-copy`)

- **Run 머리**: 한 줄에 팀 · 상태 점 · 경과 시간. 이것이 Run 상태가 보이는 유일한 자리다(D-01).
- **스트리밍**: 본문을 본 대화에 바로 보인다(D-16). 작업 기록은 원문 보기용으로 남긴다.
- **에이전트 활동**: 기본은 "에이전트 3명 작업 중" 한 줄이고, 펼치면 역할별 한 줄씩 보인다. 실패 이유는 접지 않는다(CR-015-03 유지).
- **결정 카드**: 동사 버튼 + 산출물 이름·버전으로 보인다(CR-015-07 유지). 내부 ID는 title에만 둔다.
- **Run 끝**: "변경 n개 검토" 버튼 하나만 둔다. 반복되는 검토 링크를 없앤다.
- **움직임**: 패널 열기, 스트리밍 커서, 메뉴 등장을 150ms 안쪽으로 한다. `prefers-reduced-motion`에서는 끈다.
- **세부 손질**: 정렬·hover·포커스 링 같은 마무리에는 `make-interfaces-feel-better` 스킬을 보조로 쓴다(선택).
