# 세션 묶음·템플릿·증거 요약 플랜

작업 중인 플랜이다. 명세가 아니며 완료되면 삭제한다. 동작 계약은 각 단계가 고치는 [workbench](../specs/workbench.md), [라이브러리](../specs/features/library.md), [기능 미리보기](../specs/features/feature-preview.md), [canvas](../specs/features/canvas.md)와 새 기능 명세가 소유한다.

## 목표

"Corral 통합 기능 고도화" 제안서를 로드맵으로 채택하지 않고 부족분만 메운다. 사용자의 작업 단위는 세션이다. 새 Task 원장, 의존성 그래프, Agent Definition 원장, 추천·분해·Refiner, Scratch, 차트, 이벤트 트리거, 원격 협업은 만들지 않는다.

브랜치 `feat/session-advancement`는 `feat/product-redesign`(83671d64) 위에 쌓는다. 리디자인 브랜치에 커밋이 더해지면 merge로 가져온다.

## 확정 결정 (2026-11-10)

1. **작업 단위는 세션이다.** 화면에 "작업 보드", "Task", "백로그"를 쓰지 않는다. 작업 보드 미리보기는 1단계에서 지운다.
2. **6단계는 라이브 평가를 거친다.** 로그인된 GPT 모델 luna와 terra로 잰다. terra가 등록되어 있지 않으면 등록한다. 결과가 있을 때만 병합한다.
3. **auto 모드는 지금의 세 템플릿으로 고정한다.** 새 패턴은 초안 기능만 쓴다.
4. **세션 완료 기준은 저장 팀의 기준을 덮어쓴다.** 회의 인계와 같다. 검토 레시피가 다른 기준을 고정한 팀은 기존 규칙대로 시작을 거절한다.
5. **예약은 auto 세션만 받는다.** 저장 팀 세션 예약은 하지 않는다.

## 단계별 메모

- **1단계**: 서버와 계약은 바꾸지 않는다. 사이드바가 같이 쓰는 `sessionListState`는 고치지 않는다. 플래너 안과 달리 완료 묶음은 펼친 채 둔다. 대부분의 세션이 완료라서 접으면 목록이 비어 보인다.
- **2단계**: 프롬프트 품질은 재지 않는다. 구조(strict 컴파일, 도구 범위, mock 실행 완주)만 검증한다.
- **3단계**: 목록에서는 기록 시각만 비교한다. 정확한 현재 유효성은 기존 검사 보기가 계산한다. 터미널에서 직접 바꾼 변경은 잡히지 않는다.
- **5단계**: `work_sessions`에 열을 더하며 마이그레이션은 쓰지 않는다. 화면에 "기준 충족"이라고 쓰지 않는다.
- **6단계**: `AUTO_TEMPLATES`를 `TEAM_PATTERNS`에서 분리해 세 개로 고정한다. `AUTO_TEMPLATE_VERSION`과 auto 라우터 프롬프트는 바뀌지 않는다.

## 구현 전에 확인할 것

- MockAdapter가 병렬 + Join 구조를 완주하는지(2단계 첫 테스트).
- 일반 세션 요청이 실행 입력의 기준을 만드는 경로와 `work_sessions` 스키마 생성 코드(5단계).
- `/preview/task-board`를 지운 뒤 알 수 없는 feature 주소의 처리(1단계).
- 세션이 수백 개일 때 프로젝트 세션 목록의 비용(1단계에서 한 번 잰다).
