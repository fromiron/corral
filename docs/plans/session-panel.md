# 세션 패널: 작업 계획

세션(대화) 화면은 지금 상단의 보기 탭(대화 · 파일 · 변경 · 실행 기록)으로 화면 전체를 바꾼다. 그래서 실행 기록이나 변경을 보는 동안 대화와 입력창이 화면에서 사라지고, 터미널은 파일 화면 안에서만 열린다. 이 계획은 대화를 늘 화면에 두고, 오른쪽 패널 하나에 필요한 것을 탭으로 열고 닫는 구조로 바꾼다.

명세: [세션 패널](../specs/features/session-panel.md)(새로 씀), [Workbench](../specs/workbench.md), [채팅 위젯](../specs/chat-widgets-contract.md), [실행 기록 관찰](../specs/features/execution-monitor.md), [대화 입력 흐름](../specs/features/composer-flow.md), [파일 경로 검색](../specs/features/file-search.md), [Desktop](../specs/desktop-contract.md).

브랜치는 `feat/session-panel`이고 `fix/session-screen-density`의 끝에서 갈라졌다. 밀도 브랜치는 아직 `develop`에 합쳐지지 않았다(38 커밋 앞). 이 계획의 화면은 밀도 브랜치의 변경(활동 바의 칩, 중지가 서는 곳, 560px 최소 폭)을 전제로 한다.

단계마다 명세 → 실패하는 테스트 → 구현 순서로 하고 단계마다 커밋한다. 새 구조의 목표 동작은 새 기능 명세에 쓴다. 기존 명세에서 지금 동작을 적은 문단은 그 동작을 실제로 바꾸는 단계에서 고친다. 단계마다 `pnpm lint`, `pnpm typecheck`, 관련 테스트를 돌리고 실제 화면에서 확인한다.

시안과 비교 자료는 저장소에 싣지 않는 곳에 있다: `output/session-panel-mockups/`(눌러 볼 수 있는 시안 `prototype.html`, 오늘 화면과 나란히 둔 `index.html`), `ux-flows/session-panel.proposed.flow.json`(제안 흐름 지도), `ux-flows/notes/session-panel-comparison.md`(기능별 경로 비교). 시안은 그림이지 계약이 아니다. 시안에는 정한 것과 만드는 사람이 고른 것이 섞여 있으므로, 명세에는 아래 장부의 "정한 것"만 옮긴다.

## 결정 장부

### 사용자가 정한 것 (2026-11-16)

1. 대화는 늘 화면에 남는다. 오른쪽 패널 하나에 탭을 하나씩 열고 닫는다. 미리 열려 있는 탭은 없다. 상단의 보기 탭은 없앤다.
2. 화면의 어느 것도 다른 것이 이미 말한 것을 되풀이하지 않고, 같은 일을 하는 조작을 둘 두지 않는다.
3. "+"는 그 자리에 뜨는 목록이다. 탭이 없으면 같은 목록이 패널 안에 놓이고 "+"는 없다. "새 탭" 화면은 두지 않는다.
4. 탭 줄은 하나다. 문서 두 개를 나란히 보는 것(문서 그룹 둘)은 없앤다. 팀 그래프 탭과 그 안의 D&D는 그대로 둔다.
5. 패널이 넓으면 파일 트리가 문서 왼쪽 열로 붙는다. 좁으면 트리와 문서는 각각 탭이다.
6. 열어 둔 탭은 대화마다 따로 가진다.
7. 터미널은 패널의 탭으로도, 화면 아래의 도크로도 연다.
8. 왼쪽 사이드바와 오른쪽 패널은 끌어서 폭을 조절한다.
9. 브라우저 탭은 외부 사이트를 포함한 모든 주소를 연다.
10. 브라우저의 주석: 버튼을 누르면 테두리가 움직임과 함께 그려지고, 요소를 누르면 그 자리에서 적으며, 스타일을 바꿔 볼 수 있다. 위·아래 버튼은 두지 않는다. 품질 기준은 사용자가 보여 준 다른 도구의 화면이다.
11. 주석 칸의 보내기는 대화로 바로 보낸다. "모아 두기"를 켜면 주석이 번호로 쌓여 입력창에 들어가고 보내기는 입력창에서만 한다.

### 내가 정하고 보고한 것 (이의 없었음)

- 폭: 대화 영역 최소 560px, 패널 최소 360px, 패널 기본 폭은 작업 영역의 45%. 패널 폭은 사이드바처럼 앱에서 하나를 기억한다.
- 자리가 없으면 패널은 서랍으로 뜨고, 서랍은 하단 터미널까지 덮는다. 넓히기는 대화를 가리고 패널만 보인다.
- 상단의 터미널 버튼은 하단 도크를 여닫는다(Ctrl+J). 패널을 넓혔거나 서랍일 때는 그 버튼이 패널 머리로 옮겨 간다.
- 메시지 영역은 160px 아래로 내려가지 않는다. 모자라면 하단 도크가 물러난다.
- "+" 목록의 순서는 파일, 터미널, 변경, 실행 기록, 브라우저, 작업이다. 터미널과 브라우저는 늘 새 탭을 열고 나머지는 열린 탭이 있으면 그 탭으로 간다.
- 팀 그래프 탭으로 가는 길은 상단 더 보기 메뉴의 "Corral 설계 열기" 하나다.
- 대화 옆에 놓인 실행 탭에는 상태 줄이 없다(답 행이 상태와 시간을 말한다). 진행 중 · 실패 · 중지는 탭에 표시한다. 넓히면 상태 줄, 일시정지 · 중지, 지난 실행을 보는 동안의 알림 줄이 돌아온다.
- 입력창 위의 변경 칩은 변경 탭이 탭 줄에 없을 때만 보인다.
- 탭이 넘치면 이름을 줄이고, 그다음 아이콘만 남기고(터미널은 번호를 남긴다), 그다음 스크롤한다. 선택한 탭은 이름과 닫기를 늘 보인다.
- 선택하지 않은 탭은 가리키거나 초점을 두면 아이콘 자리에 닫기가 나온다. 가운데 버튼과 Delete로도 닫는다.
- 탭은 끌어서 순서를 바꾼다. 터미널 탭은 패널과 하단 도크 사이를 끌어 옮기고, 메뉴로도 옮긴다.
- Paddock이 없으면 하단 도크는 한 줄 안내와 버튼 하나만 보인다.
- 변경 검토의 파일 목록은 지금처럼 왼쪽에 둔다.
- 새 이벤트, 실행의 시작과 종료, 늦게 온 결과는 탭을 열지도, 선택을 바꾸지도, 닫지도, 패널을 여닫지도 않는다. 탭은 사용자가 연 것만 열린다.
- 선택한 탭을 닫으면 오른쪽 이웃이, 없으면 왼쪽 이웃이 선택된다. 마지막 탭을 닫으면 패널은 열린 채 "+"의 목록을 보인다.
- 파일 · 변경 · 실행 탭을 닫는 것은 숨기는 것이다. 실행, 대화의 입력 초안, 열어 둔 문서, 터미널을 끝내거나 지우지 않는다(터미널 탭을 닫는 것은 S4에서 따로 정한다).
- 선택하지 않은 탭은 한 번 본 뒤로 화면 상태(보기, 선택, 스크롤, 그래프 위치)를 그대로 둔다. 탭을 닫으면 그 화면 상태는 남지 않는다. 실행 탭을 닫으면 그 실행 화면에서 쓰던 지시 초안도 남지 않는다(지금 다른 실행으로 바꿀 때와 같다).
- 실행 탭은 실행마다 하나다(실행 #n). 같은 실행을 열면 그 탭으로 간다. "+"의 실행 기록은 가장 최근 실행을 연다.
- "+" 목록에는 지금 열 수 있는 것만 있다. 파일과 변경은 지금 조건대로 프로젝트 폴더가 연결됐거나 파일 작업을 한 번 연 대화에, 실행 기록은 실행이 있는 대화에 나온다. 열 수 있는 것이 하나도 없으면 패널 여닫기 버튼도 없다.
- 주소는 지금의 매개변수로 선택된 탭을 가리킨다. `panel`이 없는 대화 주소는 패널이 닫힌 상태다. 매개변수가 하나도 없는 주소는 그 대화가 기억한 모습을 되살린다. 주소가 가리키는 탭이 닫혀 있으면 연다. 뒤로 가기는 주소를 되돌릴 뿐 탭을 닫지 않는다.
- 대화마다 탭 목록 · 순서 · 선택 · 패널의 열림 여부를 이 기기에 기억한다. 넓히기는 주소에도 기억에도 남지 않는다. 탭 없이 열려 있던 패널은 닫힌 것으로 되살린다.
- 실행 조작(일시정지 · 재개 · 중지)은 화면에 한 곳이다. 대화가 보이는 동안 실행 탭의 머리는 그 조작을 보이지 않고 입력창의 것을 쓴다. 넓혀서 대화가 가려진 동안에만 실행 탭 머리의 조작이 돌아온다. 전체 중지 확인은 누른 자리에서 묻는다. 그 자리가 없어지면(넓히기를 풂, 탭을 닫음, 다른 실행, 다른 대화) 확인 대기는 버려지고 취소는 보내지지 않는다. 탭만 바꿨다 돌아오면 남아 있다.
- 넓힌 동안 중지와 응답에 닿는 길은 지금의 전체 화면 보기와 같다: 실행 탭은 머리의 조작과 응답하기, 파일 · 변경 탭은 넓히기를 풀어 대화로 간다.
- 상단 경로의 실행 선택기는 S1에서 그대로 둔다. 실행 탭이 선택된 동안 보이고, 고르면 그 실행의 탭을 열거나 그 탭으로 간다. 탭 이름과 같은 번호를 두 번 말하는 문제는 S2에서 정한다.
- 읽기 전용 파일 뷰어가 하던 원본 폴더 읽기는 파일 탭의 대상 선택(원본 · 사본)이 맡는다. 원본과 사본을 동시에 나란히 보는 것은 탭 줄을 하나로 정한 데 따라 없어진다.
- 대화를 앞으로 가져오는 동작(선택 첨부, 파일 참조, 응답하기, 조언 읽기)은 패널이 옆에 있으면 패널을 그대로 두고, 넓힌 상태면 넓히기를 풀고, 서랍이면 서랍을 닫는다.
- 사용자가 탭을 열면 포커스는 그 탭으로 간다. 닫으면 열었던 조작으로, 그것이 없으면 패널 여닫기 버튼으로 돌아간다. 서랍은 떠 있는 동안 포커스를 안에 가둔다.
- 이름: 이 계획의 "패널"은 세션 화면 오른쪽의 탭 패널이다. 실행 화면 안의 오른쪽 상세(실행 상세 · 확인 필요 · 실행 정보)는 "실행 화면의 상세 영역"이라 부르고 둘을 섞어 쓰지 않는다.

### 시안을 만들며 고른 것 (계약이 아니다. 해당 단계에서 다시 정한다)

- 패널이나 하단 도크를 끌어서 숨긴 뒤 다시 열면 끌기 전 크기로 돌아온다(사이드바는 최소 폭으로 돌아온다).
- 실행 상세와 실행 정보가 보기 줄 아래에서 시작하는 폭(1000px 미만).
- 팀 편집기가 패널 폭에서 팔레트 · 캔버스 · 속성을 세로로 쌓는 배치(지금 편집기는 고정 폭 배치다).
- 브라우저: 탭을 여럿 여는 것, 주소를 치는 동안의 제안 목록, 제목이 없을 때 호스트 이름을 탭 이름으로 쓰는 것.
- 주석의 수치와 자리: 좁은 배치로 바뀌는 폭(560px), 스타일 시트의 높이(45%), 떠 있는 스타일 보기와 주석 칸의 크기, 이름표가 글자를 가리지 않게 자리를 고르는 순서, 번호 표시의 자리, 움직임의 시간.
- 주석의 동작: Esc가 닫는 순서, 화살표 키로 범위를 바꾸는 조건, 다른 요소를 고르면 쓰던 주석이 칩으로 남는 것, 보낸 뒤 그 요소의 미리보기 변경을 되돌리는 것, 입력창에서 보낸 뒤 주석 모드를 유지하는 것, 실행 중에 합류로 보낼 때 스크린샷을 싣지 않는 것.

### 정해지지 않은 것

- 외부 사이트의 로그인, 내려받기, 권한 요청, 저장소 분리. 사용자가 정한다(S5 전).
- 패널 안에 놓은 브라우저 뷰 위에 앱의 팝오버 · 서랍 · 끌기 표시와 주석 화면을 그릴 수 있는지(B0). 안 되면 주석 화면을 페이지 안에 넣는 방식이 계약에 들어간다.
- 웹 빌드의 브라우저 탭(지금 생각: 관리형 미리보기만).
- 실행 밖에서 고친 파일을 변경 개수에 넣을지.
- 터미널 탭을 닫으면 터미널을 끝내는지, 끊긴 터미널을 어떻게 되찾는지.
- 저장하지 않은 문서 탭을 닫을 때 묻는 방식(지금 도킹의 저장 · 버리기 · 취소를 그대로 쓸지).
- 회의 화면에도 패널을 둘지.
- 창이 1024px보다 좁아 사이드바가 서랍이 되는 폭에서의 패널.

## S1. 패널 셸

대화를 늘 싣고 그 옆에 패널을 놓는 틀만 만든다. 패널 안의 내용은 지금 화면을 그대로 쓴다: 파일 탭은 지금의 파일 화면(도킹 전체), 변경 탭은 지금의 변경 화면, 실행 탭은 지금의 실행 기록이다. 그래서 이 단계에서는 파일 탭 안에 문서 탭과 터미널이 그대로 들어 있고, 상단의 터미널 버튼은 파일 탭을 열어 그 안의 터미널을 보인다. 이 겹침은 S3과 S4에서 없어진다.

이 단계에 들어가는 것: 탭 줄과 "+" 목록(파일 · 변경 · 실행 기록), 답 행의 "실행 #n"과 결과 · 파일 · 변경 링크가 해당 탭을 여는 것, 패널 여닫기, 폭 조절(사이드바의 분할선을 킷의 공용 부품으로 꺼낸다), 넓히기, 자리가 없을 때의 서랍, 대화마다의 탭 저장, 기존 주소(`panel`, `run`, `view`)가 같은 것을 여는 것, 대화가 보이는 동안 실행 탭 머리의 실행 조작을 감추는 것(중지가 화면에 둘이 되지 않게). 상단 보기 탭과 읽기 전용 파일 뷰어 버튼은 이 단계에서 없앤다(뷰어가 하던 일은 대화 옆의 파일 탭이 한다).

이 단계에 들어가지 않는 것: 실행 탭의 상태 줄 · 실행 선택기의 자리 · 변경 칩(S2), 탭의 종류별 내용 바꾸기(S3 이후), 하단 도크(S4), 탭 끌기(S3).

이 단계의 사실: 탭 줄은 대화마다지만 파일 탭 안의 도킹 배치(열린 문서 · 터미널 · 크기)는 S3까지 지금처럼 프로젝트마다 하나다. 파일 탭 안의 창 전환기는 상단 줄에서 패널 안으로 옮긴다. 킷에는 닫을 수 있는 탭 줄, 사이드바 밖의 분할선, 옆 서랍이 없다(지금 파일 뷰어의 서랍은 손으로 짠 것이다). 셋을 킷의 부품으로 먼저 만든다. 대화마다의 기억은 지금의 `corral:session-view:v1` 저장을 대신하며 옮겨 주지 않는다.

오늘 셸의 동작을 코드에서 확인한 기록은 `ux-flows/notes/session-shell-today.md`에 있다(저장소에 싣지 않는다).

## B0. 브라우저 스파이크

지금 미리보기는 별도 창의 `WebContentsView`다. 패널 안에 놓으면 그 뷰는 앱 화면 위에 그려지는 별도 층이라, 앱의 "+" 목록, 서랍의 어둠, 탭을 끄는 동안의 표시, 주석의 테두리 · 주석 칸 · 스타일 보기를 그 위에 그릴 수 있는지 확인해야 한다. 확인할 것: 뷰가 패널의 자리와 크기를 따라가는지, 앱 화면이 그 위에 그려지는지, 주석 화면을 페이지 안(격리된 스크립트)에 넣었을 때 엄격한 CSP 페이지와 한글 입력에서 동작하는지, 앱 화면이 겹칠 때 뷰를 그림으로 바꿔 두는 방식이 쓸 만한지. 제품 코드는 바꾸지 않고 결과만 이 계획에 적는다.
