# 02-UX-Spec 구현 대조표

- 대상: [02-UX-Spec](../proposals/workbench-v0.1/02-UX-Spec.md)(Workbench 개선안 v0.1).
- 기준: main, 2026-10-17. 관련: [Workbench 개선 플랜](Workbench-Improvement-Plan.md), CR-009–CR-013.
- 표시: **구현**은 화면에서 동작을 확인했다. **부분**은 일부만 했고 남은 점을 적었다. **미룸**은 Bell의 지시나 이유가 있어 하지 않았다.

| 절 | 요구 | 상태 | 구현과 남은 점 |
|---|---|---|---|
| §1 | 프로젝트 / 세션 / 확인 필요 / 팀 라이브러리 / 설정 정보 구조 | 구현 | 왼쪽 사이드바(프로젝트, 세션 검색·목록, 확인 필요 수, 새 세션, 팀 라이브러리, 모든 프로젝트, 모델). Run·Task·Artifact를 전역 메뉴에 늘어놓지 않는다. |
| §1 | 새 프로젝트는 폴더 연결 또는 자료로 시작 | 구현 | 만들기 화면에 "연결할 폴더(선택)"이 있다. 비우면 자료로 시작하고, 나중에 프로젝트 화면에서 연결할 수 있다. |
| §1 | 목적 한 줄로 세션, 모델 호출 없는 자동 제목 | 구현 | 제목이 비면 목적 첫 줄. |
| §2 | 좌 약 240px · 우 약 360px, 조절, 좁은 폭은 탭, 레이아웃 기억 | 구현 | 끌기와 화살표 키로 너비 조절, 숨기기, 이 브라우저에 기억. 1024px 미만은 세션·작업·패널 탭. |
| §2 | 머리줄: 프로젝트·세션·복사본·팀 revision·실행 상태·권한 모드, 실제/모의 표시 | 구현 | 권한은 "파일 작업 없음 / 폴더 관측만 / 작업 복사본에만 쓰기"로 보인다. 전체 경로는 줄여 보이고 툴팁에 전체를 둔다(프로젝트 화면). |
| §3 작업 | 요청·진행·질문·승인·결과 중심, 원문은 Run 카드에서 | 구현 | 요청 카드, Run 카드, 결정 대기 승인, 실행 상세 탭으로 원문 접근. 새 이벤트가 와도 자동 스크롤하지 않는다. |
| §3 작업 | 완료 카드: 수행함 / 검증함 / 못 끝냄 / 다음 행동, 에이전트 요약 구분 | 구현 | "수행함·못 끝냄", "에이전트 결과(에이전트가 쓴 글)", 다음 행동(변경 검토)을 둔다. "검증함"은 그 Run의 종료 snapshot과 같은 tree에서 돈 검증이 있을 때만 보이고, 없으면 "검증 안 함"이다. |
| §3 팀 설계 | Canvas 유지, 실행에 적용된 revision과 다음 초안 구분 | 구현 | 팀 설계 탭은 저장한 팀 편집기다. 머리줄에 팀 revision, 탭 안내에 "다음 Run이 저장한 revision을 쓴다"를 둔다. |
| §3 실행 상세 | 설계 그래프·실행 트리·협업 로그, 선택 유지 | 구현 | Run 화면과 같은 `RunDetail`을 실행 상세 탭에 넣었다. 선택한 Run·실행·결과는 주소에 남는다. |
| §3 검토 | 중앙 diff, 좌 파일 목록, 우 의견·Reins·검증, 사이드바 접기 | 구현 | |
| §3·§9 | 작업 화면으로 돌아갈 때 선택 파일과 scroll 위치 보존 | 구현 | 선택 파일·범위는 주소에 남는다. 세션 탭별 scroll 위치는 이 탭(sessionStorage)에 남아 돌아오면 그 자리로 간다. |
| §4 | 비교 범위 선택, 기준 snapshot A → B, 새 변경 수 | 구현 | 세션 전체·마지막 검토 이후·Run별, 그리고 "원본 폴더(Git 작업 트리)": HEAD → 지금 디스크(스테이징 표시, 추적 안 하는 파일 포함). 원본은 읽기만 하며 index도 쓰지 않는다. tree id 앞 8자리와 "새 변경 N". |
| §4 | 파일 검색 / 미검토만 / 종류 / 생성 파일 | 구현 | 생성·잠금 파일은 접고 개수를 보인다. 삭제는 접지 않는다. |
| §4 | [통합][나란히][원본][검토함][의견 추가] | 구현 | 검토함은 파일 내용(blob)별 읽음 표시라 승인과 다르다. 줄 번호를 눌러 의견을 단다. |
| §4 | 의견은 쪽·전후 버전에 묶이고 새 revision에 자동 재부착 안 함 | 구현 | CR-013. |
| §4 | 큰 diff는 파일 하나씩, 바이너리·누락은 "변경 없음"이 아님 | 구현 | 파일 하나씩 읽는다. 바이너리·1 MiB 초과는 그렇게 표시한다. |
| §4 | 계산 시간 초과 시 "계산 중단"과 원문·내려받기, 무한 spinner 금지 | 구현 | 비교는 worker에서 계산하고 3초가 넘으면 멈춰 "계산 중단"과 원문·내려받기를 보인다. 줄이 너무 많으면 전체 교체로 보인다고 알린다. |
| §5 | 새 세션: 프로젝트 → 목적 → 팀 → 파일이면 폴더·복사본·기준 확인 → 실행 전 요약 → 실행 | 구현 | 복사본을 만들 때 기준 commit과 제외되는 미커밋 변경 수를 보인다. 입력창 아래 실행 전 요약(팀 revision·모델·파일 작업·한도·모드). |
| §6 | 완료 아래 "이 세션에서 계속", 후속 목표가 새 brief | 구현 | |
| §6 | 실행 중 target chip과 적용 경계, target 바뀌어도 초안 유지, 종료 시 버튼 갱신 | 구현 | "대상: … · 다음 모델 요청에 전달". 대상 목록은 실행 중 1.5초마다 갱신한다. |
| §6 | 대기 자동 시작은 한 번 명시 설정, 항목별 취소·수정(새 version) | 구현 | 기본 꺼짐. 이 페이지가 Run 종료를 본 뒤에만 시작하고, 다시 시작한 서버에서는 시작하지 않는다. 수정은 원래 항목을 지우고 새 항목으로 기록한다. |
| §6 | 모든 전송에 command ID, 재시도는 같은 ID | 구현 | 응답을 잃고 다시 보내면 같은 ID를 써서 Run이 둘 생기지 않는다. |
| §7 | Reins 단계(접수·첨부·전달·미전달 …) 표시, 별도 큐 금지 | 구현 | 세션 기록의 지시 항목이 Run의 directive 상태를 그대로 보인다. "addressed·verified"는 검토 의견 상태(CR-013)로 표시한다. |
| §8 | 빈 상태·에러 표 | 구현 | 세션 없음, 파일 미연결, 폴더 이동·삭제, 작업 복사본 사라짐, 비교 준비 중, 변경 0, 제외 파일 안내, 실패·취소 Run의 남은 결과, 반영 충돌, 서버 연결 끊김(상태를 단정하지 않음). "기록 손상"은 서버 오류 문장으로만 보인다. |
| §8 | 확인 필요 Inbox: 처리할 것만, 열어도 닫히지 않음 | 구현 | CR-013. |
| §9 | 서버 사실 / 편집 / 뷰 / 스트림 상태 분리 | 구현 | 서버 저장, 편집기 store, 주소·localStorage의 뷰 상태, 실행 스트림이 서로 다르다. |
| §10 | 키보드: 탭·패널 크기·트리·diff·Reins, IME Enter 미전송, Ctrl/⌘+Enter | 구현 | 탭은 화살표, 패널 너비는 화살표, 의견은 줄 번호 버튼. |
| §10 | 좁은 화면 통합 diff·탭 패널 | 구현 | |
| §10 | 모의 데모: 프로젝트 2·세션 6·다중 파일·취소·피드백 | 구현 | 브라우저 데모의 `/projects`에 "예시 프로젝트 만들기"(프로젝트 2·팀·세션 6). 두 번째 프로젝트는 예시 폴더를 연결·신뢰하고, 팀이 파일을 바꿀 수 있으며, 첫 세션에 작업 복사본이 있다. 데모 worker 안의 메모리 폴더(`demo/workspace.ts`)가 서버와 같은 규칙(경로, 읽은 뒤에만 변경, 작업 기록, Run 시작·종료 snapshot)으로 파일 도구·비교·의견·판단·반영·되돌리기를 처리한다. 검증 명령은 컴퓨터에서 명령을 실행하므로 데모에서는 "로컬 서버에서만"이라고 알린다. 새로고침하면 폴더 상태는 처음으로 돌아간다(데모 Run과 같다). |
| §11 | 측정 목표(전환 p95 300 ms, diff p95 500 ms 등), 사용자 평가 | 구현(측정) | 2026-10-17 측정, [Performance.md](../Performance.md) "Workbench 화면 측정". 세션 500개·프로젝트 30개·바뀐 파일 301개(200 KB 파일 포함)에서 diff 표시 p95 361 ms, 세션 전환 p95 162 ms, 패널 크기 조절 long task 0, 네 화면 axe serious 0. 처음 실행의 diff 827 ms는 Myers diff·가상화·git 호출 축소로 고쳤다. 5명 사용자 평가는 사람 참가자가 필요하다. 진행 안내(참가자·환경 준비·과제 3개 스크립트·성공 기준·심각도·분석)와 결과 기록지를 [docs/evaluation](../evaluation/Workbench-Usability-Test.md)에 준비했다. 실시는 진행자(Bell)가 한다. |
