# 세션 화면 밀도 개선: 작업 계획

세션(대화) 화면을 1280×800에서 걸어 보고 잰 결과, 핵심 작업은 한두 번의 클릭으로 닿는다. 복잡하게 느껴지는 까닭은 깊이가 아니라 한 화면에 함께 놓이는 양과, 같은 일을 하는 길이 여럿인 데 있다. 이 계획은 그중 방향이 정해진 것을 고치고, 큰 항목은 시안으로 방향을 정한 뒤 고친다.

명세: [Workbench](../specs/workbench.md), [채팅 위젯](../specs/chat-widgets-contract.md), [컴포저 흐름](../specs/features/composer-flow.md), [실행 모니터](../specs/features/execution-monitor.md), [모델·추론·리소스](../specs/models-and-resources.md).

브랜치는 `develop`에서 분기한 `fix/session-screen-density` 하나다. 단계마다 커밋하고, 동작이 바뀌는 단계는 명세 → 실패하는 테스트 → 구현 순서로 한다. 단계마다 `pnpm lint`, `pnpm typecheck`, 관련 테스트를 돌리고 실제 화면에서 확인한다. E2E 흐름 묶음은 끝에 한 번 돌린다.

잰 값과 걷기 기록은 저장소에 싣지 않는 `ux-flows/`에 있다(지도 `session-tasks.flow.json`, 기록 `runs/`, 정리 `notes/session-screen.md`). 고친 뒤 같은 여정을 다시 걸어 새 기록으로 남기고 비교한다.

| 단계 | 내용 | 상태 |
|---|---|---|
| S0 | 설정의 작업 폴더 줄: 긴 경로가 입력과 버튼을 줄 밖으로 밀어냄 | 완료 |
| S1 | 폴더가 없는 대화의 안내: 문구가 가리키는 곳과 버튼이 여는 곳이 다름 | 완료 |
| S2 | 도구 줄의 모델 칩: 긴 이름이 두세 줄이 되어 컴포저가 자람 | 방향 확인 중 |
| S3 | 라이브러리 리소스 행의 "관리"가 그 항목을 연다 | 다음 |
| S4 | 경로의 제목 메뉴는 대화 고르기만 한다 | 다음 |
| S5 | 대화 탭으로 돌아오면 실행 선택을 푼다 | 다음 |
| S6 | 큰 항목 셋의 시안과 결정 | S3–S5 다음 |

## S2. 모델 칩

지금 칩이 줄을 바꾸는 것은 정해진 동작이다. [Workbench](../specs/workbench.md)의 검증 문단은 좁은 폭에서도 선택 요약이 잘리지 않아야 한다고 하고, 킷의 ModelPicker는 그에 맞춰 긴 이름을 여러 줄로 보인다(`packages/react/src/design-kit/README.md`의 ModelPicker·InputMessage 항목, `ModelPicker.stories.tsx`의 `LongNameNarrow`). 한편 [컴포저 흐름](../specs/features/composer-flow.md)은 도구 줄이 늘 한 줄 높이라고 한다. 두 문장이 긴 모델 이름에서 부딪친다.

컴포저의 도구 줄은 한 줄 모드(`toolbar="single"`)라 왼쪽 묶음이 자리를 내주고, 1280 폭에서도 칩들이 줄을 채워 36자 이름은 222×48(두 줄), 파일 뷰어를 연 632 폭에서는 155×68(세 줄)이 된다.

어느 문장을 따를지 정해지면 그 명세를 먼저 고치고 구현한다. 팀(Corral) 칩은 이미 한 줄 말줄임이다.

## S3. 라이브러리의 "관리"

리소스 행의 "관리"는 설정의 맞는 구역을 열지만 항목을 고르지 않는다. 링크가 항목을 싣고, 설정이 그 항목을 연 채로 뜬다.

## S4. 제목 메뉴

경로의 대화 제목 메뉴와 "더 보기" 메뉴가 이름 바꾸기, 완료 기준, 고정, 보관을 함께 싣는다. 제목 메뉴에는 대화 목록만 남기고 동작은 "더 보기"에만 둔다. [Workbench](../specs/workbench.md)의 세션 메뉴 문장을 먼저 고친다.

## S5. 실행 선택

실행 기록에서 지난 실행을 본 뒤 대화 탭으로 돌아오면 주소에 선택이 남아, 컴포저에 "다른 실행을 보는 중" 경고가 뜨고 활동 바가 선택한 실행을 말한다. 대화 탭에서는 선택을 풀어 활동 바가 늘 진행 중이거나 마지막인 실행을 말하게 한다. 지난 실행은 실행 기록 탭에서만 고른다. 초안과 보낼 대상은 바뀌지 않는다. [채팅 위젯](../specs/chat-widgets-contract.md)과 [컴포저 흐름](../specs/features/composer-flow.md)의 실행 선택 문장을 먼저 고친다.

## S6. 시안으로 정할 것

지금 화면과 제안을 나란히 보이고 방향을 정한 뒤 구현한다. 활동 바의 Reins 조작은 승인 없이 빼거나 미루지 않는다.

- 펼친 활동 바: 실행 중에 펼치면 컴포저가 147에서 380px로 자라고 역할 이름과 "중지"가 두 번씩 나온다.
- 파일을 보는 자리 셋: 상단 "파일" 탭, 대화 옆 "파일 뷰어", 터미널 보기 안의 "파일" 창. 파일 뷰어를 열면 "파일 뷰어 닫기"가 둘이다.
- 실행 기록으로 가는 길 넷: 응답 행의 "실행 #n", 상단 "실행 기록" 탭, "결과 화면에서 보기", 상단 경로의 실행 표지. "실행 기록" 탭은 실행 목록이 아니라 마지막에 본 보기를 다시 연다.
