# 초기 개발의 테스트 운영

기본 E2E의 범위는 [데모·출시 명세](../specs/features/demo-release.md)를 따른다. 매 UI 변경마다 상세 브라우저 시나리오 전체를 통과시키는 것을 개발의 전제로 삼지 않는다.

| 명령 | 용도 |
|---|---|
| `pnpm test:e2e` | PR CI와 일반 개발의 Chromium 스모크 2개. 대화 전송·답변·재로드, 캔버스 포인터 연결 |
| `pnpm test:e2e:extended` | 변경한 영역의 상세 시나리오를 필요할 때 선택 실행 |
| `pnpm release:gate` | 전체 확장 E2E와 다중 브라우저·접근성·IME를 포함한 출시 검증 |

서버 스모크는 먼저 `pnpm --filter @corral/studio build`가 필요하다. 공급자 응답은 기존 로컬 fake를 쓰며 유료 API는 호출하지 않는다. 기본 검사는 Chromium만 설치하면 된다. 확장 검사의 Firefox 프로젝트는 `pnpm --filter @corral/studio exec playwright install firefox`로 따로 준비한다.

특정 회귀만 확인할 때는 파일과 프로젝트를 지정한다.

```sh
pnpm test:e2e:extended e2e/server/server.spec.ts --project=server --workers=1
```

세션 테스트는 현재 `Session views`의 대화·파일·변경·실행 기록을 구분한다. 파일의 도킹 메뉴는 파일 화면에서 열고, 다른 탭으로 이동한 뒤 보존된 입력을 검사할 때와 실제 입력할 때를 구분한다. 실행 완료는 개별 실행 행의 부분 일치 텍스트가 아니라 Run의 정확한 상태나 확정 결과로 기다린다. 디자인킷 전환 뒤에도 키보드 조작·전체 식별자 펼치기·초안 보존 같은 원래 검증 목적은 유지한다.

로컬에서 확장 검사 전체를 돌릴 때는 `--workers=2`를 준다(CI의 값이다). 워커가 많으면 실행이 끝나기 전의 짧은 구간을 보는 스펙이 흔들린다. 흔들린 스펙은 단독으로 다시 돌려 가른다.

## 흐름 장면

대화 화면의 전이가 화면을 흔들지 않는지를 재는 장면 검사다. 동작의 기준은 [대화 입력 흐름](../specs/features/composer-flow.md)과 [표시 상태](../specs/features/presence.md)가 정하고, 여기에는 재는 방법과 합격선을 적는다.

```sh
pnpm --filter @corral/studio build
pnpm --filter @corral/studio exec playwright test --config playwright.flow.config.ts
```

- Chromium에서 워커 하나로만 돈다. 워커를 늘리면 여러 워커가 `test-results/flow/report.json`을 함께 써서 깨진다. 전체는 30분쯤 걸린다.
- 서버는 `e2e/server/harness.ts`의 하네스가 테스트마다 띄운다. 스크립트 어댑터와 가짜 응답만 쓰고 외부 호스트는 하네스가 막는다.
- 기본 게이트와 확장 구성에 들어 있지 않다. 대화 타임라인, 실행 행, 컴포저, 활동 바, 사이드바의 대화 행, 회의 화면을 바꿨을 때 해당 장면을 돌린다.

`e2e/flow/probe.ts`가 구간마다 재고 `e2e/flow/scene.ts`가 합격선을 단언한다. 결과는 `test-results/flow/report.json`에, 전이 전후 화면은 `test-results/flow/<장면>/<단계>.png`에 남는다.

| 재는 것 | 합격선 |
|---|---|
| 구간 시작 때 있던 `[data-chat-item]`과 `[data-session-row]`의 컨테이너 기준 위치 변화 | 1px 이하. 한 프레임만 움직여도 실패다 |
| 끝을 따라가는 중: 타임라인 마지막 항목의 아래 가장자리와 컴포저 위 가장자리의 간격 변화 | 1px 이하 |
| 위로 올려 읽는 중: 항목의 화면 기준 위치 변화 | 1px 이하 |
| 입력 상자 아래 가장자리의 화면 위치 변화 | 0px (빈 대화의 첫 전송은 제외) |
| 화면에 보이는 `[data-presence-label]` 가운데 같은 대상(`run:<id>`, `execution:<id>`)의 수 | 하나. 사이드바의 대화 행에는 이 속성이 없다 |
| 1280×800에서 상단 줄과 쉬는 컴포저 높이의 합 | 200px 이하 |
| 본문 열 너비 | 720–760px |

| 장면 | 재는 전이 | 추가 확인 |
|---|---|---|
| ① 대기 | 빈 대화 → 요청 전송 → 실행 시작 → 완료 | 활동 바가 실행 전후 같은 높이, 밝은·어두운 테마 |
| ② 여러 역할 | 세 역할이 함께 작업 중인 상태에서 하나씩 완료 | 닫힌 활동 바가 화면에 보이는 역할을 다시 말하지 않음, 펼쳐서 합류까지 조작 두 번, reduced motion |
| ③ 합류·끼어들기 | 합류 전송 → 읽힘, 끼어들기 → 응답이 끊기고 전달됨, 읽히지 못한 합류가 새 요청으로 시작 | 키보드만으로, 끊긴 응답이 제자리에 남음. 출력과 성공이 따로 닿는 변형, 답 본문이 먼저 해제되는 변형 |
| ④ 승인·입력 대기 | 작업 중 → 응답 대기 → 답함 → 작업 중. 카드를 화면 밖으로 올린 뒤 활동 바에서 승인 | 같은 요청이 화면에 한 번, 입력해 둔 초안 보존, Enter로 승인되지 않음 |
| ⑤ 인용 | 구절 선택 → 칩 → 전송 → 보낸 칩에서 원문으로 | 키보드만으로, 칩이 늘어도 입력 아래 가장자리 고정 |
| 사이드바 | 실행 종료 → 2초 안에 다음 실행 시작 | 행이 묶음을 옮기지 않음, 응답 대기는 즉시 이동 |
| 회의 | 사람 메시지 → 자동 선택 → 답변, 수신자 없음, 연쇄 8회에서 계속 카드 | 대화와 같은 컴포저 |

합격선을 낮추거나 구간·장면을 지워서 통과시키지 않는다. 재시도로 가리지 않는다. Playwright는 시작할 때 `test-results`를 지우므로, 실패한 실행의 trace와 `report.json`은 다시 돌리기 전에 옮겨 둔다.

## 추가·수정 기준

- 데이터·권한·취소·명령·상태 전이는 단위·통합 테스트로 검증한다. DOM 순서, 장식 클래스, 고정 픽셀, 번역 문구를 이유로 E2E를 늘리지 않는다.
- 실제 브라우저가 필요한 경계만 E2E로 남긴다. 포인터 hit testing, 실제 포커스·키보드, 페이지 재로드와 서버 연결이 해당한다.
- 기본 스모크는 두 흐름으로 유지한다. 새 상세 기능은 기존 단위·통합 테스트에 추가하고, 브라우저 검증이 필요하면 해당 파일만 선택 실행한다.
- 포인터 입력은 실제 핸들로 보내고 결과를 확인한다. `force`, DOM 이벤트 직접 호출, 임의 sleep, timeout 증가로 가려진 핸들이나 잘못된 대상을 통과시키지 않는다.
- 캔버스와 무관한 서버 테스트는 그래프를 UI로 매번 재조립하지 않고 기존 fixture/API를 우선한다. 현재 확장 검사에 남은 중복 UI 준비는 해당 시나리오를 수정할 때 함께 줄인다.
- 한 테스트는 한 사용자 결과를 확인한다. 화면의 모든 중간 상태를 고정하지 않는다. 재시도는 0이며, 실패 trace에서 대상 부재·입력 가림·서버 실패를 먼저 구분한다.

기존 상세 파일은 선택 검증용으로 유지한다. 기본 게이트에서 제외됐다는 사실은 그 시나리오의 통과나 출시 준비 완료를 뜻하지 않는다.
