# 초기 개발의 테스트 운영

기본 E2E의 범위는 [데모·출시 명세](../specs/features/demo-release.md)를 따른다. 매 UI 변경마다 상세 브라우저 시나리오 전체를 통과시키는 것을 개발의 전제로 삼지 않는다.

| 명령 | 용도 |
|---|---|
| `pnpm test:e2e` | PR CI와 일반 개발의 Chromium 스모크 2개. 대화 전송·답변·재로드, 캔버스 포인터 연결 |
| `pnpm test:e2e:extended` | 변경한 영역의 상세 시나리오를 필요할 때 선택 실행 |
| `pnpm release:gate` | 전체 확장 E2E와 다중 브라우저·접근성·IME를 포함한 출시 검증 |

서버 스모크는 먼저 `pnpm --filter @corral/studio build`가 필요하다. 공급자 응답은 기존 로컬 fake를 쓰며 유료 API는 호출하지 않는다. 기본 검사는 Chromium만 설치하면 된다. 확장 검사의 Firefox 프로젝트는 `pnpm --filter @corral/studio exec playwright install firefox`로 따로 준비한다.

특정 회귀만 확인할 때는 파일과 프로젝트를 지정한다.

```sh
pnpm test:e2e:extended e2e/server/server.spec.ts --project=server --workers=1
```

세션 테스트는 현재 `Session views`의 대화·파일·변경·실행 기록을 구분한다. 파일의 도킹 메뉴는 파일 화면에서 열고, 다른 탭으로 이동한 뒤 보존된 입력을 검사할 때와 실제 입력할 때를 구분한다. 실행 완료는 개별 실행 행의 부분 일치 텍스트가 아니라 Run의 정확한 상태나 확정 결과로 기다린다. 디자인킷 전환 뒤에도 키보드 조작·전체 식별자 펼치기·초안 보존 같은 원래 검증 목적은 유지한다.

## 추가·수정 기준

- 데이터·권한·취소·명령·상태 전이는 단위·통합 테스트로 검증한다. DOM 순서, 장식 클래스, 고정 픽셀, 번역 문구를 이유로 E2E를 늘리지 않는다.
- 실제 브라우저가 필요한 경계만 E2E로 남긴다. 포인터 hit testing, 실제 포커스·키보드, 페이지 재로드와 서버 연결이 해당한다.
- 기본 스모크는 두 흐름으로 유지한다. 새 상세 기능은 기존 단위·통합 테스트에 추가하고, 브라우저 검증이 필요하면 해당 파일만 선택 실행한다.
- 포인터 입력은 실제 핸들로 보내고 결과를 확인한다. `force`, DOM 이벤트 직접 호출, 임의 sleep, timeout 증가로 가려진 핸들이나 잘못된 대상을 통과시키지 않는다.
- 캔버스와 무관한 서버 테스트는 그래프를 UI로 매번 재조립하지 않고 기존 fixture/API를 우선한다. 현재 확장 검사에 남은 중복 UI 준비는 해당 시나리오를 수정할 때 함께 줄인다.
- 한 테스트는 한 사용자 결과를 확인한다. 화면의 모든 중간 상태를 고정하지 않는다. 재시도는 0이며, 실패 trace에서 대상 부재·입력 가림·서버 실패를 먼저 구분한다.

기존 상세 파일은 선택 검증용으로 유지한다. 기본 게이트에서 제외됐다는 사실은 그 시나리오의 통과나 출시 준비 완료를 뜻하지 않는다.
