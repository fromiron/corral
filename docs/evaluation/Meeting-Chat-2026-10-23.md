## 변경과 실패 재현

- 새 회의는 연결 모델의 이름과 빈 선택 역할로 시작한다. 개발 역할은 **개발 역할 적용**을 명시적으로 선택하거나 직접 입력할 때 부여한다. 기존 저장 이름·역할·대화는 변경하지 않는다.
- 일반 질문에는 짧게 답하고, 이유·선호 변경은 앞 대화를 문맥으로 이어 받는다. 선택 역할은 현재 주제에 관련될 때 적용한다. 회의 실행 표식을 Coordinator에서 worker로 전달해 일반 작업의 계획·보고·산출물 제출 지시가 채팅에 섞이지 않게 했다. 정상 최종 응답은 기존 Coordinator 출처·권한·취소 검사를 거쳐 기록한다.
- 사용자·모델 발언을 개별 메시지로 표시하고 응답을 스트리밍한다. 라운드·반론 버튼·2회 상한을 제거했다. 기존 저장 `rounds`·참조 ID와 legacy 명령 재전송은 호환성을 위해 유지한다. `/반론` 입력은 일반 메시지다.
- 비서는 요청받았을 때만 회의록·플랜을 작성한다. 사람의 검토·채택 전에는 작업 인계를 시작하지 않는다. 기록이 생기기 전에는 회의록·인계 패널을 표시하지 않고, 실행·사용량 상세는 상세 활동에서 확인한다.
- 기본 역할 강제, 모델 변경 후 이름 잔존, 빈 역할 거절, `/반론` 강제 변환, 업무 프롬프트 혼입, 라운드 묶음·기본 사용량 노출·스트림 미표시에 대한 실패를 먼저 재현했다. 뒤이은 화면 점검에서는 낮은 창에서 컴포저가 대화 공간을 차지해 자료 첨부를 접고 기본 입력창 높이를 줄였다. 선택 자료·오류·재시도·IME 동작은 보존한다.

## 경계

- 이번 실제 모델 시험은 대화·역할 전환·비서 플랜까지다. 변경 후 인계·실행 연결은 위 결정적 실제 서버 E2E로 확인했으며 이전 실모델 파일 수정 결과를 이번 후보의 새 실모델 실행으로 표시하지 않는다.
