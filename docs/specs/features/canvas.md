# 기능 명세: 팀 편집기 — 정의를 만드는 경험

- 상태: accepted (2026-11-08)
- 기준: [스펙](../product-contract.md) §4.1–4.2, §5, [팀 그래프 모델](team-graph.md), [기술 설계](../technical-design.md) §4, §13
- 비목표: Loop·Decision의 **실행**(GraphRunner·검토 루프는 [기술 설계](../technical-design.md)), 실행 중 구조 변경, 사람이 정하는 노드 위치, 실행 기록을 편집기 캔버스에 겹쳐 보이기(실행은 [실행 기록 관찰](execution-monitor.md)에서 본다), 승인 단계를 넣는 패턴

## 사용자 관측 동작

1. **한 화면.** `/corrals/:id/edit`는 경로 막대, 왼쪽 구조 목록, 가운데 캔버스, 선택할 때만 떠오르는 설정 시트로 이뤄진다. 시험 실행을 열면 오른쪽에 실행 패널이 붙는다. 세션의 "팀 설계 열기" 도킹 탭도 같은 편집기이며 시험 실행 패널만 없다.
2. **자동 배치.** 사람은 노드 위치를 정하지 않는다. 상자(Loop·팀)마다 안의 단계를 왼쪽에서 오른쪽 층으로 놓고 내용에 맞게 크기를 정하며, 부모 안에서는 한 덩어리로 놓인다. 이어진 단계는 한 줄에 놓이고, 한 포트에서 갈라진 단계와 판정의 갈래는 포트 순서대로 아래에 쌓인다. 호출 전용 에이전트는 흐름 아래 한 줄에 놓인다. 편집 후 노드는 새 자리로 옮겨 가고 연결선이 따라간다. 동작 줄이기를 켠 사람에게는 바로 새 자리에 놓인다.
3. **단계 추가.** 팔레트(에이전트·검토·승인·검사·라우터·규칙·Loop·팀·합류·출력), ⌘K 명령, 끌어 놓기로 추가한다. 놓는 자리가 구조를 정한다.
   - 연결 위에 놓으면 그 사이에 끼운다.
   - 단계 위에 놓으면 그 뒤에 붙이고, 그 단계가 이어 가던 곳은 새 단계가 이어 간다. 새 단계에 나갈 포트가 없으면(출력) 갈래로 붙는다.
   - 상자 위에 놓으면 상자 안 흐름의 끝에 넣는다. 빈 상자면 본문 시작과 출구 사이에 넣는다.
   - 빈 곳에 놓으면 연결 없이 맨 위에 둔다.
   - 팔레트를 누르거나 ⌘K로 추가하면 선택이 자리를 정한다: 연결이면 끼우고, 상자면 안에, 단계면 뒤에, 없으면 빈 곳.
   - 둘 수 없는 자리(출력 뒤, 판정이 아닌 단계를 반복 연결 위에)는 끄는 동안 이유와 함께 거절한다.
4. **연결.** 출력 포트를 끌어 입력 포트·단계·상자에 놓는다. 끄는 동안 이을 수 있는 입력 포트가 표시되고, 거절되면 이유가 포인터 옆에 나온다. 상자에 놓으면 상자 밖에서는 `enter`, 안에서는 `exit`로 잇는다. 한 출력 포트는 여러 단계로 갈 수 있다(병렬, [팀 그래프](team-graph.md)). 포인터 없이도 설정 시트의 포트별 "연결할 곳" 목록으로 같은 연결을 만든다. 연결을 누르면 선택되고 시트나 Delete로 지운다. 제어 연결은 실선과 화살표, 호출 링크는 점선과 이름표로 구별한다.
5. **상자.** 선택한 형제 단계를 Loop나 팀으로 감싼다. 들어오던 연결은 상자의 `enter`로, 본문은 같은 단계로, 나가던 연결은 `exit`과 `next`로 바뀐다. 바깥 상자의 `exit`·`repeat`으로 가던 연결은 그대로 둔다. 상자를 지우면 안의 단계는 남아 부모로 옮겨 가고, `enter`로 들어오던 곳은 본문의 첫 단계로, 출구로 가던 단계는 상자의 다음 단계로 이어진다. 구조 목록에서 단계를 상자 위로 끌면 그 안으로, 팀 줄 위로 끌면 맨 위로 옮긴다. 상자는 자기 자신이나 자기 안의 상자로 들어가지 않는다.
6. **패턴.** ⌘K와 설정 시트에서 선택에 패턴을 적용한다. 선택이 없으면 새 에이전트를 놓을 자리에 만들고 그 에이전트에 적용한다.
   - **검토 루프로 감싸기:** 선택을 Loop(3회)로 감싸고, 출구로 가던 마지막 단계 뒤에 검토 에이전트와 검토 판정을 둔다. `pass`는 Loop의 `exit`, `revise`는 `repeat`으로 간다.
   - **검사 루프로 감싸기:** 같은 방식으로 검사 판정을 둔다. `pass`는 `exit`, `fail`은 `repeat`으로 간다. 검사는 모델을 부르지 않는다.
   - **병렬로 나누기:** 선택한 에이전트 하나를 복제해 같은 앞 단계에서 함께 시작하게 하고, 둘의 출력을 합류(모두 기다림)로 모아 원래의 다음 단계로 잇는다. 앞 단계가 없는 단계는 나눌 수 없다.
7. **참조 팀.** ⌘K는 같은 프로젝트의 다른 저장된 팀을 그 팀의 현재 저장 revision을 가리키는 팀 상자로 넣는다. 참조 팀은 접힌 타일로만 보이고 안을 이 편집기에서 고치지 않는다. 설정 시트에서 그 팀의 편집기를 열고, 더 새 revision이 있으면 그 revision으로 바꾼다.
8. **선택과 키보드.** 누르면 선택하고, Shift·⌘·Ctrl로 더하거나 빼며, 빈 곳에서 Shift를 누른 채 끌면 틀 안의 단계를 더한다. 빈 곳을 누르거나 Escape를 누르면 선택을 지운다. 화살표는 그 방향의 가장 가까운 이웃으로 선택과 포커스를 옮긴다. Delete·Backspace는 선택을 지운다. ⌘K·Ctrl+K는 편집기 안에 포커스가 있을 때 편집기 명령을, 밖에서는 앱 명령을 연다. Ctrl/⌘+Z는 되돌리기, Shift를 더하거나 Ctrl+Y는 다시 하기다. 텍스트 입력 중에는 브라우저 기본 되돌리기를 쓴다. IME 조합 중 Enter는 아무 동작도 하지 않는다. 포인터 없이 추가·선택·연결·감싸기·옮기기·삭제를 모두 할 수 있다.
9. **문제 표시.** 컴파일 진단을 해당 노드·연결 위에 기호와 문구로, 구조 목록의 줄에도 표시한다. 오류와 경고는 다른 기호다. 구조 목록의 문제 수를 누르면 문제 목록이 열리고, 항목을 누르면 그 노드·연결을 선택해 화면 안으로 가져온다. 현재 런타임이 아직 실행하지 않는 구조는 `RUNTIME_UNSUPPORTED` 경고로 보이며 시험 실행은 거절된다. 오류가 있으면 시험 실행을 시작할 수 없다.
10. **접기.** Loop·팀 상자를 캔버스나 구조 목록에서 접으면 한 장의 타일이 되어 요약(최대 회차, 정의 위치)과 안의 단계 이름, 안쪽의 가장 심한 문제를 보인다. 안을 드나들던 연결은 타일에 그린다. 접기는 화면 상태이며 정의를 바꾸지 않는다.
11. **설정 시트.** 무엇을 선택했는지에 따라 내용이 바뀐다.
    - 에이전트: 이름, 실행 방식(흐름 안·호출될 때), 지시, 모델, 추론, 도구와 권한, 출력 형식, 입력, 호출 링크(위임의 부모 질문 허용 포함), 실패 후 재시도, 메모, 하네스 설정.
    - 판정: 이름, 종류(검토·승인·규칙), 검사 ID 목록, 라우터 경로, 입력, 메모.
    - Loop: 이름, 최대 회차, 예산(모델 호출·출력 토큰·시간), 정체 감지, 검토 레시피, 메모.
    - 팀: 이름, 정의 위치(이 팀 안·참조 revision), 메모. 합류: 기다리는 방식. 출력: 최종 확정 전 승인, 입력, 메모.
    - 단계마다 출력 포트별 연결 목록과 "연결할 곳" 선택, 감싸기·패턴·삭제, 그 단계의 문제.
    - 여럿을 고르면 개수와 감싸기·패턴·삭제, 연결을 고르면 양 끝과 삭제.
    - 팀 설정(구조 목록 아래): 이름, 요청, 기준, 실행 한도(모델 호출·출력 토큰·위임 깊이·시작하는 에이전트 수·실행 마감).
12. **입력.** 입력의 출처를 run 입력, 앞 작업 출력, 이전 회차 출력, 고정 버전, 질문 답변 중에서 고른다. 출처 목록에는 흐름 안의 에이전트만 나온다. 고정 버전은 산출물 버전 ID를 받아야 추가된다. 연결할 때 기본 입력을 제안하지만 사람이 바꿀 수 있다.
13. **저장과 이동.** 작업 공간에서 팀을 만들고, 열고, 복제한다. Save는 정의를 저장하며 정의가 바뀌었을 때만 새 revision이 된다. 정의를 JSON 파일로 내보내고 가져온다. 이해하지 못하는 버전·필드는 오류로 거절한다. 같은 팀의 라우트 편집기와 도킹 탭은 하나의 작업 사본을 써서 초안과 되돌리기를 공유한다. 저장하지 않은 채 떠나면 묻는다(도킹 탭은 세션이 사본을 지키므로 묻지 않는다).
14. **시험 실행.** 경로 막대의 시험 실행이 실행 패널을 연다. 패널에는 실행 준비(역할별 모델·하네스 덮어쓰기), 실행 제어, 실행 보기, 승인, 산출물, Reins와 실행 화면 링크가 있다. 서버 모드에서는 실행 전에 저장한다.
15. **되돌리기.** Undo/Redo는 편집기의 아직 실행되지 않은 정의 변경만 되돌린다. 끌어 놓기·감싸기·패턴 하나는 되돌리기 한 번이다. 선택이 가리키던 단계가 되돌리기로 사라지면 선택에서 빠진다.
16. **실행 통계.** 경로 막대의 토글로 저장된 revision의 최근 실제 실행을 모은 수치를 단계 위에 겹친다([실행 통계](run-stats.md)).

## 계약

- **정의 원본:** `packages/contracts`의 Zod. 현재 JSON Schema는 생성물(`packages/contracts/generated/`)이며 `pnpm contracts:check`가 최신인지 검사한다. 현재 생성물과 Zod는 같은 fixture에 같은 판정을 내야 한다. `contracts/*.schema.json`은 [초기 seed](../../../contracts/README.md)이며, 현재 규격과 공유하는 초기 fixture만 호환성을 검사한다. 노드 수 정책은 [사용량 예산과 자원 정책](../product-contract.md#9-사용량-예산과-자원-정책)을 따른다.
- **포트 표와 구조 규칙:** [팀 그래프 모델](team-graph.md)이 정한다. 편집기의 연결·배치·감싸기 규칙과 compiler가 같은 포트 표와 상자 경계 규칙을 쓴다. 편집기 검사는 신뢰 경계가 아니며 runtime이 같은 compiler를 다시 쓴다.
- **편집 명령:** 모든 조작은 초안을 받아 새 초안이나 거절 이유(`EditRejection`)를 돌려주는 순수 함수다(`packages/react/src/team-editor/commands.ts`). 캔버스·구조 목록·명령 메뉴·설정 시트는 어떤 명령을 부를지만 고른다. 한 명령은 되돌리기 한 단계다.
- **배치:** 위치는 정의와 접힘 상태만으로 정해지는 함수다(`packages/react/src/team-editor/layout.ts`). 위치·크기·뷰포트를 저장하지 않으며 definitionHash에 영향이 없다.
- **진단:** `{ code, severity, message, nodeId?, edgeId?, linkId? }`. `code`는 고정 enum이며 UI 문구는 메시지 카탈로그에서 code로 찾는다.
- **참조 팀 확인:** 편집기는 참조한 팀의 해당 revision 정의를 저장소에서 읽어 compiler에 넘긴다. 읽지 못한 참조는 `TEAM_REF_NOT_FOUND`다.
- **IR:** 유효한 정의만 `CompiledPlan`으로 바뀐다([팀 그래프](team-graph.md)).
- **저장 revision:** 저장 시 definitionHash가 바뀌면 `definitionRevision`이 1 오른다. 같은 정의를 다시 저장하면 revision은 그대로다.
- **저장 표시:** 성공한 저장은 경로·팀 목록·세션의 팀 요약과 역할 안내에 즉시 반영한다. 미저장 초안과 이미 시작한 실행의 정의는 바꾸지 않는다. 저장할 변경이 없거나 저장 중이면 Save는 비활성이다.
- **템플릿 사본:** 템플릿 편집 진입만으로 저장하지 않는다. 이름과 사본 저장을 확인한 뒤 편집기를 열며, 같은 프로젝트의 동명 사본은 번호로 구별한다. 사본 이름에 번호가 붙으면 저장 대화상자가 같은 이름 계산으로 저장될 이름을 미리 알려 준다.
- **목표에서 팀 초안:** 로컬 제안은 모델을 호출하지 않는다. 보안 PR 검토처럼 알려진 작업의 목표는 해당 검토·작성·검증 역할과 근거 기준을 제안하고, 일반 목표도 첫 문장의 짧은 이름을 쓰되 전체 목표는 brief에 보존한다. 템플릿이 정한 도구 권한과 최종 승인 경계는 바꾸지 않는다.

## 보안·성능·접근성

- 가져오기 파일은 신뢰하지 않는다. strict schema로 거절하고 크기를 제한한다(1 MiB).
- 노드 상태와 문제는 색만이 아니라 기호·문구로 표시한다. 캔버스는 키보드를 받는 하나의 영역이며 노드·상자·접기·삽입 지점은 이름 있는 버튼이다. 포트 끌기는 포인터 지름길이고 같은 연결을 설정 시트에서 만들 수 있다.
- 배치 이동은 동작 줄이기 설정을 따른다.
- 배치는 편집마다 다시 계산한다. 노드 수 상한 안에서 한 번의 편집이 화면을 멈추지 않아야 한다.
