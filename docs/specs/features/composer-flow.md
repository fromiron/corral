# 기능 명세: 대화 입력 흐름

- 상태: accepted
- 비목표: 접수된 지시의 철회, 실행 중인 도구의 중단, 대기 요청의 끌어서 순서 바꾸기, 브라우저 창 전체에 고정한 overlay, 모델이 정하는 화면 구성

입력, 실행 감독, 중간 개입, 응답을 한 화면의 한 줄기로 정한다. 지시의 접수·전달·종료의 뜻과 전달 상태는 [Reins](reins.md)가, 상태 이름은 [표시 상태](presence.md)가, 답변 인용은 [답변 인용](reply-citation.md)이, 위젯의 데이터와 상세는 [채팅 위젯 계약](../chat-widgets-contract.md)이 정한다.

## 사용자 관측 동작

### 화면 틀

대화 창은 위에서부터 상단 줄, 타임라인, 컴포저다.

- 상단 줄은 경로, 창 전환, 도구만 갖는다. 실행 상태와 실행 조작은 여기에 없다.
- 컴포저는 대화 창 안에서 타임라인의 아래 가장자리에 놓인 한 면이다. 타임라인은 컴포저 높이만큼 아래 여백을 가져 마지막 항목이 가려지지 않는다. 브라우저 창 전체에 고정한 overlay는 아니다.
- 컴포저는 위에서부터 활동 바, 대기 요청, 칩 줄, 입력, 도구 줄이다. 활동 바와 도구 줄은 내용과 무관하게 한 줄 높이를 늘 차지한다. 대기 요청과 칩 줄은 있을 때만 보이고 위쪽으로 자란다. 입력의 아래 가장자리는 움직이지 않는다.
- 회의도 같은 틀과 같은 컴포저를 쓴다.

### 전송

입력창은 하나이고 전송 방식은 셋이다.

| 전송 | 뜻 |
|---|---|
| 새 요청 | 실행이 없을 때 보낸다. 새 실행을 바로 시작한다 |
| 합류 | 진행 중인 실행 단위의 다음 모델 요청에 실린다(지시, 전달 방식 `next_request`) |
| 끼어들기 | 진행 중인 모델 응답을 끊고 다음 요청에 바로 실린다(지시, 전달 방식 `interrupt`) |
| 다음 요청 | 진행 중인 실행이 끝난 뒤 시작할 대기 요청으로 쌓인다 |

보내기 키가 무엇을 하는지는 상황이 정한다.

| 상황 | 보내기 키 | 끼어들기 키 | Alt+Enter | 도구 줄의 대상 |
|---|---|---|---|---|
| 실행 없음 | 새 요청 | 새 요청 | 새 요청 | 없음 |
| 실행 중, 합류할 대상 있음 | 합류 | 끼어들기 | 다음 요청 | 대상 역할 |
| 실행 중, 대상이 끼어들기를 받지 못함 | 합류 | 합류 | 다음 요청 | 대상 역할 |
| 실행 중, 합류할 대상 없음 | 다음 요청 | 다음 요청 | 다음 요청 | 이유 한 줄 |
| 응답 대기 | 합류 | 합류 | 다음 요청 | 대상 역할 · 결정 뒤에 읽힘 |
| 회의 | 회의에 보내기 | 회의에 보내기 | 회의에 보내기 | 수신자: 자동 · 지정 · 없음 |

- 보내기 키는 환경설정의 값이다. 보내기 키가 Enter이면 끼어들기 키는 Mod+Enter, 보내기 키가 Mod+Enter이면 끼어들기 키는 Mod+Shift+Enter다.
- 도구 줄 오른쪽은 지금 쓸 수 있는 키와 그 뜻을 한 줄로 보인다. 보내기 버튼 옆 메뉴는 같은 선택을 포인터로 고르게 한다. 보내기 버튼의 접근성 이름은 "보내기"로 고정하고 설명에 지금의 전송을 붙인다.
- `/next`, `/steer`, `/interrupt`는 그 전송을 한 번 고른다.
- IME 조합 중의 Enter는 보내지 않는다.

### 합류 대상

- 한 역할이 답하는 실행에서 대상은 그 실행 단위다.
- 여러 역할이 일하는 실행에서 대상은 활동 바에서 고른 실행 단위다. 고르지 않았으면 대화에 답을 쓰는 실행 단위다.
- 대상은 도구 줄 왼쪽에 역할 이름으로 보이고, 누르면 지금 지시를 받을 수 있는 실행 단위에서 고른다.
- 첫 글자를 칠 때 대상이 고정된다. 고정된 대상이 지시를 받을 수 없게 되면 다른 대상이나 다음 요청으로 조용히 바꾸지 않고 막으며 이유를 적는다. 대상을 고르지 않고 쓰기 시작한 초안은 고정되지 않아, 쓰는 동안 실행이 끝나면 새 요청으로, 실행이 시작되면 합류로 보낸다.
- 과거 실행을 보는 것만으로 대상이나 초안이 바뀌지 않는다.
- 텍스트 첨부와 답변 인용은 어느 전송에도 실린다. 이미지와 참조·검증 범위처럼 새 실행에만 쓰이는 것은 새 요청과 다음 요청에만 실리고, 합류·끼어들기일 때는 "새 요청에만 적용" 한 줄로 알린다. 실행 중에도 이미지와 참조를 붙일 수 있다: 다음 요청으로 보내면 함께 가고, 합류·끼어들기로 보내면 초안에 남는다. 한 요청의 참조·텍스트 첨부·이미지는 합쳐 20개까지이고, 넘으면 보내기 전에 그 이유를 알린다.

### 보낸 메시지의 메타 줄

사용자 메시지 아래에는 한 줄이 늘 있다. 그 메시지가 어떻게 됐는지를 이 줄이 끝까지 말한다. 줄의 높이는 내용과 무관하다. 보낸 시각과 메시지 동작(복사·편집·갈래)도 이 줄에 있고, 가리키거나 포커스가 들 때 보인다. 그 메시지가 어떻게 됐는지는 늘 보인다.

| 전달 상태와 조건 | 메타 줄 |
|---|---|
| `accepted`·`queued` | 합류 대기 · 다음 단계에 읽힘 |
| `queued`이고 대상이 승인·질문을 기다림 | 결정 뒤에 읽힘 |
| `attached_to_request` | 전달하는 중 |
| `delivered`, 합류 | 읽힘 · 역할 |
| `delivered`, 끼어들기 | 끼어듦 · 응답을 끊고 전달됨 · 역할 |
| `expired`, 넘겨받아 대기 중 | 먼저 끝나 다음 요청으로 대기 |
| `expired`, 넘겨받아 시작됨 | 먼저 끝나 새 요청으로 시작 |
| `not_delivered`, 또는 `expired`인데 넘겨받지 않음 | 전달되지 않음 · 다시 보내기 |
| `delivery_unknown` | 전달 여부를 확인하지 못함 |

합류·끼어들기의 메타 줄은 역할 이름을 보내기의 대상 이름과 같은 규칙으로 쓴다. 이름을 누르면 그 실행 단위의 실행 기록이 열린다. "읽힘"은 그 메시지를 실은 요청이 시작됐다는 뜻이고 모델이 따랐다는 뜻이 아니다. 끼어들기는 그 메시지를 실은 요청 바로 앞의 응답이 실제로 끊겼을 때만 "끼어듦"이고, 끊을 응답이 없어 그냥 실렸으면 "읽힘"이다. 합류·끼어들기에 실은 텍스트 첨부는 보낸 메시지 아래에 이름으로 보인다.

새 요청과 다음 요청은 시작하면 바로 아래의 실행 행이 실행 번호와 상태를 말한다. 메타 줄은 그것을 되풀이하지 않는다. 시작하지 못한 요청의 메타 줄은 이유를 한 줄로 말하고(누르면 런타임이 말한 원문이 열린다) 그때 도움이 되는 동작만 같은 줄에 둔다. 예약 요청처럼 메시지의 종류가 따로 있으면 줄의 첫머리에 쓴다.

넘겨받은 메시지는 대화에 한 번만 그린다. 보낸 자리의 메시지가 남아 메타 줄로 넘겨받았음을 말하고, 시작된 요청은 그 바로 아래에 실행 행으로만 이어진다(요청의 동작은 보낸 자리의 메시지가 갖는다). 보낸 자리의 메시지가 대화에 없거나(실행 기록 창에서 보낸 지시) 그 사이에 다른 항목이 있으면(한 Run에서 여럿이 넘겨받힌 경우) 시작된 요청이 자기 메시지를 그린다. 자기 메시지를 그린 요청은 보낸 자리의 메시지가 대화에 있으면 여느 시작된 요청처럼 줄을 쓴다(넘겨받았음은 보낸 자리의 줄이 한 번 말한다). 보낸 자리의 메시지가 대화에 없을 때만 자기 줄이 넘겨받았음을 말한다. 넘겨받은 요청을 사람이 대기 줄에서 빼거나 편집하려고 가져가면 보낸 메시지의 줄은 "전달되지 않음 · 다시 보내기"다.

넘겨받았는지는 세션의 기록이 말한다. 화면은 넘겨받기 규칙을 스스로 판정하지 않는다. 보고 있는 동안 지시가 읽히지 못하고 끝나면 줄은 세션을 한 번 다시 읽을 때까지 그대로 있다가, 넘겨받은 요청이 있으면 그것을, 없으면 "전달되지 않음 · 다시 보내기"를 말한다. "다시 보내기"는 그 메시지의 글과 텍스트 첨부를 새 요청으로 보낸다.

### 대기 요청과 넘겨받기

- 대기 요청은 서버가 시작한다. 세션의 Run이 끝나면 맨 앞의 대기 요청을 한 번 시작한다. 화면이 열려 있지 않아도 시작한다. Run이 막 끝난 뒤에 도착한 대기 요청이 남지 않게, 대기 요청이 더해질 때 그 세션에 끝나지 않은 Run이 없으면 같은 규칙으로 바로 시작한다.
- 자동 시작은 세션 설정이고 기본은 켬이다. 끄면 대기 요청은 사람이 "지금 시작"을 누를 때까지 남는다. 서버 대기열이 없는 브라우저 데모에는 이 설정이 보이지 않는다.
- 합류로 보낸 메시지가 읽히기 전에 대상이 성공으로 끝나면, 서버가 그 메시지를 대기열 맨 앞의 요청으로 넘겨받아 Run이 끝나는 대로 시작한다. 자동 시작이 꺼져 있어도 시작한다. 대상이 실패했거나 사람이 취소해서 읽히지 못한 메시지는 넘겨받지 않는다. 넘겨받은 뒤에 사람이 그 Run을 취소하면 넘겨받은 요청은 보통 대기 요청처럼 자동 시작 설정을 따른다(꺼져 있으면 사람이 시작할 때까지 남는다).
- 서버를 다시 시작한 뒤에는 이미 끝나 있던 Run 뒤의 대기 요청을 스스로 시작하지 않는다.
- 대기 요청의 지금 시작·편집·제거는 유지한다. 편집하려고 입력창으로 가져온 대기 요청은 다시 보낼 때도 다음 요청이다(실행 중이어도 합류로 바뀌지 않는다. 권한 방식과 첨부가 그대로 따라간다).
- 요청을 편집하려고 입력창으로 가져오면(대기 요청, 보낸 요청의 편집, 거절된 요청의 편집, 이전 요청 되살리기) 글·권한 방식·텍스트 첨부·이미지·참조가 함께 돌아온다. 참조는 글 안의 자기 자리에 칩으로 돌아오고, 손대지 않고 다시 보내면 처음과 같은 내용이 실린다.
- 대기 줄의 요청은 텍스트 첨부와 이미지를 파일 타일로 보인다(이미지는 이름과 파일 표시).

### 활동 바

활동 바는 실행 상태를 말하는 하나뿐인 줄이다. 실행이 없어도 같은 높이로 있다. 닫힌 한 줄은 아래에서 먼저 맞는 것을 보인다.

1. 화면에 보이지 않는 응답 대기. 하나면 무엇을 기다리는지와 "보기"를, 여럿이면 건수와 "보기"를 보인다. 승인·거절은 그 줄이 허용하는 것을 남김없이 말할 때만 함께 낸다: 도구 호출의 승인이고 그 호출의 인자가 모두 한 줄에 있으며 잘리지 않고 다 보일 때, 그리고 중단점(멈춘 단계의 이름)일 때. 줄에 없는 인자가 있는 호출(다른 작업 폴더나 실행 방식이 붙은 명령, 쓰거나 고칠 내용이 있는 파일 쓰기·편집), 여러 줄이거나 잘리는 대상(줄을 가르는 문자는 종류와 무관하게 여러 줄이다. 명령 끝에 붙은 줄바꿈(LF)과 그 사이의 공백·탭만 세지 않는다), 보이지 않는 글자, 보통 공백이 아닌 공백류, 오른쪽에서 왼쪽으로 쓰는 글자가 든 대상과 앞뒤에 공백이 붙은 경로(줄이 그 글을 순서대로 다 보이지 못한다), 최종 출력·검사·사람의 결정·경로·한도의 승인은 "보기"만 낸다. 파일 이동은 어디서 어디로인지를 함께 쓴다. 글이 잘리게 되면(폭, 옆에 들어온 낱말, 글꼴) 승인·거절은 바로 빠지고, 다시 다 보이면 돌아온다. 경계에서 들어왔다 나가기를 되풀이하지 않는다(돌아올 때는 여유가 있어야 한다). 움직임 줄이기를 켠 사람에게도 같다.
2. 화면에 보이지 않는 작업 중 역할의 활동.
3. 합류 대상 실행 단위의 지금 활동(도구 이름은 작업 기록이 쓰는 이름).
4. 쉬는 상태의 요약: 끝난 실행의 상태 · 계획 n/m · 변경 n.

화면에 이미 보이는 실행 행이나 응답 카드가 말하는 것은 활동 바가 다시 말하지 않는다. 펼친 곳의 역할 행이 말하는 것도 닫힌 줄이 다시 말하지 않는다. 오른쪽에는 컨텍스트 점유(측정이 있을 때)가 있다. 서버 연결이 끊겼거나 실행 기록을 잃었을 때도 이 줄이 말한다.

활동 바를 펼치면:

- 살아 있는 실행 단위마다 한 행: 상태, 지금 활동, 경과, "보기"(그 역할의 실행 행으로 이동. 행이 대화의 창 밖에 있으면 불러와 그 자리로 간다. 대화에 행이 없는 실행 단위만 실행 기록에서 연다), "여기에 합류"(합류 대상을 바꿈). 같은 역할의 실행 단위가 여럿이면 보내기 메뉴와 같은 이름으로 가른다. [감독](advisor.md)의 행은 지켜보는 중 또는 검토 중, 그리고 전달된 조언 수를 보인다. 감독은 합류 대상이 아니라 "여기에 합류"가 없고 "보기"는 실행 기록의 그 실행 단위를 연다. 작업 중인 역할의 수와 중지 확인이 세는 수에 감독은 들지 않는다. 다른 실행 단위가 모두 끝나고 감독의 마지막 검토만 남았으면 닫힌 줄이 그것을 말한다.
- 작업 계획(Todo). 계획을 읽는 곳은 여기 하나다.
- 일시정지·재개·중지. 중지는 활성 실행 단위가 둘 이상이거나 그 수를 아직 모를 때 확인을 묻는다. 일시정지하는 중에도 중지할 수 있다. 실행 조작은 실행 기록의 조작과 같은 명령 경로를 쓴다(보내는 동안 다시 눌리지 않고, 확인되지 않은 명령을 새 명령으로 다시 보내지 않는다).
- 입력이 비어 있고 실행 중이면 보내기 자리에 중지가 온다. 방금 보낸 뒤와 활동 바의 승인이 다른 것으로 바뀐 뒤에는 잠깐(0.6초) 그 자리의 버튼이 눌리지 않는다: 같은 자리를 이어 누른 것이 중지나 다음 승인이 되지 않는다. 바의 0.6초는 그 승인의 버튼이 화면에 그려진 때부터 세고(빠졌다 돌아오면 다시 센다), 그 자리에 먼저 온 "보기"에도 같다. 처음 뜬 승인이라도 "보기"가 있던 자리에 버튼이 뒤늦게 오면 같다(여러 건을 말하던 줄의 "보기"도 그 자리다). 움직임 줄이기를 켜도 같다. 키를 누르고 있어 되풀이되는 입력은 바의 버튼과 여닫이를 다시 누르지 않는다.
- 활동 바에서 보낸 결정이 거절되면 그 줄이 거절됐음을 말하고 "보기"로 카드를 연다. 실행 조작이 거절되거나 응답을 잃었을 때도 그 줄이 말한다. 응답을 잃은 알림은 그 Run의 상태가 바뀌거나 Run이 끝나면 사라진다(다시 누를 것이 없다). 끝난 Run의 거절은 입력란 아래에 한 번 말한다.
- 컨텍스트 상세와 압축.

입력이 비어 있고 실행이 진행 중이면 보내기 버튼 자리는 중지다.

### 튐 없는 본문

상태가 바뀔 때 이미 화면에 있는 항목은 자리를 옮기지 않는다.

1. 컴포저 높이가 변해도 타임라인 항목의 위치는 변하지 않는다. 끝을 따라가는 중이면 끝을 유지한다.
2. 사람의 응답이 필요한 카드는 타임라인의 맨 끝 한 자리(지금 필요한 것)에만 그린다. 실행 행 중간에 끼워 넣지 않는다.
3. 실행 행은 머리 줄(역할 · 상태 · 경과), 본문, 꼬리 줄(변경 · 결과 · 검사)이다. 상태 옆에는 [표시 상태](presence.md)의 세부가 올 수 있다. 머리 줄과 꼬리 줄은 실행이 시작될 때부터 자리를 차지하고, 상태가 바뀌면 같은 줄 안에서 글자만 바뀐다. 본문은 아래로만 자란다.
4. 사용자 메시지의 메타 줄은 늘 한 줄이다.
5. 타임라인 위쪽이나 중간에 새 블록을 끼워 넣지 않는다.
6. 항목 수에 따라 배치 방식을 바꾸지 않는다.
7. 사이드바의 세션 행은 상태와 무관하게 같은 높이다.

### 지금 필요한 것

진행 중인 실행이 기다리는 승인, 질문, 확장 요청, 계속 여부는 타임라인 맨 끝의 한 자리에 모인다. [확인 필요](inbox.md)와 실행 기록이 쓰는 것과 같은 응답 영역이고, 대화를 떠나지 않고 답한다. 답하면 그 카드는 제자리에서 한 줄 결과로 접힌다. 같은 요청의 응답 조작은 한 화면에 한 곳에만 있다. 승인과 거절은 명시적인 버튼으로만 보내며 Enter나 Escape로 결정하지 않는다.

## 계약

- 지시 명령은 전달 방식 `next_request` 또는 `interrupt`와 선택적 텍스트 첨부를 갖는다([API 계약](../api-contract.md)). 끼어들기를 받지 못하는 어댑터에서 Coordinator는 `next_request`로 낮추고 receipt에 그 사실을 남긴다. 화면은 대상 실행 단위가 끼어들기를 받을 수 있을 때만 끼어들기를 제시한다.
- 합류 대상 목록은 Run 투영에서 읽는다.
- 메타 줄의 전달 상태는 Run 투영의 지시 기록에서 읽는다. 따로 주기 조회하지 않는다. 끝난 Run의 기록은 그 메시지가 화면에 그려질 때 한 번 읽고, 세션을 다시 열어도 다시 읽지 않는다. 끝났는지 아직 모르는 Run(앱이 막 떠서 Run 목록을 읽기 전)의 기록은 그 한 번으로 치지 않는다: 살아 있는 Run의 줄은 그 Run의 살아 있는 기록을 따르고, 끝난 뒤의 줄은 끝난 기록을 말한다. 읽지 못한 기록은 그 메시지가 화면에 있는 동안 다시 묻는다.
- 세션은 `autoStart`(기본 true)를 저장한다. 대기 요청의 시작은 그 항목의 명령 ID로 멱등이고, 서버와 화면이 같은 항목을 함께 시작해도 실행은 하나다.
- 넘겨받은 항목은 원래 지시의 ID를 `carriedFrom`으로 갖는다. 한 지시는 한 번만 넘겨받는다. [감독](advisor.md)의 조언은 넘겨받지 않는다.
- 타임라인 항목은 `data-chat-item`, 지금 필요한 것은 `data-pending-tray`, 사이드바의 세션 행은 `data-session-row`를 갖는다.
- 초안, 첨부, 고정된 대상은 창 전환, 과거 실행 보기, 확인 필요를 다녀오는 동안 보존한다.

## 수용 시나리오

```gherkin
Given 한 역할이 답하는 실행이 진행 중이다
When 입력하고 보내기 키를 누른다
Then 메시지는 그 실행 단위의 지시로 접수되고 메타 줄은 "합류 대기 · 다음 단계에 읽힘"이다
When 그 메시지를 실은 요청이 시작된다
Then 메타 줄은 "읽힘"으로 바뀌고 줄 수는 그대로다

Given 모델 응답이 흐르는 중이다
When 끼어들기 키로 보낸다
Then 그 응답은 중단된 출력으로 제자리에 남고 실행은 이어지며 메타 줄은 "끼어듦"이다

Given 도구가 실행 중이다
When 끼어들기 키로 보낸다
Then 도구는 끊기지 않고, 그 도구가 끝난 직후의 요청에 메시지가 실린다

Given 대상 역할에 쓰기 시작한 초안이 있다
When 그 역할이 끝나 지시를 받을 수 없게 된다
Then 전송은 막히고 이유가 보이며 다른 대상이나 다음 요청으로 바뀌지 않는다

Given 합류로 보낸 메시지가 읽히기 전에 대상이 성공으로 끝났다
Then 그 메시지는 대기열 맨 앞의 요청이 되고 Run이 끝나면 시작되며 메타 줄은 "먼저 끝나 새 요청으로 시작"이다

Given 합류로 보낸 메시지가 읽히기 전에 사람이 실행을 취소했다
Then 메타 줄은 "전달되지 않음 · 다시 보내기"이고 새 실행은 시작되지 않는다

Given 넘겨받은 요청이 Run의 종료를 기다리고 자동 시작이 꺼져 있다
When 사람이 그 Run을 취소한다
Then 넘겨받은 요청은 대기열에 남고 새 실행은 시작되지 않는다

Given 대기 요청이 있고 대화 화면을 닫았다
When 실행이 끝난다
Then 서버가 맨 앞의 대기 요청을 한 번 시작한다

Given 실행이 승인을 기다린다
Then 승인 카드는 타임라인 맨 끝에 한 번 보이고 대화에서 답할 수 있다
When 카드를 화면 밖으로 올린다
Then 활동 바가 무엇을 기다리는지와 승인·거절을 보인다

Given 실행이 질문을 기다린다
Then 질문은 같은 자리에 보이고 대화를 떠나지 않고 답한다

Given 실행이 시작되고, 본문이 흐르고, 승인을 기다리고, 끝난다
Then 각 전이에서 이미 화면에 있던 항목의 위치 변화는 1px 이하다

Given 입력에 칩이 더해지거나 대기 요청이 쌓인다
Then 입력의 아래 가장자리는 움직이지 않는다
```

## 보안·성능·접근성

- 메시지와 지시 본문은 사용자 입력이다. 원시 HTML을 실행하지 않는다.
- 모든 전송과 대상 선택, 활동 바의 펼침과 조작, 응답은 키보드로 할 수 있다. 포커스 순서는 타임라인, 지금 필요한 것, 컴포저다.
- 활동 바의 상태 변화는 표시 상태가 바뀔 때만 알린다. 경과 시간은 알리지 않는다.
- 모션은 킷의 토큰만 쓰고, 움직임 줄이기 설정에서는 글자 교체와 높이 변화가 즉시 일어난다.
- 화면에 보이는지의 관찰은 대화 창 하나에 관찰자 하나로 한다. 실행 행마다 조회나 구독을 더하지 않는다.
