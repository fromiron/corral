# 기능 명세: 추론 판정 입력 구성

- 상태: accepted
- 비목표: 회의 선택 변경, 모델별 추론 수준 보정, 외부 판정 호출, 검증되지 않은 가중치의 기본 배포.

## 사용자 관측 동작

`effort-text-v3`는 현재 요청과 최신 도구 결과를 정해진 토큰 예산 안에 함께 남긴다. 메인 모델의 요청은 바꾸지 않는다. 배포 번들과 가중치가 v3 전처리를 명시할 때만 사용하며, 기존 v4 번들의 `effort-text-v2` 경로는 유지한다. 자동 판정의 수준·실패·취소 규칙은 [로컬 AI](local-intelligence.md)가 정한다.

## 계약

- 입력은 기존 `ReasoningInput`이다. 지원 예산은 256, 512, 1,024토큰이며 모델의 실제 엔진 상한과 같아야 한다. 회의 요청에는 적용하지 않는다.
- Rust `tokenizers` 0.22.2와 해시가 고정된 모델 전용 tokenizer JSON을 사용한다. 학습과 제품은 헬퍼의 같은 구성 함수를 호출한다. 토크나이저의 자동 padding/truncation은 끄고, 접두어·구분자·BOS/EOS를 포함한 최종 문자열을 다시 토큰화해 예산을 검증한다.
- 과제·단계 및 도구 이름·상태의 고정 부분을 먼저 계산한다. 나머지는 현재 요청 40%, 도구 정보 40%, 이전 문맥 20%로 배분한다. 반올림 나머지는 현재 요청에 준다. 빈 구간과 사용하지 않은 예산은 현재 요청, 최신 도구 결과, 이전 문맥 순으로 재분배한다.
- 도구는 제공된 순서의 마지막 항목부터 최대 3개를 사용한다. 각 이름과 상태는 남기며, 결과·인자는 최신 호출부터 채운다. 이전 문맥은 계획, 이전 요청, 이전 응답 순으로 채운다. 긴 요청과 도구 결과는 토큰 경계에서 앞뒤를 함께 남긴다. 표시된 구분자도 토큰 수에 포함한다.
- Pi 입력 생성기도 마지막 assistant의 마지막 3개 호출을 원래 순서대로 전달한다. 한 응답에서 4개 이상 호출해도 최신 호출의 결과와 상태가 잘리지 않는다.
- 도구 이름 등 필수 부분만으로 예산을 넘거나, 긴 현재 요청과 최신 결과의 앞뒤를 함께 남길 수 없으면 입력을 거절한다. 조용히 상태나 필수 결과의 뒷부분을 버리거나 예산 밖 텍스트를 엔진에 넘기지 않는다. 모든 요청 필드의 길이와 호출 수는 기존 계약으로 제한한다.
- 제품 상태는 `completed/failed/pending`이며 누락은 `unknown`이다. 연구 자료를 가져오는 경계에서만 `success/error`를 `completed/failed`로 변환한다. 결과 본문으로 상태를 추측하지 않는다.
- 헬퍼의 `prepare_effort` 요청은 `{id, op, input, tokenBudget}`을 받아 `{type:'prepared', id, text, tokenCount, tokenBudget, preprocessVersion}`을 반환한다. 준비 전용 프로세스는 모델이나 추론 라이브러리를 불러오지 않는다.
- `embed_effort`는 같은 입력을 구성한 뒤 effort 모델로 계산한다. 일반 임베딩 요청은 기존 형식을 사용한다. 런타임 응답은 임베딩과 토큰 수만 포함하며 판정 입력 원문을 반환하거나 로그에 기록하지 않는다.
- 후보 manifest는 schema 3으로 tokenizer 파일의 URL·크기·SHA-256을 고정한다. 가중치 schema 4는 `effort-text-v3`, tokenizer SHA-256, 입력 토큰 상한을 포함하며 manifest와 다르면 로드를 거절한다. schema 2 번들과 schema 3 가중치는 기존 경로를 사용한다.
- schema 4의 `openPolicy: none` 후보는 열림 판정층 없이 수준 판정층의 최댓값을 사용한다. 리뷰·분석이라는 이유로 수준을 올리지 않는다. 이 정책에서 열림 판정층을 함께 제공하면 로드를 거절한다. 기존 `set-high`·`floor-high` 가중치는 열림 판정층을 유지한다. 배포 기본 가중치는 후보 검사로 바뀌지 않는다.
- 캐시 식별자는 모델 해시, 토크나이저 해시, 전처리 버전, 토큰 예산과 입력 해시를 포함한다. 요청 취소 후 늦은 결과의 폐기와 실제 계산 종료 후 슬롯 해제는 기존 엔진 규칙을 따른다.
- 장치 변경과 종료는 아직 토크나이저·모델을 불러오는 중인 헬퍼도 끝내고 시작 대기를 거절한다. 이전 시작의 늦은 준비 완료가 새 엔진의 상태를 바꾸지 않는다.

## 학습 입력의 실행 근거

- 후보 학습용 입력은 `prepareModelRequest`에서 캡처한 실제 `ReasoningInput`을 사용한다. 코호트의 요청 문장이나 시작 상태 표시는 입력을 재작성하는 근거가 아니다. 특히 이미 수정된 저장소로 새 작업을 시작한 사례는 실제 캡처가 `turn`이면 그대로 `turn`이다.
- `bind-inputs.ts`는 고정된 측정 index가 가리키는 receipt와 첫 준비 기록을 읽어 `whole_task_fixed_policy` 범위의 입력을 만든다. 코호트·index·receipt·캡처의 해시와 사례·그룹·분할·실행 수준의 대응을 확인한다. 같은 사례의 조건별 첫 입력이 다르면 결합을 거절한다. 학습·검증 자료만 허용하며 최종 평가 자료는 받지 않는다.
- 이 범위는 전체 과제를 한 추론 수준으로 실행한 결과를 뜻한다. 중간 단계의 최적 행동을 증명하지 않는다. `step_counterfactual`이나 뒤의 준비 기록을 이 범위로 바꾸어 가져오지 않는다. 실제 상태 복원과 개입의 검증은 별도 근거가 필요하며 파일 해시만으로 이를 대신하지 않는다.
- `embed.ts`는 캡처 결합을 다시 검증하고 실제 입력만 임베딩한다. 과거 요청 문장 자료는 명시적 `--legacy-input`으로만 읽으며, 이 모드는 `effort-text-v3` 후보 임베딩에 사용할 수 없다. 모델·전처리 해시 외에 입력 근거의 종류와 판단 범위도 임베딩 메타데이터에 기록한다.
- 원문을 포함하는 결합 파일은 저장소 밖에 저장한다. 출력은 기존 파일을 덮어쓰지 않으며 로그에는 원문을 출력하지 않는다.

## 수용 시나리오

```gherkin
Given 이전 응답이 길고 최신 도구 결과가 성공 또는 실패다
When 256, 512, 1,024토큰으로 각각 구성한다
Then 현재 요청과 최신 도구 이름·상태·결과가 모두 남는다
And 최종 토큰 수는 특수 토큰을 포함해 선택한 예산 이하다

Given 한국어·일본어·영어·코드·Unicode 입력이다
When 학습용 준비와 제품 임베딩이 같은 예산을 사용한다
Then 입력 구성과 토크나이저 결과가 일치한다

Given 토크나이저 해시나 가중치의 토큰 예산이 manifest와 다르다
When 판정기를 만든다
Then 로드를 거절하고 다른 버전의 입력을 대신 사용하지 않는다

Given 가중치는 기존 effort-v4다
When 새 헬퍼로 기존 판정과 회의 분석을 실행한다
Then 기존 모델과 전처리를 그대로 사용한다

Given 코호트의 시작 상태 표시는 step이지만 첫 실제 준비 입력은 turn이다
When 고정 정책 실행 결과와 학습 입력을 결합한다
Then 입력은 캡처된 turn 그대로다
And 원래 시작 상태 표시는 입력 밖의 메타데이터에만 남는다

Given 학습 입력 또는 참조한 캡처가 바뀌었거나 조건별 첫 입력이 다르다
When 후보 임베딩을 준비한다
Then 결합을 거절하고 모델을 실행하지 않는다
```

## 보안·성능

- 토크나이저 파일은 설치 시 크기와 해시를 검증한다. 헬퍼는 네트워크를 사용하지 않는다. 오류는 입력 원문과 파일 경로를 포함하지 않는다.
- 준비 결과를 반환하는 모드는 명시적인 로컬 연구 도구용이다. 원문·라벨·임베딩과 실험 기록은 Git 작업 트리 밖에 저장한다.
- 각 예산의 효율은 해당 LiteRT 엔진 상한에서 측정한다. 긴 그래프에 짧은 문자열만 넣은 결과를 짧은 그래프의 성능이라고 보고하지 않는다.
- 의존성 근거: [Hugging Face tokenizers 0.22.2](https://docs.rs/tokenizers/0.22.2/tokenizers/), Apache-2.0. 학습 환경의 같은 버전 및 번들의 SentencePiece 토크나이저와 결과를 대조한다.
