# 기능 명세: 사용 한도가 풀리면 다시 보내기

- 상태: accepted
- 비목표: 남은 한도 보이기, 리셋 시각 추측, 다른 모델로 바꿔 보내기, 실패한 실행의 도구 기록 이어 붙이기, 짧은 요청 제한(`RATE_LIMIT`)의 재시도, 회의·예약 실행·결과 질문

## 사용자 관측 동작

구독 사용 한도 때문에 대화의 요청이 실패하면, 한도가 풀리는 시각에 서버가 그 요청을 다시 보낸다.

- **대상.** 대상은 다음 조건을 모두 만족하는 Run이다.
  - 세션 대화의 요청(새 요청·다음 요청·대기 요청)으로 시작했다.
  - 실패로 끝났다.
  - 실행 단위 하나 이상이 모델 요청의 사용 한도 실패로 끝났다.
  - 공급자가 리셋 시각을 알려 주었다.
  - 리셋 시각이 실패 시각으로부터 10분 이상 뒤다.
  - 리셋 시각이 그보다 가까우면 아무것도 하지 않고 지금처럼 실패만 보인다.
- **다시 보낼 요청.** 그 Run을 시작한 요청의 사본이 대기열 맨 앞에 쌓인다. 글·텍스트 첨부·이미지·참조·권한 방식·모델과 팀 선택이 모두 원래 요청과 같다. 카드에는 "HH:MM에 다시 보냄"(Resends at HH:MM)이 보인다. 시각은 리셋 시각에 1분을 더한 값이다. 지금 시작·편집·제거는 다른 대기 요청과 같다.
- **시작.** 그 시각이 되면 서버가 다시 보낼 요청을 시작한다. 화면이 열려 있지 않아도 시작한다.
  - 세션의 자동 시작 설정을 따른다. 기본은 켬이다. 꺼져 있으면 사람이 "지금 시작"을 누를 때까지 남는다.
  - 서버가 그 시각에 꺼져 있었으면 다시 켜진 뒤 바로 시작한다. 다만 시각이 24시간 넘게 지났으면 자동으로 시작하지 않고 카드만 남는다.
- **한 번만.** 자동으로 다시 보내는 것은 사람이 쓴 요청 하나당 한 번이다. 다시 보낸 요청이 또 한도로 실패하면 새 사본을 만들지 않는다. 그때는 보낸 요청의 "다시 보내기"를 사람이 누른다.
- **다른 요청이 먼저 끝나면 지운다.** 시각 전에 같은 세션에서 다른 Run이 시작해 끝났으면, 다시 보낼 요청은 시작하지 않고 대기열에서 지운다. 사람이 다른 모델로 직접 다시 보낸 경우가 여기에 든다. 세션이 보관되면 시작하지 않는다.
- **지우기.** 사람이 다시 보낼 요청을 지우면 그 시각에 아무것도 시작하지 않는다. 뒤의 대기 요청은 보통 대기 요청처럼 다음 Run이 끝날 때 시작한다.
- **순서.** 다시 보낼 요청이 맨 앞이므로, 그 뒤의 대기 요청도 그 시각까지 자동으로 시작하지 않는다. 뒤의 요청은 실패한 요청의 결과를 전제로 썼을 수 있기 때문이다. 어느 카드든 "지금 시작"은 바로 시작한다.
- **표시.** 다시 보낸 요청은 대화에서 사람이 보낸 요청과 같은 자리에 보이고, 메타 줄에 "한도가 풀려 다시 보냄"(Resent after the usage limit reset)을 단다.
- **문맥.** 다시 보낸 요청이 받는 대화 문맥은 다른 다음 요청과 같다. 실패한 Run의 요청과 끝 상태는 실리고, 그 Run의 도구 기록은 실리지 않는다([LLM 런타임](../llm-runtime.md#continuation-and-accounting)). 파일 변경은 Paddock에 남아 있다.

## 계약

- **리셋 시각의 출처.** 모델 요청 실패의 분류(`packages/adapter-pi/src/ported/dsh/retry.ts`)가 `QUOTA`일 때만 리셋 시각을 읽는다. 출처는 두 가지이고, 둘 다 있으면 늦은 쪽을 쓴다. 짧은 일반 `retry-after`가 본문이 말한 리셋을 가리지 않게 하기 위해서다.
  - 응답의 `retry-after-ms`·`retry-after` 헤더
  - ChatGPT 구독 한도 글의 "Try again in ~N min."(Pi가 오류 본문의 `resets_at`으로 만든 글). 이 경우 리셋 시각은 분 단위로만 정확하다.

  둘 다 없으면 리셋 시각은 없다. 리셋 시각은 분류할 때의 시각(주입한 `now`)에 더해 ISO 시각으로 남긴다.
- **실패 기록.**
  - 모델 요청 기록의 `failure`에 `resetAt`(ISO 또는 null)을 남긴다.
  - 실행 단위가 한도 실패로 끝나면 `AgentSettlement.usageLimit = { resetAt }`이 되고, `execution.settled` 페이로드에도 `usageLimit: { resetAt }`이 실린다.
  - projection의 실행 단위 보기에 `usageLimit`가 남는다.
- **다시 보낼 요청의 기록.** 대기 요청 `SessionEntry`에 `resend: { of, runId, notBefore }`가 붙는다.
  - `of`는 원래 요청의 entryId, `runId`는 실패한 Run, `notBefore`는 리셋 시각 + 1분이다.
  - 같은 `runId`의 `resend` 항목은 세션에 하나뿐이다. 서버가 같은 끝을 두 번 보고해도 하나만 생긴다.
  - `resend`가 있는 항목에서는 다시 만들지 않는다(한 번만).
- **판단.** "만들지, 기다릴지, 시작할지, 지울지"는 순수 함수 하나가 정한다. `packages/core/src/usage-limit-resend.ts`이며, 주입한 시각을 받는다. 판단 규칙의 출처는 샘플 저장소의 사용 한도 복구 판단(`limitRecoveryCommand`)이다.
  - 리셋 시각이 실패 시각보다 이르거나 같으면 만들지 않는다. 만료된 창을 새 실패와 함께 받아 재시도 고리가 생기지 않게 하기 위해서다.
  - 리셋 시각이 24시간 넘게 지났으면 자동 시작하지 않는다.
  - 보관된 세션에서는 시작하지 않는다.
- **시작 경로.** 서버 대기열(`apps/server/src/session-queue.ts`)이 다른 대기 요청과 같은 시작 명령으로 시작한다. 명령 ID도 같아서, 화면의 "지금 시작"과 서버의 시작이 같은 Run 하나에 닿는다.
  - `notBefore` 전에는 그 세션의 대기열을 시작하지 않고, `notBefore`에 다시 보도록 시계를 건다. 시각은 주입한다.
  - 서버가 시작할 때는 모든 세션의 다시 보낼 요청에 시계를 다시 건다.
- **보관 경로.** 세션 기록의 JSON 항목이다. 형식 검사는 `packages/core/src/repository/index.ts`의 항목 검사가 한다. 옛 기록 이전은 없다.

## 수용 시나리오

```gherkin
Given 세션의 요청이 ChatGPT 사용 한도로 실패했고 공급자가 42분 뒤 리셋을 알렸다
When 그 Run이 끝난다
Then 대기열 맨 앞에 같은 글의 요청이 "HH:MM에 다시 보냄"으로 쌓인다
And 그 요청의 시작 선택·권한·첨부는 원래 요청과 같다

Given 다시 보낼 요청이 기다리는 중이다
When 그 시각이 된다
Then 서버가 그 요청을 시작하고, 대화의 메타 줄에 "한도가 풀려 다시 보냄"이 보인다

Given 다시 보낼 요청이 기다리는 중이다
When 사람이 다른 모델로 새 요청을 보내 그 Run이 끝난다
Then 다시 보낼 요청은 시작하지 않고 대기열에서 지워진다

Given 서버가 같은 Run의 끝을 두 번 보고한다
Then 다시 보낼 요청은 하나만 생긴다

Given 다시 보낸 요청이 또 사용 한도로 실패한다
Then 새 다시 보낼 요청은 생기지 않는다

Given 리셋까지 10분이 남지 않았거나, 분류가 RATE_LIMIT이거나, 리셋 시각이 없다
Then 다시 보낼 요청은 생기지 않는다

Given 다시 보낼 요청이 기다리는 중이고 그 뒤에 대기 요청이 있다
When 시각 전에 Run이 끝나는 일이 생긴다
Then 뒤의 대기 요청은 자동으로 시작하지 않는다
And 사람이 뒤의 카드에서 "지금 시작"을 누르면 그 요청이 시작한다

Given 서버가 리셋 시각을 지나 다시 켜졌고 시각이 24시간 안에 지났다
Then 서버가 다시 보낼 요청을 바로 시작한다

Given 리셋 시각이 24시간 넘게 지났다
Then 자동으로 시작하지 않고 카드만 남는다
```

## 보안·성능·접근성

- **보안.** 리셋 시각을 얻으려고 오류 본문이나 헤더 전체를 저장하지 않는다. 분류 결과의 시각 하나만 남긴다. 다시 보내는 요청은 원래 요청의 권한 방식과 Harness를 그대로 쓴다. 권한을 넓히지 않는다.
- **성능.** 시계는 세션마다 하나다. 서버를 시작할 때 프로젝트의 세션을 한 번 읽는다.
- **접근성.** 카드의 시각은 글로 보이고 화면 읽기 프로그램도 읽는다. 시각은 사용자의 로케일 시각 형식이다.
