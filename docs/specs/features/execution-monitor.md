# 기능 명세: 실행 기록 관찰

- 상태: implemented
- 비목표: 실행 엔진 교체, 그래프 편집, 실행 당시 화면 좌표의 복원.

## 사용자 관측 동작

세션의 실행 기록과 독립 Run 화면은 같은 Run 관찰 화면을 사용한다. 기본 진입은 완료 여부와 관계없이 그래프다. 명시적 결과 링크는 결과 화면을 열며, 완료 이벤트가 화면을 전환하지 않는다.

Run 선택·상태·전체 제어는 상단 한 곳에 둔다. 트리에서 실행을, 그래프에서 노드를 선택한다. 상세는 개요(입력·출력·근거·분기), 호출, 사용량, Reins로 나누고 승인은 탭 밖에서 접근한다. Reins는 명시적으로 선택한 실행만 대상으로 한다. 없는 대상은 안내하고 다른 대상으로 대체하지 않는다.

1280px 이상에서는 트리·중앙·상세, 768–1279px에서는 중앙과 트리 또는 상세, 768px 미만에서는 한 영역을 표시한다. 기준은 Run 컨테이너다. 스트리밍·영역 전환·크기 변경은 선택, 스크롤, 그래프 위치와 확대율, Reins 초안을 초기화하지 않는다. 그래프 맞춤은 최초 표시와 사용자의 맞춤 요청에만 수행한다.

개요의 Run 전체 작업·계획·질문 목록은 필요할 때 펼친다. 시간축의 선택 버튼과 관측 구간은 별도 영역으로 배치한다.

## 계약

기존 공유 RunSessionStore의 수명과 단일 구독을 유지한다. 결과·근거·분기·승인·복구·Reins의 명령 및 receipt 경로는 기존 계약을 따른다. 닫은 상세의 포커스는 열었던 컨트롤로 돌아간다. Run을 바꾸면 이전 실행·자료·결과 선택을 지운다.

전체 취소 확인 대기는 같은 브라우저 탭의 새로고침 뒤에도 원래 Run에만 남는다. 확인 전에는 취소 명령이 전송되지 않았음을 표시하며, 실행 종료·명시 확인·계속 실행 선택으로 해제한다. 다른 Run으로 이동하거나 실행 조작 화면을 떠나면 확인 대기를 폐기하며, 원래 Run으로 돌아와도 되살리지 않는다. 다른 Run을 확인 없이 취소하지 않는다.

## 수용 시나리오

- 완료 Run을 기본 주소로 열면 그래프가 보인다. 명시적 결과 주소는 결과를 보인다.
- 실행 선택 후 다른 상세 탭을 열어도 Reins 초안은 남는다. 닫으면 트리/그래프의 진입점으로 포커스가 돌아간다.
- 이전 Run의 늦은 조회 응답은 새 Run의 정의·배치·선택을 덮어쓰지 않는다.
- 노드 이동·연결·삭제 입력은 정의를 바꾸지 않는다. 그래프 확대 후 파일 뷰어를 열어도 확대율은 유지된다.
- 승인 대기, 대상 누락, 근거·결과와 메시지 분기에 계속 접근할 수 있다. 좁은 승인 표시에서도 판단 대상 버전과 그 판단 기준은 확인할 수 있다.

## 보안·성능·접근성

디자인킷의 기본 Tabs를 그대로 사용한다. 상태에는 텍스트를 제공하고 키보드로 트리·상세·탭에 접근한다. 작성 D&D 및 Reins의 권한·취소 계약은 변경하지 않는다. 스트림 토큰이 그래프 전체나 이력 전체 계산을 유발하지 않는다. 기본 E2E는 기존 스모크 두 흐름을 유지한다.

## 실행 상태와 관측 관계

노드 요약은 task별 현재 시도를 집계한다. task의 유효한 activeExecutionId가 있으면 그것을, 없으면 가장 높은 attemptNo의 마지막 시도를 사용한다. 모델 생성·도구·정리 작업과 준비·대기·정지·취소를 구분한다. 현재 시도들의 상태가 다르면 상태별 개수를 함께 보여준다. 진행 중 상태를 우선하되 별도 task의 미해결 실패·취소를 숨기지 않는다. 성공한 재시도는 완료로 표시하고 이전 실패 수는 이력으로 남긴다.

Decision의 승인 상태를 전역 user_action 승인에서 추정하지 않는다. 귀속 근거가 없는 승인은 Run 영역에 표시한다. Output의 완료는 output.nodeId가 일치할 때만 표시한다. Loop는 관측된 반복 회차와 마지막 결과를 표시한다.

정적 정의 간선과 관측된 위임·질문을 구분한다. 질문 응답 task의 자식을 위임으로 중복 집계하지 않는다. 관측 간선은 실제 존재하는 agent 노드 사이의 실행·질문 기록으로만 만들고 대상 invocation에 맞는 핸들을 사용한다. 부모에게 보내는 질문은 scheduled 부모의 in 핸들을 사용한다. 관측 없는 간선을 실행 중이라고 강조하지 않으며 모든 강조는 정적 표시다.

같은 관계의 정적 간선과 관측 간선은 라벨을 중복 표시하지 않는다. 그래프 노드·간선·컨트롤은 앱에서 선택한 밝은/어두운 테마를 따른다. 시작 준비·취소 정리·종료 상태를 현재 Run 상태와 구분하며, 종료된 Run의 미정산 모델 호출은 진행 중 요청으로 단정하지 않고 종료 미확인 요청으로 표시한다.

관측 관계의 횟수·진행 수 캡션은 노드 포트 이름과 다른 간선 라벨을 가리지 않는다. 같은 source 핸들에 관측 관계가 있으면 정적 허용 간선은 선으로 남기고 중복 종류 라벨은 생략한다. 밝은/어두운 테마에서 캡션과 포트의 읽기 간격을 유지하며, 포트 이름의 불투명한 배경이 뒤를 지나는 간선을 가려 글자를 읽을 수 있게 한다.

- 같은 task가 실패 후 성공하면 완료와 이전 실패 이력이 보인다.
- 서로 다른 task의 성공과 실패는 실패를 숨기지 않고 상태별 수로 보인다.
- 취소는 실패로 표시하지 않는다. 모델·도구·대기 상태가 각각 구분된다.
- 도구 승인과 관련 없는 Decision은 전역 승인 때문에 대기·실패로 바뀌지 않는다.
- 질문 응답자는 질문으로 한 번만 관측되고, 존재하지 않는 노드나 핸들로 간선을 만들지 않는다.
- 관계없는 projection revision과 streaming 변화는 그래프 전체를 다시 렌더하지 않는다.

## 과거 시점과 관측 시간 구간

과거 조회는 `runSeq`까지의 연속 이벤트 prefix에 기존 `emptyProjection`과 `applyEvent`를 적용한 읽기 전용 표시 상태다. 명시한 시점이 현재 마지막 순번과 같아도 최신 복귀 전에는 과거 조회다. 순번 0은 시작 전 빈 상태다. 같은 기록 시각도 순번으로 구분한다. 요청 시점까지 기록이 아직 오지 않았으면 로딩, 중간 순번이 빠졌으면 누락으로 구분하고 마지막 연속 prefix까지만 복원한다. 라이브 이벤트·투영은 변경하지 않는다.

실행 시간축은 실행 인스턴스마다 별도 행을 둔다. 생성부터 처음 관측된 종료까지가 수명 구간이고, 상태 변경에 따라 대기와 활동 구간을 나눈다. 종료가 관측되지 않은 실행의 구간은 prefix의 마지막 관측 시각까지만 그린다. 반복·재시도를 같은 막대로 합치지 않는다.

모델 호출 시간은 예산 예약으로 연결한 model_request effect의 dispatch_observed와 model.finished가 둘 다 있을 때만 표시한다. 준비 시각은 모델 전송 시각으로 대체하지 않는다. 도구 시간은 tool.started와 tool.finished가 모두 있을 때만 표시한다. 순번에 대응되는 완료 응답 참조와 완료된 캐시가 있을 때만 과거 응답 본문을 표시한다. 진행 토큰·미래 완료 응답은 섞지 않는다.


주소의 `atSeq`는 0 이상의 안전한 정수다. 없으면 최신 조회이며, 세션 주소에는 Run ID도 함께 기록한다. 시점 이동은 주소를 교체하고 Run 전환은 실행·자료·결과·시점을 초기화한다. 그래프가 기본이며 시간축과 기존 이벤트 목록을 선택할 수 있다. 이벤트 선택과 이전·다음·디자인킷 기본 Slider로 시점을 이동한다. 최신 복귀는 cursor를 명시적으로 해제한다.

과거 상태는 상단 상태 옆에도 과거 조회임을 표시한다. 요청 순번까지 이벤트를 읽는 동안 초기 빈 투영을 실행 상태나 오류로 표시하지 않는다. 대화·파일 등 다른 주 화면으로 이동하면 cursor를 해제한다. 대화의 결과 링크를 연 뒤 브라우저 뒤로가기는 그 대화로 돌아간다.

과거 화면의 그래프·트리·호출·모델 판단·사용량·자료·결과는 같은 prefix를 사용한다. 현재 실행에 보내는 Reins·승인·전체 제어는 과거 조회에서 비활성화한다. 최신 복귀 시 원래 실행 대상의 현재 유효성을 확인한다. 라이브 입력 초안은 과거 조회 중에도 보존한다. 순번 귀속이 없는 현재 파일 작업·검증·복구 정보는 과거 근거로 표시하지 않고 최신 조회를 안내한다. 누락 범위는 경고하고 복원 가능한 마지막 연속 기록까지만 표시한다.

- 과거 시점을 새로고침하면 같은 Run과 순번을 연다. 새 라이브 이벤트는 선택한 시점을 이동시키지 않는다.
- 과거 자료나 실행이 없으면 다른 최신 대상으로 대체하지 않는다. 미래 캐시 본문과 진행 토큰은 표시하지 않는다.
- 시점 0과 현재 head의 명시적 시점도 읽기 전용이며 최신 복귀만 현재 제어를 활성화한다.
- 기록 10,000개에서 기존 이벤트 가상화를 유지한다. 스트리밍 토큰만 바뀔 때 prefix를 다시 reduce하지 않는다.
표시 전용 Context는 projection·events·streams만 치환한다. 정의, 본문 캐시와 명령 함수는 기존 세션을 사용하며 Context 밖에서는 기존 라이브 표시가 유지된다. 트리·그래프·호출·결과·사용량은 동일한 prefix를 읽고, 해당 prefix에서 알려지지 않은 참조의 캐시 본문은 표시하지 않는다.
