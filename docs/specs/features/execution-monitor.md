# 기능 명세: 실행 기록 관찰

- 상태: implemented
- 비목표: 실행 엔진 교체, 그래프 편집, 실행 당시 화면 좌표의 복원.

## 사용자 관측 동작

세션의 실행 기록과 독립 Run 화면은 같은 Run 관찰 화면을 사용한다. 기본 진입은 완료 여부와 관계없이 **그래프**다. AgentRun의 상단 실행 제어, 중앙 작업, 오른쪽 대상 상세 구성을 사용한다. 프로젝트·세션 탐색은 앱 왼쪽 사이드바가 맡는다.

중앙은 그래프·작업 흐름·시간축·이벤트·결과 중 하나를 표시한다. 보기 전환은 실행 머리 가까이에 두며 하단 도크로 나누지 않는다. 각 보기는 하나의 질문에 답하고 다른 보기의 질문을 반복하지 않는다. 그래프는 에이전트 단위로 누가 누구와 일했고 지금 어디가 움직이는지, 작업 흐름은 실행 단위로 일을 어떻게 나눠 어떤 순서로 처리했고 무엇이 넘어갔는지, 시간축은 언제 얼마나 걸렸는지, 이벤트는 정확히 무엇이 기록됐는지, 결과는 이 Run이 만든 읽을 수 있는 결과가 무엇인지를 보인다. 그래프 보기는 같은 질문을 관계도와 목록 두 표시로 답한다. 관계도를 화면에 맞추면 이름을 읽을 수 없을 만큼 작아지는 좁은 화면에서는 목록 표시로 시작하고, 사용자가 표시를 고른 뒤에는 그 선택을 따른다. 목록은 에이전트 노드마다 한 행에 이름·모델·상태·현재 실행 단위(회차·시도)·관측된 경과를 보이며 사용량·비용을 두지 않는다. 행을 고르는 것은 관계도의 노드를 고르는 것과 같다. 결과 보기는 결과 버전마다 이름·출처 실행·버전을 보이고 기존 결과 읽기로 연다. 출처는 에이전트 이름·실행 번호·시도로 적어, 이름이 같은 결과를 만든 실행이 서로 구분된다. 본문을 더 보관하지 않는 결과는 이름 아래 둘째 줄에 그 사실을 적는다. 주소로 연 단계 결과는 그 결과가 속한 묶음 아래에 선택된 행으로 보인다. 결과가 아직 없으면 제목 하나로 그 상태를 보인다(진행 중이면 "아직 결과 없음", 끝났으면 "결과 없이 끝남"). 실행 화면에 결과만 담는 하단 띠를 따로 두지 않는다. 도구 호출 목록과 호출별 소요 시간은 작업 흐름에 두지 않고 선택한 실행의 상세와 시간축에서 본다. 실행 관계도는 작성 화면의 정의 그래프와 저장 좌표를 사용하지 않는다.

작업 흐름은 위에서 아래로 내려가는 디자인킷 AgentTree다. 카드 하나가 실행 하나이며, 부모 실행이 위임한 실행을 자식으로 둔다. 재시도와 회차는 각자의 카드다. 카드는 에이전트 이름·모델·상태, 그 실행이 만든 자료 이름과 회차·시도, 관측된 시작·종료로 계산한 경과 시간을 보인다. 카드에는 그 실행이 보낸 것만 짧게 표기한다. 전달 표기가 이름을 밝힌 자료 버전은 카드에 따로 한 번 더 적지 않는다. 만든 자료마다 그 자료를 읽거나 모델 입력에 포함한 다른 실행의 에이전트를, 보낸 질문마다 대상 에이전트와 답변 여부를 보인다. 받은 쪽 카드에는 같은 전달을 다시 쓰지 않으며, 기록되지 않은 전달을 시간 순서로 추정하지 않는다. Loop는 반복 규칙에 따라 한 그룹으로 표시한다. 카드를 고르면 오른쪽에 그 실행의 상세를 연다. 작업 흐름은 처음 열 때 펼쳐진 상태로 보이며, 접은 가지는 화면이 살아 있는 동안 접힌 채로 남는다. 계획 도구가 기록한 계획은 흐름 위의 한 줄로 접혀 있고, 완료 단계 수/전체 단계 수와 지금 단계를 보이며 펼치면 전체 계획을 보인다. 계획이 여러 개면 개수를 함께 보이고 펼쳐서 각 계획을 본다. 기록된 계획이 없으면 이 줄을 두지 않고 가짜 단계나 진행률을 만들지 않는다. 기록된 Decision 분기가 있으면 흐름 아래에 결정 근거를 디자인킷 DecisionTree로 표시하며 기록된 선택만 강조한다.

실행 머리에는 요청 제목·상태·경과 시간을 간결하게 보인다. 긴 요청은 두 줄로 요약하고 실행 정보에서 전체 내용을 읽는다. 머리의 확장 내용은 제한된 높이 안에서 스크롤하며 중앙 작업 공간을 밀어내지 않는다. 요청 기록이 없으면 정의 이름을 쓴다. 실패로 끝난 실행은 상태 옆에 기록된 종료 사유 한 줄과 실패한 실행의 상세를 여는 진입점 하나를 둔다. 검토 레시피가 멈춘 실행은 그 한 줄 대신 머리 아래에 레시피 상태(멈춘 이유와 회차별 결과)를 보이고, 이유를 두 번 쓰지 않는다. 확장이 물은 것에 답한 뒤 확장이 남긴 알림은 실행이 살아 있거나 그 글이 보관된 동안 응답 영역에 남는다. 원인 코드가 있으면 그 코드의 화면 이름을 보이고, 코드 없이 서버 문장만 있으면 "기록된 이유" 아래에 그 문장을 고치지 않고 둔다. 좁은 머리에서는 제어가 화면 밖으로 밀리지 않도록 다음 줄로 내려간다. 팀·시작 시각·실행 ID·숫자 통계·저장 팀 편집 링크·시작 출처·종료 사유는 실행 정보의 상세에 둔다. Run 선택과 전체 제어는 기존 세션 상단 경로와 실행 조작 한 곳을 따른다. 활동은 노드 이름·시도·회차·상태를 머리로 두고, 도구 호출은 디자인킷 도구 호출 묶음으로 표시한다. 완료된 기록은 접어서 접근하고 실패·진행 중 기록은 찾을 수 있게 유지한다.

오른쪽은 **명시적으로 연 노드의 전체 실행 목록/실행 상세, 확인 필요, 실행 정보 중 하나**의 상세와 제어만 표시한다. 기본은 닫힘이며 빈 현황 카드나 전체 결과·계획 목록을 상시 쌓지 않는다. 실행 선택은 활동·작업 흐름·시간축의 정확한 실행 진입점 또는 그래프 팝오버의 상세 동작에서 한다. 다른 그래프 노드의 빠른 확인은 열려 있는 오른쪽 대상과 주소의 실행 선택을 바꾸지 않는다. 상세를 명시적으로 열면 오른쪽 내용을 교체한다. 선택한 실행의 상세는 탭 없이 한 화면으로, 그 실행에 속한 것만 보인다. 순서는 상세 머리, 진행 중인 실행의 지시하기, 그 실행이 만든 결과·건드린 파일·검사, 실패한 단계, 마지막 모델 요청의 컨텍스트 추정 한 줄, 호출 대화다. 상세 머리에는 에이전트 이름과 정확한 실행 번호·회차·시도를 표시한다. Run 전체 작업·계획 목록, 실행 환경, 모델 연결, 하네스 진단, Run 전체 변경과 사용량은 실행 상세에 두지 않고 실행 정보에서만 연다. 대상이 없거나 사라지면 안내하고 다른 실행으로 대체하지 않는다. 응답 영역에서 마지막 질문·승인에 답해 영역이 닫히면 그 안에 있던 포커스는 실행 제목으로 간다. 질문·승인을 기다리는 동안 머리의 실행 상태 표시가 그 진입점인 응답하기 버튼이 되고(둘 이상이면 개수를 붙인다), 따로 떨어진 진입점은 두지 않는다. 응답 영역이 이미 같은 화면에 보이면 머리의 표시는 상태만 말하고 응답하기는 응답 영역에 한 번만 있다. 다른 항목을 보고 있어도 진입점은 유지한다. 새 질문·승인이 생겼을 때 화면이 넓고 오른쪽이 닫혀 있으면 확인 필요를 한 번 연다. 포커스는 옮기지 않는다. 이미 연 상세·실행 정보·결과·지시하기를 대체하지 않고, 사용자가 닫은 뒤에는 같은 질문·승인 때문에 다시 열지 않는다. 새 이벤트는 사용자가 읽는 상세나 결과를 자동으로 바꾸지 않는다.

현재 결과와 자료 본문은 버전을 유지한 채 **중앙**에서 읽는다. 명시적 결과 주소(`view=results`, `result`) 및 자료 주소(`artifact`)도 중앙에서 열린다. 돌아가기 또는 닫기로 이전 보기·선택·스크롤·그래프 위치를 복원한다. 결과 본문과 실행 상세를 오른쪽에 함께 쌓지 않는다. 완료 이벤트는 현재 화면을 전환하지 않는다. 자료 수명·본문 접근 자격은 기존 API 계약을 따르며 열 수 없는 자료를 최신 버전으로 대체하지 않는다.

Reins는 명시적으로 **지시하기**를 선택했을 때 중앙에서 연다. 열면 포커스는 지시 입력란으로 가고, 그 실행이 더는 지시를 받지 않으면 지시하기 영역으로 간다. 지시하기는 끝나지 않은 실행에만 제공하며, 끝난 실행에 보냈던 지시와 전달 여부는 그 실행의 호출 대화에서 본다. 실행을 살펴보는 것만으로 입력 대상을 바꾸지 않는다. 대상과 다음 모델 요청 등 적용 시점을 명시하고 입력 초안의 원래 Run·실행 경계를 유지한다. 다른 실행을 조회하거나 결과를 읽어도 작성 중 지시 대상은 바뀌지 않는다. 닫기는 입력 초안을 버리거나 실행을 종료하지 않는다. 접수·대기·전달·취소 중·취소됨의 의미와 기존 명령·receipt·권한 경계는 유지한다. 필요 없는 빈 지시 안내와 반복 계획·도구 활동은 지시 입력 주변에 쌓지 않는다.

질문·답변의 첨부는 자료 이름과 생성자 관계를 표시하며 본문 열람 가능 여부와 구분한다. 판단 근거는 작업의 역할·제출 자료, 승인의 대상·현재 상태, 정확히 참조한 검사의 이름·판정·종료 코드·시간 초과 여부를 표시한다. 검사는 같은 Run 소유의 일치하는 참조만 연결하며 확인 불가일 때도 원래 참조를 보존한다. 현재 상태를 판단 당시 상태로 표현하거나 검사 원문 출력을 관계 화면에 복사하지 않는다.

Run 컨테이너가 중앙 최소 폭(640px)과 오른쪽 패널(360px)을 담으면 함께 표시한다. 그보다 좁으면 한 번에 한 영역을 표시하고 닫기로 중앙에 돌아온다. 보기·결과·상세 전환은 기존 store·구독·초안·스크롤·그래프 위치와 확대율을 유지한다. 각 보기는 실제 표시 영역의 크기가 확보된 뒤 처음 초기화하고 이후 숨겨도 유지한다. 기존 Run을 처음 열 때는 초기 스냅숏 순번까지 관측 기록을 읽은 뒤 그래프를 초기화한다. 부분 이력의 첫 노드만으로 화면을 맞추지 않는다. 그래프 맞춤은 최초 표시와 사용자의 맞춤 요청에만 수행한다. 보기 식별자는 표시 이름·언어·이벤트 개수와 독립적이며 새 이벤트가 필터·선택·키보드 초점을 초기화하지 않는다. 시간축의 에이전트별/작업별 선택도 유지한다. 실행이 응답을 기다리거나 일시정지된 동안 시간축은 마지막 기록 시각에서 멈추고, 기다리는 시간만큼 축을 늘려 기록을 눌러 보이지 않는다.

호출은 선택한 실행의 대화로 보인다. 각 호출은 이름·상태·인자·결과 자료 링크를 보인다. 호출별 소요 시간은 시간축에서만 보인다. 수명이 끝난 모델 응답은 호출·지시 전달 관계와 본문 미보관을 표시하며 빈 응답이나 생성 중으로 표현하지 않는다. 진행 중 Run의 스트리밍과 완료 텍스트는 유지한다.

## 반복 작업 표시

Loop는 실행 횟수만큼 복제한 노드 열이 아니라 하나의 반복 구조로 표시한다. 작업 흐름과 실행 트리는 정의된 Loop마다 이름, 관측된 회차 수, 현재 상태·최근 관측 결과와 유효한 반복 상한을 한 그룹에 표시한다. 회차 수와 유효한 상한, 현재 상태는 가장 최근 진입의 것이다(다시 들어온 Loop의 이전 진입 회차는 회차 선택 목록에서 본다). 유효한 상한은 그 진입에서 돌 수 있는 회차 수다. 한도 정책이 적용된 진입에서는 적용 전에 끝난 회차 수에 상한을 더한 값이고, 상한이 없는 Loop는 상한을 적지 않는다. 한도 정책이 적용됐으면 무엇이 바뀌었는지(추론 수준 또는 모델)를 같은 그룹에 한 줄로 보인다. 반복 계속·종료는 기록된 분기·outcome으로 설명하고, 기록 없는 선택을 추정하지 않는다. 실행 관계도는 같은 에이전트의 회차·시도를 하나의 노드로 모으며, 정의의 Loop·되돌림·종료 노드를 표시하지 않는다. 회차와 시도는 작업 흐름·시간축·선택한 에이전트의 실행 목록에서 조회한다. 작성 화면의 Loop·되돌림·종료 연결과 D&D는 유지한다.

기본 펼침은 각 Loop의 최신 관측 회차다. 회차 선택은 그 Loop의 실행·산출물·관계·결정 metadata만 필터링한다. 현재 Run 상태·승인·Reins 대상·본문 접근 자격을 과거로 되돌리지 않는다. 명시적으로 선택한 회차는 새 회차가 시작해도 유지하고, 최신 추적을 선택하면 이후 회차를 따라간다. 존재하지 않는 명시적 회차는 다른 회차로 대체하지 않고 선택 없음으로 안내한다. 실행 직접 링크나 실행 선택은 해당 실행이 속한 회차를 보이게 하며, 다른 회차를 살펴본다는 이유로 명령 대상을 바꾸지 않는다.

선택한 회차가 실제로 사용한 이전 회차의 carry input은 정확한 자료·작성자·관계 metadata로 연결할 수 있다. 그 이전 회차 전체를 재귀적으로 펼치거나 과거 본문을 복구하지 않는다. 회차가 늘어도 기본 화면의 Loop·에이전트·결정 카드 수는 누적 회차 수만큼 증가하지 않는다. 회차 선택 목록과 명시적으로 연 상세만 전체 기록에 접근할 수 있다. 이 표시 계약은 실행 엔진의 반복·깊이 상한을 바꾸지 않는다.

- 많은 회차를 가진 Loop도 기본 화면에는 Loop 그룹 하나와 최신 회차의 실행·관계·결정이 표시된다.
- 이전 회차를 선택하면 해당 회차의 정확한 실행·자료 관계를 확인할 수 있지만 수명이 끝난 본문은 열리지 않는다.
- 새로운 회차가 도착하면 최신 추적 중인 그룹만 바뀌며 명시적으로 고른 회차와 Reins 대상은 유지된다.
- 두 Loop는 서로의 회차를 바꾸지 않는다. 취소·반복 상한 도달·승인 대기는 실제 현재 상태와 결과로 표시된다.

실행 탐색과 비교의 이름은 세션의 기록된 요청, 세션 이름 또는 실행 당시 정의·팀 이름으로 설명한다. 같은 세션의 실행 번호와 현지 시작 시각으로 구분하며, 현재 팀의 이름 변경으로 과거 실행 이름을 덮어쓰지 않는다. 이름 근거가 없으면 일반 실행 표기와 시각을 사용하고 정확한 실행 ID는 펼칠 수 있는 진단 정보에 보존한다. 비교 대상이 없거나 하나뿐이면 존재하지 않는 실행을 조회하지 않고 프로젝트 실행 목록에서 두 실행을 선택하는 경로를 안내한다.
명령 팔레트는 세션·팀 이름과 실행 번호를 사용하며 요청 본문을 검색 가능한 이름으로 승격하지 않는다. 비공개 본문 검색은 기존의 명시적 동의 경로를 따른다.

## 계약

기존 공유 RunSessionStore의 수명과 단일 구독을 유지한다. 현재 승인·Reins와 원래 요청으로 다시 실행하는 명령 및 receipt 경로는 기존 계약을 따른다. 보존한 대화 답변은 산출물 본문·실행 체크포인트와 구분하며 과거 산출물 재사용이나 메시지 시점 복원에 사용하지 않는다. 닫은 상세의 포커스는 열었던 컨트롤로 돌아간다. Run을 바꾸면 이전 실행·자료·결과 선택을 지운다.

실행 머리와 대화 입력 옆에는 Run 전체 명령의 receipt 가운데 아직 적용을 기다리는 것(접수·대기)과 확인이 필요한 것(거절·만료·오류·응답 미확인)만 보인다. 적용·대체·취소된 receipt는 그 결과가 조작한 자리에 이미 보이므로 남기지 않는다.

전체 취소 확인 대기는 같은 브라우저 탭의 새로고침 뒤에도 원래 Run에만 남는다. 확인 전에는 취소 명령이 전송되지 않았음을 표시하며, 실행 종료·명시 확인·계속 실행 선택으로 해제한다. 다른 Run으로 이동하거나 실행 조작 화면을 떠나면 확인 대기를 폐기하며, 원래 Run으로 돌아와도 되살리지 않는다. 다른 Run을 확인 없이 취소하지 않는다.

## 수용 시나리오

- 완료 Run과 진행 중 Run을 기본 주소로 열면 그래프가 선택되고 오른쪽은 닫혀 있다. 명시적 결과 주소는 중앙에서 해당 결과를 연다.
- 같은 도구를 여러 번 연이어 부른 실행은 활동에 `이름 ×N` 한 행으로 보이고, 실패한 호출이 있으면 그 묶음은 펼쳐져 있다.
- 넓은 화면에서도 선택 전에는 오른쪽이 닫혀 있다. 그래프 노드 클릭은 중앙 크기를 유지하는 빠른 확인 팝오버만 연다. 명시적으로 상세를 열면 중앙과 함께 보이고 좁은 화면에서는 중앙을 대신한다.
- 실행이 하나인 노드도 여러 실행이 있는 노드도 같은 빠른 확인 동작을 사용한다. 열려 있는 다른 실행 상세·승인·실행 정보는 팝오버를 열거나 닫아도 교체되지 않는다.
- 팝오버에서 선택한 실행의 상세·열람 가능한 결과·지시하기는 정확한 실행과 자료 버전을 연다. 결과와 지시는 오른쪽 상세를 거치지 않고 중앙에서 열린다. 지시 대상은 명시적 지시하기에서만 바뀐다.
- 실행이 많은 노드는 짧은 목록과 전체 실행 진입점을 제공한다. 실행 전 질문 대상은 실행 없음으로 표시하고 다른 실행을 대신 열지 않는다.
- 팝오버는 한 번에 하나만 보인다. Esc·닫기·바깥 클릭·그래프 이동으로 닫히며 그래프 위치와 확대율은 유지된다. 키보드로 닫으면 노드로, 상세를 열면 상세로 포커스가 이동한다. 닫힌 상세의 포커스는 팝오버 안의 사라진 버튼 대신 원래 노드로 돌아간다.
- 결과·자료를 열고 돌아오면 이전 보기와 선택이 유지된다. 늦은 결과·새 이벤트가 그 선택을 바꾸지 않는다.
- 지시 초안을 쓰고 다른 실행을 조회해도 명시적으로 지시 대상을 바꾸기 전에는 원래 대상으로 남는다.
- 실행 선택 후 다른 상세 탭을 열어도 Reins 초안은 남는다. 닫으면 활동/그래프의 진입점으로 포커스가 돌아간다.
- 이전 Run의 늦은 조회 응답은 새 Run의 정의·배치·선택을 덮어쓰지 않는다.
- 노드 이동·연결·삭제 입력은 정의를 바꾸지 않는다. 그래프 확대 후 파일 뷰어를 열어도 확대율은 유지된다.
- 현재 승인 대기, 대상 누락 안내, 관측된 근거·현재 결과와 원래 요청으로 다시 실행에 계속 접근할 수 있다. 메시지에서 과거 산출물이나 실행 시점을 복원하는 분기 동작은 제공하지 않는다. 좁은 승인 표시에서도 판단 대상 버전과 그 판단 기준은 확인할 수 있다.
- 대화의 결과 링크를 연 뒤 브라우저 뒤로가기는 그 대화로 돌아간다.

## 보안·성능·접근성

중앙 보기와 상세 탭은 디자인킷의 기본 Tabs를 그대로 사용한다. 상태에는 텍스트를 제공하고 키보드로 활동·상세·탭에 접근한다. 작성 D&D 및 Reins의 권한·취소 계약은 변경하지 않는다. 스트림 토큰이 그래프 전체나 이력 전체 계산을 유발하지 않는다. 기본 E2E는 기존 스모크 두 흐름을 유지한다.

## 실행 상태와 관측 관계

노드 요약은 task별 현재 시도를 집계한다. task의 유효한 activeExecutionId가 있으면 그것을, 없으면 가장 높은 attemptNo의 마지막 시도를 사용한다. 모델 생성·도구·정리 작업과 준비·대기·정지·취소를 구분한다. 현재 시도들의 상태가 다르면 상태별 개수를 함께 보여준다. 진행 중 상태를 우선하되 별도 task의 미해결 실패·취소를 숨기지 않는다. 성공한 재시도는 완료로 표시하고 이전 실패 수는 이력으로 남긴다.

Decision의 승인 상태를 전역 user_action 승인에서 추정하지 않는다. 귀속 근거가 없는 승인은 Run 영역에 표시한다. Output의 완료는 output.nodeId가 일치할 때만 표시한다. Loop는 관측된 반복 회차와 마지막 결과를 표시한다.

실행 관계도에는 실행 기록이 있는 agent 노드와 기록된 질문의 대상 agent 노드만 표시한다. 같은 역할을 쓰는 서로 다른 nodeId는 합치지 않으며, 같은 nodeId의 반복·재시도는 한 노드와 정확한 실행 목록으로 표시한다. 아직 실행되지 않은 질문 대상은 요청 대상으로 표시하고 실행 중으로 추정하지 않는다. 미사용 역할, 정의의 허용 간선·포트, Loop·Decision·Output 노드는 관계도에 나타나지 않는다. 관측이 없으면 빈 상태를 표시하고 정의로 대체하지 않는다.

관계는 기록된 부모→자식 위임, 질문·응답, 자료 작성자→읽은 실행, 자료 작성자→모델 입력에 포함한 실행만 연결한다. 위임은 task당 한 번 세며 재시도와 질문 응답 task를 중복 집계하지 않는다. 질문과 응답의 방향을 구분한다. 읽음과 입력 포함은 별도 사실로 유지하고 같은 관계·에이전트 쌍의 동일 자료 버전은 한 번 센다. 동일 에이전트의 서로 다른 실행 사이 관계도 보존한다. 자료 생성·작업 성공·시간 인접·정의 연결만으로 전달을 추정하지 않는다. 본문 수명과 무관하게 관측 metadata는 남으며 다른 Run이나 존재하지 않는 실행을 관계 끝점으로 사용하지 않는다.

노드는 디자인킷 AgentGraph의 작은 표식·이름·모델 표현을 따른다. 모델과 표식은 기록된 실행·프로필에서 얻고 확인할 수 없는 모델이나 수치를 만들어 넣지 않는다. 현재 상태와 실패·취소·대기 구분은 텍스트와 상태 표식으로 전달한다. 작업 중인 노드는 킷의 강조색 halo가 숨 쉬듯 커졌다 작아지고, 승인을 기다리는 노드는 같은 halo가 경고색으로 숨 쉰다. 끝났거나 멈춘 노드에는 halo를 두지 않으며, 동작 줄이기 설정에서는 halo가 움직이지 않고 남는다. 실제 최상위 실행을 중심 역할로 표현하되 모든 팀에 조정자가 있다고 가정하지 않는다. 관측된 관계를 기준으로 배치하고 새 토큰이나 상태 갱신만으로 노드 위치를 바꾸지 않는다. 새 참여자는 기존 노드의 위치와 사용자가 조정한 뷰포트를 유지하며 추가한다.

노드 클릭은 주변 관계를 강조하고 디자인킷 Popover로 빠른 확인을 연다. 팝오버는 배경을 가리는 막이나 별도 탐색 탭 없이 노드 근처에 배치한다. 에이전트 이름과 실행별 짧은 작업·산출물 이름, 실행 번호·회차·시도·상태를 보여 준다. 기본 목록은 진행 중인 실행을 우선하고 최근 실행을 포함해 최대 세 개다. 생략된 실행이 있을 때 전체 실행 진입점을 표시하며 전체 목록은 명시적으로 오른쪽에서 연다. 실행이 하나여도 자동으로 상세로 넘어가지 않는다. 실행별 상세, 현재 열람 가능한 자료, 지시 가능한 실행의 지시하기를 제공하며 실행을 자동으로 추정하지 않는다. 긴 로그·설정·승인 결정·본문·지시 입력은 팝오버에 넣지 않는다. 팝오버의 명시적 이동은 팝오버를 닫고 대상 영역을 연다. 일반 닫기는 선택 강조를 유지하고, 다른 노드를 클릭하면 새 노드를 강조한다. 새 이벤트는 열려 있는 팝오버의 노드나 기존 상세 대상을 바꾸지 않는다. Run 전환은 팝오버와 선택을 초기화한다. 팝오버는 키보드·터치로 열 수 있고 화면 경계 안에 배치되며 좁은 화면에서도 필요한 동작에 접근할 수 있다.

관계 종류·방향·횟수는 접근 가능한 이름과 선택된 관계의 짧은 표기로 구분한다. 진행 상태는 기록된 사실로만 판단한다. 위임은 받은 실행의 현재 시도가 끝나지 않았을 때, 자료 전달은 그 자료를 입력에 포함한 모델 호출이 끝나지 않았거나 자료를 읽은 실행이 끝나지 않았을 때, 질문은 답이 오기 전까지 진행 중이다. 응답은 진행 상태를 갖지 않는다. 받은 실행의 현재 시도가 실패한 위임은 실패로 표시한다. 종료된 Run에서는 어떤 관계도 진행 중의 색과 속도로 표시하지 않는다. 그래프 노드·간선·컨트롤은 앱의 밝은/어두운 테마를 따르며, 동작 줄이기 설정에서는 모션 없이 같은 상태를 전달한다.

관계도는 디자인킷 AgentGraph의 무대를 따른다. 간선은 노드 표식의 중심끼리 잇고 표식 아래에 그리며, 포트·연결 핸들·끝 화살촉을 두지 않는다. 중심 역할 노드에 닿는 관계는 중심 노드에서 세로로 나간 뒤 둥근 모서리로 꺾여 상대에게 가고, 그 밖의 관계는 직선이다. 같은 에이전트 쌍의 반대 방향 관계는 겹치지 않는 평행선으로 그린다. 간선은 항상 보내는 쪽에서 받는 쪽으로 흐르는 점선으로 방향을 보인다. 진행 중인 위임은 강조색, 진행 중인 자료 전달은 성공색, 미해결 질문은 경고색으로 킷의 속도로 흐른다. 끝난 관계는 회색의 성긴 점선으로 느리게 흐르며 조금 옅다. 실패한 위임은 흐르지 않는 파괴색 실선이다. 한 쌍의 관계 중 진행 중인 것이 있으면 그 상태를 우선하고(질문, 위임, 자료 전달 순), 없으면 실패, 그다음 끝남으로 표시한다. 동작 줄이기 설정에서는 모든 흐름이 멈추고, 각 간선 중간의 작은 꺾쇠로 방향을 보인다. 범례는 화면에 있는 상태만 나열하고, 끝난 실행에서 상태가 하나뿐이면 두지 않는다. 노드를 선택하면 그 노드의 관계마다 종류와 횟수를 짧게 표기하고, 표기는 방향을 함께 보인다. 무대는 끌어서 이동하고 휠과 확대·축소·맞춤 컨트롤로 확대율을 바꾸며, 노드를 끌어 옮기거나 연결할 수 없다.

- 같은 task가 실패 후 성공하면 완료와 이전 실패 이력이 보인다.
- 서로 다른 task의 성공과 실패는 실패를 숨기지 않고 상태별 수로 보인다.
- 취소는 실패로 표시하지 않는다. 모델·도구·대기 상태가 각각 구분된다.
- 도구 승인과 관련 없는 Decision은 전역 승인 때문에 대기·실패로 바뀌지 않는다.
- 질문 응답자는 질문 관계로 관측되고 위임으로 중복 집계하지 않는다. 존재하지 않는 노드로 간선을 만들지 않는다.
- 관계없는 projection revision과 streaming 변화는 그래프 전체를 다시 렌더하지 않는다.

## 현재 표시와 관측 시간

Run 화면은 항상 최신 관측 상태를 보여준다. 완료한 Run은 최종 상태와 생성·전달·검토·분기의 관계 정보를 읽을 수 있다. 과거 시점 슬라이더, 이전·다음 기록으로 화면을 재구성하는 모드와 최신 복귀 조작은 제공하지 않는다. 기존 주소의 `atSeq`는 현재 조회로 정규화한다. 이벤트를 선택하면 해당 기록의 상세만 열고 화면 전체의 시점을 바꾸지 않는다.

과거 산출물 본문·버전 비교·복원·과거 결과 재사용을 탐색하는 UI는 제공하지 않는다. 현재 본문 접근 자격은 API의 산출물 수명 계약을 따르며, 명시적으로 선택한 자료가 더 이상 열 수 없으면 다른 자료로 대체하지 않고 안내한다. 생성자·소비자·판단 근거·선택한 분기·후속 결과·시각의 관계 정보는 본문 없이 표시한다. 현재 실행의 승인과 Reins는 기존 명령 경로를 유지한다.

같은 세션에서 새 실행이 성공하면 화면에 남아 있는 완료 차례는 산출물 접근 메타데이터를 다시 확인한다. 다시 확인하는 동안 이전 접근 가능 여부로 결과 링크나 본문 읽기를 재개하지 않는다. 이 갱신은 현재 snapshot metadata만 읽고, 과거 본문·실행 이력을 다시 읽거나 완료 실행마다 영구 구독을 만들지 않는다. 이미 보존된 대화 답변·입력 초안·현재 명령 소유자는 유지하고, 갱신된 접근 자격에서 제외된 캐시는 비운다.

그래프·작업 흐름·관측 시간축·이벤트 목록은 같은 중앙 공간에서 전환한다. 실행 시간축은 디자인킷 AgentLanes로 agent 노드마다 한 행(이름과 모델)을 두고 실행 인스턴스를 별도 구간으로 그리며, 반복·재시도를 한 구간으로 합치지 않는다. 구간 이름은 그 실행이 만든 산출물 이름이고, 없으면 노드 이름이다. 회차와 두 번째 이후의 시도 번호를 덧붙이며, 구간에는 그 실행이 사용한 도구를 표시한다. 실행이 자식 실행을 기다린 시간(`waiting_children`)은 구간을 끊어 빈 틈으로 그려, 한 실행이 일한 부분만 블록으로 남는다. 끊긴 블록들은 여전히 한 실행이므로 함께 선택된다. 질문 답변이나 승인을 기다린 시간은 구간 안에 확인 필요 색으로 칠한다. 관측된 전달은 구간 사이의 점선으로 잇는다. 위임은 부모 실행에서 자식 실행이 시작한 시각으로 잇되, 부모가 그 자식을 기다리며 끊긴 틈이 있으면 그 틈이 시작하는 블록 끝에서 출발한다. 산출물 전달은 그 산출물을 만든 실행의 생성 시각에서 그것을 읽거나 모델 입력에 포함한 실행의 그 시각으로 잇는다. 같은 실행 쌍의 산출물 전달은 처음 관측된 한 번만 긋는다. 끝난 전달선은 시간축을 열 때 그려지며 나타나고, 받는 구간이 진행 중인 전달선은 흐르는 점선으로 보인다. 진행 중인 Run에서 끝나지 않은 구간은 현재 시각까지 자라고 그 끝에 '지금'을 표시한다. 종료된 Run은 마지막 관측 시각까지 표시한다. 질문·승인을 기다리는 구간은 확인 필요로 보드 아래에 모으고, 그 항목을 고르면 해당 실행을 선택한다. 보드 위에는 설명 문구를 두지 않는다. 실행을 고르면 보드 아래에 그 실행의 모델 호출과 도구 호출 중 소요 시간이 관측된 것을 기록 순서대로, 모델 요청 순번이나 도구 이름과 소요 시간·길이 막대로 보이며 호출 식별자를 나열하지 않는다. 시간축은 에이전트별(위 AgentLanes)과 작업별을 전환해 본다. 작업별 시간축은 디자인킷 PlanVsActual 구성으로 Run의 작업(작업 보드의 작업)마다 한 행을 두고, 첫 시도가 배정된 시각부터 완료된 시각까지를 실제 구간으로 그린다. 완료 기록 없이 끝난 작업은 마지막 시도의 종료 시각까지, 진행 중인 작업은 진행 중인 Run에서는 현재 시각까지, 종료된 Run에서는 마지막 기록까지 그린다. 아직 배정되지 않은 작업은 구간 없이 대기로 표시한다. 시작한 작업 행을 고르면 그 작업의 마지막 시도 실행을 선택해 에이전트별 시간축과 같은 실행 상세를 연다. 선택한 실행이 속한 작업의 구간은 선택 외곽선으로 표시하고, 아직 시작하지 않은 작업은 고를 수 없다. 작업별 보드 위에도 설명 문구를 두지 않는다. 행 이름은 작업의 노드 이름이고, 제출한 산출물이 있으면 그 이름을 덧붙인다. 예정 시간은 기록되지 않으므로 예정 막대·예상 종료·예정 대비 판정·범례를 표시하지 않고, 비용은 사용량에서만 보인다. 모델 호출 시간은 연결된 dispatch 관측과 완료가 모두 있을 때, 도구 시간은 시작·완료가 모두 있을 때만 표시한다.

이벤트 보기는 기록된 이벤트를 순번 순으로 보이는 원본 목록이다. 목록은 중앙의 남은 높이를 채우고 보이는 행만 그린다. 행은 순번, Run 시작 기준 경과 시각, 주체, 기록 문장, 이벤트 종류를 보인다. 주체는 사용자·에이전트·런타임마다 다른 아이콘을 이름 앞에 둔다. 가장 많은 런타임은 흐린 색으로, 사용자와 에이전트는 더 드러나게 칠한다. 목록 위에는 각 열의 이름을 보이는 열 머리를 둔다. 주체·종류·실행으로 거르며, 실행은 식별자 대신 에이전트 이름과 회차·시도로 고른다. 이벤트를 고르면 목록 옆(좁으면 아래)에 행에 없는 것만 보인다. 기록 문장과 정확한 기록 시각, 그 이벤트를 일으킨 원인 이벤트(`causedByEventIds`), 속한 실행과 그 실행 상세를 여는 동작, 기록된 payload 전체를 디자인킷의 JSON 표시로 보이며, 행에 이미 있는 순번·종류·주체는 반복하지 않는다. 원인 이벤트를 고르면 필터에 가려져 있어도 필터를 풀고 그 이벤트를 선택해 목록에서 보이게 한다. 원인이나 실행이 없는 이벤트는 해당 칸을 두지 않는다. 고르기 전에는 빈 상세 칸을 두지 않고 목록이 전체 폭을 쓴다. 새 이벤트는 필터·선택·스크롤을 바꾸지 않는다.

- 과거 시점 주소로 열어도 현재 승인·Reins·결과 접근을 막지 않는다.
- 새 라이브 이벤트는 작업 흐름과 현재 상태에 반영되며 진행 텍스트 변화만으로 관계 기록을 다시 계산하지 않는다.
- 기록되지 않은 전달·판단·분기·후속 관계를 시간 순서만으로 추정하지 않는다.
- DecisionTree를 읽거나 숫자키를 눌러도 새로운 판단·승인 명령을 보내지 않는다.


## 관계·판단 기록

실행 흐름은 관측된 작성·읽기·모델 입력·질문/응답·검토·위임·분기·최종 출력 관계만 연결한다. 산출물 본문이나 과거 화면을 복원하지 않고 식별자·이름·작성 실행·소비 실행·판단 근거 metadata로 표시한다. 작성자에서 소비자로 이어지는 자료 경로는 전송 의도와 구별하며, 모델 입력 포함을 지시의 이해·준수 증거로 표시하지 않는다. 시각이 가깝거나 정의 간선이 있다는 이유로 관측 간선을 만들지 않는다.

실제 Decision 분기 선택은 Coordinator가 `workflow.branch_selected`로 기록한다. 기록은 Decision 노드, 반복 회차, 선택한 포트와 다음 노드/포트, 결정에 사용한 제어 revision, 근거 자료·승인·검토·검사·작업 참조와 실제 실행 시도를 담는다. 근거는 결정 경로에서 직접 얻고, 다른 실행의 최근 승인이나 검토를 대신 연결하지 않는다. 취소되거나 종료된 scope의 늦은 결정 응답은 분기 기록과 다음 실행을 만들지 않는다. 추론 노력 관측인 `decision.*`와 작업 흐름 분기는 서로 다른 기록이다.

[감독](advisor.md)의 조언도 관계·판단 기록이다. 접수된 조언(`advice.admitted`)은 관계도에서 감독 실행 단위에서 대상 실행 단위로 가는 관계(조언과 그 수)다. 심각도·전달 방식·전달 상태는 이벤트 기록의 문장이 말하고, 조언의 글은 대상 실행 단위의 기록 안 그 조언의 줄에서 읽는다(전달하지 못해 보존된 조언도 그 실행 단위의 기록 끝에 있다). 버려진 조언(`advice.suppressed`)은 감독 실행 단위의 기록에 심각도와 버린 이유로만 보이고 대상과의 관계를 만들지 않는다. 조언이 전달됐다는 것을 대상이 따랐다는 증거로 표시하지 않는다. 관계도에서 감독은 조언을 한 번이라도 낸 뒤에만 노드로 나타난다.

기존 기록에 분기 관측이 없으면 미기록으로 표시한다. 사용자에게 보이는 관계와 근거는 산출물의 과거 본문 보관을 요구하지 않는다. 실행 시도와 반복은 식별자를 유지하고, 동일 기록의 중복 전달은 중복 관계를 만들지 않는다.
