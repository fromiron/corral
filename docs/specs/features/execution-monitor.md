# 기능 명세: 실행 기록 관찰

- 상태: implemented
- 비목표: 실행 엔진 교체, 그래프 편집, 실행 당시 화면 좌표의 복원.

## 사용자 관측 동작

세션의 실행 기록과 독립 Run 화면은 같은 Run 관찰 화면을 사용한다. 기본 진입은 완료 여부와 관계없이 디자인킷 AgentRun 구성의 한 열 **실행 요약**이다. 위에서부터 요약 카드, 보기 탭, 활동, 결과를 둔다. 요약 카드는 계획 도구의 작업 계획이 있으면 그 항목과 완료 수를, 없으면 agent 노드마다 현재 실행의 상태와 관측된 경과 시간을 한 줄씩 보인다. 활동은 실행마다 노드 이름·시도·회차·상태를 머리로 두고 그 실행의 도구 호출을 디자인킷 도구 호출 묶음의 평평한 행으로 보이며, 머리를 누르면 그 실행을 선택한다. 결과는 현재 결과 산출물을 카드로 보인다. Run 머리글의 실행·결과 탭(디자인킷 Tabs)이 실행 요약과 결과 화면을 바꾼다. 결과 탭과 명시적 결과 링크가 결과 화면을 열며, 완료 이벤트가 화면을 전환하지 않는다.

보기 탭(디자인킷 TabsSubtle)은 활동·작업 흐름·시간축·이벤트·그래프를 바꾸며 기본은 활동이다. 작업 흐름은 생성한 에이전트, 산출물, 자료를 읽거나 전달받은 실행, 검토·분기와 후속 결과를 연결해 보여주고, 시간은 각 관계의 보조 정보다. 관계 카드로 보인 산출물은 그 아래 생성된 산출물 목록에 다시 나열하지 않는다.

Run 선택·상태·전체 제어는 상단 한 곳에 둔다. 작업 흐름은 디자인킷 AgentHandoff의 연결과 자료 카드를 사용하고, 각 전달 쌍을 독립적으로 구성해 병렬·역방향 관계를 임의의 직렬 흐름으로 만들지 않는다. 생성·읽음·입력 포함·질문 전달·검토를 기록된 관계 이름으로 구분한다. 결정 근거는 디자인킷 DecisionTree의 질문·선택지 구성을 읽기 전용으로 사용하며, 기록된 선택만 강조한다. 추천이나 첫 선택지를 실제 분기로 대신하지 않고 기록이 없으면 알 수 없음을 표시한다. 활동·작업 흐름·시간축에서 실행을, 그래프에서 노드를 선택한다. 오른쪽 패널은 맨 위에 확인 필요(질문·승인, 없으면 비어 있다는 안내)를, 그 아래 선택한 실행의 상세를 둔다. 상세는 개요(입력·출력·근거·분기), 호출, 사용량, Reins로 나누고 승인은 상세 탭 밖에서 접근한다. 패널을 접으면 확인 필요는 한 열의 맨 위로 옮겨 계속 보인다. Reins는 명시적으로 선택한 실행만 대상으로 한다. 없는 대상은 안내하고 다른 대상으로 대체하지 않는다.

질문·답변의 첨부는 자료 이름과 생성자 관계를 표시하며 본문 열람 가능 여부와 구분한다. 판단 근거는 작업의 역할·제출 자료, 승인의 대상·현재 상태, 정확히 참조한 검사의 이름·판정·종료 코드·시간 초과 여부를 표시한다. 검사는 같은 Run 소유의 일치하는 참조만 연결하고, 상세를 조회할 수 없으면 참조를 보존한 채 확인 불가로 표시한다. 현재 상태를 판단 당시 상태로 표현하지 않는다. 검사의 원문 출력은 이 관계 화면에 복사하지 않는다.

실행 선택은 활동 목록이 맡으며 별도의 실행 트리 열을 두지 않는다. 활동의 실행은 시작 순서를 따르고, Loop는 회차를 머리에 표시하며 재시도는 각각의 시도로 식별한다. 실행 머리는 노드 이름, 모델, 상태와 관측된 기록으로 계산한 경과 시간을 보이고, 대기 대상·오류는 선택한 실행의 상세에서 보인다. 비용 추정은 사용량에서만 보인다.

1280px 이상에서는 한 열과 오른쪽 패널(360px)을 함께, 그 미만에서는 한 열만 표시하고 패널을 열면 같은 자리를 대신한다. 기준은 Run 컨테이너다. 스트리밍·영역 전환·크기 변경은 선택, 스크롤, 그래프 위치와 확대율, Reins 초안을 초기화하지 않는다. 그래프 맞춤은 최초 표시와 사용자의 맞춤 요청에만 수행한다.

호출은 선택한 실행의 대화로 보인다. 연속된 도구 호출은 디자인킷의 도구 호출 묶음으로 접고, 각 호출은 이름·상태·인자·결과 자료 링크와 시작·종료가 모두 관측된 경우의 소요 시간을 보인다. 개요의 Run 전체 작업·계획·질문 목록은 필요할 때 펼친다. 시간축의 선택 버튼과 관측 구간은 별도 영역으로 배치한다.

수명이 끝난 모델 응답은 호출·지시 전달 관계를 유지하고 본문 미보관을 명시한다. 이를 모델이 빈 응답을 생성했거나 아직 생성 중인 상태로 표시하지 않으며, 캐시의 과거 텍스트로 대신하지 않는다. 진행 중인 Run의 현재 응답은 기존 스트리밍과 완료 텍스트 표시를 유지한다.

## 반복 작업 표시

Loop는 실행 횟수만큼 복제한 노드 열이 아니라 하나의 반복 구조로 표시한다. 작업 흐름과 실행 트리는 정의된 Loop마다 이름, 관측된 회차 수, 현재 상태·최근 관측 결과와 유효한 반복 상한을 한 그룹에 표시한다. 반복 계속·종료는 기록된 분기·outcome으로 설명하고, 기록 없는 선택을 추정하지 않는다. 정의 그래프의 Loop·되돌림·종료 연결은 유지하며 회차마다 그래프 노드를 만들지 않는다.

기본 펼침은 각 Loop의 최신 관측 회차다. 회차 선택은 그 Loop의 실행·산출물·관계·결정 metadata만 필터링한다. 현재 Run 상태·승인·Reins 대상·본문 접근 자격을 과거로 되돌리지 않는다. 명시적으로 선택한 회차는 새 회차가 시작해도 유지하고, 최신 추적을 선택하면 이후 회차를 따라간다. 존재하지 않는 명시적 회차는 다른 회차로 대체하지 않고 선택 없음으로 안내한다. 실행 직접 링크나 실행 선택은 해당 실행이 속한 회차를 보이게 하며, 다른 회차를 살펴본다는 이유로 명령 대상을 바꾸지 않는다.

선택한 회차가 실제로 사용한 이전 회차의 carry input은 정확한 자료·작성자·관계 metadata로 연결할 수 있다. 그 이전 회차 전체를 재귀적으로 펼치거나 과거 본문을 복구하지 않는다. 회차가 늘어도 기본 화면의 Loop·에이전트·결정 카드 수는 누적 회차 수만큼 증가하지 않는다. 회차 선택 목록과 명시적으로 연 상세만 전체 기록에 접근할 수 있다. 이 표시 계약은 실행 엔진의 반복·깊이·예산 상한을 바꾸지 않는다.

- 많은 회차를 가진 Loop도 기본 화면에는 Loop 그룹 하나와 최신 회차의 실행·관계·결정이 표시된다.
- 이전 회차를 선택하면 해당 회차의 정확한 실행·자료 관계를 확인할 수 있지만 수명이 끝난 본문은 열리지 않는다.
- 새로운 회차가 도착하면 최신 추적 중인 그룹만 바뀌며 명시적으로 고른 회차와 Reins 대상은 유지된다.
- 두 Loop는 서로의 회차를 바꾸지 않는다. 취소·반복 상한 도달·승인 대기는 실제 현재 상태와 결과로 표시된다.

실행 탐색과 비교의 이름은 세션의 기록된 요청, 세션 이름 또는 실행 당시 정의·팀 이름으로 설명한다. 같은 세션의 실행 번호와 현지 시작 시각으로 구분하며, 현재 팀의 이름 변경으로 과거 실행 이름을 덮어쓰지 않는다. 이름 근거가 없으면 일반 실행 표기와 시각을 사용하고 정확한 실행 ID는 펼칠 수 있는 진단 정보에 보존한다. 비교 대상이 없거나 하나뿐이면 존재하지 않는 실행을 조회하지 않고 프로젝트 실행 목록에서 두 실행을 선택하는 경로를 안내한다.
명령 팔레트는 세션·팀 이름과 실행 번호를 사용하며 요청 본문을 검색 가능한 이름으로 승격하지 않는다. 비공개 본문 검색은 기존의 명시적 동의 경로를 따른다.

## 계약

기존 공유 RunSessionStore의 수명과 단일 구독을 유지한다. 현재 승인·Reins와 원래 요청으로 다시 실행하는 명령 및 receipt 경로는 기존 계약을 따른다. 보존한 대화 답변은 산출물 본문·실행 체크포인트와 구분하며 과거 산출물 재사용이나 메시지 시점 복원에 사용하지 않는다. 닫은 상세의 포커스는 열었던 컨트롤로 돌아간다. Run을 바꾸면 이전 실행·자료·결과 선택을 지운다.

전체 취소 확인 대기는 같은 브라우저 탭의 새로고침 뒤에도 원래 Run에만 남는다. 확인 전에는 취소 명령이 전송되지 않았음을 표시하며, 실행 종료·명시 확인·계속 실행 선택으로 해제한다. 다른 Run으로 이동하거나 실행 조작 화면을 떠나면 확인 대기를 폐기하며, 원래 Run으로 돌아와도 되살리지 않는다. 다른 Run을 확인 없이 취소하지 않는다.

## 수용 시나리오

- 완료 Run을 기본 주소로 열면 실행 요약(요약 카드·활동·결과)이 보인다. 명시적 결과 주소는 결과를 보인다.
- 실행 선택 후 다른 상세 탭을 열어도 Reins 초안은 남는다. 닫으면 활동/그래프의 진입점으로 포커스가 돌아간다.
- 이전 Run의 늦은 조회 응답은 새 Run의 정의·배치·선택을 덮어쓰지 않는다.
- 노드 이동·연결·삭제 입력은 정의를 바꾸지 않는다. 그래프 확대 후 파일 뷰어를 열어도 확대율은 유지된다.
- 현재 승인 대기, 대상 누락 안내, 관측된 근거·현재 결과와 원래 요청으로 다시 실행에 계속 접근할 수 있다. 메시지에서 과거 산출물이나 실행 시점을 복원하는 분기 동작은 제공하지 않는다. 좁은 승인 표시에서도 판단 대상 버전과 그 판단 기준은 확인할 수 있다.
- 대화의 결과 링크를 연 뒤 브라우저 뒤로가기는 그 대화로 돌아간다.

## 보안·성능·접근성

상세 탭은 디자인킷의 기본 Tabs를, 보기 탭은 TabsSubtle을 그대로 사용한다. 상태에는 텍스트를 제공하고 키보드로 활동·상세·탭에 접근한다. 작성 D&D 및 Reins의 권한·취소 계약은 변경하지 않는다. 스트림 토큰이 그래프 전체나 이력 전체 계산을 유발하지 않는다. 기본 E2E는 기존 스모크 두 흐름을 유지한다.

## 실행 상태와 관측 관계

노드 요약은 task별 현재 시도를 집계한다. task의 유효한 activeExecutionId가 있으면 그것을, 없으면 가장 높은 attemptNo의 마지막 시도를 사용한다. 모델 생성·도구·정리 작업과 준비·대기·정지·취소를 구분한다. 현재 시도들의 상태가 다르면 상태별 개수를 함께 보여준다. 진행 중 상태를 우선하되 별도 task의 미해결 실패·취소를 숨기지 않는다. 성공한 재시도는 완료로 표시하고 이전 실패 수는 이력으로 남긴다.

Decision의 승인 상태를 전역 user_action 승인에서 추정하지 않는다. 귀속 근거가 없는 승인은 Run 영역에 표시한다. Output의 완료는 output.nodeId가 일치할 때만 표시한다. Loop는 관측된 반복 회차와 마지막 결과를 표시한다.

정적 정의 간선과 관측된 위임·질문을 구분한다. 질문 응답 task의 자식을 위임으로 중복 집계하지 않는다. 관측 간선은 실제 존재하는 agent 노드 사이의 실행·질문 기록으로만 만들고 대상 invocation에 맞는 핸들을 사용한다. 부모에게 보내는 질문은 scheduled 부모의 in 핸들을 사용한다. 관측 없는 간선을 실행 중이라고 강조하지 않는다. 관측된 진행 중 실행·간선은 디자인킷의 모션으로 강조하고, 동작 줄이기 설정에서는 같은 상태를 정지된 표시와 텍스트로 전달한다.

같은 관계의 정적 간선과 관측 간선은 라벨을 중복 표시하지 않는다. 그래프 노드·간선·컨트롤은 앱에서 선택한 밝은/어두운 테마를 따른다. 시작 준비·취소 정리·종료 상태를 현재 Run 상태와 구분하며, 종료된 Run의 미정산 모델 호출은 진행 중 요청으로 단정하지 않고 종료 미확인 요청으로 표시한다.

관측 관계의 횟수·진행 수 캡션은 노드 포트 이름과 다른 간선 라벨을 가리지 않는다. 같은 source 핸들에 관측 관계가 있으면 정적 허용 간선은 선으로 남기고 중복 종류 라벨은 생략한다. 밝은/어두운 테마에서 캡션과 포트의 읽기 간격을 유지하며, 포트 이름의 불투명한 배경이 뒤를 지나는 간선을 가려 글자를 읽을 수 있게 한다.

- 같은 task가 실패 후 성공하면 완료와 이전 실패 이력이 보인다.
- 서로 다른 task의 성공과 실패는 실패를 숨기지 않고 상태별 수로 보인다.
- 취소는 실패로 표시하지 않는다. 모델·도구·대기 상태가 각각 구분된다.
- 도구 승인과 관련 없는 Decision은 전역 승인 때문에 대기·실패로 바뀌지 않는다.
- 질문 응답자는 질문으로 한 번만 관측되고, 존재하지 않는 노드나 핸들로 간선을 만들지 않는다.
- 관계없는 projection revision과 streaming 변화는 그래프 전체를 다시 렌더하지 않는다.

## 현재 표시와 관측 시간

Run 화면은 항상 최신 관측 상태를 보여준다. 완료한 Run은 최종 상태와 생성·전달·검토·분기의 관계 정보를 읽을 수 있다. 과거 시점 슬라이더, 이전·다음 기록으로 화면을 재구성하는 모드와 최신 복귀 조작은 제공하지 않는다. 기존 주소의 `atSeq`는 현재 조회로 정규화한다. 이벤트를 선택하면 해당 기록의 상세만 열고 화면 전체의 시점을 바꾸지 않는다.

과거 산출물 본문·버전 비교·복원·과거 결과 재사용을 탐색하는 UI는 제공하지 않는다. 현재 본문 접근 자격은 API의 산출물 수명 계약을 따르며, 명시적으로 선택한 자료가 더 이상 열 수 없으면 다른 자료로 대체하지 않고 안내한다. 생성자·소비자·판단 근거·선택한 분기·후속 결과·시각의 관계 정보는 본문 없이 표시한다. 현재 실행의 승인과 Reins는 기존 명령 경로를 유지한다.

같은 세션에서 새 실행이 성공하면 화면에 남아 있는 완료 차례는 산출물 접근 메타데이터를 다시 확인한다. 다시 확인하는 동안 이전 접근 가능 여부로 결과 링크나 본문 읽기를 재개하지 않는다. 이 갱신은 현재 snapshot metadata만 읽고, 과거 본문·실행 이력을 다시 읽거나 완료 실행마다 영구 구독을 만들지 않는다. 이미 보존된 대화 답변·입력 초안·현재 명령 소유자는 유지하고, 갱신된 접근 자격에서 제외된 캐시는 비운다.

작업 흐름·그래프·관측 시간축·이벤트 목록은 보조 보기다. 실행 시간축은 디자인킷 AgentLanes로 agent 노드마다 한 행(이름과 모델)을 두고 실행 인스턴스를 별도 구간으로 그리며, 반복·재시도를 한 구간으로 합치지 않는다. 구간 이름은 그 실행이 만든 산출물 이름이고, 없으면 노드 이름이다. 회차와 두 번째 이후의 시도 번호를 덧붙이며, 구간에는 그 실행이 사용한 도구를 표시한다. 관측된 전달은 구간 사이의 점선으로 잇는다. 위임은 부모 실행에서 자식 실행이 시작한 시각으로, 산출물 전달은 그 산출물을 만든 실행의 생성 시각에서 그것을 읽거나 모델 입력에 포함한 실행의 그 시각으로 잇는다. 같은 실행 쌍의 산출물 전달은 처음 관측된 한 번만 긋는다. 끝난 전달선은 시간축을 열 때 그려지며 나타나고, 받는 구간이 진행 중인 전달선은 흐르는 점선으로 보인다. 진행 중인 Run에서 끝나지 않은 구간은 현재 시각까지 자라고 그 끝에 '지금'을 표시한다. 종료된 Run은 마지막 관측 시각까지 표시한다. 질문·승인을 기다리는 구간은 확인 필요로 보드 아래에 모으고, 그 항목을 고르면 해당 실행을 선택한다. 종료된 Run은 '다시 재생'으로 같은 시간 범위 위에 기록된 구간을 시작부터 순서대로 그릴 수 있고, 재생은 기록을 바꾸지 않는다. 동작 줄이기 설정에서는 재생을 제공하지 않는다. 시간축은 에이전트별(위 AgentLanes)과 작업별을 전환해 본다. 작업별 시간축은 디자인킷 PlanVsActual 구성으로 Run의 작업(작업 보드의 작업)마다 한 행을 두고, 첫 시도가 배정된 시각부터 완료된 시각까지를 실제 구간으로 그린다. 완료 기록 없이 끝난 작업은 마지막 시도의 종료 시각까지, 진행 중인 작업은 진행 중인 Run에서는 현재 시각까지, 종료된 Run에서는 마지막 기록까지 그린다. 아직 배정되지 않은 작업은 구간 없이 대기로 표시한다. 행 이름은 작업의 노드 이름이고, 제출한 산출물이 있으면 그 이름을 덧붙인다. 예정 시간은 기록되지 않으므로 예정 막대·예상 종료·예정 대비 판정·범례를 표시하지 않고, 비용은 사용량에서만 보인다. 모델 호출 시간은 연결된 dispatch 관측과 완료가 모두 있을 때, 도구 시간은 시작·완료가 모두 있을 때만 표시한다.

- 과거 시점 주소로 열어도 현재 승인·Reins·결과 접근을 막지 않는다.
- 새 라이브 이벤트는 작업 흐름과 현재 상태에 반영되며 진행 텍스트 변화만으로 관계 기록을 다시 계산하지 않는다.
- 기록되지 않은 전달·판단·분기·후속 관계를 시간 순서만으로 추정하지 않는다.
- DecisionTree를 읽거나 숫자키를 눌러도 새로운 판단·승인 명령을 보내지 않는다.


## 관계·판단 기록

실행 흐름은 관측된 작성·읽기·모델 입력·질문/응답·검토·위임·분기·최종 출력 관계만 연결한다. 산출물 본문이나 과거 화면을 복원하지 않고 식별자·이름·작성 실행·소비 실행·판단 근거 metadata로 표시한다. 작성자에서 소비자로 이어지는 자료 경로는 전송 의도와 구별하며, 모델 입력 포함을 지시의 이해·준수 증거로 표시하지 않는다. 시각이 가깝거나 정의 간선이 있다는 이유로 관측 간선을 만들지 않는다.

실제 Decision 분기 선택은 Coordinator가 `workflow.branch_selected`로 기록한다. 기록은 Decision 노드, 반복 회차, 선택한 포트와 다음 노드/포트, 결정에 사용한 제어 revision, 근거 자료·승인·검토·검사·작업 참조와 실제 실행 시도를 담는다. 근거는 결정 경로에서 직접 얻고, 다른 실행의 최근 승인이나 검토를 대신 연결하지 않는다. 취소되거나 종료된 scope의 늦은 결정 응답은 분기 기록과 다음 실행을 만들지 않는다. 추론 노력 관측인 `decision.*`와 작업 흐름 분기는 서로 다른 기록이다.

기존 기록에 분기 관측이 없으면 미기록으로 표시한다. 사용자에게 보이는 관계와 근거는 산출물의 과거 본문 보관을 요구하지 않는다. 실행 시도와 반복은 식별자를 유지하고, 동일 기록의 중복 전달은 중복 관계를 만들지 않는다.
