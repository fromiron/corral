# 기능 명세: 실행 기록 관찰

- 상태: implemented
- 비목표: 실행 엔진 교체, 그래프 편집, 실행 당시 화면 좌표의 복원.

## 사용자 관측 동작

세션의 실행 기록과 독립 Run 화면은 같은 Run 관찰 화면을 사용한다. 기본 진입은 완료 여부와 관계없이 그래프다. 명시적 결과 링크는 결과 화면을 열며, 완료 이벤트가 화면을 전환하지 않는다.

Run 선택·상태·전체 제어는 상단 한 곳에 둔다. 트리에서 실행을, 그래프에서 노드를 선택한다. 상세는 개요(입력·출력·근거·분기), 호출, 사용량, Reins로 나누고 승인은 탭 밖에서 접근한다. Reins는 명시적으로 선택한 실행만 대상으로 한다. 없는 대상은 안내하고 다른 대상으로 대체하지 않는다.

1280px 이상에서는 트리·중앙·상세, 768–1279px에서는 중앙과 트리 또는 상세, 768px 미만에서는 한 영역을 표시한다. 기준은 Run 컨테이너다. 스트리밍·영역 전환·크기 변경은 선택, 스크롤, 그래프 위치와 확대율, Reins 초안을 초기화하지 않는다. 그래프 맞춤은 최초 표시와 사용자의 맞춤 요청에만 수행한다.

## 계약

기존 공유 RunSessionStore의 수명과 단일 구독을 유지한다. 결과·근거·분기·승인·복구·Reins의 명령 및 receipt 경로는 기존 계약을 따른다. 닫은 상세의 포커스는 열었던 컨트롤로 돌아간다. Run을 바꾸면 이전 실행·자료·결과 선택을 지운다.

## 수용 시나리오

- 완료 Run을 기본 주소로 열면 그래프가 보인다. 명시적 결과 주소는 결과를 보인다.
- 실행 선택 후 다른 상세 탭을 열어도 Reins 초안은 남는다. 닫으면 트리/그래프의 진입점으로 포커스가 돌아간다.
- 이전 Run의 늦은 조회 응답은 새 Run의 정의·배치·선택을 덮어쓰지 않는다.
- 노드 이동·연결·삭제 입력은 정의를 바꾸지 않는다. 그래프 확대 후 파일 뷰어를 열어도 확대율은 유지된다.
- 승인 대기, 대상 누락, 근거·결과와 메시지 분기에 계속 접근할 수 있다.

## 보안·성능·접근성

디자인킷의 기본 Tabs를 그대로 사용한다. 상태에는 텍스트를 제공하고 키보드로 트리·상세·탭에 접근한다. 작성 D&D 및 Reins의 권한·취소 계약은 변경하지 않는다. 스트림 토큰이 그래프 전체나 이력 전체 계산을 유발하지 않는다. 기본 E2E는 기존 스모크 두 흐름을 유지한다.

## 실행 상태와 관측 관계

노드 요약은 task별 현재 시도를 집계한다. task의 유효한 activeExecutionId가 있으면 그것을, 없으면 가장 높은 attemptNo의 마지막 시도를 사용한다. 모델 생성·도구·정리 작업과 준비·대기·정지·취소를 구분한다. 현재 시도들의 상태가 다르면 상태별 개수를 함께 보여준다. 진행 중 상태를 우선하되 별도 task의 미해결 실패·취소를 숨기지 않는다. 성공한 재시도는 완료로 표시하고 이전 실패 수는 이력으로 남긴다.

Decision의 승인 상태를 전역 user_action 승인에서 추정하지 않는다. 귀속 근거가 없는 승인은 Run 영역에 표시한다. Output의 완료는 output.nodeId가 일치할 때만 표시한다. Loop는 관측된 반복 회차와 마지막 결과를 표시한다.

정적 정의 간선과 관측된 위임·질문을 구분한다. 질문 응답 task의 자식을 위임으로 중복 집계하지 않는다. 관측 간선은 실제 존재하는 agent 노드 사이의 실행·질문 기록으로만 만들고 대상 invocation에 맞는 핸들을 사용한다. 부모에게 보내는 질문은 scheduled 부모의 in 핸들을 사용한다. 관측 없는 간선을 실행 중이라고 강조하지 않으며 모든 강조는 정적 표시다.

- 같은 task가 실패 후 성공하면 완료와 이전 실패 이력이 보인다.
- 서로 다른 task의 성공과 실패는 실패를 숨기지 않고 상태별 수로 보인다.
- 취소는 실패로 표시하지 않는다. 모델·도구·대기 상태가 각각 구분된다.
- 도구 승인과 관련 없는 Decision은 전역 승인 때문에 대기·실패로 바뀌지 않는다.
- 질문 응답자는 질문으로 한 번만 관측되고, 존재하지 않는 노드나 핸들로 간선을 만들지 않는다.
- 관계없는 projection revision과 streaming 변화는 그래프 전체를 다시 렌더하지 않는다.
