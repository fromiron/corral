# 기능 명세: 모델 연결과 자동 모델 목록

- 상태: accepted
- 비목표: 모델 즐겨찾기·숨기기, 공급자별 요금제 조회, Anthropic 구독 로그인, 직접 추가한 엔드포인트의 OpenAI 호환 외 프로토콜, 연결만으로 팀의 역할 모델을 바꾸는 것.

## 사용자 관측 동작

### 연결

설정 → 모델 → **연결**은 지금 연결된 공급자를 보여 주고, **연결 추가**로 Pi가 지원하는 모든 공급자와 직접 추가한 엔드포인트를 연결한다. 프로필이 그 공급자를 쓰고 있지 않아도 연결할 수 있다.

- 연결 방법은 공급자가 지원하는 것만 보인다: 구독 로그인(공급자 자체 로그인 화면), API 키. Anthropic은 API 키만이다.
- 환경 변수에 키가 있는 공급자와 Codex CLI 로그인은 연결된 것으로 보인다. 화면에서 지울 수 없는 연결은 그 출처를 보인다.
- 연결된 공급자의 줄은 방법, 쓸 수 있는 모델 수, 만료(구독)와 연결 해제를 보인다.
- 연결 해제는 그 공급자의 자격 증명만 지운다. 프로필과 엔드포인트 설정은 그대로다.

### 연결하면 바로 쓰는 모델

연결된 공급자의 모델은 프로필을 만들지 않아도 모델을 고르는 모든 자리(입력창 모델 선택기, 팀 편집기의 역할 모델, 회의 참가자, 기본값)에 나온다. 설정 파일은 바뀌지 않는다.

- 목록은 Pi가 그 자격 증명으로 쓸 수 있다고 답한 대화 모델이다. 구독 로그인은 그 구독이 부를 수 있는 모델만 나온다.
- 이름 있는 프로필(`model-a` 등)은 그대로 있고 목록의 맨 앞 묶음이다. 같은 공급자·모델을 가리키는 프로필이 있으면 그 모델은 프로필로만 한 번 나온다.
- 모델 선택기는 검색 필드와 공급자별 묶음을 가진다. 검색은 모델 이름, 모델 ID, 공급자 이름을 본다. 열면 현재 선택이 보이는 위치에 있다.
- 연결을 해제하거나 공급자가 모델을 내리면 그 모델은 목록에서 빠진다. 이미 그 모델을 고른 세션·역할은 다른 모델로 바뀌지 않고, 쓸 수 없는 현재 값으로 보인다([모델·추론·리소스](../models-and-resources.md)).

### 추론 수준

Pi 내장 공급자의 모델은 Pi의 모델 정보가 주는 추론 수준 목록을 그대로 쓴다. 수준을 고르면 Pi가 그 공급자의 형식으로 바꿔 보낸다. 공급자 기본값은 추론 설정을 보내지 않는다.

### 직접 추가한 엔드포인트

OpenAI 호환 엔드포인트는 주소와 인증 방법만으로 추가할 수 있다. 모델을 적지 않아도 된다.

- 엔드포인트를 저장하거나 그 키를 저장하면 서버가 그 주소의 `/models`에서 모델 목록을 가져온다. 연결의 **모델 새로 고침**으로 다시 가져온다.
- 가져온 모델의 컨텍스트 창, 출력 한도, 이미지 입력, 추론 지원은 아래 순서로 정한다. 화면은 값마다 출처를 보인다.
  1. 설정에 적은 값
  2. 엔드포인트의 `/models` 응답이 준 값
  3. models.dev 카탈로그에서 모델 ID가 일치하는 항목
  4. 엔드포인트 기본값(컨텍스트 32,000, 출력 4,096, 추론·이미지 없음)
- 추론을 지원하는 모델은 `low`, `medium`, `high`와 공급자 기본값을 고를 수 있고, OpenAI식 `reasoning_effort`로 보낸다. 그 형식을 받지 않는 서버를 위해 모델별로 추론을 끌 수 있다(설정의 `reasoning: false`).
- 목록을 가져오지 못하면 설정에 적은 모델만 쓴다. 실패의 범주는 [연결 확인](model-connection-check.md)과 같은 말로 보인다.

## 계약

### 모델 참조

모델을 고른 값은 계속 프로필 ID 하나다(`modelProfile`). 연결에서 온 모델의 ID는 공급자와 모델에서 정해진 방식으로 만든다.

- `<공급자 ID>:<모델 ID>`가 [Identifier](../../../packages/contracts/src/ids.ts)이면 그대로 쓴다.
- 아니면 허용되지 않는 문자를 `_`로 바꾸고 끝에 `.`과 원래 문자열 SHA-256의 앞 8자를 붙인다. 길이는 Identifier 한도 안으로 자른다.
- 설정의 프로필 ID가 같은 문자열이면 설정의 프로필이 이긴다.
- ID는 연결 상태와 무관하게 풀린다. 연결되지 않은 공급자의 ID로 시작한 요청은 "없는 프로필"이 아니라 그 공급자에 연결하라는 `CAPABILITY_DENIED`로 거절한다.

Run은 지금처럼 시작할 때 공급자, 모델, 한도, 추론 능력, 인증 방법을 snapshot에 고정한다. 실행 중 연결이나 목록이 바뀌어도 그 Run은 고정한 값을 쓴다.

### 설정 스키마

- `modelProfiles`에는 개수 한도가 없다.
- `modelProviders[].models`는 비어 있거나 없어도 된다. 적은 항목은 가져온 목록에 더해지고, 같은 ID면 적은 값이 이긴다.
- 연결과 모델 새로 고침은 `.corral/config.json`을 쓰지 않는다.

### 목록의 출처와 보관

- 내장 공급자의 목록은 Pi의 `getAvailable`이 답한 것이다. 동적 목록을 가진 공급자는 연결 직후와 서버 시작 때 Pi의 `refresh`로 갱신한다.
- 엔드포인트의 목록은 사용자 설정 디렉터리의 캐시에 둔다(작업공간 밖, 자격 증명 파일과 다른 파일). 캐시에는 주소의 origin, 가져온 시각, 모델 ID와 한도·능력만 있다. 키와 응답 원문은 없다.
- 캐시는 가져올 때의 origin에 묶인다. 설정의 주소 origin이 바뀌면 그 캐시를 쓰지 않는다.
- 서버 시작 때는 캐시를 읽기만 하고 외부 요청을 보내지 않는다.

### 엔드포인트 모델 가져오기

- 주소는 요청 본문으로 받지 않는다. 저장된 엔드포인트의 `/models`에만 GET을 보내고, 그 origin에 묶인 키만 쓴다. redirect는 따라가지 않는다.
- 제한: 10초, 응답 2MiB, 모델 2,000개. 넘으면 실패이고 이전 목록을 유지한다.
- 응답에서 읽는 필드: `data[].id`와, 있으면 `context_length`, `context_window`, `top_provider.max_completion_tokens`, `max_output_tokens`, `supported_parameters`의 `reasoning`·`reasoning_effort`, `architecture.input_modalities`의 `image`. 그 밖의 필드는 버린다.
- models.dev 일치 규칙: 모델 ID가 정확히 같거나, `공급사/` 접두를 뗀 ID가 같은 항목. 여러 항목이 일치하면 한도는 가장 작은 값, 추론·이미지는 모든 항목이 지원할 때만 지원으로 본다.
- models.dev 카탈로그가 없거나 24시간보다 오래됐으면 가져오기 전에 한 번 갱신을 시도한다. 실패해도 가져오기는 계속한다. 이 요청에는 사용자 데이터가 없다.
- 설정 revision이나 자격 증명이 가져오는 도중 바뀌면 늦은 결과를 버린다. 같은 엔드포인트의 가져오기는 한 번에 하나다.
- Hive의 DeepSeek V4.1 Flash처럼 [모델 안내](../../guides/models.md)에 등록된 주소·모델의 기본값과 추론 매핑은 가져온 값보다 앞선다(설정에 적은 값 다음).

### Run과 엔드포인트 정의

Run snapshot의 엔드포인트 해시는 그 Run이 쓰는 모델 하나의 유효 정의(주소, 인증 방식, 캐시·세션 설정, 그 모델의 한도·능력)를 덮는다. 다른 모델이 목록에 더해지거나 빠져도 준비된 요청은 거절되지 않는다. 그 모델의 정의가 바뀌면 지금처럼 거절한다.

### 추론

- 내장 공급자: 추론을 지원하는 모든 모델에 Pi의 `getSupportedThinkingLevels` 결과를 수준 목록으로 쓴다. 기록하는 매핑은 Pi의 `thinkingLevelMap` 값이고 없으면 수준 이름이다. Corral이 직접 시험하지 않은 형식에서는 이 기록이 실제 전송 형식과 다를 수 있다.
- 고정 수준은 Pi의 `reasoning` 옵션으로 넘긴다. 공급자 기본값은 옵션을 넘기지 않는다. Codex와 Anthropic의 기존 처리, Hive 매핑, 추론 능력 identity의 고정과 검사는 그대로다.
- 추론 선택의 legacy·provider default·고정·자동 모드와 [추론 판정](effort-routing.md)은 바뀌지 않는다.

### API

HTTP 경로와 필드는 [API 계약](../api-contract.md)에 적는다. 응답은 지금처럼 상태·만료·능력만 담고 token, 키, 콜백 주소, 로컬 경로를 담지 않는다.

- `GET /model-profiles`는 이름 있는 프로필과 연결에서 온 모델을 함께 주고, 항목마다 어느 쪽인지 표시한다.
- `GET /model-auth`는 연결된 공급자와 프로필·엔드포인트가 쓰는 공급자를 주고, 공급자마다 쓸 수 있는 모델 수를 준다.
- 로그인, API 키 저장, 연결 해제는 Pi가 아는 모든 공급자와 등록된 엔드포인트에 쓸 수 있다. 모르는 공급자는 `TARGET_NOT_FOUND`다.
- 엔드포인트 모델 새로 고침은 config revision을 받고, 다르면 `REVISION_CONFLICT`다.

## 수용 시나리오

- 프로필이 OpenAI 둘뿐인 작업공간에서 GitHub Copilot에 구독 로그인하면, 설정 파일이 바뀌지 않은 채 Copilot의 모델이 입력창 선택기에 나오고 그중 하나로 요청을 시작할 수 있다.
- OpenAI에 구독 로그인만 한 상태에서는 그 구독이 부를 수 있는 모델만 나온다. API 키를 넣으면 API 키로 쓸 수 있는 모델이 나온다.
- 프로필 `model-a`가 `openai/gpt-6-luna`이면 선택기에 그 모델은 `model-a` 한 줄만 있다.
- 연결에서 온 모델을 고른 세션에서 그 공급자를 연결 해제하면, 세션의 선택은 그대로이고 쓸 수 없는 값으로 보이며 요청은 연결 안내와 함께 거절된다. 다시 연결하면 같은 선택으로 요청이 나간다.
- 모델 ID에 `/`가 있는 모델(`vendor/name`)도 고를 수 있고, 같은 공급자·모델은 서버를 다시 시작해도 같은 ID다.
- 프로필 25개를 가진 설정이 저장되고 읽힌다.
- 주소와 키만으로 엔드포인트를 저장하면 `/models`의 모델이 선택기에 나온다. 설정 파일의 `models`는 비어 있다.
- `/models`가 401이면 목록은 비어 있고 인증 실패가 보인다. 키를 고쳐 저장하면 다시 가져온다.
- `/models`가 한도보다 큰 응답이나 redirect를 주면 이전 목록이 남는다.
- 가져오는 도중 엔드포인트 주소를 바꿔 저장하면 늦은 결과는 버려지고, 이전 origin의 캐시는 새 주소에 쓰이지 않는다.
- models.dev에 일치 항목이 둘이고 컨텍스트가 128,000과 200,000이면 128,000을 쓴다. 하나만 추론을 지원하면 추론 없음이다.
- 추론을 지원하는 엔드포인트 모델에 `high`를 고르면 요청에 `reasoning_effort: "high"`가 있고, 공급자 기본값이면 그 필드가 없다. 설정에 `reasoning: false`를 적으면 수준이 나오지 않는다.
- 준비된 요청이 있는 동안 같은 엔드포인트의 다른 모델이 목록에 더해져도 그 요청은 나간다.
- Google 모델(Corral이 직접 시험하지 않은 형식)에 Pi가 주는 수준이 선택기에 나오고, 고른 수준이 Pi의 `reasoning` 옵션으로 넘어간다.
- 실행 중인 Run은 연결 해제·목록 변경·새로 고침의 영향을 받지 않는다(이미 받은 token이 거절되는 경우는 공급자 오류로 보인다).

## 보안·성능·접근성

- 키와 token은 지금처럼 사용자 설정 디렉터리의 자격 증명 저장소에만 있다. 응답, 로그, 캐시, 이벤트, export에 나오지 않는다.
- 엔드포인트 요청은 저장된 주소에만 가고, 키는 그 origin에만 간다. 작업공간 파일이 저장된 키를 다른 호스트로 돌릴 수 없다는 기존 경계를 유지한다.
- 연결과 새로 고침은 모델 추론을 부르지 않는다. 통상 CI는 외부 요청을 보내지 않는다(요청 함수와 시간을 주입한다).
- 모델 600개에서 선택기를 여는 것과 검색 입력이 끊기지 않아야 한다. 프로필 보기는 연결된 공급자의 모델에만 능력 계산을 한다.
- 선택기의 검색 필드는 이름을 가지고, 묶음은 그룹 이름으로 읽힌다. 화살표·Home·End·Enter·Escape와 트리거로의 포커스 복귀는 기존과 같다. 연결 추가의 공급자 목록도 키보드로 고를 수 있다.
