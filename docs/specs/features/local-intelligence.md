# 기능 명세: 로컬 AI 공통 임베딩 엔진

- 상태: accepted
- 비목표: 메인 모델·공급자 자동 변경, 권한·비용 상한 확대, 여러 서버 프로세스 사이의 엔진 공유, 벡터 DB, 범용 판정 프레임워크, 두 런타임 병행, 구형 판정 모델 fallback.

## 사용자 관측 동작

설정 → 모델의 **로컬 AI** 패널에서 다음을 확인하고 조작한다.

- 모델 이름(EmbeddingGemma 2 Text 270M)과 상태: 설치 안 됨 / 설치 중 / 준비 중 / 사용 가능 / 업데이트 필요 / 오류 / 이 환경에서 사용할 수 없음.
- 설치 버튼, 진행률, 설치 취소. 설치는 사용자가 누를 때만 시작한다.
- 연산 장치: CPU(기본) / GPU / 자동. 선택한 장치와 실제로 실행 중인 장치를 따로 표시한다.
- 회의 분석 사용 여부.
- 외부 판정 보완: 사용 안 함 / 불확실할 때 Jev. 연결 상태, API 키 입력, 외부로 보내는 범위를 함께 표시한다.

자동 추론 사용 여부는 기존 자동 추론 스위치가 정한다. 로컬 AI 패널은 같은 스위치를 다시 두지 않는다. 실행 기록의 판정 표시는 출처(로컬 모델 / 외부 판정 / 기본값), 정책 버전, 실제 적용 수준, fallback 이유를 보여준다.

## 계약

### 엔진

- 서버 인스턴스마다 엔진 하나를 두고 자동 추론과 회의 분석이 공유한다. 서버 종료 때 엔진도 닫는다.
- 런타임은 LiteRT-LM C 라이브러리를 불러오는 상주 헬퍼 프로세스 하나다. 서버와는 표준 입출력으로만 통신하고 네트워크 포트를 열지 않는다. 헬퍼는 다른 함수를 부르기 전에 라이브러리의 C API 버전을 확인한다. 메이저가 1이 아니거나 마이너가 0보다 낮으면 엔진을 오류 상태로 둔다. 헬퍼는 요청을 한 스레드에서 차례로 처리한다. 준비 전에 헬퍼가 끝나면 실패로 처리한다.
- 추론은 한 번에 하나만 한다. 자동 추론 판정이 먼저이고, 회의 분석은 작은 묶음 사이에서 양보한다. 대기열 길이에는 상한이 있다.
- 진행 중인 계산은 취소할 수 없다. 시간을 넘긴 호출자는 결과를 버리고, 실행 슬롯은 실제 계산이 끝났을 때 푼다. 장치 변경과 종료는 대기 요청을 거절하고 헬퍼 프로세스를 끝내는 방식으로 처리한다.
- 헬퍼가 실패하면 엔진은 오류 상태가 되고, 60초 뒤 다음 요청에서 다시 시작할 수 있다.
- 장치
  - CPU: 물리 코어 수만큼, 최대 6개 스레드를 쓴다. x64는 논리 코어의 절반, arm64는 논리 코어 수를 물리 코어 수로 본다.
  - GPU: 초기화에 실패하면 오류로 표시하고 CPU로 몰래 바꾸지 않는다.
  - 자동: GPU를 먼저 시도하고, 실패하면 CPU로 실행하면서 실제 장치를 보고한다.
  - CPU용과 GPU용 인스턴스를 동시에 두지 않는다. GPU 캐시는 번들 디렉터리 안에 둔다.
- 작업 접두어는 Google 모델 카드를 따른다. 입력 앞뒤 공백을 지운 뒤 붙인다.
  - 분류: `task: classification | query: `
  - 군집: `task: clustering | query: `
  - 검색 질의: `task: search result | query: `
  - 검색 대상 문서: `title: none | text: `
- 출력은 정규화된 768차원 벡터다. 임베딩 캐시 키에는 작업 종류, 전처리 버전, 번들 버전이 들어간다.
- 설치 상태는 엔진을 만들 때와 설정을 조회할 때 읽는다. 판정 요청마다 디스크를 읽지 않는다.

### 설치

- 번들 구성: 기반 모델 파일, 플랫폼별 LiteRT-LM 라이브러리, manifest(릴리스, 파일별 URL·크기·sha256, C API 버전, 임베딩 차원, 전처리 버전). 라이브러리는 공식 `litert-lm-api` 휠에서 꺼낸다. manifest는 휠의 sha256과 꺼낸 파일의 sha256을 모두 고정한다. 분류기 가중치는 Corral 패키지에 포함되고, 기반 모델 sha256·차원·전처리 버전이 맞지 않으면 불러오지 않는다.
- 설치 위치는 앱 데이터 영역의 `corral/local-ai/<release>/`다. 프로젝트 폴더에는 설치하지 않는다.
- 설치는 설정 패널이나 `corral local-ai install`로 시작하고, `corral local-ai status`로 상태를 본다.
- 다운로드는 HTTPS만 허용한다. 크기와 sha256을 확인하고, `.part`에 받은 뒤 이름을 바꾸며, 완료 표시는 마지막에 쓴다. 취소하거나 실패하면 완료 표시를 남기지 않는다.
- 요청을 처리하는 중에는 자동으로 업데이트하지 않는다. 새 릴리스는 새 디렉터리에 설치하고 엔진을 다시 시작할 때 쓴다. 실행 중인 엔진은 이전 디렉터리를 계속 읽는다.
- 이전 판정 모델 디렉터리(`corral/effort-judge`)에서는 이전 manifest에 적힌 파일과 그 설치 표시만 지운다. 디렉터리는 비었을 때만 지운다.
- 런타임 라이브러리가 없는 플랫폼에서는 상태를 "이 환경에서 사용할 수 없음"으로 두고, 자동 추론은 기본 수준을 쓴다.

### 자동 추론 판정 (`corral-effort-v1`)

- 수동 추론 수준과 공급자 기본값에서는 판정하지 않는다.
- 자동 추론의 판정 입력은 `ReasoningInput`의 판정용 사본이다. 현재 요청, 계획, 최근 도구 호출, 이전 요청, 이전 응답 순으로 넣고 256토큰에서 자른다. 요청 앞에 붙는 Corral 배정 메타데이터(ID, 기준, 한도)는 넣지 않는다. 각 부분의 길이 상한은 전처리 버전이 정한다. 메인 모델 요청의 컨텍스트는 바꾸지 않는다.
- 로컬 분류기는 low / medium / high / xhigh의 보정된 확률을 낸다. 가장 높은 확률이 분류기 번들의 보류 기준보다 낮으면 판정을 보류한다.
- 판정이 명확하면 확률이 가장 높은 수준을 선택된 모델이 지원하는 low–xhigh 수준으로 옮긴다. 같은 수준이 없으면 가장 가까운 상위 수준, 상위도 없으면 가장 가까운 하위 수준을 쓴다. 자동 추론은 off·minimal·max를 고르지 않고, 지원하지 않는 수준은 요청에 싣지 않는다.
- 보류했을 때 외부 판정이 허용돼 있으면 Jev를 한 번 호출한다. 허용되지 않았으면 medium을 쓰고 fallback 이유를 `abstained`로 남긴다.
- 실패, 시간 초과, 판단 불가는 medium이다. fallback 이유는 `unavailable`(설치 안 됨, 지원하지 않는 환경, 엔진 오류), `timeout`, `provider_error`, `invalid_response`, `limit`(실행의 판정 횟수 초과), `missing_input`, `abstained` 중 하나다. 압축 요청은 판정 없이 medium이다.
- 로컬 판정과 외부 판정은 하나의 3초 제한 시간을 함께 쓴다.
- 기록에는 번들 버전, 정책 버전, 판정 출처, 실제 적용 수준, fallback 이유가 남는다. 입력 원문과 키는 남기지 않는다.
- 자동 적용으로 판정한 요청은 관측 경로에서 같은 로컬 모델로 다시 판정하지 않는다.
- 이전 정책(`mixdog-relative-v1`)으로 남은 실행 기록은 읽기만 한다. 그 값으로 모델을 실행하지 않는다.

### 회의 분석과 외부 판정

회의 분석이 비서 입력에 들어가는 규칙은 [workbench](../workbench.md)의 회의 절이 정한다. 외부 판정의 키 보관과 전송 범위는 [모델과 리소스](../models-and-resources.md)가 정한다. 두 기능은 각 단계를 구현하면서 해당 문서에 추가한다.

## 수용 시나리오

```gherkin
Given 로컬 AI가 설치되지 않았다
When 자동 추론 역할이 모델 요청을 준비한다
Then 요청은 medium으로 나가고 fallback 이유는 unavailable이다
And 다운로드는 시작되지 않는다

Given 로컬 AI가 사용 가능하고 판정이 명확하다
When 자동 추론 역할이 모델 요청을 준비한다
Then 판정 수준이 모델이 지원하는 수준으로 적용되고 정책 버전은 corral-effort-v1이다
And 관측 경로는 같은 요청을 다시 판정하지 않는다

Given 로컬 판정이 보류됐고 외부 판정이 허용되지 않았다
When 요청을 준비한다
Then 요청은 medium으로 나가고 외부 요청은 없다

Given 설치가 진행 중이다
When 사용자가 설치를 취소한다
Then 완료 표시가 남지 않고 다음 설치는 처음부터 크기와 해시를 확인한다

Given GPU를 선택했고 GPU 초기화가 실패한다
When 엔진이 시작된다
Then 상태는 오류이고 실제 장치는 표시되지 않으며 CPU로 몰래 실행하지 않는다

Given 판정이 진행 중이다
When 실행이 취소된다
Then 판정 결과는 버려지고 요청은 나가지 않으며 실행 슬롯은 계산이 끝난 뒤 풀린다

Given 서버가 종료된다
When 헬퍼가 판정을 계산하는 중이다
Then 대기 요청은 거절되고 헬퍼 프로세스는 종료가 확인된다
```

## 보안·성능·접근성

- 판정과 분석은 로컬에서 처리한다. 헬퍼는 최소 환경 변수로 실행하고 네트워크를 열지 않는다. 모델과 라이브러리는 manifest에 고정한 해시로만 불러온다.
- 성능 목표: 기준 머신에서 warm p95가 CPU 150 ms 이하(256토큰), GPU 20 ms 이하다.
- 라이브러리 사실
  - LiteRT-LM C API: `litert-lm-api` 0.19.0 휠의 `liblitert-lm`. 내보내는 함수는 `LITERT_LM_C_API_1.0` 버전 태그가 붙어 있고, 임베딩 함수는 `c/embedding_engine.h`에 있다.
  - 모델: `litert-community/embeddinggemma-2-text-270m-litert-lm` 리비전 `9be6e8b90982095dc05c2bd162e4b954ee4dbac7`, Apache-2.0.
  - 접두어: `google/embeddinggemma-2`의 `config_sentence_transformers.json`.
- 설정 패널은 기존 디자인 키트를 쓰고, 설치 진행과 상태는 status 영역에서 읽을 수 있게 한다.
