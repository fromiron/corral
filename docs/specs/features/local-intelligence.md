# 기능 명세: 로컬 AI 공통 임베딩 엔진

- 상태: accepted
- 비목표: 메인 모델·공급자 자동 변경, 권한 확대, 여러 서버 프로세스 사이의 엔진 공유, 벡터 DB, 범용 판정 프레임워크, 두 런타임 병행. 추론 수준 판정은 [추론 판정](effort-routing.md)이 정하며 이 엔진을 쓰지 않는다.

## 사용자 관측 동작

설정 → 모델의 **로컬 AI** 패널에서 다음을 확인하고 조작한다.

- 번들의 모델 이름(회의 분석: EmbeddingGemma 2 Text 270M)과 번들 상태: 설치 안 됨 / 설치 중 / 준비 중 / 사용 가능 / 업데이트 필요 / 오류 / 이 환경에서 사용할 수 없음.
- 설치 버튼, 진행률, 설치 취소, 제거. 설치는 사용자가 누를 때만 시작한다. 설치 버튼 옆에는 내려받는다는 말과 크기를 보인다. 크기는 [추론 판정](effort-routing.md)의 설치 크기 표시와 같다. 설치가 실패한 뒤에도 같다.
- 연산 장치: CPU(기본) / GPU / 자동. 선택한 장치와 실제로 실행 중인 장치를 따로 표시한다.
- 회의 분석 사용 여부.

## 계약

### 엔진

- 서버 인스턴스마다 엔진 하나를 두고 회의 분석이 쓴다. 서버 종료 때 엔진도 닫는다.
- 엔진은 번들의 회의 분석 모델(EmbeddingGemma 2 Text 270M)을 쓴다.
- 런타임은 LiteRT-LM C 라이브러리를 불러오는 상주 헬퍼 프로세스 하나다. 서버와는 표준 입출력으로만 통신하고 네트워크 포트를 열지 않는다. 헬퍼는 다른 함수를 부르기 전에 라이브러리의 C API 버전을 확인한다. 메이저가 1이 아니거나 마이너가 0보다 낮으면 엔진을 오류 상태로 둔다. 헬퍼는 모델을 manifest의 입력 길이 상한으로 불러오고 요청을 한 스레드에서 차례로 처리한다. 모델이 준비되기 전에 헬퍼가 끝나면 실패로 처리한다.
- 입력 길이 상한은 manifest가 정한다. 회의 분석 모델은 256토큰이다.
- 헬퍼 실행 파일은 내려받지 않고 Corral과 함께 배포한다. 데스크톱 런타임은 패키지를 만드는 OS/arch에서 빌드한 헬퍼를 로컬 AI 패키지의 `bin/`에 넣고, 런타임 검사에서 그 헬퍼를 실행해 본다. 소스 체크아웃에서는 `pnpm --filter @corral/local-intelligence build:helper`로 빌드한 헬퍼를 쓴다. 엔진은 `CORRAL_LOCAL_AI_HELPER`, 패키지의 `bin/`, 체크아웃의 빌드 결과 순으로 찾는다. 헬퍼가 없으면 상태는 "이 환경에서 사용할 수 없음"이다.
- 추론은 한 번에 하나만 하며 회의 분석은 작은 묶음 단위로 계산한다. 대기열 길이에는 상한이 있다.
- 진행 중인 계산은 취소할 수 없다. 시간을 넘긴 호출자는 결과를 버리고, 실행 슬롯은 실제 계산이 끝났을 때 푼다. 장치 변경과 종료는 대기 요청을 거절하고 헬퍼 프로세스를 끝내는 방식으로 처리한다.
- 헬퍼가 실패하면 엔진은 오류 상태가 되고, 60초 뒤 다음 요청에서 다시 시작할 수 있다.
- 장치
  - CPU: 물리 코어 수만큼, 최대 6개 스레드를 쓴다. x64는 논리 코어의 절반, arm64는 논리 코어 수를 물리 코어 수로 본다.
  - GPU: 초기화에 실패하면 오류로 표시하고 CPU로 몰래 바꾸지 않는다.
  - 자동: GPU를 먼저 시도하고, 실패하면 CPU로 실행하면서 실제 장치를 보고한다.
  - CPU용과 GPU용 인스턴스를 동시에 두지 않는다. GPU 캐시는 번들 디렉터리 안에 두고, 헬퍼를 시작할 때 캐시 폴더를 만든다.
- 작업 접두어는 Google 모델 카드를 따른다. 입력 앞뒤 공백을 지운 뒤 붙인다.
  - 분류: `task: classification | query: `
  - 군집: `task: clustering | query: `
  - 검색 질의: `task: search result | query: `
  - 검색 대상 문서: `title: none | text: `
- 출력은 정규화된 768차원 벡터다. 임베딩 캐시 키에는 모델, 작업 종류, 전처리 버전, 번들 버전이 들어간다.
- 설치 상태는 엔진을 만들 때와 설정을 조회할 때 읽는다. 요청마다 디스크를 읽지 않는다.

### 설치

- 번들 구성: 회의 분석 모델 파일, 플랫폼별 LiteRT-LM 라이브러리, manifest(릴리스, 파일별 URL·크기·sha256, C API 버전, 모델의 임베딩 차원·입력 길이 상한·전처리 버전). 라이브러리는 공식 `litert-lm-api` 휠에서 꺼낸다. manifest는 휠의 sha256과 꺼낸 파일의 sha256을 모두 고정한다.
- 이전 릴리스만 설치돼 있으면 상태는 "업데이트 필요"다. 자동으로 내려받지 않으며, 새 릴리스를 설치하기 전까지 회의 분석은 대체 선택을 쓴다.
- 설치 위치는 앱 데이터 영역의 `corral/local-ai/<release>/`다. 프로젝트 폴더에는 설치하지 않는다.
- 설치는 설정 패널이나 `corral local-ai install`로 시작하고, `corral local-ai status`로 상태를 본다. `corral local-ai`는 install과 status만 있다. 제거는 설정 패널에서 한다.
- 설치된 번들의 **제거**는 확인 뒤에만 한다. 확인은 지워질 크기를 말하고, 크기는 설치 때 보이는 내려받을 크기와 같다.
- 설치가 진행 중이거나 임베딩이 계산 슬롯을 잡았거나 대기열에 있으면 거절한다. 파일과 헬퍼는 그대로다. 응답은 409 `RESOURCE_CAPACITY`이고 문구는 `an install is in progress` 또는 `a computation is in progress`다. 문구에 로컬 경로를 넣지 않는다.
- 거절되지 않으면 Corral이 시작한 헬퍼만 끝내고, 이 루트의 회의 분석 릴리스 디렉터리(현재와 이전 릴리스)만 지운다. `local-ai/d1`과 그 안의 판정 모델은 지우지 않는다.
- 끝나면 상태는 설치 안 됨(`missing`)이다. 이미 없으면 다시 제거해도 설치 안 됨이고 다른 파일은 그대로다.
- 파일을 다 쓴 뒤 그 설치를 받아들이기 전에 제거되면, 그 완료는 늦은 사건이다. 늦은 완료는 설치로 확정하지 않고, 그 사이에 다시 생긴 릴리스 디렉터리는 지운다. 상태는 설치 안 됨으로 남는다.
- 디렉터리를 지우지 못하면 설치 안 됨으로 보고하지 않는다. 헬퍼는 이미 멈췄을 수 있고, 폴더가 남아 있으면 설치된 상태다. 판정 모델은 그대로다.
- 설정 패널의 설치는 서버가 진행한다. 설치 전에 내려받을 크기를 보여주고, 설치 중에는 받은 크기와 전체 크기를 보여준다. 라이브러리 압축 해제는 진행률 없이 끝난다. 한 서버에서 설치는 하나만 진행한다. 진행 중에 다시 요청하면 새로 받지 않고 같은 설치를 보여준다. 이미 설치됐거나 이 환경에서 쓸 수 없으면 설치를 시작하지 않는다.
- 설치를 취소하거나 서버가 종료되면 다운로드를 멈추고 부분 파일을 지운다. 완료 표시가 없으므로 설치되지 않은 상태로 남는다.
- 설치가 실패하면 이유를 보여주고 다시 설치할 수 있다. 설치 실패와 엔진 오류의 이유에는 로컬 경로를 넣지 않는다. 설치가 끝나면 서버를 다시 시작하지 않아도 다음 회의 분석부터 쓴다.
- 다운로드는 HTTPS만 허용한다. 크기와 sha256을 확인하고, `.part`에 받은 뒤 이름을 바꾸며, 완료 표시는 마지막에 쓴다. 취소하거나 실패하면 완료 표시를 남기지 않는다.
- 요청을 처리하는 중에는 자동으로 업데이트하지 않는다. 새 릴리스는 새 디렉터리에 설치하고 엔진을 다시 시작할 때 쓴다. 실행 중인 엔진은 이전 디렉터리를 계속 읽는다.
- 서버가 시작할 때 이전 판정 모델 디렉터리(`corral/effort-judge`)에서 이전 판정 모델이 설치한 파일과 그 설치 표시만 지운다. 디렉터리는 비었을 때만 지우고, 정리에 실패해도 서버는 시작한다. 이전 판정 모델을 내려받거나 불러오는 경로는 없다.
- 런타임 라이브러리가 없는 플랫폼에서는 상태를 "이 환경에서 사용할 수 없음"으로 둔다.

### 회의 분석

- 응답자는 명시적 수신자와 @멘션, 메시지의 호칭 규칙, 로컬 선택기, 대체 선택 순으로 정한다. 비서는 사람이 명시적으로 요청할 때만 답하고 호칭 규칙과 선택기의 대상이 아니다.
- 호칭 규칙은 명시적 수신자와 @멘션이 없는 일반 메시지에만 적용한다. 로컬 AI 없이 동작하고 등록 참가자의 표시 이름과 별칭만 본다. 이름 비교는 대소문자를 구분하지 않는다.
  - 지목: 문장 첫머리의 이름이 호격(`솔아`, `루나 님`, `Sol,`)이거나, 주제 조사와 함께 묻는 문장(`솔은 어때?`)이거나, 답변 지시(`루나가 답해줘`)로 이어지거나, 문장 끝의 호격(`어떻게 생각해, 솔?`)이면 그 참가자를 고른다. 묻거나 시키는 문장에서 이름을 이어 쓰면(`솔이랑 루나랑 해봐`) 함께 고른다. 이름을 언급만 한 문장(`솔이 말한 메뉴 어때?`)이나 이름으로 시작하는 다른 낱말(`솔직히`)은 지목이 아니다.
  - 전원: `다들`, `모두`, `각자`, `여러분`, `everyone` 같은 표현으로 의견을 물으면 제외 대상을 뺀 전원을 고른다. 제외 대상이 있을 때의 `나머지`, `다른 사람`도 같다.
  - 제외: `X 말고`, `X 빼고`, `X 제외`, `X는 답하지 마`, `except X`의 대상은 이 메시지에서 어떤 경로로도 호출하지 않는다. 모든 참가자를 제외한 메시지는 제외를 적용하지 않는다.
  - 규칙이 응답자를 정하지 못하면 제외만 적용하고 다음 단계로 넘어간다. 같은 참가자를 지목하고 제외한 메시지도 같다.
- 로컬 회의 선택기는 학습된 가중치 없이 임베딩 코사인 유사도로 한 명을 고른다. 현재 메시지와 참가자의 표시 이름·역할 설명 사이 유사도에 0.25, 그 참가자의 최근 확정 발언 중 가장 가까운 유사도에 0.75를 곱해 더한다. 아직 발언이 없는 참가자는 역할 설명이 있으면 역할 유사도를 그대로 점수로 쓰고, 역할 설명도 없으면 0점이다. 먼저 답한 참가자가 이후의 호칭 없는 메시지를 모두 가져가지 않게 하기 위해서다. 동점은 등록 순서를 따른다. 역할 설명과 확정 발언이 모두 없으면 판정 없음으로 둔다. 표시 이름은 발언과 지목 대상을 연결하는 데 쓰며 이름만 보고 능력이나 성격을 추측하지 않는다. 일반 대화도 지원하며 코딩 역할을 강제하지 않는다.
- 회의 임베딩은 서버 수명 안에서 텍스트 해시로 다시 쓴다. 메모리에는 해시와 벡터만 두고 원문은 두지 않으며, 보관 수에 상한이 있다.
- 회의 분석을 사용하지 않으면 호칭 규칙을 적용한 뒤 기존 참가자 응답 경로를 사용한다. 분석을 사용하는데 판정이 없거나 실패하거나 등록되지 않은 ID·중복 ID를 반환하면 허용된 참가자 한 명만 고른다. 응답 대상이 있으면 그 참가자, 없으면 최근 확정 발언자, 둘 다 없으면 저장된 일반 메시지 순서에 따른 순환 순서를 사용한다. 비서는 이 대체 선택의 대상이 아니다.
- 로컬 선택은 1.5초 안에 끝내며 시간을 넘기면 대기 중인 호출을 취소하고 대체 선택을 사용한다. 최근 6개 메시지 묶음의 최대 12개 확정 발언을 시간순으로 전달하며 각 발언의 안정적인 ID와 발언자를 유지한다. 아직 끝나지 않은 답변이나 미래 발언을 선택 근거로 사용하지 않는다.
- 유효한 빈 선택은 응답하지 않는다는 뜻이며 실패와 구분한다. 일반 메시지에 빈 참가자 목록과 빈 답변 목록을 저장하고 Run을 만들지 않는다. 명시 지목·비서·반론 요청에는 빈 참가자 목록을 허용하지 않는다. 선택 결과는 메시지의 참가자 목록으로 저장한다. 같은 명령의 재전송은 저장된 선택을 재사용하고 다시 판정하거나 Run을 중복 생성하지 않는다. 저장 전 세션 revision이 바뀌면 적용하지 않는다.
- 입력 원문은 학습 자료나 로그에 자동 저장하지 않는다. 응답 실행·취소·기록은 기존 MeetingService와 Coordinator 경로가 담당한다. 사용자 관측 규칙은 [workbench](../workbench.md)의 회의 절을 따른다.

### 회의 선택기 평가

- 회의 선택은 응답자 집합 일치·정밀도·재현율과 맥락 유형별 결과를 보고한다. 비교는 같은 표본 ID·원문·라벨로 수행한다. 작성한 합성 시나리오의 정확도를 실제 사용자 대화의 결과라고 주장하지 않는다.
- 실제 기록 골드셋은 개발자가 추출 도구를 직접 실행할 때만 만들고, 판정자가 모델 예측을 보지 않은 채 라벨을 붙인다. 판정자는 사람 또는 이름을 밝힌 LLM이며 라벨을 판정자별로 따로 저장한다. LLM 라벨은 사람 라벨과 구분해 보고하고 사람의 정답이라고 주장하지 않는다.
- 골드셋의 원문과 라벨은 저장소 밖의 사용자 전용 디렉터리에 두고 공유하지 않는다. 저장소와 보고서에는 건수와 지표 같은 집계만 남긴다. 저장 전에 키·토큰·이메일을 지우고 홈 경로를 가린다.
- 골드셋은 세션 단위로 조정용과 최종 평가용으로 나누고, 최종 평가용은 후보 선택에 쓰지 않는다. 같은 사람의 재라벨 일치율을 함께 보고해 라벨 자체의 한계를 밝힌다.

## 보안·성능·접근성

- 분석은 로컬에서 처리한다. 헬퍼는 최소 환경 변수로 실행하고 네트워크를 열지 않는다. 모델과 라이브러리는 manifest에 고정한 해시로만 불러온다.
- 성능 참고치: 회의 분석 모델 256토큰의 warm p95가 CPU 150 ms, GPU 20 ms다. CPU 종류와 자원 상태에 따라 크게 달라지는 참고치이며 합격 기준이 아니다.
- 라이브러리 사실
  - LiteRT-LM C API: `litert-lm-api` 0.19.0 휠의 `liblitert-lm`. 내보내는 함수는 `LITERT_LM_C_API_1.0` 버전 태그가 붙어 있고, 임베딩 함수는 `c/embedding_engine.h`에 있다.
  - 회의 분석 모델: `litert-community/embeddinggemma-2-text-270m-litert-lm` 리비전 `9be6e8b90982095dc05c2bd162e4b954ee4dbac7`, Apache-2.0.
  - 접두어: `google/embeddinggemma-2`의 `config_sentence_transformers.json`.
- 설정 패널은 기존 디자인 키트를 쓰고, 설치 진행과 상태는 status 영역에서 읽을 수 있게 한다.
