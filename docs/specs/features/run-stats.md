# 기능 명세: 실행 통계 — 팀 편집기에서 본 최근 실행

- 상태: accepted (2026-11-08)
- 기준: [팀 편집기](canvas.md), [팀 그래프 모델](team-graph.md), [실행 기록 관찰](execution-monitor.md)
- 비목표: 실행 중인 상태 표시, 한 실행의 기록을 캔버스에 겹쳐 보이기(실행은 [실행 기록 관찰](execution-monitor.md)에서 본다), 모의 실행, 여러 revision 합산, 통화 비용 환산

## 사용자 관측 동작

1. **켜고 끄기.** 팀 편집기 경로 막대의 "실행 통계" 토글로 캔버스에 수치를 겹친다. 처음에는 꺼져 있고 정의를 바꾸지 않는다. 켜져 있는 동안 토글 옆에 기준 revision과 센 실행 수가 보인다.
2. **세는 실행.** 그 팀의 저장된 revision 중 경로 막대에 보이는 것(버전 N)에서 시작한, 실제 모델로 돈, 이미 끝난 실행을 시작 시각이 늦은 것부터 최대 20개 센다. 모의 실행, 다른 revision의 실행, 아직 끝나지 않은 실행은 세지 않는다. 센 실행이 없으면 토글 옆에 그렇다고 보이고 단계에는 수치가 없다.
3. **단계별 수치.** 수치는 단계 타일과 상자 바로 아래에 붙는 작은 표시다.
   - Loop: 실행당 평균 회차, 그리고 회차 상한에 닿은 실행 수 / 센 실행 수.
   - 판정: 갈래별로 그 갈래가 선택된 횟수. 한 실행 안에서 여러 번 선택되면 모두 센다.
   - 에이전트: 출력 토큰 비중(센 실행 전체의 출력 토큰 중 이 단계의 몫). 실패한 실행(execution)이 있으면 실패 수, 다시 시도한 실행이 있으면 재시도 수를 덧붙인다.
   - 센 실행 어디에서도 실행되지 않은 단계에는 "실행 안 됨"이 보인다. 출력과 호출 링크에는 수치가 없다.
4. **실행으로 이어지기.** 수치를 누르면 그 수치를 만든 실행 목록이 열린다. 각 줄은 시작 시각, 실행 상태, 그 실행에서의 값(회차, 선택 횟수, 실패·재시도 수, 출력 토큰)을 보이고 그 실행 화면(`/runs/:runId`)으로 간다. Loop의 상한 수치는 상한에 닿은 실행만, 판정 갈래는 그 갈래를 고른 실행만, 실패·재시도는 그런 일이 있었던 실행만 보인다.
5. **편집 중.** 수치는 저장된 revision 기준이다. 저장하지 않은 초안에서도 같은 id의 단계에는 그대로 보이고, 새로 추가한 단계에는 없다. 편집해도 다시 읽지 않는다. 저장해 새 revision이 되면 그 revision의 실행을 다시 읽는다.
6. **다시 읽기.** 토글을 켤 때와 기준 revision이 바뀔 때 읽는다. 실행이 끝나도 저절로 바뀌지 않으며, 토글을 껐다 켜면 다시 읽는다.
7. **읽기 실패.** 읽지 못하면 토글 옆에 실패를 보이고 단계에는 수치가 없다. 편집은 그대로 된다.

## 계약

- **집계:** 저장된 실행의 정의 snapshot(`source`)·모드·projection만으로 계산하는 순수 함수다(`packages/core/src/run-stats.ts`). 단계는 node id로 맞춘다.
  - 회차: projection의 `loopIterations[loopNodeId]` 길이. 상한 도달: 그 Loop의 마지막 회차 결과가 `cap_reached`.
  - 판정 갈래: `workflow.branch_selected`의 `selectedPort`.
  - 실패: 그 node의 execution 중 상태가 `failed`인 것. 재시도: `attemptNo`가 1보다 큰 execution.
  - 출력 토큰: 그 node execution들의 model call `usage.outputTokens` 합. usage가 보고되지 않은 호출은 더하지 않는다.
- **API:** `GET /api/v1/corrals/:corralId/revisions/:revision/stats`. 없는 팀이나 revision은 404다. 다른 API와 같은 세션·origin 경계를 따른다. 응답에는 실행 id, 상태, 시각, 수와 node id만 있고 메시지·산출물 본문, 모델 응답, 경로는 없다.
- **transport:** `RuntimeTransport.getRunStats(corralId, revision)`. 서버 모드는 위 API를, 브라우저 데모는 같은 집계 함수를 in-process로 쓴다.
- **표시 상태:** 토글과 펼친 목록은 화면 상태이며 저장하지 않는다.

## 수용 시나리오

```gherkin
Scenario: 이 revision의 끝난 실제 실행만 센다
  Given 팀의 revision 3에서 시작한 실제 실행 22개, 모의 실행 1개, 진행 중인 실제 실행 1개와 revision 2의 실제 실행이 있다
  When revision 3의 편집기에서 실행 통계를 켠다
  Then 시작 시각이 늦은 끝난 실제 실행 20개만 센다

Scenario: Loop 회차와 상한
  Given 센 실행 4개에서 Loop가 1, 2, 3, 3회 돌았고 3회짜리 하나는 상한에 닿았다
  Then Loop에는 평균 2.3회와 상한 1/4가 보인다
  When 상한 수치를 누른다
  Then 상한에 닿은 실행 하나만 목록에 보이고 그 실행 화면으로 갈 수 있다

Scenario: 판정 갈래와 에이전트 실패·재시도
  Given 검토 판정이 revise를 3번, pass를 2번 골랐고 작성 에이전트의 execution 하나가 실패해 다시 시도됐다
  Then 판정에는 revise 3과 pass 2가 보인다
  And 작성 에이전트에는 출력 토큰 비중, 실패 1, 재시도 1이 보인다

Scenario: 초안과 새 단계
  Given 실행 통계가 켜진 채 저장하지 않은 새 에이전트를 추가한다
  Then 기존 단계의 수치는 그대로이고 새 에이전트에는 수치가 없다
  When 저장해 revision 4가 된다
  Then revision 4의 실행을 다시 읽고, 아직 없으면 실행이 없다고 보인다

Scenario: 실행이 없거나 읽지 못한다
  Given revision의 끝난 실제 실행이 없다
  Then 단계에는 수치가 없고 실행이 없다고 보인다
  Given 통계를 읽지 못한다
  Then 실패가 보이고 편집은 계속된다
```

## 보안·성능·접근성

- 응답에 본문·경로·키가 없다. 실행 화면 링크는 같은 세션 경계 안이다.
- 서버는 그 팀의 실행 목록을 늦은 순으로 훑어 조건에 맞는 20개에서 멈춘다. 집계는 실행 수와 execution 수에 비례한다.
- 수치는 문구와 숫자로 보이며 색에만 기대지 않는다. 수치마다 이름 있는 버튼이고 키보드로 목록을 열고 닫는다.
