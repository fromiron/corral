# 기능 명세: 파일 경로 검색과 빠른 열기

- 상태: accepted
- 비목표: 내용 검색·다중 파일 교체의 엔진 교체, 에이전트 검색 도구 변경, 원본 폴더 쓰기

## 사용자 관측 동작

세션 화면 어디서든 **빠른 열기**(⌘P / Ctrl+P, 파일 트리 머리의 버튼)를 열 수 있다. 경로 일부를 입력하면 현재 대상(세션 작업 사본, 없으면 프로젝트 원본 폴더)의 파일·폴더가 순위대로 보인다. 고르면 사본의 파일은 파일 탭의 문서로 열고, 이미 열린 문서면 그 탭으로 간다. 원본 폴더의 항목은 파일 창에서 드러낸다. 빠른 열기는 현재 탭·초안·문서를 닫거나 바꾸지 않는다. Escape로 닫으면 여는 컨트롤로 포커스가 돌아간다.

결과 행은 경로를 보인다. 대상이 사본인지 원본인지 입력란 옆에 보인다. `@` 참조 검색도 같은 경로 검색을 쓴다.

설정 › 진단은 지금 쓰는 경로 엔진을 보인다. FFF를 쓰는지, 내장 엔진을 쓰는지, FFF를 못 쓰는 경우 그 이유를 보인다.

## 계약

- **경로 후보의 범위**는 엔진과 관계없이 같다. Git 폴더면 Git의 추적 파일과 ignore되지 않은 미추적 파일, 아니면 폴더 걷기 결과다. 상대 경로 검사(`safeRelative`)를 통과해야 하고, 결과마다 `assertPlainPath`로 symlink가 없는지와 종류(파일·폴더)를 다시 확인한다. 보호 경로 규칙도 그대로 적용한다.
- **FFF 엔진**(`@ff-labs/fff-node`)을 서버가 쓸 수 있으면 FFF가 순위를 정한다. 순위에는 퍼지 일치, 파일 수정 빈도·최근성(frecency), Git 상태가 반영된다. 빠른 열기에서 연 파일은 아직 순위에 반영하지 않는다.
  - FFF 결과 가운데 위 범위에 속하고 확인을 통과한 경로만 쓴다.
  - FFF 결과가 요청한 개수보다 적으면 내장 순위로 채운다. 그래서 FFF 색인이 늦거나 놓친 파일도 내장 범위에서 찾을 수 있다.
- 서버는 `GET /health`의 `pathEngine`으로 지금 엔진과 마지막 대체 이유를 알린다(경로 없음). 색인 상한 이유(`indexCap`)는 후보 목록이 잘렸을 때다.
- **내장 엔진**은 현재 목록에 `rankFuzzy`를 쓴다. 다음 경우 내장 엔진만 쓰고 진단에 이유를 남긴다:
  - FFF 네이티브 모듈을 불러오지 못했다.
  - 이 플랫폼용 바이너리가 없다.
  - 색인 상한에 걸렸다.
  - 호출이 실패했다.
- 색인은 대상(사본 generation 또는 원본 폴더)마다 하나다.
  - 동시에 유지하는 색인 수에 상한이 있고, 오래 쓰지 않은 색인부터 닫는다.
  - 사본을 지우기 전과 서버 종료 때 색인을 닫는다. 닫지 못해도 사본 삭제를 막지 않고 내장 엔진으로 돌아간다.
- FFF의 frecency 저장소는 작업공간의 Corral 데이터 디렉터리(`.corral/path-search/`) 안에만 두고, 로그·진단 복사·내보내기에 경로를 남기지 않는다.
- FFF 호출은 JS 스레드에서 동기로 돈다. 그래서 한 번의 경로 질의에 시간 상한을 두고, 넘으면 내장 엔진 결과를 쓴다. 취소·새 질의·대상 전환 뒤의 늦은 결과는 버린다.
- 내용 검색(`searchContents`)과 "모두 바꾸기" 제안은 내장 엔진을 쓴다. 이들의 완전성·잘림·건너뜀 계산은 [workbench](../workbench.md#파일-내용-검색)를 따른다.

## 수용 시나리오

```gherkin
Given FFF를 쓸 수 있는 서버와 Git 사본이 있다
When 빠른 열기에서 "srvc" 를 입력한다
Then apps/server/src/files/service.ts 가 결과에 있다
And symlink 뒤의 파일과 ignore된 미추적 파일은 없다

Given FFF 네이티브 모듈을 불러오지 못한다
When 빠른 열기에서 검색한다
Then 내장 엔진 결과가 보이고 설정 › 진단에 이유가 보인다

Given 빠른 열기가 열린 채 다른 사본으로 대상을 바꾼다
When 이전 대상의 응답이 늦게 도착한다
Then 그 결과는 보이지 않는다
```

## 보안·성능·접근성

- FFF 0.11.0 MIT, `ffi-rs` MIT, 플랫폼별 `@ff-labs/fff-bin-*`. 바이너리에 포함된 crate의 고지는 `THIRD-PARTY-NOTICES/`에 둔다. 직접 의존성 `@ff-labs/fff-node`의 버전·출처는 `docs/dependency-lock.json`에, 전이 패키지(`ffi-rs`, `@ff-labs/fff-bin-*`)는 `pnpm-lock.yaml`과 release inventory에 있다. FFF 바이너리의 crate 고지는 `THIRD-PARTY-NOTICES/fff-crates.txt`다.
- Desktop 런타임 점검(`apps/desktop/scripts/check-runtime.mjs`)은 FFF 로드와 경로 질의를 확인한다.
- 빠른 열기는 CommandMenu 대화상자이며 결과 수와 대상을 화면 읽기 프로그램에 알린다.
