# 기능 명세: 파일 경로 검색과 빠른 열기

- 상태: accepted
- 비목표: 내용 검색·다중 파일 교체의 엔진 교체, 에이전트 검색 도구 변경, 원본 폴더 쓰기

## 사용자 관측 동작

세션 화면 어디서든 **빠른 열기**(⌘P / Ctrl+P, 파일 트리 머리의 버튼)를 열 수 있다. 경로 일부를 입력하면 현재 대상(세션 작업 사본, 없으면 프로젝트 원본 폴더)의 파일·폴더가 순위대로 보인다. 고르면 사본의 파일은 파일 탭의 문서로 열고, 이미 열린 문서면 그 탭으로 간다. 원본 폴더의 항목은 파일 창에서 드러낸다. 빠른 열기는 현재 탭·초안·문서를 닫거나 바꾸지 않는다. Escape로 닫으면 여는 컨트롤로 포커스가 돌아간다.

결과 행은 경로를 보인다. 대상이 사본인지 원본인지 입력란 옆에 보인다. `@` 참조 검색도 같은 경로 검색을 쓴다.

설정 › 진단은 지금 쓰는 경로 엔진(내장)을 보인다.

## 계약

- **경로 후보의 범위**: Git 폴더면 Git의 추적 파일과 ignore되지 않은 미추적 파일, 아니면 폴더 걷기 결과다. 상대 경로 검사(`safeRelative`)를 통과해야 하고, 결과마다 `assertPlainPath`로 symlink가 없는지와 종류(파일·폴더)를 다시 확인한다. 보호 경로 규칙도 그대로 적용한다.
- **순위**: 내장 엔진이 현재 목록에 `rankFuzzy`를 쓴다. 서버 경로는 `GET …/search?q=&limit=`(최대 50개)다.
- 질의를 바꾸거나 대상을 바꾼 뒤 늦게 도착한 결과는 버린다.
- 내용 검색(`searchContents`)과 "모두 바꾸기" 제안의 완전성·잘림·건너뜀 계산은 [workbench](../workbench.md#파일-내용-검색)를 따른다.

## 수용 시나리오

```gherkin
Given Git 사본이 있다
When 빠른 열기에서 "srvc" 를 입력한다
Then apps/server/src/files/service.ts 가 결과에 있다
And symlink 뒤의 파일과 ignore된 미추적 파일은 없다

Given 빠른 열기가 열린 채 다른 사본으로 대상을 바꾼다
When 이전 대상의 응답이 늦게 도착한다
Then 그 결과는 보이지 않는다
```

## 보안·성능·접근성

- 빠른 열기는 CommandMenu 대화상자이며 결과 수와 대상을 화면 읽기 프로그램에 알린다.
