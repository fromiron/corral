# 기능 명세: 변경 검토의 실행별 묶음

- 상태: accepted
- 비목표: 변경 조각을 실행에 귀속하기, 누가 바꿨는지(에이전트의 명령인지 사람인지) 가르기, 읽음 기록 이후 범위와 실행 범위를 묶기, 묶음마다 판단하기, 모델이 쓰는 요약, Git 보기의 stage · unstage, 브라우저 데모의 묶음

## 사용자 관측 동작

[변경 검토](../workbench.md#캡처한-컨텍스트와-대화-표시-밀도)의 파일 목록은 비교 범위가 대화 전체일 때, 바뀐 파일을 그 파일이 바뀐 때에 따라 묶는다. 어느 요청 동안 무엇이 바뀌었는지를 범위를 바꾸지 않고 한 목록에서 본다.

- 묶음은 실행마다 하나와 "실행 밖"(Outside runs) 하나다. 실행의 묶음은 그 실행이 돌던 동안 바뀐 파일이고 머리는 "실행 #n"이다. 실행 밖은 어느 실행도 돌지 않던 동안 바뀐 파일이다. 새 실행의 묶음이 위에 오고 실행 밖은 맨 아래다.
- 묶음은 그 동안 바뀐 것을 말하고, 누가 바꿨는지는 말하지 않는다. 실행 중에 사람이 고친 파일도 그 실행의 묶음에 든다. Corral의 파일 도구가 쓴 그대로인지는 행의 출처 표시가 말한다. 출처 표시의 도움말은 파일 도구가 쓰지 않은 변경을 "명령이나 Corral 밖에서 바뀜"(Changed by a command or outside Corral)이라고 한다. 사람이 바꿨다고 하지 않는다.
- 한 파일이 여러 때에 바뀌었으면 그 묶음마다 행이 있다. 어느 행을 골라도 여는 것은 그 파일의 대화 전체 비교다. 읽음과 변경 검토의 표시, 의견, 판단은 지금처럼 대화 전체 비교에 붙고 묶음과 상관없다. 고른 파일의 행은 모두 고른 것으로 보인다.
- 실행 묶음의 머리는 버튼이다. 누르면 비교 범위가 그 실행이 된다(주소의 `scope=run`).
- 묶음이 둘 이상일 때만 묶는다. 하나뿐이면 목록은 묶지 않은 그대로다.
- 목록 머리의 파일 수는 바뀐 파일의 수이고 행의 수가 아니다. 묶음의 머리는 그 묶음의 파일 수를 보인다.
- 찾기, 종류, 검토하지 않은 것만 보기는 행에 걸린다. 행이 남지 않은 묶음은 보이지 않는다.
- 생성 · 잠금 파일은 지금처럼 목록 끝의 접힌 묶음 하나에 있고 실행별로 나누지 않는다.
- 검토는 보이는 목록의 첫 행의 파일로 열린다. 다음 · 이전 파일 이동은 보이는 순서대로 파일을 한 번씩만 지난다.
- 비교 범위 선택에는 대화 전체, 읽음 기록이 있을 때의 읽음 기록 이후, 그리고 지금 고른 실행만 있다. 다른 실행의 비교는 그 묶음의 머리나 대화의 변경 링크로 연다. 바꾼 것을 뒤의 실행이 모두 되돌린 실행은 묶음이 없으므로 그 비교는 대화에서 연다.
- 읽음 기록 이후 범위와 실행 범위의 목록은 묶지 않는다. 브라우저 데모도 묶지 않는다.

## 계약

- `GET /api/v1/sessions/:sessionId/changes`는 `scope=session`과 함께 `group=run`을 받는다. 다른 범위에 `group`을 주면 `SCHEMA_INVALID`다. `group`이 없는 조회는 전과 같고 비용이 늘지 않는다.
- `group=run`의 응답은 구간이 있는 실행의 ID를 시작한 순서로 `runs`에 싣고, 파일마다 `runs`(그 파일이 바뀐 동안 돌던 실행의 ID)와 `outsideRuns`(불리언)를 싣는다. 이 필드들이 없는 응답은 묶지 않은 목록이다.
- 묶는 규칙은 구간이다. 세션의 기준 tree에서 응답의 `to` tree까지를 실행의 시작 tree와 끝 tree로 끊고, 잡은 순서대로 늘어놓는다(같은 시각이면 기록한 순서). 이웃한 두 tree 사이에 경로가 바뀌었으면 그 파일은 그 사이에 돌던 모든 실행의 `runs`에 든다. 돌던 실행이 없는 사이였으면 `outsideRuns`가 참이다.
- 마지막 점은 응답의 `to`와 같은 tree다. 사본을 두 번 읽지 않는다.
- 파일의 `runs`도 실행을 시작한 순서다. 화면은 응답의 순서로 묶음을 놓으므로 실행 목록을 기다리지 않는다.
- 응답의 모든 파일은 `runs`가 비어 있지 않거나 `outsideRuns`가 참이다. 화면이 거르거나 접어 보이지 않는 행은 이 불변식과 상관없다.
- 구간이 없는 실행: 시작 tree가 기록되지 않은 실행, 끝났는데 끝 tree가 기록되지 않은 실행, 지금 사본이 만들어지기 전에 돈 실행. 그 실행 동안의 변경은 `outsideRuns`로 간다.
- 진행 중인 실행의 구간은 `to`까지다. 막 끝난 실행의 끝 tree를 잡는 중이면 기다린 뒤 읽는다.
- 실행이 겹쳐 돌았으면 겹친 동안 바뀐 파일은 겹친 실행 모두에 든다.
- 비교는 이름 변경을 따라가지 않는다. 이름을 바꾼 파일은 삭제와 추가 두 파일이다.
- 조회는 실행 기록과 스냅샷을 만들거나 바꾸지 않는다.

## 수용 시나리오

```gherkin
Given 실행 #1이 셸 명령으로 a.txt를 바꾸고 끝났다
And 그 뒤 사람이 터미널에서 b.txt를 만들었다
When 대화 전체 범위의 변경 검토를 연다
Then "실행 #1" 묶음에 a.txt가, "실행 밖" 묶음에 b.txt가 있다

Given 실행 #1이 a.txt를 바꾸고 끝난 뒤 사람이 a.txt를 다시 고쳤다
When 대화 전체 범위의 변경 검토를 연다
Then a.txt의 행이 "실행 #1"과 "실행 밖" 양쪽에 있다
And 어느 행을 골라도 같은 비교가 열린다
And 목록 머리의 파일 수는 1이다

Given 실행 #1이 a.txt를 바꿨고 실행 #2가 그것을 처음대로 되돌렸다
When 대화 전체 범위의 변경 검토를 연다
Then a.txt는 목록에 없고 두 실행의 묶음도 없다

Given 끝난 실행 #1의 끝 tree가 기록되지 않았다
When 대화 전체 범위의 변경 검토를 연다
Then 그 실행 동안 바뀐 파일은 "실행 밖"에 있고 0개 변경으로 보이지 않는다

Given 묶음이 "실행 #2"와 "실행 #1" 둘이다
When "실행 #1"의 머리를 누른다
Then 비교 범위가 실행 #1이 되고 범위 선택에 "실행 #1"이 고른 것으로 보인다

Given 바뀐 파일이 모두 실행 #1 동안 바뀌었다
When 대화 전체 범위의 변경 검토를 연다
Then 목록은 묶음의 머리 없이 파일만 보인다
```

## 보안·성능·접근성

- 응답에 새로 실리는 것은 그 세션의 실행 ID뿐이다. 요청 본문이나 경로 밖의 것을 싣지 않는다.
- 구간 하나에 Git 호출이 한 번이고, 양 끝 tree가 같은 구간은 호출하지 않는다. 파일 탭과 첨부 확인처럼 묶음을 보이지 않는 조회는 `group` 없이 읽는다.
- 묶음은 제목이 있는 목록이다. 실행 묶음의 머리 버튼은 "실행 #n"과 파일 수로 읽힌다. 같은 파일의 행이 여럿이어도 각 행의 이름은 지금과 같다.
