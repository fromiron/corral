# 팀 공통 Outrider

팀 구조의 **공통 Outrider 추가**에서 모델, 검토 원칙과 대상을 설정한다. **팀 전체**이면 나중에 추가한 작업자도 질문할 수 있다. **직접 선택**이면 선택한 작업자만 질문할 수 있다. 팀 구조에서 설정을 다시 열어 대상 명단과 한도 때문에 질문할 수 없는 이유를 확인하고 설정을 바꾸거나 제거할 수 있다. 설정 적용과 제거는 각각 되돌리기 한 단계다. 취소와 같은 값 적용은 작업 사본을 바꾸지 않는다.

직접 선택한 작업자나 참조 팀을 삭제하면 그 작업자와 삭제한 참조의 구성원을 선택 대상에서도 뺀다. 다른 작업자와 참조 팀의 선택은 보존한다. 삭제를 되돌리면 선택도 복구된다. 나중에 같은 ID를 받은 새 작업자는 직접 고를 때까지 자문 대상에 들지 않는다.

작업자에 고정된 Harness가 있으면 편집기는 해당 프로젝트와 revision의 유효 도구를 조회한다. `ask`가 없는 작업자는 대상 명단과 작업자 설정에 그 이유를 보이고, 아직 읽지 못한 권한은 확인되지 않았다고 표시한다. 편집기의 조회 결과는 실행 권한을 부여하지 않는다.

## 요청형 자문

작업자가 필요할 때 질문하면 같은 공통 Outrider가 그 질문에 답한다. 질문마다 요청자에게 속한 응답 작업이 생기고 그 질문의 허용된 자료를 받는다. 답은 요청자의 해당 질문으로만 돌아간다. 기록에서 질문 가능 대상, 실제 질문의 대기와 답변을 구별한다. 질문이 없으면 응답 작업이나 조언자 모델 호출도 없다. 실행 순서와 최종 산출물 출처는 그대로다.

팀 정의의 선택 필드 `sharedOutrider`는 모델 프로필, 검토 원칙, 전체 또는 선택 대상 노드 ID를 보관한다. 저장, 복제와 JSON 내보내기·가져오기는 그 선택을 보존한다. 편집기와 실행기는 같은 규칙으로 이번 실행에서 질문할 수 있는 작업자를 계산한다. 인라인 상자의 작업자와 고정 revision 참조 팀의 실행 사본에 속하는 작업자도 포함한다. 대상은 작업하는 scheduled·callable 에이전트이며 관찰자나 공통 조언자는 포함되지 않는다.

자문은 실행 사본에만 질문 허용 관계와 응답용 callable 역할을 더한다. 작업자의 기존 권한과 수동 질문 관계는 설정을 해제해도 보존된다. 응답 역할에는 답변과 허용된 읽기만 준다. 권한과 질문·시간·동시성·깊이·동적 실행 한도는 [협업 계약](../product-contract.md)의 적용을 받는다. 한 요청의 실패·취소·시간 초과는 해당 요청자에게 알려지며 닫힌 질문에 늦은 답을 실을 수 없다. 이미 시작한 실행은 고정된 설정을 쓴다.

공통 조언자에게 실제로 보낸 질문에는 `message.question_created`의 선택 표시 `sharedOutrider: true`가 붙는다. 기록에서 열린 공통 질문은 ‘답변 대기’, 답이 확정된 질문은 ‘답변 받음’으로 보이고, 취소·시간 초과는 각각의 종료 상태를 표시한다.

이 필드가 없는 팀의 동작과 [관찰형 Outrider](advisor.md)의 지시 전달 경로는 기존과 같다. 사용자에게 보이는 이름이나 기존 질문 연결에서 공통 설정을 추정하지 않는다. [편집 시나리오](canvas.feature)

## 요청할 때 산출물 리뷰

팀 공통 Outrider 설정의 **산출물 리뷰**는 기본으로 꺼져 있다. 켜면 **요청할 때** 적용되며 정의의 `sharedOutrider.artifactReview: true`에 저장한다. 적용·제거·되돌리기·재열기와 실행 스냅샷은 공통 설정과 같은 규칙을 따른다. 설정 자체로 검토를 시작하거나 제출을 막지 않는다.

작업자는 자신의 읽기 범위에 있는 정확한 산출물 버전을 골라 공통 Outrider에게 수정 의견을 요청한다. `ask`의 선택 인자 `reviewArtifactVersionId`가 이 버전을 지정하며, 질문의 `artifactRefs`에 해당 버전이 한 번 포함된다. 서버는 해당 실행 스냅샷의 리뷰 허용 대상과 요청자의 읽기 권한을 확인한 뒤 기존 질문을 연다. 권한이 없거나 버전을 읽을 수 없으면 응답 작업을 만들지 않는다. 이 인자가 없는 질문은 자료를 첨부해도 일반 자문이다. 리뷰를 꺼도 질문할 수 있다.

시험 기록은 질문 ID와 `message.question_created.reviewArtifactVersionId`를 사용해 요청자, 응답 Outrider, 리뷰한 버전과 의견을 함께 보여준다. 다음 버전이 작성돼도 V1에 대한 의견은 V1에 남는다. 기존 산출물 수명 규칙에 따라 본문을 읽을 수 있는 동안만 해당 버전을 연다. 읽을 수 없게 된 버전은 그 버전의 식별 정보와 의견을 보존하고 본문을 열 수 없음을 알린다.

원래 생산자가 의견을 받아 새 버전을 직접 제출하거나 원래 버전을 그대로 제출한다. 시험 패널에는 `output.finalized`로 확정된 버전마다 제출자와 버전을 표시하고 그 버전을 열 수 있다. 리뷰 답 자체로 수정 완료나 필수 통과 상태를 만들지 않는다.
