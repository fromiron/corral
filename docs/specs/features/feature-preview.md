# 기능 명세: 기능 미리보기

- 상태: accepted
- 비목표: 실제 작업 보드·PR 연동·브라우저 자동화, 샘플 데이터의 저장·내보내기

## 사용자 관측 동작

아직 백엔드가 없는 기능의 흐름을 샘플 데이터로 보여 주는 화면이다. `/preview`는 목록이고 `/preview/$feature`는 개별 미리보기다.

| feature | 흐름 |
|---|---|
| `task-board` | 프로젝트 작업 보드: 작업 목록 → 상세(단계·파일·연결 세션) → 상태 변경 → 결과 |
| `pr-review` | PR 요약·검사·댓글: 목록 → diff와 검사 → 댓글·수정 요청 → 결과 |
| `browser-qa` | 브라우저 QA: 열기 → 스냅숏 → 조작 → 콘솔 오류 → 스크린샷 → 대화 첨부 |

- 진입점은 링크뿐이다:
  - 사이드바 하단 "기능 미리보기"
  - 프로젝트 작업공간 머리 더 보기 메뉴의 "작업 보드 미리보기"
  - 변경 탭 더 보기 메뉴의 "PR 미리보기"
  - 미리보기 창의 "브라우저 QA 미리보기"
  
  링크는 `returnTo`를 담고, 미리보기의 돌아가기는 원래 화면으로 간다. 실제 화면 안에 샘플 내용을 그리지 않는다.
- 모든 미리보기 화면은 상단에 "미리보기 · 샘플 데이터"를 계속 보인다. 사용자가 한 행동의 결과에는 "시뮬레이션"이 붙는다.
- "초기화"는 샘플 상태를 처음으로 되돌린다.

## 계약

- 샘플 데이터는 `apps/studio/src/feature-preview/` 안의 fixture 하나가 정의한다. 미리보기들은 같은 프로젝트·세션·실행·파일 이름과 고정 기준 시각을 공유한다.
- 상태는 미리보기 전용 store에만 둔다. 실제 세션·실행·inbox·사용량·배지·알림에 샘플 값을 더하지 않는다.
- 미리보기 코드는 `services.tsx`·`@corral/client`·transport를 쓰지 않는다. API·Git·파일·모델·예약·승인 요청을 보내지 않는다.
- 컴포넌트 안에 타이머를 두지 않는다. 진행처럼 보이는 값은 고정 기준 시각과 `useNow`로 계산한다.
- 실제 연결 실패를 미리보기로 대체하지 않는다.

## 수용 시나리오

```gherkin
Given 작업 보드 미리보기를 연다
When 작업 하나의 상태를 "완료"로 바꾼다
Then 그 작업에 "시뮬레이션" 표시가 붙고 서버 요청은 0회다
And 사이드바·확인 필요의 수는 바뀌지 않는다
When 초기화를 누른다
Then 처음 상태로 돌아간다
```

## 보안·성능·접근성

- import 경계 테스트와 모든 호출에서 실패하는 services stub·fetch spy 테스트로 실제 호출이 없음을 고정한다.
- 샘플 경로·이름은 실제 사용자 정보처럼 보이지 않는 예시만 쓴다.
