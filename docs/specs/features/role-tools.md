- 비목표: MCP 연결의 등록·신뢰·인증 화면 이동(지금의 리소스 관리가 맡는다), 도구 선택으로 권한 주기, `strict` 정책에서 MCP 쓰기, 도구 목록의 서버 저장, MCP 리소스(문서) 읽기를 역할별로 고르기, Outrider·관찰 전용 역할의 도구 선택

## 사용자 관측 동작

조사자만 이슈를 검색하게 하려면 그 역할에 **이슈 검색** 도구 하나만 고른다. 같은 연결의 다른 도구(이슈 수정)와 나중에 그 연결에 생긴 도구는 따라오지 않는다. 다른 역할은 그 도구를 부를 수 없다.

### 팀원과 에이전트 원본의 외부 도구

1. 팀원 설정과 에이전트 원본 편집에서 **사용할 스킬** 다음에 **외부 도구**가 있다. 고른 도구를 **연결 이름 · 도구 이름**으로 보이고, 각 항목에 **선택 해제**가 있다. 아무것도 고르지 않은 역할에는 **도구 추가**만 보인다.
2. **도구 추가**는 선택기를 연다. 이 프로젝트에 등록된 MCP 연결을 보이고, 연결마다 상태(사용 가능, 신뢰 필요, 로그인 필요, 꺼짐)를 말한다. 연결을 고르면 그 연결의 도구를 확인한다. 도구 확인은 지금의 연결 검사를 쓴다: 신뢰하고 인증한 연결에서만 되고, stdio 연결은 대화의 Paddock을 골라야 한다. 확인하지 못하면 이유와 **연결 관리**로 가는 동작을 보인다.
3. 확인된 도구를 여러 개 체크한다. 이미 고른 것은 체크돼 있다. 주 동작은 대상을 말한다: 팀원이면 **{이름}에게 적용**, 원본이면 **에이전트 원본에 적용**. 적용은 한 번이고 팀에서는 되돌리기 한 번으로 돌아간다. 바꾼 것이 없으면 적용할 수 없고 **취소**는 역할을 바꾸지 않는다.
4. 등록된 연결이 있을 때만 검색란을 보인다. 연결이 없으면 그 사실을, 목록을 읽지 못하면 실패 상태와 **다시 시도**를 보인다. 두 경우 모두 **연결 관리**에 초점을 둔다. 연결 관리는 현재 프로젝트의 **설정 › MCP 연결**을 편집 중인 화면 위에 연다. 설정을 닫으면 같은 팀원이나 원본과 선택기의 미적용 선택이 그대로 남고 연결 목록을 다시 읽는다.
5. 도구를 고르는 것은 권한을 주지 않는다. 고른 도구는 그 역할의 실행 정책이 MCP를 허용하고 그 연결과 그 도구를 허용할 때만 쓰인다. 그렇지 않으면 그 항목에 이유와 복구 동작을 보인다.
   - 실행 정책이 없거나 `strict`다: **실행 정책 고르기**(상세 설정의 실행 정책으로 간다).
   - 정책이 그 연결을 고르지 않았거나 그 도구를 허용하지 않는다: 같은 동작.
   - 연결이 지워졌거나 꺼졌다: **연결 관리 / 선택 해제**.
   선택을 조용히 빼지 않는다. 고치기 전에는 실제 모델 실행을 시작할 수 없다.
6. 모의 시험은 외부 도구를 부르지 않는다. 고른 도구가 있는 팀원에는 그 사실을 한 줄로 알린다.
7. 실행의 **적용된 Harness**는 그 역할이 받은 MCP 연결과 정확한 도구 이름을 보인다. 차단된 호출은 실행 기록에 차단으로 남는다.
8. 브라우저 데모에서는 **로컬 서버에서 사용** 한 줄을 보인다.

### 원본과 사본

9. 에이전트 원본의 도구 선택은 팀에 추가할 때 사본으로 복사된다. 한 팀원에서 고치면 그 자리만 달라지고, 한 역할을 여러 자리가 함께 쓰면 그 자리의 사본을 만든다([에이전트 라이브러리](agent-library.md)).
10. 교체 미리보기는 도구 선택의 차이를 **도구와 권한**에 넣는다.

## 계약

- **필드.** `AgentRole.mcpTools`는 `{ serverId, name }`의 목록이다. `name`은 허용 목록과 실행 이벤트가 쓰는 정확한 도구 식별자(`mcp__<serverId>__…`)다. 같은 항목은 한 번만 저장한다. 필드가 없으면 이 기능이 생기기 전과 같다. 팀을 열거나 저장하는 것으로 필드를 채우지 않는다. Outrider·관찰 전용 역할로 바꾸면 필드를 지운다.
- **해석.** 한 가지 해석 경로와 표는 [하네스 계약](../harness-contract.md#역할의-mcp-도구-선택)에 있다. 선택은 계층 병합 결과를 **좁히기만** 한다.
- **스냅샷.** 실행 스냅샷의 허용 도구에는 고른 식별자만 남고, MCP 연결은 고른 도구의 연결만 남는다. 프로젝트 도구 설정의 revision과 해시를 함께 고정한다. 선택으로 유효한 도구나 연결이 달라지면 스냅샷 해시가 달라진다. 선택을 명시했다는 사실만으로는 해시를 바꾸지 않는다. 시작한 Run은 시작 때의 스냅샷으로 끝난다.
- **기존 규칙.** 연결의 신뢰·인증·승인·취소, 실행 직전의 신뢰 재확인, 모의 실행의 MCP 거절, 검토 전용 요청과 격리 모델의 MCP 거절은 그대로다.
- **도구 목록.** 선택기는 연결 검사(`probeMcp`)의 결과만 쓴다. 서버는 도구 목록을 저장하지 않는다. 검사는 한 번에 하나다.
- **저장 범위.** 연결의 주소·인증 정보·검사 응답 본문은 팀 정의와 에이전트 원본에 저장하지 않는다. 연결 id와 도구 식별자만 저장한다.

## 수용 시나리오

```gherkin
Given 도구 두 개(search_issues, update_issue)를 가진 신뢰한 MCP 연결과 그 연결을 허용하는 실행 정책이 있다
And 조사자에게 그 정책을 고르고 외부 도구로 search_issues만 골랐다
When 실제 모델 실행에서 조사자가 search_issues를 부른다
Then 호출이 실행되고 연결의 호출 수가 1 늘어난다
When 조사자가 update_issue를 부른다
Then 호출은 차단으로 기록되고 연결의 호출 수는 그대로다

Given 위 팀에서 연결에 새 도구 close_issue가 생겼다
When 같은 팀을 다시 실행한다
Then 조사자는 close_issue를 쓸 수 없다

Given 같은 팀의 작성자는 도구를 고르지 않았고 실행 정책이 없다
When 작성자가 search_issues를 부르려 한다
Then 그 도구는 작성자의 실행에 없다

Given 실행 정책이 없는 역할에 외부 도구를 골랐다
Then 그 항목에 실행 정책이 필요하다는 이유와 "실행 정책 고르기"가 보인다
And 실제 모델 실행은 시작되지 않고 모델 요청은 0회다

Given 고른 도구의 연결을 리소스 관리에서 지웠다
Then 팀원 설정에 그 항목과 "연결 관리 / 선택 해제"가 보이고 선택은 남아 있다

Given 실행 정책이 허용한 도구가 셋인 역할에 빈 목록을 저장했다
Then 그 역할의 실행에는 MCP 도구가 없다

Given 도구 선택기에서 두 도구를 체크했다
When 취소한다
Then 역할과 되돌리기 기록은 그대로다
When 다시 체크하고 적용한 뒤 되돌리기를 한 번 한다
Then 두 도구가 함께 빠진다

Given 실행 중 사람이 실행을 취소했다
Then 진행 중이던 MCP 호출은 취소로 기록되고 늦게 온 결과는 반영되지 않는다
```

## 보안·성능·접근성

- 선택은 권한을 넓히지 못한다. `strict`의 MCP 금지, 허용 도구의 교집합, 연결별 신뢰와 인증은 선택과 무관하게 유지된다.
- 식별자는 정리된 공급자 이름이다. 연결이 도구를 지우고 정리했을 때 같은 이름이 되는 다른 도구를 만들면 같은 식별자를 물려받는다. 연결 설정이 바뀌면 신뢰를 다시 받는 규칙이 이 경우를 막는 장치다.
- 선택기를 여는 것만으로는 검사를 시작하지 않는다. 사람이 연결을 골라 도구 확인을 눌렀을 때 시작하고, 닫으면 취소한다.
- 선택기는 이름 있는 대화상자이고 연결 상태·이유·선택을 색만으로 알리지 않는다. 키보드로 연결 선택, 도구 체크, 적용을 할 수 있다.
