# 기능 명세: 세션 증거 요약

- 상태: accepted
- 비목표: 완료를 확정하는 새 원장, "검증됨"·"기준 충족" 같은 판정, 목록에서 현재 tree와의 정확한 일치 계산, LLM 요약, 인박스 항목 종류 추가

## 사용자 관측 동작

프로젝트의 세션 탭에서 세션 행은 그 세션에 이미 기록된 세 가지 사실을 보인다. 세션을 열지 않고 "검사했는가, 사람이 판단했는가, 원본에 반영했는가"를 본다.

| 사실 | 보이는 말 | 출처 |
|---|---|---|
| 검사 | 검사 통과 / 검사 뒤 변경됨 | 세션의 가장 최근 검사 기록 |
| 판단 | 승인함 / 수정 요청함 | 세션의 가장 최근 검토 판단 |
| 반영 | 반영함 | 세션의 가장 최근 반영 기록 |

- 사실은 행의 보조 줄 앞쪽에 검사 · 판단 · 반영 순서로 놓인다. 기록이 없는 사실은 자리를 차지하지 않는다.
- **검사**: 가장 최근 검사가 끝났고 판정이 통과일 때만 보인다. 그 검사 뒤에 Corral이 기록한 파일 쓰기가 있으면 "검사 통과"가 아니라 "검사 뒤 변경됨"을 보인다. 실패·오류·취소·판정 불가인 검사는 통과로 보이지 않는다. 실패와 오류는 검토 묶음의 "검사 실패"가 이미 보이므로 다시 쓰지 않는다.
- **판단**: 가장 최근 판단을 보인다. 그 판단 뒤에 Corral이 기록한 파일 쓰기가 있으면 보이지 않는다. 그 경우는 검토 묶음의 "확인하지 않은 파일 쓰기"가 맡는다.
- **반영**: 가장 최근 반영이 끝까지 적용됐을 때만 보인다. 부분 적용·충돌·실패는 검토 묶음의 "반영이 깔끔하게 끝나지 않음"이 맡는다.
- 이 사실들은 묶음을 바꾸지 않는다. 묶음 규칙은 [세션 목록의 상태와 처리할 항목](../workbench.md#세션-목록의-상태와-처리할-항목)이 정한다.
- 검사의 이름은 행에 보이지 않는다. 이름과 결과는 세션의 검사 보기에 있다.
- "검사 뒤 변경됨"과 검토 묶음의 "확인하지 않은 파일 쓰기"는 한 행에 함께 보일 수 있다. 앞은 검사가 낡았다는 사실이고 뒤는 사람이 아직 보지 않은 쓰기가 있다는 사실이다.
- 화면은 "검증됨", "완료 확인", "기준 충족"이라고 쓰지 않는다. 정확한 현재 유효성(검사한 tree와 지금 tree의 일치)은 세션의 검사 보기가 계산해 보인다.

## 계약

- `GET /api/v1/projects/:projectId/session-evidence`는 읽기 전용이며 `SessionEvidenceView[]`를 돌려준다. 보관하지 않은 세션마다 한 항목이다.

  | 필드 | 값 |
  |---|---|
  | `sessionId` | 세션 식별자 |
  | `check` | `{ name, verdict, writesSince } \| null`. 가장 최근 검사가 `completed`일 때만 값이 있다. `verdict`는 `pass`·`fail`·`inconclusive`·`not_evaluated` |
  | `decision` | `{ decision, writesSince } \| null`. `decision`은 `approved`·`changes_requested` |
  | `integration` | 가장 최근 반영의 상태 또는 `null` |

- `writesSince`는 그 기록의 시각 뒤에 그 세션에 적용된 파일 쓰기 기록이 하나라도 있는지다. 검사는 검사한 tree를 잡은 시작 시각을, 판단과 반영은 기록한 시각을 기준으로 하고, 쓰기는 접수한 시각으로 비교한다. 그래서 검사가 도는 동안의 쓰기도 "뒤의 쓰기"다. 기록 시각만 비교하며 Git을 읽지 않는다. 터미널이나 외부 편집기가 직접 바꾼 변경은 잡히지 않는다.
- 응답은 요청 본문, 파일 경로, 검사 출력, 판단 메모를 담지 않는다. 검사의 이름은 그 검사를 돌릴 때 기록된 설정 이름이다. 그 뒤 설정에서 이름을 바꾸거나 지워도 기록된 이름을 보인다.
- 이 조회는 검사·판단·반영·세션·실행의 어떤 상태도 바꾸지 않고, 검사를 실행하지 않는다.
- 조회는 세션 수와 상관없이 표마다 한 번의 질의로 읽는다.
- 프로젝트가 없으면 404 `TARGET_NOT_FOUND`다. 보관한 프로젝트는 세션을 그대로 돌려준다. 브라우저 데모처럼 서버 작업공간이 없으면 화면은 이 조회를 하지 않고 사실을 보이지 않는다.
- 화면은 세션 탭이 인박스를 읽는 때에 함께 읽는다. 조회가 실패하면 사실을 보이지 않고 마지막으로 읽은 값도 지우며, 인박스와 같은 한 줄로 실패와 다시 시도를 보인다. 그 줄은 무엇을 읽지 못했는지(검토할 항목, 검사·판단·반영 기록, 또는 둘 다)를 말하고 다시 시도는 둘을 함께 읽는다. 실패를 "기록 없음"으로 보이지 않는다.

## 수용 시나리오

```gherkin
Given 세션 A의 가장 최근 검사가 통과로 끝났고 그 뒤 파일 쓰기가 없다
When 프로젝트 세션 탭을 연다
Then A의 행에 "검사 통과"가 보인다

Given 세션 A의 검사 통과 뒤에 Corral이 파일을 썼다
When 세션 탭을 연다
Then A의 행에 "검사 뒤 변경됨"이 보이고 "검사 통과"는 어디에도 없다

Given 세션 B의 가장 최근 검사가 취소됐거나 판정 불가다
Then B의 행에 검사 사실이 없다

Given 세션 C를 승인했고 그 뒤 파일 쓰기가 없으며 반영이 끝까지 적용됐다
Then C의 행에 "승인함 · 반영함"이 이 순서로 보인다

Given 세션 C를 승인한 뒤 Corral이 파일을 썼다
Then C의 행에 "승인함"이 없고 C는 검토 묶음에 "확인하지 않은 파일 쓰기"로 있다

Given 증거 조회가 실패했다
Then 어떤 행에도 검사·판단·반영 사실이 없고 실패와 다시 시도가 한 줄로 보인다
And "기록 없음"으로 읽히는 표시는 없다

Given 증거 조회의 응답을 받았다
Then 응답에 요청 본문, 파일 경로, 검사 출력, 판단 메모가 없다
```

## 보안·성능·접근성

- 로컬 경로와 사용자 메시지 본문을 응답과 로그에 넣지 않는다.
- 질의는 세션마다 반복하지 않는다. 세션 300개인 프로젝트에서 응답 시간을 한 번 재서 기록한다.
- 사실은 글자로 보이며 색만으로 구분하지 않는다. 행의 접근 가능한 이름은 바뀌지 않고, 사실은 보조 줄의 일부로 읽힌다.
