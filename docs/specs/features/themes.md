# 기능 명세: 화면 테마와 개인 테마

- 상태: accepted
- 비목표: 레이아웃·컴포넌트·글꼴·모서리·여백을 테마로 바꾸기, VS Code·iTerm 등 다른 도구의 테마 파일 읽기, 테마 공유 서버, 프로젝트나 세션마다 다른 테마, 운영체제 밝기에 따라 이름 있는 테마 둘을 번갈아 쓰기, 창 여러 개 사이의 즉시 동기화

## 사용자 관측 동작

설정 › 일반의 **화면 테마**는 하나의 선택이다. 선택지는 이름 목록이 아니라 카드로 보인다. 카드마다 그 테마의 색으로 그린 작은 견본(표면, 글자, 강조, 코드 몇 줄)과 이름이 있어, 고르기 전에 어떤 모습인지 보인다. 시스템 카드는 라이트와 다크를 반씩 보인다. 지금 적용 중인 카드 하나만 선택 표시를 갖는다. 화살표 키로 옮기면 옮긴 카드가 곧바로 적용된다. 선택지는 세 묶음이다.

1. 시스템 · 라이트 · 다크. 디자인킷의 기본 색이고 화면은 테마 기능이 없을 때와 같다. 시스템은 운영체제의 밝기를 따른다.
2. 내장 테마. 널리 쓰이는 편집기 색 구성을 Corral 화면에 맞춘 것이다. 목록과 출처는 [THIRD-PARTY-NOTICES/themes.md](../../../THIRD-PARTY-NOTICES/themes.md)가 소유한다.
3. 개인 테마. 이 기기에서 만든 테마다.

테마를 고르면 곧바로 앱 전체에 적용된다. 바뀌는 것은 색뿐이다: 표면, 글자, 테두리, 선택·호버, 상태 색(오류·성공·주의·정보), 강조와 포커스, 코드 구문 색(편집기, 변경 비교, 대화의 코드 블록), 터미널의 16색. 레이아웃, 컴포넌트, 인터페이스 밀도, 열린 문서와 터미널의 내용은 그대로다. 편집기와 터미널은 다시 만들지 않고 색만 바꾼다.

앱을 다시 열면 첫 화면부터 고른 테마로 그린다. 기본 색으로 잠깐 그렸다가 바뀌지 않는다.

### 개인 테마

개인 테마도 같은 카드다. 카드의 메뉴에 편집 · 내보내기 · 삭제가 있다. 개인 테마 묶음의 마지막 자리는 **새 테마** 카드이고, 묶음 머리에 **가져오기**가 있다. 개인 테마가 없으면 묶음에는 가져오기와 새 테마 카드만 있다. 이름을 따로 나열한 목록은 두지 않는다.

- **새 테마**는 지금 적용 중인 테마를 복제해 편집 화면을 연다. 시스템이면 지금 보이는 쪽(라이트 또는 다크)을 복제한다. 기본 색을 복제한 개인 테마는 그때 화면에 쓰인 색에서 시작하고, 표면 단계는 테마 계산을 따르므로 킷 기본과 조금 다를 수 있다.
- **편집 화면**은 이름, 밝기 기준(라이트/다크), 색을 세 묶음으로 보인다: 기본 색(배경, 글자, 보조 글자, 강조, 선택, 오류, 성공, 주의, 정보), 코드 색(주석, 키워드, 문자열, 숫자, 함수, 타입, 변수, 상수), 터미널 색(16색). 색마다 견본 타일이 있고, 누르면 킷의 색 선택기(색 영역, 색상 슬라이더, `#rrggbb` 입력, 그 테마의 색 견본, 지원하는 브라우저에서는 스포이트)가 열린다. 투명도와 다른 색 형식은 없다. 터미널 16색은 기본 여덟 색과 밝은 여덟 색의 두 줄 타일로 보인다.
  - 색을 바꾸면 앱 전체가 그 색으로 곧바로 보인다(미리보기). 편집 화면의 견본은 넓은 화면에서 색을 고르는 동안 계속 보이고, 좁은 화면에서는 색 위에 놓인다. 견본은 본문·보조 글자, 버튼, 선택된 행, 상태 표시, 코드 한 토막, 터미널 16색을 함께 보인다.
  - 글자로 쓰이는 색(글자, 보조 글자, 강조, 오류, 성공, 주의, 정보)은 색 선택기 안에 배경과의 대비 값을 보인다. 4.5:1에 못 미치면 그 색의 타일 옆에도 값과 함께 낮은 대비로 표시한다. 기준을 넘는 색 옆에는 값을 적지 않는다. 저장은 막지 않는다.
  - **저장**하면 개인 테마 카드로 남고 그 테마가 적용된다. 이름이 1~40자가 아니거나 다른 개인 테마가 쓰는 이름이면 저장하지 않고 이름 칸을 표시한다. 새 테마의 처음 이름은 복제한 테마의 이름에 번호를 붙인 것이다. **취소**(또는 Escape)하면 편집 전에 쓰던 테마로 돌아가고 바꾼 색은 버린다. 바꾼 것이 있으면 버리기 전에 확인한다.
- **내보내기**는 그 테마 하나를 Corral 테마 JSON 파일로 내려받는다. 파일 이름은 테마 이름에서 파일 이름에 쓸 수 없는 글자를 뺀 것이다.
- **가져오기**는 Corral 테마 JSON 파일을 읽어 개인 테마로 더한다. 더하기만 하고 적용하지는 않는다. 형식이 맞지 않으면 아무것도 더하지 않고 이유를 보인다.
- **삭제**는 확인 뒤 지운다. 적용 중인 테마를 지우면 그 테마의 밝기 기준에 맞는 라이트 또는 다크로 돌아간다.

## 계약

### 테마

테마는 다음 값으로만 이루어진다. 색은 모두 `#rrggbb`(소문자·대문자 모두 받고 소문자로 저장)이다.

| 필드 | 값 |
|---|---|
| `name` | 앞뒤 공백을 뺀 1~40자 |
| `base` | `light` 또는 `dark`. `color-scheme`, 킷의 오버레이·그림자 조합, 데스크톱 창의 밝기에 쓴다 |
| `ui` | `background`, `foreground`, `muted`, `emphasis`, `selection`, `error`, `success`, `warning`, `info` |
| `syntax` | `comment`, `keyword`, `string`, `number`, `function`, `type`, `variable`, `constant` |
| `terminal` | 16색 배열. 순서는 ANSI 0~15(검정, 빨강, 초록, 노랑, 파랑, 자홍, 청록, 흰색, 이어서 밝은 여덟 색) |

- 나머지 토큰(표면 단계 2~8, 조용한 채움, 버튼·행의 채움, 테두리, 입력 테두리, 선택된 행, 포커스 링, 강조의 호버 값, 채운 오류 표면 위의 글자색)은 위 값에서 **한 함수**가 계산한다. 내장 테마와 개인 테마가 같은 함수를 쓴다. 그래서 내장 테마를 복제해 저장한 개인 테마는 원본과 같은 화면을 낸다. 호버·눌림 오버레이, 그림자, 대화상자 가림막은 계산하지 않고 킷의 반투명 값을 테마의 `base`에 맞춰 쓴다.
- 테마 값은 테마 모듈 한 곳에만 있다. 컴포넌트는 지금처럼 토큰만 쓰고 색 값을 직접 쓰지 않는다([DESIGN.md](../../../DESIGN.md)의 킷 규칙).
- 테마는 문서 루트의 킷 토큰 값을 덮어써서 적용한다. 킷 토큰 파일과 Corral 테마 파일의 기본값은 바꾸지 않는다.

### 선택과 저장

- 환경설정에 `palette`가 더해진다: 없음(기본 색), 내장 테마 ID, 개인 테마 ID 중 하나다. 기존 `theme`(시스템/라이트/다크)의 뜻과 금고 내보내기 형식은 바뀌지 않는다.
  - 시스템·라이트·다크를 고르면 `theme`을 그 값으로 하고 `palette`를 비운다.
  - 이름 있는 테마를 고르면 `palette`를 그 ID로 하고 `theme`을 그 테마의 `base`로 한다. 그래서 금고 내보내기에는 밝기만 실린다.
  - 금고에서 가져온 환경설정이 `theme`을 지금과 다른 값으로 바꾸면 `palette`를 비운다. 같으면 그대로 둔다.
- `palette`가 가리키는 테마를 찾을 수 없거나 읽을 수 없으면 `theme`만으로 그리고 `palette`를 비운다.
- 개인 테마는 이 기기의 브라우저 저장소에만 둔다. 서버, 금고, 진단 복사, 로그로 보내지 않는다. 개수는 20개까지다. 넘으면 새 테마와 가져오기를 막고 이유를 보인다.
- 개인 테마 ID는 이 기기에서 만든다. 가져온 파일의 값으로 정하지 않는다.
- 저장소에 쓰지 못하면(용량, 차단) 저장을 실패로 알리고 편집 화면과 바꾼 색을 그대로 둔다. 저장된 것으로 표시하지 않는다.

### 테마 JSON

```json
{
  "corralTheme": 1,
  "name": "…",
  "base": "dark",
  "ui": { "background": "#272822", "…": "…" },
  "syntax": { "comment": "#88846f", "…": "…" },
  "terminal": ["#272822", "…"]
}
```

- 가져오기는 다음을 모두 만족할 때만 받는다: 파일 크기 64KB 이하, JSON 객체, `corralTheme`이 1, 위 표의 필드가 빠짐없이 있고 다른 필드가 없음, 모든 색이 `#rrggbb`, `terminal`이 정확히 16개. 하나라도 어긋나면 전체를 거절하고 일부만 받지 않는다.
- 같은 이름의 개인 테마가 이미 있으면 이름 뒤에 번호를 붙여 따로 더한다. 기존 테마를 덮어쓰지 않는다.
- 내보낸 파일을 다시 가져오면 이름(번호 제외)과 모든 색이 같다.
- 가져온 값은 색으로만 쓴다. 이름은 글자로만 표시한다. 스타일 시트나 HTML로 넣지 않는다.

### 적용 범위

- **편집기**(Monaco): 표면·글자·선택 색과 `syntax`의 구문 규칙을 받는다. 테마를 바꿔도 편집기를 다시 만들지 않는다.
- **터미널**(xterm): 배경·글자·커서·선택 색과 `terminal` 16색을 받는다. xterm의 최소 대비 보정(4.5:1)은 그대로 켜 둔다. 기본 색(시스템·라이트·다크)에서는 지금처럼 xterm의 기본 16색을 쓴다.
- **변경 비교·소스 보기**: 이름 있는 테마에서는 `syntax` 색으로 구문을 칠한다. 기본 색에서는 지금의 GitHub 라이트·다크 구문 색을 쓴다.
- **대화의 코드 블록**: 주석·문자열·숫자·키워드를 `syntax` 색으로 칠한다. 기본 색에서는 지금과 같은 색이다.
- **데스크톱 창**: 테마의 `base`가 다크인지를 지금의 창 테마 경로로 알린다. 새 IPC는 없다.
- 팀 그래프와 실행 그래프의 표면·글자·선은 토큰을 따라 함께 바뀐다.
- 분류를 나타내는 고정 색은 테마로 바뀌지 않는다: 배지의 색상, 팀 그래프의 종류 색, 에이전트 상태 아이콘의 색조, 도구 카드의 JSON 색, 편집기의 괄호 쌍 색. 관리형 미리보기와 파일 미리보기의 내용도 테마를 받지 않는다.

### 내장 테마

- 내장 테마의 `syntax`와 `terminal`은 출처 팔레트의 값을 그대로 쓴다. 출처에 터미널 색이 없으면 그 테마의 구문 색에서 고르고 고지 파일에 적는다.
- 내장 테마의 `ui`는 Corral의 대비 기준에 맞춰 조정할 수 있다: 본문·보조 글자·상태 색·강조가 표면 단계 1~5(바닥부터 대화상자·메뉴가 놓이는 단계까지) 위에서 4.5:1 이상이고, 선택된 행과 버튼·행의 채움 위의 본문도 4.5:1 이상이다. 눌림 오버레이가 겹친 순간은 이 기준에 넣지 않는다. 조정한 값은 고지 파일에 조정이라고 적는다.
- 팔레트의 출처와 라이선스를 확인하지 못한 테마는 넣지 않는다.

## 수용 시나리오

```gherkin
Given 화면 테마가 시스템이다
When 설정 › 일반에서 내장 테마 하나를 고른다
Then 설정을 닫지 않아도 앱의 표면·글자·상태 색이 그 테마로 바뀐다
And 열려 있던 문서와 터미널의 내용과 스크롤이 그대로다
And 편집기 구문 색과 터미널 16색이 그 테마의 값이다

Given 이름 있는 테마를 골라 둔 상태다
When 앱을 다시 연다
Then 첫 화면부터 그 테마로 그린다

Given 이름 있는 테마를 골라 둔 상태다
When 화면 테마에서 라이트를 고른다
Then 화면이 테마 기능이 없을 때의 라이트와 같다
And 변경 비교의 구문 색은 GitHub 라이트다

Given 내장 테마를 적용 중이다
When 새 테마를 눌러 이름만 바꾸고 저장한다
Then 개인 테마 목록에 그 이름이 있고 그 테마가 적용된다
And 화면의 색이 저장 전과 같다

Given 개인 테마 편집 화면에서 보조 글자 색을 배경과 3:1이 되게 바꿨다
Then 앱 전체의 보조 글자가 곧바로 그 색이다
And 그 색 옆에 낮은 대비 표시가 있다
When 취소하고 버리기를 확인한다
Then 편집 전에 쓰던 테마로 돌아가고 개인 테마 목록은 그대로다

Given 개인 테마 하나를 내보냈다
When 그 파일을 가져온다
Then 같은 색의 개인 테마가 번호가 붙은 이름으로 하나 더해진다
And 적용 중인 테마는 바뀌지 않는다

Given 색 하나가 "red; background: url(…)"인 테마 파일이 있다
When 가져온다
Then 아무 테마도 더해지지 않고 형식 오류를 보인다

Given 필드가 하나 더 있는 테마 파일, 터미널 색이 15개인 파일, 64KB를 넘는 파일이 있다
When 각각 가져온다
Then 모두 거절한다

Given 개인 테마가 20개다
Then 새 테마와 가져오기를 쓸 수 없고 이유가 보인다

Given 적용 중인 개인 테마가 있다
When 그 테마를 삭제한다
Then 그 테마의 밝기 기준에 맞는 라이트 또는 다크로 그린다

Given 환경설정이 가리키는 개인 테마가 저장소에 없다
When 앱을 연다
Then 라이트 또는 다크로 그리고 오류 화면을 내지 않는다

Given 브라우저 저장소에 쓸 수 없다
When 개인 테마를 저장한다
Then 저장 실패를 보이고 편집 화면과 바꾼 색이 남아 있다

Given 이름 있는 테마를 적용 중이다
When 금고에서 화면 테마가 다른 값인 환경설정을 적용한다
```

## 보안·성능·접근성

- **보안**: 가져온 파일의 값은 `#rrggbb` 검사를 통과한 색으로만 CSS 값이 된다. 임의 문자열이 스타일이나 마크업에 들어가는 경로가 없다. 테마 파일은 로컬 경로·키·대화 내용을 담지 않는다. 개인 테마는 기기 밖으로 나가지 않는다.
- **성능**: 테마 적용은 루트의 토큰 값을 바꾸는 한 번의 동기 적용이다. 미리보기는 색을 바꿀 때마다 같은 경로를 쓴다. 편집기와 터미널은 다시 만들지 않는다. 측정한 수치는 없다.
- **접근성**: 화면 테마 선택과 편집 화면은 키보드로 모두 조작한다. 견본 카드는 라디오 묶음으로 읽히고 카드마다 테마 이름이 접근 가능한 이름이다. 색 타일마다 접근 가능한 이름이 있고, 낮은 대비 표시는 색만이 아니라 글자로도 읽힌다. 편집 화면을 닫으면 연 컨트롤로 포커스가 돌아간다. 개인 테마의 대비는 사용자가 정하며 Corral은 표시만 한다. 내장 테마의 UI 색은 위 대비 기준을 테스트로 확인한다. 구문 색과 터미널 색은 출처 팔레트를 따르므로 4.5:1에 못 미치는 색(주석 등)이 있을 수 있다. 터미널은 xterm의 최소 대비 보정을 받는다. 화면 읽기 프로그램, 고대비 모드, 색각 이상 조건에서의 확인은 하지 않았다.
