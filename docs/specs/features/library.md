# 기능 명세: 라이브러리

- 상태: accepted
- 비목표: Skill·Hook·MCP·패키지 설정 폼을 설정 모달 밖으로 옮기기, 설정 주소 변경, 팀 정의·revision 규칙 변경

## 사용자 관측 동작

사이드바 주 메뉴의 **라이브러리**는 다시 쓰는 구성 요소를 찾고 상태를 확인하는 곳이다. 세 보기로 나뉜다.

| 보기 | 주소 | 내용 |
|---|---|---|
| 팀 | `/library/teams` | 저장한 Corral(팀) 목록 → 상세 → "이 팀으로 새 대화"·"편집"·"복제" |
| 템플릿 | `/library/templates` | 팀 템플릿과 목표에서 초안 만들기 |
| 리소스 | `/library/resources` | Skill·Hook·MCP 서버·패키지·확장 목록과 상태 |

- 팀과 템플릿은 프로젝트 필터(`?project=`)를 가진다. 필터가 없으면 마지막으로 연 프로젝트를 쓴다. 프로젝트 작업공간에는 팀 탭이 없다. 옛 `/projects/:projectId#corrals` 주소는 `/library/teams?project=:projectId`로 replace 이동한다.
- 템플릿 보기는 아래 여덟 개를 카드로 보인다. 카드는 이름, 한 줄 설명, 역할 이름을 실행 순서대로 보이고, 어떤 역할도 파일을 바꾸거나 명령을 실행하지 못하는 템플릿에는 "읽기 전용"을 표시한다. 카드의 동작은 "이 템플릿으로 새 대화"와 "사본 저장하고 편집"이며, 빈 캔버스에는 새 대화가 없다.

  | 템플릿 | 흐름 | 파일을 바꾸는 역할 |
  |---|---|---|
  | 단일 에이전트 | 에이전트 → 결과 | 없음 |
  | 구현·검토 | 구현 → 검토, 돌려보내면 수정해 다시 검토(최대 2회) → 결과 | 구현 |
  | 계획·구현·검토 | 계획 → 구현 → 검토, 돌려보내면 다시 구현(최대 2회) → 결과 | 구현 |
  | 버그 수정 | 원인 조사 → 수정 → 검토, 돌려보내면 다시 수정(최대 2회) → 결과 | 수정 |
  | 병렬 코드 리뷰 | 범위 정리 → 정확성 검토와 보안 검토를 동시에 → 모으기 → 종합 → 결과 | 없음(읽기 전용) |
  | 기술 결정 | 질문 정리 → 두 갈래 조사를 동시에 → 모으기 → 비교 문서 → 사용자 승인 → 결과 | 없음(읽기 전용) |
  | 조사 팀 | 조사(보조에게 위임) → 작성(질문) → 검토 → 사용자 승인 → 결과 | 없음 |
  | 빈 캔버스 | 노드 없음 | — |

- 템플릿의 역할은 역할 프리셋에서 온다. 프리셋은 역할의 도구·결과 형식·모델 자리를 정하고, 이름과 맡은 일의 문구는 화면 언어를 따른다. 프리셋은 구현, 계획, 검토, 원인 조사, 정확성 검토, 보안 검토, 조사, 작성 여덟 개다.
- 리소스 행은 이름, 범위(개인·프로젝트), 상태, 실패 원인과 다음 행동을 보인다. 지금 서버가 자원별로 알려 주는 원인은 루트 `SKILL.md` 패키지의 Skill 판정이다.
  - 패키지 설치 거부(크기·파일 수 한도)는 저장되지 않고, 하네스 보고 코드(`extension_load_failed`, `resource_invalid`, `policy_denied`, `sdk_start_failed`, `packages/contracts/src/harness.ts`)는 실행의 `harness.load_failed` 이벤트로만 남는다. 그래서 리소스 행에는 보이지 않는다.
  - 충돌한 도구 이름처럼 계약에 없는 세부도 보이지 않는다.
- 리소스의 "관리"는 라이브러리 주소에 `settings=<section>`·`settingsProject=<id>`를 더해 [설정 모달](../workbench.md#문맥형-설정)을 그 위에 연다. 편집·신뢰·설치·미저장 보호는 설정 모달이 소유한다. 모달을 닫으면 라이브러리의 같은 보기와 스크롤로 돌아온다.
- 세션의 팀 선택기에서 "Corral 만들기·관리"는 `/library/teams?project=<id>&returnTo=<세션 주소>`로 간다. 돌아가기는 세션의 초안·탭을 그대로 복원한다.

## 계약

- 팀 목록·상세·생성·복제·삭제는 기존 Corral API와 revision 규칙을 그대로 쓴다. 명시한 Corral이 삭제된 세션은 조용히 auto로 바뀌지 않는다.
- 템플릿에서 만든 팀의 도구와 연결은 템플릿이 정한다. 사본을 저장할 때 팀 id를 새로 발급하며, 저장한 뒤의 팀은 템플릿과 연결되지 않는다.
- 읽기 전용 템플릿의 모든 역할은 `write_file`·`delete_file`·`move_file`·`run_command`·`preview_action`을 갖지 않는다. 그 밖의 템플릿에서는 위 표의 역할만 이 도구들을 갖는다.
- 모든 템플릿은 strict 컴파일을 통과한다. 템플릿의 구조는 검증하지만 역할 문구의 품질은 보장하지 않는다.
- 리소스 보기는 읽기 전용이다. 라이브러리 화면 자체에는 저장할 폼이 없다.
- 리소스 조회가 실패하면 그 묶음만 실패와 다시 시도를 보이고 다른 묶음은 유지한다. 조회 실패를 "없음"으로 표시하지 않는다.
- 브라우저 데모에서 서버 전용 리소스는 "로컬 서버에서 사용" 상태 하나로 보인다.

## 수용 시나리오

```gherkin
Given 프로젝트 A에 저장한 팀 두 개가 있다
When 사용자가 /projects/A#corrals 를 연다
Then 주소가 /library/teams?project=A 로 바뀌고 두 팀이 보인다
And 뒤로가기는 이전 작업 화면으로 간다

Given 라이브러리 리소스에서 MCP 서버의 "관리"를 누른다
When 설정 모달에서 값을 바꾸고 저장하지 않은 채 닫으려 한다
Then 저장하고 이동 / 버리기 / 계속 편집을 묻는다

Given 템플릿 보기를 연다
When "병렬 코드 리뷰"의 사본을 저장한다
Then 저장한 팀은 strict 컴파일을 통과하고 어떤 역할에도 파일 쓰기·명령 도구가 없다
And 같은 템플릿을 한 번 더 저장하면 이름이 겹치지 않는 별개의 팀이 된다

Given "구현·검토" 템플릿으로 만든 팀이 있다
When mock 실행을 시작한다
Then 검토가 한 번 돌려보낸 뒤 통과하고 실행이 결과까지 간다

Given 루트에 SKILL.md가 있는 패키지를 설치했다
When 리소스 보기를 연다
Then 그 행에 Skill로 판정했다는 원인과 다음 행동이 보인다
```

## 보안·성능·접근성

- 리소스 행은 로컬 경로·토큰을 보이지 않는다.
- 보기 전환은 디자인킷 Tabs이고 목록은 Table이다.
