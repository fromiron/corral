# 기능 명세: 에이전트 라이브러리와 팀 사본

- 상태: accepted
- 기준: [라이브러리](library.md), [팀 편집기](canvas.md), [팀 구성](team-composition.md), [팀 그래프 모델](team-graph.md), [HTTP 계약](../api-contract.md)
- 비목표: 원본을 고치면 여러 팀이 함께 바뀌는 연결(그 재사용은 참조 팀이다), 프로젝트 사이의 원본 공유, 원본의 과거 revision 본문 조회, Outrider·관찰 전용 역할의 원본, 역할별 MCP 도구 선택

## 사용자 관측 동작

**원본은 라이브러리가, 팀에서 쓰는 사본은 팀이 가진다.** 원본은 프로젝트에 속한 재사용 역할 설정이다. 팀에 넣으면 그 시점의 원본을 한 번 복사하고, 그 뒤 원본과 사본은 서로를 바꾸지 않는다.

### 라이브러리 › 에이전트

1. `/library/agents?project=<id>`는 프로젝트의 원본을 표로 보인다. 열은 이름, 맡은 일(기본 지시의 첫 줄), 스킬 수, 고친 때다. 행을 고르면 옆 상세에 기본 지시와 스킬 이름, **편집 · 복제 · 보관**이 있다. 화면의 주 동작은 **에이전트 만들기** 하나다.
   - 맡은 일은 남은 너비에 한 줄로 줄여 보이고, 고친 때는 팀 목록과 같은 상대 시간으로 표시한다.
   - `agent=<id>`가 있으면 현재 프로젝트에서 그 원본을 선택한다. 보관한 원본이면 **보관한 항목 보기**도 켠다. 설치된 스킬 이름을 확인할 수 없는 경우에는 개수를 표시한다.
2. 검색은 이름과 기본 지시에서 찾는다. 검색 결과 없음, 저장한 에이전트 없음, 조회 실패(다시 시도)를 구분한다. 조회 실패를 0개로 보이지 않는다. 빈 상태의 동작은 **에이전트 만들기**다.
3. **에이전트 만들기 · 편집**은 대화상자다. 이름, 기본 지시, 사용할 스킬, 상세 설정(모델, 추론, 도구와 권한, 결과 형식, 실행 정책)을 고친다. **에이전트 저장**이 원본을 만들거나 다음 revision을 만든다. 저장에 실패하면 입력을 그대로 두고 원인을 보인다. 고친 내용이 있는 채 닫으려 하면 묻는다. 팀이 없어도 만들 수 있다.
   - 이름과 기본 지시는 필수다. 만들기 대화상자 하나는 재시도에도 같은 `operationId`를 쓴다. 저장 충돌과 저장소 오류는 구분하여 다음 행동을 안내한다. 편집 중 원본이 바뀌면 입력을 유지하며, 사용자가 **원본 다시 불러오기**를 선택해야 최신 내용으로 교체한다.
4. **복제**는 같은 내용의 새 원본을 `{이름} 사본`으로 만든다. **보관**한 원본은 기본 목록과 팀의 선택기에서 빠지고, **보관한 항목 보기**에서 **복원**한다. 보관·편집·복제는 이미 팀에 들어간 사본을 바꾸지 않는다.
5. 원본을 고치면 그 뒤에 추가하는 사본에만 반영된다.

### 팀에 추가

6. 편집기의 **에이전트 추가**는 선택기를 연다. 검색 입력에 포커스가 가고, 이름과 지시로 찾는다. 묶음은 **내 에이전트**(프로젝트 이름 표시) · **기본 제공** · **다른 팀**이다. 저장한 에이전트가 없으면 **기본 제공**이 먼저 열린다. 행은 이름, 지시 두 줄, 스킬 이름을 보인다. 이름이 같은 항목은 묶음과 지시로 구분한다. 공통 Outrider와 관찰 전용 역할은 목록에 없다.
   - 설치된 스킬 이름을 확인할 수 없으면 개수를 표시한다. 조회 중에는 빈 목록 대신 불러오는 상태를 표시한다.
   - 프로젝트 이름은 **내 에이전트**에서만 표시한다. 목록이 길면 행만 스크롤하고 검색, 묶음, 하단 동작은 제자리에 둔다.
7. 행을 고르면 **언제나 새 팀원 자리**가 생긴다. 카드 하나가 선택돼 있어도 그 카드를 덮어쓰지 않는다. 같은 원본을 두 번 고르면 두 자리가 생긴다. 새 자리의 이름은 원본의 이름이다. 추가 한 번은 되돌리기 한 단계이고, 선택기를 닫기만 하면 초안과 되돌리기 이력은 그대로다.
8. **직접 만들기**는 이름과 맡은 일만 적어 일반 에이전트의 기본 설정으로 새 자리를 만든다. 라이브러리에 원본이 생기지 않는다.
9. 선택기를 열거나 사본을 추가하는 동작은 라이브러리를 바꾸지 않는다. 라이브러리 조회가 실패해도 **기본 제공**과 **직접 만들기**는 쓸 수 있고, 실패한 묶음은 실패와 다시 시도를 보인다.
10. 추가하는 자리: 팀 구성의 **에이전트 추가**는 최종 결과 앞, 지금 흐름의 끝에 넣는다. 흐름 그래프의 팔레트와 명령은 [팀 편집기](canvas.md)의 배치 규칙과 미리보기를 그대로 쓴다. 빈 팀의 첫 에이전트는 에이전트·출력·실행선·출력 입력을 한 번에 만든다. 이미 결과를 받는 팀에 에이전트를 더해도 기존 출력 출처는 바뀌지 않는다.
   - 팀 구성에서는 배치할 곳이 모호해도 보기를 바꾸지 않고 선택기를 연다. 추가한 자리를 선택하고, 자동으로 연결하지 못한 자리는 **연결 안 됨** 묶음에 표시한다. 이때 다음 편집이나 선택 전까지 연결되지 않았음을 오류가 아닌 상태로 알린다.

### 맡은 일과 기본 지시

11. 팀원 설정의 **맡은 일**은 그 자리가 이 팀에서 하는 일이다.
    - 재사용 원본이 있는 자리(라이브러리·기본 제공에서 왔거나 단계 지시가 이미 있는 자리)에서 **맡은 일**은 이 팀의 단계 지시다. 원본의 지시는 **기본 지시**로 접혀 있고 펼쳐서 읽고 고친다. 단계 지시가 비어 있으면 **기본 지시**가 펼쳐져 있다.
    - 원본이 없는 자리(직접 만든 에이전트, 이 기능 이전의 팀)에서 **맡은 일**은 그 역할의 지시 자체이고 **기본 지시**는 따로 없다.
    - 목록의 한 줄 요약은 단계 지시가 있으면 그것을, 없으면 역할 지시의 첫 줄을 보인다.
12. 여러 자리가 한 역할을 함께 쓰던 팀에서 한 자리의 지시·스킬·모델·권한을 고치면 그 자리만 바뀐다. 다른 자리는 그대로다.

### 교체

13. 팀원 메뉴의 **다른 에이전트로 교체**는 같은 선택기를 교체용으로 연다. 행을 고르면 미리보기가 **바뀌는 것**(기본 지시, 모델과 추론, 도구와 권한, 스킬, 결과 형식)과 **유지되는 것**(이름, 맡은 일, 받는 자료, 연결, 최종 결과 선택, 자문 대상)을 보인다. **교체**를 눌러야 바뀐다.
14. 교체할 수 없으면 원래 자리를 그대로 두고 이유를 보인다.
    - 새 역할의 결과 형식이 뒤 단계나 필수 검토가 받는 형식과 맞지 않는다.
    - 이 자리가 팀 작업 계획의 소유자인데 새 역할이 계획을 고칠 수 없다. 소유자를 먼저 다른 팀원으로 바꾸라고 안내한다.
15. 취소와 같은 내용 다시 고르기는 되돌리기 0건, 교체는 1건이다. 되돌리면 교체 전 상태 전체가 돌아온다.
16. 가져온 역할이 가리키는 실행 정책(Harness)이 이 설치에서 풀리지 않아도 참조를 지우지 않는다. 그 자리에 풀리지 않는 정책의 이름과 **다시 연결 / 선택 제거**를 보이고, 고치기 전에는 실제 모델 실행을 시작할 수 없다.

### 라이브러리에 저장

17. 팀원 메뉴의 **라이브러리에 저장**은 이름과 기본 지시를 확인받는다. 기본 지시에는 그 역할의 지시가 채워져 있고, 단계 지시·받는 자료·팀 요청은 넣지 않는다. 필요한 문장은 저장 전에 직접 옮겨 적는다. 저장하면 현재 프로젝트에 새 원본이 생긴다. 이름이 같은 원본이 있어도 덮어쓰지 않는다.
18. 라이브러리에 저장은 팀 초안과 되돌리기 이력을 바꾸지 않는다. 저장에 실패하면 입력을 보존하고 다시 시도할 수 있다.
   - 저장 대화상자 하나는 재시도에도 같은 `operationId`를 쓴다. 저장하면 대화상자를 닫고 성공을 알리며 선택기의 원본 목록을 새로 읽는다.

## 계약

### 정의의 선택 필드

`packages/contracts/src/definition.ts`가 정본이다. 세 필드 모두 없으면 이전과 같이 읽고 실행한다. 기존 팀을 열거나 저장하는 것만으로 채우지 않는다.

| 필드 | 뜻 |
|---|---|
| `WorkAgentNode.stepInstruction` | 이 자리의 단계 지시. 1–20,000자. Outrider 자리에는 없다. |
| `AgentRole.origin` | 사본의 출처. `{ kind: 'library', agentId, revision }` 또는 `{ kind: 'preset', presetId }`. 표시와 맡은 일의 규칙(11)에만 쓴다. 실행은 읽지 않는다. |
| `AgentRole.skills` | 선택한 스킬. [스킬 라이브러리](skill-library.md)가 정한다. |

- 저장·다시 열기·복제·JSON 내보내기와 가져오기는 세 필드를 보존한다.
- `origin`의 원본을 찾지 못해도(보관, 다른 프로젝트, 삭제된 프로젝트) 사본은 그대로 실행된다. 편집기는 현재 프로젝트의 라이브러리에서 찾은 원본의 이름만 보이고, 다른 프로젝트의 원본을 조회하지 않는다.
- 상세 설정의 출처에는 현재 프로젝트에서 찾은 원본의 현재 이름과 복사한 revision을 표시한다. 기본 제공 사본은 프리셋 이름을 표시한다. 출처를 찾을 수 없으면 출처 행을 표시하지 않는다.

### 단계 지시의 전달

- 역할의 지시(`role.prompt`)와 단계 지시는 작업자에게 서로 다른 입력으로 한 번씩 전달된다. 단계 지시가 없으면 단계 지시 구역은 없고 이전과 같은 입력이 전달된다. 역할 지시를 단계 지시 자리에 복제해 두 번 보내지 않는다.
- 단계 지시는 그 노드 자신의 실행에 전달된다. 예정된 실행과, 그 노드가 위임받거나 질문에 답하는 실행이 모두 해당한다. 같은 역할을 쓰는 다른 노드, 그 노드가 다른 노드에게 맡긴 작업, 공통 Outrider의 응답 작업, 관찰 작업에는 전달되지 않는다.
- 세션 대화에서 저장한 팀을 선택하면 단계 지시는 해당 위임 대상의 실행에만 전달하고 대화의 대표 에이전트에게는 전달하지 않는다. 같은 역할을 쓰는 자리들의 지시가 모두 같거나 모두 없으면 기존 역할 하나를 위임 대상으로 유지하고, 지시가 서로 다르면(지시가 없는 자리 포함) 자리 이름으로 구분해 각각 호출한다.
- 실행은 시작 때의 정의 스냅샷을 쓴다. 재시도·다음 반복 회차·체크포인트 재개 시에도 같은 단계 지시를 전달하며, 문맥을 압축해도 역할 지시와 함께 유지한다. 실행 중 라이브러리를 읽지 않는다.
- 공개 이벤트·공급자 요청 기록·로그에 단계 지시 본문을 남기지 않는다.

### 원본 레코드

`packages/contracts/src/agent-library.ts`가 정본이다.

- `LibraryAgent`: `agentId`, `projectId`, `revision`(1부터), `role`, `createdAt`, `updatedAt`, `archivedAt`(없으면 `null`).
- `role`은 `AgentRole`에서 `id`와 `origin`을 뺀 것이다. 노드 위치, 호출 관계, 팀 입력, 단계 지시, 파일 본문, 인증 정보는 담지 않는다.
- 원본은 한 프로젝트에 속한다. 다른 프로젝트의 주소로는 읽거나 고칠 수 없다(`TARGET_NOT_FOUND`).

### 저장소와 HTTP

| 메서드 · 경로 | 동작 |
|---|---|
| `GET /api/v1/projects/:projectId/agents` | 그 프로젝트의 원본을 보관한 항목까지 생성 시각 오름차순으로 반환한다. 시각이 같으면 `agentId` 오름차순이다. |
| `POST /api/v1/projects/:projectId/agents` | `{ role, operationId }`로 원본을 만든다. 201. |
| `GET /api/v1/projects/:projectId/agents/:agentId` | 원본 하나. |
| `PATCH /api/v1/projects/:projectId/agents/:agentId` | `{ role?, archived?, expectedRevision }`. `role`과 `archived` 중 하나 이상을 지정한다. |

- **중복 생성:** 같은 프로젝트에서 같은 `operationId`와 같은 `role`의 생성은 처음 만든 원본을 다시 돌려준다. 같은 `operationId`에 다른 `role`은 `IDEMPOTENCY_CONFLICT`다. 잃어버린 응답을 새 `operationId`로 다시 보내지 않는다.
- **오래된 덮어쓰기:** `expectedRevision`이 현재 revision과 다르면 `REVISION_CONFLICT`이고 아무것도 바꾸지 않는다.
- **revision:** `role`이 실제로 달라질 때만 1 오른다. 같은 내용 저장과 보관·복원은 revision을 올리지 않는다. 보관·복원은 `archivedAt`과 `updatedAt`만 바꾼다.
- **프로젝트:** 없는 프로젝트와 보관된 프로젝트에는 만들 수 없다(`TARGET_NOT_FOUND`).
- **형식:** strict schema를 통과하지 못한 본문은 `SCHEMA_INVALID`다.
- SQLite 저장소와 브라우저 저장소는 같은 저장소 계약 테스트를 통과한다. 브라우저 모드는 원본을 팀과 같은 저장소에 두고, 그 저장소가 지속되는 동안 다시 열 수 있다. 안내 데모(`/demo`)의 저장소는 방문 동안만 유지된다.
- 새 원본 저장소가 비어 있어도 기존 팀은 열리고 실행된다.

### 편집 명령

`packages/react/src/team-editor/commands.ts`의 순수 함수다. 한 명령은 되돌리기 한 단계이고, 결과가 같으면 같은 초안을 돌려준다.

- **추가:** 새 노드와 새 역할 id를 만든다. 선택 상태를 읽지 않는다. `origin`을 사본에 적는다.
- **팀 구성의 추가 위치:** 출력이 하나이고 그 출력에 들어오는 실행선이 모두 같은 단계에서 시작하면 그 단계와 출력 사이에 새 자리를 넣는다. 반복의 정상 종료와 한도 소진처럼 출발 포트가 여럿이면 각 포트에서 새 자리로 잇고 새 자리에서 출력으로 한 번만 잇는다. 새 자리는 팀 요청과 함께 최종 결과가 받던 자료를 출처별로 한 번씩 받는다. 최종 결과에 고른 자료가 없으면 가장 가까운 선행 결과를 제안한다. 기존 출력 입력은 바꾸지 않는다. 일반 에이전트와 출력이 모두 없으면 첫 자리와 출력을 함께 만든다. 그 밖에는 갈래나 출력을 임의로 고르지 않고 새 자리를 연결하지 않은 채 추가한다.
- **교체:** 노드 id, 이름, 단계 지시, 받는 자료, 실행선, 호출 링크, 출력 입력의 출처, 공통 Outrider의 직접 대상(노드 id)을 유지한다. 역할은 새 id의 사본으로 바뀐다. 이전 역할은 다른 노드가 쓰지 않으면 지운다.
- **계획 소유자:** 교체되는 자리의 역할이 `planOwnerRoleId`이면, 새 역할이 계획을 고칠 수 있을 때만 `planOwnerRoleId`를 새 역할 id로 옮긴다. 아니면 거절한다. 소유자를 조용히 지우지 않는다. 이전 역할을 다른 노드가 계속 쓰면 소유자는 그 역할에 남는다.
- **컴파일 오류:** 교체 전후에 오류 코드와 위치(노드·실행선·호출 링크·스키마 경로)를 대조한다. 새 위치에 생긴 오류도 새 오류다. 첫 새 오류를 알려주고 교체하지 않는다. 이미 있던 오류나 경고만으로 교체를 막지 않는다.
- **공유 역할:** 역할 단위 변경(지시, 스킬, 모델, 추론, 도구, 결과 형식, 실행 정책)은 그 역할을 다른 노드도 쓰고 있으면 그 자리의 역할 사본을 먼저 만든다.
- **Harness 참조:** 추가·교체는 풀리지 않는 참조를 지우지 않는다.

## 보안·성능·접근성

- 원본에는 지시와 설정만 있다. 공급자 키, 로컬 경로, 인증 정보를 담지 않으며 로그에 지시 본문을 남기지 않는다.
- 다른 프로젝트의 원본은 주소를 알아도 읽히지 않는다.
- 목록은 프로젝트 단위로 한 번 읽는다. 원본 100개에서도 검색은 입력마다 서버를 부르지 않는다.
- 선택기는 디자인킷 Dialog·Tabs·목록이다. 검색 → 묶음 → 행 → 닫기 순으로 Tab이 돌고, 행은 Enter로 고르며, 닫으면 열었던 동작으로 포커스가 돌아온다. 선택과 오류를 색만으로 알리지 않는다.
