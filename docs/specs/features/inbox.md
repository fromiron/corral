# 기능 명세: 확인 필요

- 상태: accepted
- 비목표: 승인·질문 명령 경로 추가, 일반 실패를 처리 항목으로 만들기, 완료 알림 모음, 전달된 조언을 항목으로 만들기

## 사용자 관측 동작

사이드바 주 메뉴의 **확인 필요**는 모든 프로젝트의 처리 항목을 한 화면(`/inbox`)에 모은다. 항목은 세 묶음으로 보인다.

| 묶음 | 서버 inbox 종류 |
|---|---|
| 응답 대기 | `decision`, `uncertain_write`, `uncertain_terminal` |
| 검토 | `unreviewed`, `check_failed`, `lsp_proposal`, `integration`, `advice` |
| 대기·중단 | `queued`, `recipe_stopped` |

각 행은 세션 제목과 그 항목을 말하는 한 줄을 보인다. 프로젝트 이름은 목록에 프로젝트가 둘 이상일 때만 보인다. `decision` 행은 질문인지 승인인지 짐작하지 않고 실행 번호만 보인다. 묶음 이름이 이미 상태를 말하므로 행에서 되풀이하지 않는다. 다른 종류의 행은 서버가 알려 준 요약(실패한 검사 이름, 확인할 쓰기 수, 제안 수, 반영 상태)을, 요약이 없으면 종류 이름을 보이고 실행 번호가 있으면 덧붙인다. 상세는 행이 말한 것을 되풀이하지 않는다. 목록이 보이지 않는 좁은 화면의 상세만 제목 아래에 그 한 줄을 보인다.

행을 고르면 오른쪽 상세가 열린다.

- `decision`: 그 Run의 응답 영역(승인·질문·확장 요청·계속 여부)을 그대로 보이고, 같은 화면에서 답한다. 대화의 [지금 필요한 것](composer-flow.md#지금-필요한-것)과 같은 영역이다. 응답 영역 위에는 세션 제목만 있고 상태 제목을 한 번 더 두지 않는다.
- `advice`: 대상 실행 단위가 이미 끝나 전달하지 못한 [감독](advisor.md)의 조언이다. 행은 심각도와 조언의 첫 줄을 보이고, 주 버튼은 그 실행 행으로 간다. 그 실행 행을 열어 보면 항목은 목록에서 빠진다.
- 그 밖의 종류: 정확한 대상으로 가는 주 버튼 하나를 보인다. 대기 요청의 본문은 보이지 않는다. 대상은 [Desktop 계약](../desktop-contract.md)의 알림 이동과 같다. 검토 항목은 해당 세션 검토(실패한 검사는 그 검토의 검사 보기), 대기열은 세션, 터미널은 그 터미널의 제어 화면이다.

답한 뒤에도 상세는 그 Run을 여는 버튼을 유지한다. 답한 항목이 목록에서 빠져도 그 실행으로 한 번에 돌아갈 수 있다.

항목을 고르지 않은 넓은 화면의 상세 자리는 비워 둔다. 빈 자리를 설명하는 문장은 두지 않는다.

고른 항목은 주소(`item`)에 남는다. 링크로 대상 화면에 갔다가 뒤로가기를 하면 확인 필요의 같은 항목으로 돌아온다. 확인 필요 자체는 `returnTo`를 받아, 세션에서 들어왔을 때 돌아가기로 원래 작업 위치를 복원한다.

사이드바 주 메뉴의 배지는 **응답을 기다리는 실행 수와 결과 확인이 필요한 터미널 수의 합**이다. 기준은 사이드바가 이미 받는 세션의 최신 실행 상태(응답 대기)와 `GET /terminals/attention`이다. 대기 요청·미검토 변경 같은 항목은 목록에만 있고 배지에는 들어가지 않는다. 프로젝트의 처리 항목 수는 [workbench](../workbench.md#세션-목록의-상태와-처리할-항목)의 정의(모든 inbox 항목 수)를 그대로 쓰며 프로젝트 작업공간 머리에 보인다. 데스크톱 배지의 정의는 바뀌지 않는다.

## 계약

- 목록은 화면을 열 때와 창이 다시 포커스를 얻을 때 프로젝트마다 `GET /projects/:projectId/inbox`를 묶어 읽는다. 주기적으로 모든 프로젝트를 묻지 않는다. 한 프로젝트의 조회가 실패하면 그 프로젝트 묶음에만 실패와 다시 시도를 보이고 다른 프로젝트 항목은 유지한다.
- 상세는 고른 항목 하나에 대해서만 Run 대상별 store(`runFor` + `retainRun`)를 연다. 목록 행마다 store나 구독을 열지 않는다. 고른 항목을 바꾸거나 화면을 떠나면 retain을 해제한다.
- 응답은 기존 `ApprovalPanel`·`InteractionPanel`의 명령·receipt·revision 경로를 쓴다. 성공 receipt 전에는 항목을 지우지 않는다. 닫기·Escape·다른 항목 선택은 거절·취소가 아니다. 응답을 잃으면 기존 미확인 명령 복구를 따른다.
- `/inbox`에서는 세션 화면이 내려가 있으므로 같은 Run의 응답 컨트롤은 한 곳에만 있다.
- 응답한 뒤 포커스는 다음 항목(없으면 목록 머리)으로 간다. 대화 입력창으로 옮기지 않는다. 같은 Run에 승인이 더 기다리면 그 카드의 주 버튼으로 간다.
- 늦은 응답이나 이전 조회 결과가 이미 처리된 항목을 되살리지 않는다. 목록 갱신은 고른 항목의 상세를 다른 Run으로 바꾸지 않는다. 고른 항목이 목록에서 사라지면 처리됨을 알리고 다른 항목을 자동으로 고르지 않는다.
- 다른 작업 사본이나 이미 해제된 writer의 터미널 항목은 서버가 제외한 대로 보이지 않는다.
- 브라우저 데모는 데모 workspace 클라이언트가 만든 항목을 같은 방식으로 보인다.

## 수용 시나리오

```gherkin
Given 두 프로젝트에 승인 대기 실행 하나와 대기 요청 하나가 있다
When 사용자가 확인 필요를 연다
Then 응답 대기 묶음에 승인 대기 실행이, 대기·중단 묶음에 대기 요청이 보인다
And 사이드바 배지는 1이다

Given 확인 필요에서 승인 대기 항목을 골랐다
When 사용자가 승인하고 receipt가 오기 전이다
Then 항목은 목록에 남고 승인 버튼은 진행 중으로 보인다
When 성공 receipt가 온다
Then 항목이 사라지고 포커스가 다음 항목으로 간다

Given 상세가 열린 동안 Escape를 누른다
Then 승인·거절 명령을 보내지 않는다

Given 세션에서 입력창에 초안을 쓰고 확인 필요로 갔다
When 항목을 처리하고 세션으로 돌아간다
Then 초안과 첨부가 그대로다
```

## 보안·성능·접근성

- 목록은 세션 제목·실행 번호만 보이며 요청 본문·경로·터미널 출력을 보이지 않는다.
- 프로젝트 수만큼 조회하되 화면이 열려 있을 때만 한다.
- 묶음은 제목이 있는 목록이고, 행은 키보드로 고르며, 상세는 접근 가능한 이름을 갖는다.
- 넓은 화면은 목록과 상세 두 영역이고, 1024px 미만에서는 고른 항목이 목록을 대신하며 목록으로 돌아가는 버튼을 둔다. 첫 조회가 끝나기 전에는 목록 자리에 불러오는 중임을 보인다.
