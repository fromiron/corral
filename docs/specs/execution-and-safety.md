# 실행과 안전 경계

이 문서는 승인된 실행 경계를 찾는 기준 요약이다. 지원·검증되지 않은 경로를 문서 정리만으로 활성화하지 않는다.

## 명령·효과·기록

명령은 기존 admission·Coordinator·영속 기록·projection 경로를 통과한다. HTTP 접수, worker 전달, 효과 실행, 실제 종료와 Run 완료는 별개다. 재전송은 원래 command ID·내용·revision 계약을 유지하며, 결과가 불명확한 효과를 자동 재실행하지 않는다.

취소·patch·승인은 원래 Run, 실행 시도, scope, revision과 대상 hash를 확인한다. 늦은 응답은 원래 소유자에만 반영한다. 사람의 승인·거절은 승인 카드의 명시적 버튼으로만 보낸다. 카드 안의 Enter·Escape 같은 키보드 단축키로 결정을 보내지 않으며, 버튼 자체는 키보드로 조작할 수 있다. 과거 snapshot·산출물·검사 결과를 현재 상태로 덮어쓰지 않는다.

호출 전 permit을 확인한다. UI·worker·하위 agent가 자체 사용량 원장이나 완료 원장을 만들지 않는다. 새 기능·스킬 선택은 권한 확대의 근거가 아니다.

## 동시성과 파일

ABS-06은 고정 snapshot reader 병행과 작업 사본별 단일 writer를 승인한다. 모든 시작 입구의 admission, host 전체 모델·worker·process 상한, `(hostId, runId)`별 제어·SSE·사용량·자료 소유를 함께 유지한다. 같은 작업 사본의 동시 writer는 허용하지 않는다.

초기 스펙과 통합 계획의 전역 활성 Run 하나라는 설명은 이 후속 범위의 현재 계약이 아니다.

작업 폴더 연결·신뢰·관리 사본·검토·원본 적용은 별개의 경계다. 파일 diff를 보거나 검토 체크를 했다는 이유만으로 원본 적용을 승인하지 않는다. 대상 tree가 바뀌면 검증·검토의 유효성을 다시 확인한다.

연결하고 신뢰한 폴더가 있고 그 세션에 작업 사본이 없으면, 그 세션의 에이전트는 그 폴더에서 직접 일한다. 신뢰는 명시적 동의이고, 폴더는 Git 저장소가 아니어도 된다. 작업 사본이 있는 세션은 그 사본에서만 파일을 읽고 바꾸며 원본 폴더를 직접 바꾸지 않는다.

직접 모드의 리드는 그 폴더를 목록·읽기·검색한다. 경로는 사본과 같은 검사로 폴더 안에 묶인다. 상위 경로, 절대 경로, 폴더 밖을 가리키는 심볼릭 링크는 거절한다. 파일 쓰기·삭제·이동·편집은 직접 모드에 없다. 파일 체크포인트와 복원은 세션 작업 사본의 Git 트리를 대상으로 하며, 사본이 없는 연결 폴더의 바이트를 보관하거나 되돌리지 않는다. 파일 도구로 바꾸고 되돌리려면 작업 사본을 쓴다.

직접 모드의 명령은 연결 폴더를 작업 디렉터리로 하고, 사본의 명령과 같은 trusted-native 정책과 권한 모드를 따른다. 묻기에서는 명령을 승인하기 전에 실행하지 않는다. 승인한 명령은 그 폴더를 바꿀 수 있고, 그 변경은 파일 체크포인트가 아니다. 미리보기는 작업 사본에서만 연다.

직접 모드의 실행은 명령을 쓸 수 있다는 이유로 시작할 때 폴더를 잡지 않는다. 그래서 같은 프로젝트의 다른 세션이나 예약 실행도 같은 폴더에서 함께 시작한다. 그 폴더의 단일 writer는 명령 하나가 실행되는 동안만 잡는다. 같은 폴더에서 한 번에 실행되는 명령은 하나다. 다른 명령이나 사람의 작업이 그 폴더를 잡고 있으면 새 명령은 기다리지 않고 `RUN_ALREADY_ACTIVE` 도구 오류로 거절되며, 에이전트는 그 오류를 본다. service 명령은 멈출 때까지 폴더를 잡는다. 명령이 끝나거나 취소·시간 초과로 종료가 확인되면 놓는다. 종료를 확인하지 못한 명령은 폴더를 uncertain으로 남기고, 복구가 그 명령의 종료를 확인하기 전에는 다음 명령을 막는다. 실행은 시작할 때의 폴더에서만 명령을 쓴다. 직접 모드로 시작한 실행 중에 작업 사본이 생기거나 연결 폴더가 바뀌면 다음 명령을 거절한다. 작업 사본에서 파일을 쓰는 실행은 시작할 때 그 사본의 writer를 잡고, 잡은 사본의 위치·generation이 지금 사본과 다르면 명령을 거절한다.

신뢰를 끄면 다음 실행은 파일·명령 도구 없이 시작한다. 진행 중인 실행은 다음 도구 접수에서 그 도구를 거절한다. 작업 사본이 있는 세션은 신뢰를 꺼도 읽기 도구는 남고 명령만 거절된다.

리드의 프롬프트는 작업 사본이면 세션 작업 사본에서 일한다고, 직접 모드면 프로젝트 원본 폴더에서 직접 일한다고 말한다. 도구가 없으면 폴더가 연결되지 않았거나, 신뢰되지 않았거나, 연결된 폴더를 찾을 수 없는 이유와, 사람이 폴더를 연결하거나 신뢰하거나 폴더 설정을 확인해야 한다고 말한다. 프롬프트·이벤트·로그에 절대 로컬 경로는 넣지 않는다. 폴더의 이름은 화면과 같이 세션 작업 사본 또는 프로젝트 원본 폴더다.

이 단일 writer 경계를 사용자 작업으로 확장한다. 사용자 operation은 Run과 구분한 owner/receipt를 가지며 공통 예약을 사용한다. 사본 generation과 요청 hash를 확인하고 재시작/불확실 효과를 자동 재실행하지 않는다. 명시적 공유 개발은 하나의 development writer 아래 허용된 사람 효과만 공유한다. 소유된 디버깅은 이 범위에 포함하며 agent writer·PTY·구조 변경·배포는 차단한다. 배포는 검토한 소스에 대한 strict writer를 사용하고, 외부 결과를 확인하지 못한 상태에서 자동 재배포하지 않는다. 재시작 시 uncertain이고 자동 재개하지 않는다. 상세는 [현재 Workbench](workbench.md#공유-개발-모드)를 따른다.

## 명령·편집·미리보기

일반 명령·service는 실제 관리 사본, Coordinator 승인·effect, 소유 프로세스 lease를 사용한다. `run_check`의 등록 argv·고정 검증 사본과 혼동하지 않는다. Hashline은 버전 있는 명시 선택 방식이며 기존 Pi edit의 자동 대체가 아니다.

산출물 HTML의 script 비활성 격리 preview와 관리 service의 browser preview는 다르다. 후자는 service·process·port/연결 소유권과 취소·폐기 계약을 따른다. 기능 이름이 같다는 이유로 전자의 CSP를 완화하지 않는다.

## 재접속·복구와 비밀

살아 있는 실행에 재접속하는 것, 기록을 재열람하는 것, 체크포인트로 새 Run을 시작하는 것과 효과를 자동 replay하는 것은 다르다. 재시작 후 불확실한 효과·사용량을 성공이나 미실행으로 임의 확정하지 않는다.

credential·원시 사용자 본문·내부 경로를 공개 이벤트·export·알림·로그에 노출하지 않는다. 모델·웹·Skill·다른 역할의 출력은 권한을 바꾸는 명령이 아니다. 설정과 native 확장 신뢰는 각각 해당 owner의 명시 계약을 따른다.

상세 전이·오류는 [기술 설계](technical-design.md)와 [API 계약](api-contract.md), 일반 개발 규칙은 [AGENTS.md](../../AGENTS.md)를 확인한다.

산출물 본문은 [본문 수명 계약](api-contract.md#산출물-본문-수명)에 따라 실행 및 effect 정리가 끝난 뒤 해제한다. 취소 요청이나 Run 종료 상태만으로 진행 중인 작업의 본문을 제거하지 않는다. 메타데이터와 일반 대화 차례는 본문 아카이브와 구별한다.
