## 3. RED 증거와 결함 검출 확인

| 대상 | 방식 |
|---|---|
| Coordinator 협업 | stub에서 10/11 실패. 미리 통과한 1건(동시성 상한)은 상한을 없애는 결함으로 실패 확인 |
| 결함 넣기 | 기다리는 부모가 슬롯을 잡는 결함(교착으로 실패), 타임아웃이 질문자를 깨우지 않는 결함, 응답 실행을 소환 수에서 빼는 결함. 마지막 결함은 처음 테스트로 잡히지 않아 응답이 먼저 생기는 경우의 테스트를 더했다 |
| Pi 협업 도구 | 구현 뒤 작성. worker가 questionId를 채우지 않는 결함으로 실패 확인 |
| SafeMarkdown | 그대로 HTML을 넣는 stub에서 3/4 실패 |
| Task Board·질문·산출물 보기 | stub에서 3/3 실패 |
| 테스트 자체 결함 | 고정된 event 배열을 정렬한 테스트, capability link를 지워 정의가 무효가 된 테스트를 고쳤다 |

## 4. 계약을 바꾼 것

- `AgentStartInput`에 `depth`, `assignment`(scheduled·delegated·question), `capabilities`(위임·질문 가능한 callable 노드)를 더했다.
- 계약 포트에 `Scheduler`(마감 시간), ID 종류에 `question`을 더했다. Coordinator는 `timers`를 주입받고, 주지 않으면 아무것도 시간 초과되지 않는다. 서버와 브라우저 runtime은 실제 타이머를 준다.
- 설치 정책에 `maxResidentExecutions`(12, 기술 설계 §8.1)를 더했다.
- `message.question_created.taskId`는 응답 Task다([API 계약](../../../docs/API-Contract.md) §4에 적음).
- 투영에 `questions`, `artifactReads`가 생겼다.
- Run 출력 표시는 `<pre>`에서 SafeMarkdown으로 바뀌었다.
- 의존성: `react-markdown` 10.1.0 (MIT, 2025-03 공개).

## 5. 아직 하지 않은 것

- 실제 모델로 협업 흐름 실행. 협업 도구는 faux 모델로만 검사했다.
- 사용자 취소 명령(P6). 취소 경로는 부모 종료와 질문 타임아웃에서만 쓰인다.
- 대기 순환 탐지(새 대기 edge가 순환을 만드는 경우). 질문 사슬은 깊이·소환·질문 수 상한으로만 막는다.
- 무진전(no progress) 감지와 `awaiting_user` 전환(기술 설계 §8.4).
- 캔버스 노드 집계 배지의 대기 이유. 대기 이유는 실행 트리와 Task Board에서 보인다.
- 문서 읽기 도구(`read_document`, SSRF 검사, P8)와 `search`.
