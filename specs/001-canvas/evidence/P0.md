## 3. RED 증거

각 기능 테스트는 구현 전에 **assertion 실패**로 먼저 확인했다. import 누락으로 인한 실패는 RED로 인정하지 않고, stub을 두어 assertion이 실패하는 것을 확인했다.

| 대상 | 처음 실패한 방식 |
|---|---|
| spec-check 태그 검사 | 3/4 assertion 실패 (빈 배열 반환 stub) |
| 정의 schema parity | 유효 예제 2개와 좌표 혼입 테스트 실패 (`z.never()` stub) |
| JCS 정규화 | 9/9 실패 (빈 문자열 stub) |
| definitionHash | 2/2 실패. 이 과정에서 테스트 자체의 오류 2건(정수형 키 순서, `JSON.stringify` replacer)을 발견해 테스트를 고쳤다 |
| testkit | 19/19 실패 |
| linear plan·coordinator | 16/30 실패. stub에서 우연히 통과하던 4개 테스트에 비어 있지 않음 조건을 추가해 강화했다 |
| editor model | 9/10 실패 |
| run session | 3/3 실패 |
| ReinsPanel | 5/5 실패. 이후 "종료 후에도 미전달 지시 표시" 테스트를 추가해 1건 실패 확인 후 구현 |

## 4. 테스트가 결함을 잡는지 확인한 검사

- **transport 계약:** 이벤트 하나를 빠뜨리는 transport로 공통 계약 suite를 실행해 2/3 실패를 확인했다. 처음에는 5초 timeout으로만 실패해서, 구독자 예외를 `onError`로 전달하도록 고친 뒤 즉시 `ProjectionGapError`로 실패하는 것을 확인했다.
- **Storybook a11y:** 이름 없는 버튼 story를 임시로 넣어 `button-name` 위반으로 실패하는 것을 확인했다.
- **runtime 중립성:** `packages/core`에 `node:fs`와 `buffer` import를 임시로 넣어 lint 오류 2건을 확인했다.
- **spec-check:** 존재하지 않는 `TC-CAN-999-H` 태그를 넣어 exit 1을 확인했다.

## 5. 브라우저에서 확인한 것과 발견한 결함

개발 서버를 띄워 직접 조작했다.

- 빈 캔버스에 Agent와 Output을 추가·연결하면 "Ready to run"이 되고, 실행·완료·출력이 표시된다.
- 요청 1 도중 보낸 지시는 Queued → Delivered가 되고 출력에 반영됐다. 요청 2 시작 뒤 보낸 지시는 출력에 반영되지 않았다(`directives: none`).
- 발견해 고친 결함:
  1. Zustand selector가 매번 새 함수를 반환해 무한 렌더가 발생했다.
  2. React Flow의 내장 `output` 노드 타입 이름과 겹쳐 흰 배경이 생겼다.
  3. 실행이 끝나면 Reins 패널이 비워져 만료된 지시가 사라졌다(스펙 §4.4 위반). 마지막 대상을 읽기 전용으로 유지하도록 고쳤다.
  4. 연결 핸들의 `aria-label`이 axe `aria-prohibited-attr` 위반이었다(E2E axe 검사로 발견).
