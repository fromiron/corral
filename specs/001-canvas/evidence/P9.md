# P9 증거 기록 — 데모와 릴리스 검증

- 기록일: 2026-10-15 (Asia/Tokyo)
- 범위: C-046, C-047, C-048, C-049, C-050
- 환경: 초기 구현 Node 24.14.0, 리뷰 수정·최종 검증 Node 24.19.0, pnpm 10.30.3, Linux x64. 외부 유료 호출 없는 로컬 검증.
- 최종 후보의 통합 검증: `CORRAL_PYTHON=/tmp/corral-release-python/bin/python pnpm release:gate`. 결과는 `test-results/release/evidence.json`에 source hash와 단계별 완료 시각으로 기록된다.
- 상태 `implemented`는 로컬 구현·검증을 뜻한다. `done`/hosted CI 성공을 주장하지 않는다.

- `/demo`는 static build에서 worker의 실제 Coordinator와 결정론적 adapter를 사용한다. 로컬 서버·key 없이 D&D, 지시, 미래 prompt patch에 반응하며 모의 실행 배지를 계속 표시한다.
- Chromium/Firefox에서 Tab 전용 핵심 흐름, 한국어·일본어 composition, 1280/1440/1920 화면, reduced motion, 기존 D&D/검토 Loop와 axe 검증을 실행했다. Storybook은 대기·미전달·연결 끊김·미확인 usage 상태를 포함한다.
- production 성능 fixture는 설계 노드 20, 과거 실행 100, 이벤트 10,000, 50fps 목표 수신을 사용한다. raw samples·CPU profile·flamegraph와 정확한 측정 범위는 [성능 기록](../../../docs/Performance.md)에 있다. 일반 build에는 이 fixture route가 없다.
- release gate는 명세/계약/lint/typecheck/unit·Storybook/build/E2E/static production demo/performance/license/SBOM을 검사하고 source hash에 묶인 결과를 남긴다. 112개 scenario 태그 누락도 거절한다.
- `release:check`는 별도로 opt-in한 동일 후보의 실제 모델 smoke 증거까지 요구한다. 일반 gate는 외부 유료 호출을 실행하지 않으며 오래된 smoke 기록으로 현재 후보를 승인하지 않는다.
- [README](../../../README.md), [release 절차](../../../docs/Release.md), [사례·한계](../../../docs/Case-Study.md)를 현재 동작과 검증 범위에 맞췄다.

주요 검증: Studio browser/server E2E, Storybook, `tools/release/*.test.ts`, production performance. 예비 static browser 26개와 미래 patch 2개, worker 계약 2개가 통과했고 최종 후보는 통합 gate로 다시 검증한다.

미확인: 실제 OS IME/물리 키보드 수동 검증, WebKit, 현재 후보의 유료 live 모델/Brave 호출, hosted CI/배포. 따라서 구현 상태를 hosted 검증 완료나 출시 승인으로 표시하지 않는다. 최종 성능 측정은 실제 로컬 HTTP/SSE·SQLite 경로를 포함한다. 모델 응답과 원격 네트워크 지연의 숫자는 아니다.

셀프 리뷰 수정·실제 앱 조작·현재 검증 경계는 [통합 수정 근거](review-fixes.md)를 따른다.
