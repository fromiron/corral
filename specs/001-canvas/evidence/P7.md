# P7 증거 기록 — 예산과 견고성

- 기록일: 2026-10-15 (Asia/Tokyo)
- 범위: C-037, C-038, C-039, C-040, C-041, C-061
- 환경: 초기 구현 Node 24.14.0, 리뷰 수정·최종 검증 Node 24.19.0, pnpm 10.30.3, Linux x64. 외부 유료 호출 없는 로컬 검증.
- 최종 후보의 통합 검증: `CORRAL_PYTHON=/tmp/corral-release-python/bin/python pnpm release:gate`. 결과는 `test-results/release/evidence.json`에 source hash와 단계별 완료 시각으로 기록된다.
- 상태 `implemented`는 로컬 구현·검증을 뜻한다. `done`/hosted CI 성공을 주장하지 않는다.

- 모델 호출/토큰 예산은 동기 admission에서 예약하고 확인된 사용량으로 한 번 정산한다. 미확인 예약은 환급하지 않으며 늦게 확인된 사용량은 상태를 부활시키지 않고 정산한다.
- wait graph, 질문/소환/깊이/요청 총량, wall/model/tool deadline과 의미 있는 진전 기준을 구현했다. pause 동안 질문 논리 시간만 멈춘다.
- seeded property 검증은 장부 200회, 명령 interleaving 80회를 수행한다. pause와 admission, 동시 무진전 경계의 실제 경합도 재현·수정했다.
- crash 시 예약을 미확인으로 남기고 interrupted로 전환한다. P5의 오래된 SQLite 투영 cache는 원본 이벤트에서 재구성하며 기록/정의를 덮거나 외부 호출을 재실행하지 않는다.
- 공개 archive는 allowlist 메타데이터만 포함한다. 명시적 private archive는 기준·산출물·model response·tool result를 포함하고 순서·snapshot·본문 해시를 검증한 읽기 전용 기록으로 열린다.
- SSE의 느린 소비자 버퍼는 제한하며 전송한 prefix를 flush하고 연결을 종료한다. 클라이언트는 commit cursor에서 재조회하고 중복·gap·분할 CRLF를 처리한다. 완료 응답의 불변 본문으로 끊긴 텍스트를 복구한다.
- BudgetInspector는 spentKnown·reserved·spentUnknown과 각 요청을 구분한다. 확인된 가격 snapshot이 없으므로 금액은 Unavailable이며 0으로 표시하지 않는다.

주요 검증: `budget.test.ts`, `budget-coordinator.test.ts`, `limits.test.ts`, `history.test.ts`, `response-records.test.ts`, `transport-helper.test.ts`, SQLite/client/server/React suites.

RED 확인: unknown refund, wall deadline/no-progress 누락, crash 예약 잔류, 마지막 응답·문서 입력 본문 누락, 동기 구독 해제 TDZ. 대형 SSE 기록은 수정 전 첫 byte도 못 받았고 수정 후 408개 이벤트를 305+103의 prefix로 복구했다.
