## 4. 계약을 바꾼 것

- RuntimeTransport 기준 이벤트 순서에 `effect.admitted`·`effect.settled`가 들어갔다(C-013). 공통 계약 테스트의 기대값을 넓혔고 완화하지 않았다.
- 오류 코드 `RUN_ALREADY_ACTIVE`, `REVISION_CONFLICT`를 추가했다([API 계약](../../../docs/API-Contract.md) §3).
- `CreateRunRequest`(`POST /runs`)와 생성 JSON Schema를 추가했다. 인라인 정의 시작(`StartRunRequest`)은 브라우저 runtime 전용이다.
- 투영에 effects, Loop 회차, `waitingOn`, `interruptedBy`가 생겼다.
- Run 출력과 Run 성공은 한 commit이다(읽는 쪽이 둘 중 하나만 보는 순간이 없다).
- 저장 방식은 ADR-021, 세션 방식은 ADR-022로 기록했다.

## 5. 브라우저와 실행에서 발견해 고친 결함

1. 데모 runtime에서 서버 health probe가 404 console 오류를 냈다. 서버가 보낸 페이지에만 표시(meta)를 넣고, 표시가 있을 때만 probe한다.
2. 엄격한 CSP에서 Zod 4가 `new Function` 검사로 `script-src eval` 위반을 냈다. Studio는 Zod를 jitless로 실행한다.
3. 세션 없는 탭에서 loader 실패가 화면 전체를 오류로 덮어 안내가 보이지 않았다. 세션이 없으면 안내 화면만 보인다.
4. `relativeTime`에 `now`가 없어 console 오류가 났다. `useNow`로 넘긴다.
5. 재시작한 프로세스가 같은 순번 ID를 다시 쓰면 run 삽입이 실패한다. 서버는 무작위 ID를 쓰고, 테스트의 재시작은 다른 namespace의 ID factory를 쓴다.

## 6. 아직 하지 않은 것

- GitHub Actions 실행. Firefox E2E.
- Decision 단계와 최종 승인은 실행하지 않는다(검토·승인은 P5). Loop는 구조상 Decision이 필요하므로 실제 사용은 P5부터다. 테스트에서는 주입한 decision policy로 Loop 회차 분리를 확인했다.
- 취소·일시정지·patch 명령은 `COMMAND_NOT_SUPPORTED`(P6). 따라서 C-012 완료 조건의 “취소 fence 순서”는 아직 검증하지 않았다.
- 캔버스 노드 집계 배지는 상태만 보이고 대기 이유는 실행 트리에만 보인다. 자식·질문 대기가 생기는 P4에서 배지에도 넣는다.
- 실제 대기 상태(자식·질문·승인)를 만드는 경로가 없어, 대기 이유 표시는 고정 투영으로만 확인했다.
- 실행·작업 단위 정규화 테이블(ADR-021), CSRF token·요청 빈도 제한(C-042, P8).
- Vite 개발 서버에서 로컬 서버로 붙는 개발 모드는 없다. 서버로 쓰려면 `pnpm serve`(빌드 후 서버가 Studio를 제공)를 쓴다.
- 서버의 agent는 아직 각본 agent다(Pi worker는 P3).
