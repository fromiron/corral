## 4. 계약을 바꾼 것

- `AgentHost`에 `authorizeTool`·`executeTool`·`streamText`를 더했다. `invokeTool`은 둘을 잇달아 부르는 편의 경로로 남겼다. 도구 이벤트는 `tool.requested → tool.allowed → effect.admitted → tool.started → (결과) → tool.finished → effect.settled`다. 공통 transport 계약의 기준 이벤트 순서를 이에 맞춰 넓혔다.
- `AgentStartInput`에 `mode`와 `model`(해석된 `ModelProfileSnapshot`), `ModelUsage`에 캐시·추론 token을 더했다.
- Coordinator에 `ModelResolver` 포트를 더했다. 기본값(`SIMULATED_MODELS`)은 live를 `COMMAND_NOT_SUPPORTED`로 거절한다. 서버는 로그인 전 live를 `CAPABILITY_DENIED`로 거절한다.
- RunSnapshot에 `models`(프로필별 해석 결과)가 생겼다.
- 서버 health의 `agents` 필드를 `live: boolean`으로 바꿨다.
- 새 API: `GET /model-profiles`, `GET /model-auth`, `POST /model-auth/:provider/login`, `POST …/login/callback`, `DELETE …/login`, `DELETE /model-auth/:provider`([API 계약](../../../docs/API-Contract.md)).

## 5. 실제 OpenAI 확인 (수동 opt-in)

**로그인.** Bell이 `pnpm serve` → Models → Sign in → OpenAI 페이지에서 ChatGPT 계정으로 로그인했다. 첫 시도에서는 OpenAI 페이지의 허용 단계 전이라 콜백이 오지 않았고(콜백 포트 1455가 계속 대기), 승인 후 저장됐다. 저장 결과: `~/.config/corral/credentials.json`(0600, 디렉터리 0700), OAuth 자격 증명 하나, scope에 `chatgpt.tokens.use.direct` 포함, 발급 client ID 있음, 약 1시간 유효. 내용은 메타데이터만 확인했다.

**첫 live smoke(실패, 원인 확인).** 기본 프로필 `gpt-5.4-mini`·`gpt-5.4`는 OpenAI가 400으로 거절했다: “not supported when using Codex with a ChatGPT account”. 토큰은 유효했다(401이 아님). ChatGPT 계정 로그인은 pi-ai의 ChatGPT(Codex) 카탈로그 모델만 쓸 수 있다: gpt-5.3-codex-spark, gpt-5.5, gpt-5.6-luna, gpt-5.6-sol, gpt-5.6-terra, gpt-6-astra, gpt-6-luna, gpt-6-sol, gpt-6.1-sol.

**바꾼 것.** 기본 프로필을 Bell이 고른 `model-a` = `gpt-6-luna`, `model-b` = `gpt-6.1-sol`로 바꿨다. 구독 로그인으로 카탈로그 밖 모델을 쓰는 프로필은 Run 시작 전에 이유와 쓸 수 있는 목록을 들어 `CAPABILITY_DENIED`로 거절하고, Models 화면에도 표시한다(`models.test.ts`). API 키로 연결하면 이 제한을 걸지 않는다.

**두 번째 live smoke (2026-10-15 09:12 UTC, `CORRAL_LIVE=1 pnpm test:live`, 3/3 통과).**

| 항목 | model-a (`gpt-6-luna`) | model-b (`gpt-6.1-sol`) |
|---|---|---|
| Run | succeeded, 요청 3회(write → submit → 마무리) | succeeded, 요청 3회 |
| `run.started` 모델 | openai / gpt-6-luna / oauth | openai / gpt-6.1-sol / oauth |
| usage(입력/출력 token) | 178/24, 240/40, 292/10, 모두 `reported` | 178/24, 244/44, 300/10, 모두 `reported` |

중단 검사(model-a, 세 번째 stream frame에서 cancel): 정산 `cancelled`. 앞선 두 요청은 usage가 보고됐고(180/417, 611/22, 캐시·추론 0), **중단된 요청은 usage가 보고되지 않아 모두 null(미확인)** 으로 남았다. C-052에서 열어 둔 질문의 답이다.

**결과로 고친 결함.** 정상 Run의 `model.finished`에서 캐시·추론 token이 null이었다. adapter는 값을 받았는데 Coordinator가 기록할 때 버렸다. 테스트를 추가해 실패를 확인하고 고쳤다. 이 수정 뒤에는 live smoke를 다시 돌리지 않았다.

## 6. 아직 하지 않은 것

- rate limit, 토큰 만료 후 실제 갱신(1시간 뒤), 실제 provider 오류 형식의 화면 문구.
- 두 번째 provider. CR-001에 따라 OpenAI 프로필 2개로 시작했다.
- Run 취소 명령(P6). 중단은 adapter 수준에서만 검사했다.
- worker 예산 예약·정산(P7), 모델 응답의 private transcript 보관.
- Windows·macOS에서 자격 증명 파일 권한과 콜백 포트 1455 동작.
- 로그인 콜백 포트가 Codex CLI 등과 겹칠 때의 화면 문구는 pi-ai 메시지를 그대로 보여준다. 실제로 겹친 경우는 시험하지 않았다.
