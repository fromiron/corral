# P6 증거 기록 — Reins

- 기록일: 2026-10-15 (Asia/Tokyo)
- 범위: C-031, C-032, C-033, C-034, C-035, C-036
- 환경: 초기 구현 Node 24.14.0, 리뷰 수정·최종 검증 Node 24.19.0, pnpm 10.30.3, Linux x64. 외부 유료 호출 없는 로컬 검증.
- 최종 후보의 통합 검증: `CORRAL_PYTHON=/tmp/corral-release-python/bin/python pnpm release:gate`. 결과는 `test-results/release/evidence.json`에 source hash와 단계별 완료 시각으로 기록된다.
- 상태 `implemented`는 로컬 구현·검증을 뜻한다. `done`/hosted CI 성공을 주장하지 않는다.

- 지시 접수·요청 snapshot 포함·local transport dispatch를 분리했다. Pi와 모의 adapter가 실제 전송 시작을 보고하고 receipt를 갱신한다.
- pause는 모델·외부 도구를 drain한 안전 경계에서 확정한다. 자식/질문 대기는 슬롯을 점유하지 않는다. 승인 해결은 자동 resume이 아니다.
- scope 취소 fence, 후손·도구·대기 정리, 10초 정리 경계와 실제 worker exit 확인, forced/unconfirmed 구분과 늦은 관측을 구현했다.
- 명시적 재시작은 blocked 필수 Task의 새 execution/attempt로만 수행한다. 과거 시도·산출물·지시는 보존한다.
- node 미래 설정, Loop 상한, Run 예산, criteria revision을 변경하며 활성 실행과 원본 정의를 덮지 않는다. UI는 Current → Proposed, scope·경계·소비량과 revision 충돌을 표시한다.
- 산출물의 직접 지시는 실제 요청 snapshot과 dispatch로 결정한다. 입력으로 전해진 지시, criteria, 외부 문서/모델 응답의 불변 참조는 별도 경로로 표시한다.

주요 검증: `packages/core/test/reins.test.ts`, `reins-audit.test.ts`, `packages/adapter-pi/test/pi-adapter.test.ts`, `process.test.ts`, `packages/react/test/reins-controls.test.tsx`, `review-views.test.tsx`.

RED 확인: prepare만으로 dispatch를 확인하던 테스트 3개, worker exit 전 완료 테스트, provider 오류 비밀 노출 테스트, criteria/source 참조를 열 때 비어 있던 패널 테스트가 실제 실패한 뒤 통과했다. 단순 테스트 추가만을 RED 증거로 부르지 않는다.

셀프 리뷰 수정·실제 앱 조작·현재 검증 경계는 [통합 수정 근거](review-fixes.md)를 따른다.
