| 대상 | 방식 |

| Coordinator 검토·승인 | 구현 전 5/5 실패 |

| Pi 검토 프롬프트 | 구현 뒤 작성. 실패 확인은 하지 않았다 |
| E2E | 처음 실행에서 둘 다 실패. 브라우저 runtime은 응답 지연(1.5초 × 약 30회)이 시간 제한을 넘었고, 서버 E2E는 다시 빌드하지 않은 Studio를 썼다. 지연을 `?delay=50`으로 줄이고 다시 빌드한 뒤 통과 |
| 테스트 자체 결함 | 계보 링크에서 draft@1이 "수정 대상"과 "입력"에 두 번 나와 테스트가 하나를 고르지 못했다. 입력 목록에서 수정 대상을 뺐다 |

## 4. 계약을 바꾼 것

- `planRun(definition)`은 옵션을 받지 않는다. Decision과 최종 승인이 있는 정의도 실행한다. 이를 거절하던 기존 테스트 3건(`run-plan.test.ts`, `editor-model.test.ts`, `studio.spec.ts`의 TC-CAN-004-H)은 기능이 바뀌어 실행 가능함을 검사하도록 바꿨다.
- `RunnerCallbacks.loopCapReached(loopId, rounds)`를 더했다.
- `AgentStartInput`에 `round`, `criteriaVersionId`를, 입력마다 `artifactVersionId`를 더했다. ID 종류에 `approval`을 더했다.
- 투영에 `approvals`, `reviews`, `controlRevision`, `outputApprovalId`, 산출물 `parentVersionId`가 생겼다.
- Coordinator의 `decisions` 포트는 테스트에서 분기를 직접 정할 때만 쓴다.
- 승인·검토 규칙은 [API 계약](../../../docs/API-Contract.md) §4에 적었다.

## 5. 아직 하지 않은 것

- 실제 모델로 검토 Loop 실행. 검토 JSON은 각본 agent와 faux 모델로만 만들었다.
- 지시(steer)와 산출물을 잇는 경로(CRL-RNS-010)는 P6이다. 지금은 입력 버전만 잇는다.
- 승인 요청 시간 제한, 여러 사람의 승인, 승인 취소.
- control revision을 올리는 명령(patch)은 P6이다. 지금은 0에서 바뀌지 않는다.
- 사용자 취소 명령(P6). 거절한 승인은 Run을 `cancelled`로 끝낸다.
