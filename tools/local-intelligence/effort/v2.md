# 일반 코딩 난이도 분류기

기반 모델, 768차원 임베딩, 256토큰 상한과 `effort-text-v1` 전처리는 그대로다. 배포 분류기 `effort-v2`는 32개 ReLU 은닉 노드와 4개 softmax 출력을 사용한다. 정규화는 첫 affine layer에 합쳐 추가 런타임 라이브러리를 쓰지 않는다. 자동 추론 정책 이름은 `corral-effort-v1`이며 분류기 가중치 버전과 다르다.

## 데이터와 선택

- 기존 16,123개 표본을 원본 SHA256 `2f3cea1d2ffac043ec8f886c6e57b30db35b5c73a52f6d4fa5ea0400ad5bd5f2`로 고정한다. 기존 테스트 2,182개와 SWE-bench 500개를 바꾸거나 학습으로 이동하지 않는다.
- `curriculum.tsv`는 이 저장소에서 작성한 일반 코딩 요청 48가족이다. 한·영·일 번역과 실행 단계의 `ReasoningInput` 변형을 포함한 288건이다. 짧은 요청, 기계적인 수정, 원인 추적, 다중 파일 변경, 동시성·복구 설계를 포함한다. 사람 검수나 실제 모델 성공률에 기반한 정답이 아닌 작성자의 난이도 기준이다. 저장소 MIT 라이선스를 따른다.
- 가족별로 학습·검증·테스트를 고정한다. 같은 요청의 번역과 단계 변형을 분할 사이에 흩뜨리지 않는다. 기존 검증 그룹도 후보 선택용과 확률 보정용으로 나눈다.
- 기존 데이터만 사용한 후보와 데이터를 추가한 후보에 같은 선형/32·64 노드 MLP 후보를 비교한다. 후보 선택은 검증 macro-F1의 가중 평균(기존 전체 0.3, 기존 코딩 0.4, 작성한 코딩 0.3)이다. 기존 전체·코딩 검증의 정확도와 F1이 기준 모델보다 낮은 후보는 배포 후보에서 제외한다.
- 정규화는 학습 표본으로만 적합한다. 후보 선택과 별도의 검증 그룹에서 온도를 보정하고, 과소 판정 비용을 두 배로 둔 수준 오차로 보류 기준을 선택한다. 보류 시 medium이라는 기존 기본 경로를 평가한다. 유료 판정 API의 효과나 작업 성공률을 측정한 것은 아니다.
- 선택한 모델은 `augmented-mlp32-10`이다. 상세 선택 근거는 [validation-v2.json](validation-v2.json), 최종 고정 평가는 [comparison-v2.md](comparison-v2.md)와 동명 JSON에 있다. 테스트 결과를 보고 후보를 다시 선택하지 않는다.
- 같은 32노드 분류기를 기존 데이터만으로 학습한 [분리 비교](ablation-original-data.md)도 기록했다. 기존 전체 테스트는 53.3%, 작성한 코딩 시나리오는 43.8%였다. 데이터 추가 후 각각 53.0%, 58.3%다. 데이터 추가가 모든 평가를 일률적으로 높였다고 주장하지 않는다. 분리 비교의 보류값은 배포용으로 보정하지 않았으므로 정확도·F1·수준 오차만 비교한다.

## 재현

기존 README로 `<work>/original-samples.jsonl`과 `<work>/original-cpu.f32`를 만든 뒤 실행한다. `<work>`와 모델·데이터 캐시는 저장소 밖의 지속 디렉터리에 둔다.

```sh
python tools/local-intelligence/effort/curriculum.py <work>/curriculum.jsonl
node tools/local-intelligence/effort/embed.ts <work>/curriculum.jsonl <local-ai-dir> cpu <work>/curriculum-cpu.f32
uv run --no-project tools/local-intelligence/effort/train-v2.py <work>/original-samples.jsonl <work>/original-cpu.f32 <work>/curriculum.jsonl <work>/curriculum-cpu.f32 <work>/effort-model
node tools/local-intelligence/effort/compare.ts <work>/original-samples.jsonl <work>/original-cpu.f32 <work>/curriculum.jsonl <work>/curriculum-cpu.f32 <work>/effort-model/effort-v2.json <work>/comparison-v2
```

학습 도구만 Python 3.11 이상과 고정한 NumPy/scikit-learn 환경을 사용한다. 후보가 10개인 작은 분류기 학습에는 검증된 최적화기·배열 연산을 재사용하는 것이 별도 역전파 구현보다 유지보수와 재현에 유리하다. PyTorch 전체 런타임은 필요하지 않다. 도구 버전·라이선스·호환성·공식 출처는 `training-requirements.txt`, 스크립트 머리말, `pnpm deps:record --training`이 만드는 `docs/dependency-lock.json`의 `trainingDependencies`에 기록한다. 패키지 런타임 의존성에는 포함하지 않는다.

## 해석 범위

공개 평가의 정확도 개선은 약 1%p이며 그룹 bootstrap 신뢰구간은 0을 포함한다. 통계적으로 확정된 개선이라고 주장하지 않는다. 작성한 코딩 평가도 8가족 48건으로 작고 독립적인 사람 검수가 없어 실제 작업 성공률을 대신하지 않는다. SWE-bench의 라벨 기준선은 원래 자료 준비 때 참조돼 완전히 독립적이지 않다. GPU에서 새 분류기를 비교하는 검증은 별도다.

새 보류 기준의 기존 전체 테스트 판정 비율은 99.7%(기준 모델 91.7%)다. 따라서 외부 판정으로 보완하는 빈도가 줄 수 있다. 보류 기준은 검증 분할의 수준 오차로 정한 것이며, 확률이 실제 작업의 성공 가능성을 뜻하지 않는다. 외부 판정까지 포함한 품질·비용 비교는 아직 수행하지 않았다.
