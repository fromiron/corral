# 실제 기록 골드셋

공개 대리 라벨, 작성한 합성 시나리오, 교사 모델의 출력은 서로 다른 것을 재므로 어느 것도 정답이 아니다. 이 도구는 실제 기록으로 판정자가 라벨을 붙인 평가 기준을 만든다. 경계와 보고 규칙은 [로컬 AI 명세](../../../docs/specs/features/local-intelligence.md#분류기-평가)를 따른다.

## 절차

```sh
node tools/local-intelligence/gold/extract.ts --out ~/.local/share/corral-training/gold
node tools/local-intelligence/gold/label.ts ~/.local/share/corral-training/gold
```

- `extract.ts`는 Codex 세션과 작업공간의 `.corral/corral.db`를 읽기 전용으로 읽고 건수만 출력한다. 같은 입력과 시드는 같은 항목을 만든다.
- `label.ts`는 `127.0.0.1:4179`에서 사람용 라벨링 화면을 연다. 라벨은 `labels.jsonl`에 추가 기록되며 중간에 멈췄다가 이어서 할 수 있다.
- LLM 판정자의 라벨은 `labels.<모델 ID>.jsonl`에 `{id, label, at, rater}`로 따로 저장한다. 사람 라벨과 합치지 않는다.
- 테스트: `node --test tools/local-intelligence/gold/*.test.ts`

## 항목

| 종류 | 입력 | 정답 |
|---|---|---|
| 요청 | 사람이 쓴 요청과 직전 턴 | 제대로 처리할 수 있는 가장 낮은 추론 수준 |
| 실행 단계 | 요청, 직전 계획, 도구 호출 최대 3개 | 그 결과를 받은 다음 모델 턴에 필요한 가장 낮은 추론 수준 |
| 회의 | 그 시점까지의 확정 발언과 역할 설명 | 답해야 할 참가자 집합 |

- 입력 형식은 [제품 입력](../../../packages/adapter-pi/src/reasoning-input.ts)과 회의 선택기의 이력 규칙을 따른다. 수준의 뜻은 [라벨 기준표](../effort/label-rubric.md)를 쓴다.
- 서브에이전트 지시문, 주입된 지침, 승인된 계획 전문은 사람이 쓴 요청이 아니므로 뺀다. 실행 단계는 긴 작업이 표본을 채우지 않도록 요청마다 하나, 세션마다 최대 8개만 뽑는다.
- `@` 없이 수신자를 직접 고른 회의 메시지는 그 선택을 라벨로 쓴다. `@`를 입력한 메시지는 선택기를 거치지 않으므로 뺀다.
- 항목의 10%는 다른 ID로 한 번 더 나온다. 이 재라벨 일치율이 모델이 넘을 수 없는 상한의 추정치다. 앞선 판정이 남아 있는 같은 문맥에서 LLM이 다시 판정한 값은 재라벨로 세지 않는다.
- `판단 불가`와 `모호함`은 틀린 답이 아니라 라벨이 없는 항목으로 집계한다. 회의의 모호함은 선택기가 보류해야 할 사례로 따로 본다.

## 데이터 경계

- 출력 디렉터리가 Git 작업 트리 안이면 거부한다. 디렉터리는 0700, 파일은 0600으로 만든다.
- 키, 토큰, 접속 URL의 토큰, 이메일을 저장 전에 지우고 홈 경로를 `~`로 가린다.
- 라벨링 서버는 loopback에만 바인딩하고 다른 Host와 Origin을 거부한다. 항목의 분할, 출처, 재라벨 관계, 모델 예측은 화면으로 보내지 않는다. 원문은 HTML이 아닌 글자로만 그린다.
- 원문, 라벨, 임베딩을 저장소에 넣거나 공유 페이지로 게시하지 않는다.

## 한계

한 사람이 쓴 기록이고 대부분 Corral 개발 대화다. 한국어가 대부분이고 일본어는 없다. 회의는 모두 참가자 3명이라 참가자 수에 따른 변화를 재지 못한다. 이 골드셋의 수치는 이 사용자의 이 작업에 대한 값이다.
